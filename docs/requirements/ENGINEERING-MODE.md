## 1. 文档体系各仓自持（FR-V1——2026-09-12 用户裁定）

### 1.1 总体目标

一个开发者在同一工作区里同时维护本仓与对端仓时，本仓的文档只承载本仓自己的事项——对端的条目、批次档与需求不写进本仓；本仓缺的文档层就地补齐，不因「另一仓已有」而省略。

### 1.2 动机（事故溯源）

2026-09-12 凌晨的泄露事故 = **跨仓登记**：他方把外部产品线的债（含一条安全项）登记进对端仓台账，随主线合入并推到两个公开远端。内容层已清（历史移除 + 远端改写 + 本地清对象），**机制上没有闸**。

**本仓侧的同病形态**：

| 面 | 本批前现状（实测） |
|---|---|
| `docs/requirements/` | **不存在**——本仓需求写在 CLI 仓需求档里 |
| `docs/batches/` | **不存在**——本仓批档全住 CLI 仓 |
| `docs/design/` | **55 档**（顶层 `.md` 含 `README.md`；as-of 2026-09-12 实测）——**已自持**（反证本仓有能力自持） |
| 活台账指针 | 2/2 条指向 CLI 仓 |
| 台账头部 | 含跨仓引用（`ENGINEERING-MODE（CLI 仓）§1.13`） |

塌的是**需求层与批档层**；本档即需求层的补齐。

### 1.3 功能性需求

- **F1 台账射程**：本仓台账（需求池 / 技术待办）只收本仓条目——禁登记他仓 / 他项目 / 他产品线事项；**跨仓指针同样禁止**（含与对端仓的互引）。范围边界：不判**散文**里的对端提及（机检不可判——留评审），只判路径形态。
- **F2 批次档同规**：本仓批次档只登记本仓范围（含本仓的受影响文件与验收）——本仓批档住本仓。
- **F3 文档体系各仓自持**：需求档 / 设计档 / 批次档 / 台账一律本仓自持；本仓需求必须住本仓——**非复制**（语义同源、本端原文自持）。
- **F4 缺失层必须补齐**：本仓缺失的文档层就地补建——**不得以「另一仓已有」「避免重复」为由省略本仓文档**；**逐层成套**（缺层逐层补齐 + 需求层逐档三值——不得只建单层壳）。
- **F5 约束须落提示词层**：F1–F4 的行为面必须在本仓提示词层落地（不只文档层）——文档层是规格（人读 + 评审对象），提示词是代理运行期实际读到的纪律。
- **F6 机检闸**：本仓台账条目的证据 / 指针路径须在**本仓内可解析**；违规一律 fail-closed（**「存量 / 入基线」已废**——阈值 = 0；F14 同条）；L4② 判序（含外仓前缀排除 + 全匹配）见本仓设计 `docs/design/LEDGER-SELF-CONTAINED.md` §7.1。落点 = 本仓自持检查器。
- **F7 核验职责**：同一机制跨多个实现面产出**一式多份设计**时，主 agent 有义务核验各份逻辑是否一致（核验四维 = 裁定同源 / 判据同一 / 边界同形 / 差异显式登记）；该职责须落提示词层（本仓「多实现面纪律」节）。
- **F8 提示词通用化**：提示词中的多实现面条文不得绑死本产品两端（不得以本产品术语作示例、不得夹维护者注）；A1 勘察 checklist ④ 同步通用化。
- **F9 存量无豁免（宽口径 + 溯及既往——2026-09-12 05:08 用户改判）**：凡**触及本仓**的存量批档一律处置——① 实施面全在本仓 → 迁移入本仓；② 两端均有实施面 → 各仓持其份；**不得以「历史已收口 / 审计链 / 重复 / 量大 / 在飞」为由豁免任何一档**（在飞档处置照给，执行时点随其收口）。
- **F10 文档体系逐层成套（2026-09-12 05:17 用户标准）**：本仓文档体系**逐层对位**（仓根档 / 文档地图 / 台账 / 需求 / 设计 / 提示词双源 / 批次档 / 归档 / 指南），每层对位形态逐行登记；需求层**逐档三值齐备**（① 建本仓需求档 · ② 已有对位（允许异名——注明本仓实际档名；**异层者一律建档——不得以 design 层充当**）· ③ 本端无此面（写理由））；**不得只建单层壳**。
- **F11 需求层必须在本仓有档（2026-09-12 10:57 用户裁定「全部啊！」）**：**需求层必须在本仓有档**——「对端有」「design 层有」**不构成**需求层缺失的理由；**② 已有对位不得以 design 层充当**（需求住 `docs/requirements/`、设计住 `docs/design/`——两层各持其档）。范围边界：不动设计档的层位判定（设计档不迁层）。
- **F12 结构档位硬限无豁免（测试档同规——2026-09-12 10:58 用户裁定）**：>500 行硬限**无豁免通道**——「存量 / 不增内容 / 有先例」均不构成豁免理由；本仓超限档**本批拆**（拆分判据 = 设计档 D18 四条：① 组内同面 · ② 迁出组夹具 ⊆ 新档自持集 · ③ 切点零交叉 · ④ 两档 ≤500 且余量充足）。范围边界：不改测试语义——迁出例逐字搬移（断言零改 / 零增 / 零删），**用例数守恒**（余档 + 新档 = 原档实测数）；新档自持夹具（零跨档 import），并登记入 `test/files.mjs`。
- **F13 跨仓引用形态零残留（2026-09-12 10:58 / 11:06 用户裁定）**：本仓设计档 / 需求档 / 批次档正文引用对端仓文档一律**规范形态**（`名称（仓别）§N`——去 `.md` 后缀、去路径前缀）；**历史登记表 / 变更记录同受约束**（语义保留、形态规范化）；**存量不是合法态**（未清理的残留 = 破例先例源）。范围边界：**实施面文件路径**（受影响文件表 / `files` 声明 / 证据行）按「路径去仓前缀 + `（仓别）`」标注，不按节号形态（路径无节号可指）；对端仓同形残量 = 跨仓写域（列清单、上报，不代写）。

- **F14 先例不构成例外依据（2026-09-12 11:40 用户裁定）**：任何「以前也这样 / 已落形态 / 他批先例 / 存量在案」**都不构成偏离规则的依据**——**例外的唯一依据是判据句（可机判）**；找不到判据句 → **按规则办，或停下上报**；不得以先例为由放行。
  **同条（看得见的每一行都是先例）**：设计档 / 需求档 / 批次档 / 台账 / 变更记录中的**残留即示范**——合规形态必须显式（**机检命中即红**）；历史语义可保留、**形态必须规范**；**「存量豁免 / 入基线」不得再设（阈值 = 0）**。
  **同条（例外须带消解期）**：任何登记在案的例外必须写明**消解路径与到期条件**——否则 = 永久先例 = 变相废规。
  范围边界：判据射程 = **形态面**（A 类叙述性提及收紧为**封闭枚举**——枚举外即红）；散文语义本身不属机检射程（留评审——与 F1 边界同源）；不新设「枚举外白名单 / 逐项豁免」通道。

### 1.4 非功能性需求

- **N1 零假阳**：机检新规则对本仓合法内容零命中（无路径散文 /「名称（仓别）§N」规范形态不入判据）——零假阳才能常驻。
- **N2 fail-closed**：跨仓登记形态必被拦住（新增违规阻断、退出码非零）。
- **N3 可分步**：存量迁移允许分期——**每期须有明确触发条件与逐档清单**，不得停在「待议」。
- **N4 否决在案（否定式需求）**：**不得**以「本仓无自持需求档 / 批档」为由放宽为「允许跨仓指针」。
- **N5 不跨仓依赖**：本仓检查器为**独立实现、语义同源**——不跨仓 import（判据 = 各仓自持 + 多实现面纪律「各端独立实现、语义同源」；`src/ledger.mjs` 头注载明同形态——在位事实）。

### 1.5 两轴并列（不留两套口径）

本档管**条目与归属**（轴一）；文档正文引用他仓文档仍按既有 V1 跨仓边界规范（「名称（仓别）§N」= 显式域外——轴二，见本仓 `docs/design/README.md` 规则）。
一句话：**正文可以指他仓（规范形态），条目与归属不行**。
