# 工具系统（TOOLS）— 需求

> 板块：工具系统（注册表/调度/安全边界/描述规范）。需求层文档（`docs/requirements/`）。
> 来源：2026-09-10 自 `../design/TOOLS.md` 抽取需求陈述（§4 安全边界 / §10 描述六要素——设计档保留机制细节）。
> 状态：**现行**。
> 设计+测试见 `../design/TOOLS.md`。

## 1. 总体需求

工具是模型作用于外部世界的**唯一入口**。工具系统必须做到：注册面单一可枚举、调度确定、安全边界可解释、
描述文本足以让模型正确路由、**配置申报与消费一一对应（无死键）**。

## 2. 功能性需求

| # | 需求 | 说明 |
|---|---|---|
| F1 | 注册面单一 | 工具注册表是权威列举面——新增/删除工具须改一处且可被探针枚举 |
| F2 | 描述六要素 | 工具描述（md/内嵌）必含：① 一句话语义 ② 参数关系 ③ 路由/反模式 ④ 副作用与权限 ⑤ 错误形态 ⑥ 多端一致 |
| F3 | 描述多端一致 | CLI / VS Code 同语义（逐字锚走评审流程） |
| F4 | 触发即证据 | 工具执行期间的 console 输出回显到结果（调试价值） |
| F5 | 交互轻量 | 工具不该与用户对话；需用户输入的场合（如 `question`）由专门机制承担 |
| F6 | `websearch` 后端选择面单一 | 后端由 `websearch.apiKey` 触发：有 key → Tavily 结构化搜索；无 key → Bing 兜底（零配置可用）。不设独立后端选择键——`provider` 死键已移除（2026-09-11 第 36 批）。**判定句**：申报面（`config.mjs` DEFAULTS / README 配置模板）无 `provider` 键 ∧ `src/` 零 `websearch.provider` 读取（扫描 0 命中）∧ 无 key 调用行为与现状一致 |

## 3. 非功能性需求

| # | 维度 | 标准 |
|---|---|---|
| N1 | 安全模型 | **信任模型 + 审批门控 + 快照为真实防线**——不以文本匹配拦截破坏性操作（"安全剧场"已否决：恶意模型必然绕过，拦住的多是正常操作） |
| N2 | 路径边界 | **无边界解析**：相对路径相对 cwd、绝对路径原样、符号链接正常跟随；**无目录限制**——信任模型 + 权限门禁为唯一防线 |
| N3 | 命令 | **零文本拦截**：破坏性命令一律放行，走审批 + 快照；仅保留危险标注（只给人看红标，不拦截）。bash 超时 120s |
| N4 | 网络 | SSRF 防护（localhost / 内网 / 云元数据 `169.254.169.254`）；响应体 ≤5MB；HTML 转文本 |
| N5 | 资源上限 | read ≤2000 行 / 输出 ≤200,000 字符（超限落盘 + 预览）；write 前自动语法检查（JS） |
| N6 | 执行边界 | `execute` = 纯净 node ESM 子进程，与 bash 同边界（无伪沙箱、无 import 阻断、无预置全局）；**文件能力唯一入口 = 专用工具**；超时 SIGKILL（默认 30s，上限 600s） |
| N7 | lint 零依赖 | `node --check` 快路径 + 语言级联（tsc/ruff/cargo/go vet）；eslint 级联已删（2026-09-02，零依赖政策） |
| N8 | 配置面诚实 | 工具配置的申报面（DEFAULTS / 配置文档模板 / 两端写入面）与消费面一一对应：申报键必有代码读取点；无读取点的键不申报（发现即删——声明 + 文档 + 写入面收口）。**判定句**：`websearch.provider` → 零申报 ∧ 零读取；遗留磁盘值 → `loadConfig` 不抛、行为与未设置一致（兼容判定） |

## 4. 范围边界（不做）

- 不做文件系统沙箱 / 目录白名单（N2：信任模型取代）
- 不做命令文本黑名单拦截（N3：安全剧场）
- 不做 `execute` 的 import 阻断或伪沙箱（历史 `exec-prelude` 已退役）
- 不设 websearch 显式后端选择键（`provider` 枚举已移除——后端选择由 `apiKey` 触发承担；多后端并存（如 DeepSeek 官方搜索端点，Gitee #IKEI3M 待外部证据）到来时另批设计选择面）
