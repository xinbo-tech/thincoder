## 2.7 提示词编写纪律（15 条——A 内容性 / B 表达性 / C 工程纪律）

**A. 内容性纪律（写什么/放哪）**

1. **层归属先行**：每句内容先过 §4 判定法定槽位——放错层的句子一律不写；同槽不重复、同槽复用
2. **单一权威源**：同一规则只在一处详述——其他位置至多一行指针（"per discipline-xxx"），不复制正文
3. **人格不越层**：人格层只写身份/边界/交付物；流程和规则绝不混入人格层；反之纪律层不重宣言身份
4. **双端语义同源**：双语端文件按多实现面纪律——各端原文自持、互不追赶、端特有段原地保留、差异如实上报

**B. 表达性纪律（怎么写——继承注意力优化 7 原则，PROMPT-ATTENTION-RESTRUCTURE §需求）**

5. **优先级排序**：最高优先规则（听用户的闸/批准门/叫停）放文件最前部——含"前 20% 巡检词"要求
   （AC-2：`WAIT` / `initiated by the user` / `Do NOT` / `auto`/`manual`）
6. **规则独立成短句 + 加粗关键词**：关键指令一行一条，加粗触发词；标题（`##`/`###`/伪标题
   `**xxx:**`）独占一行
7. **命令句 + 否定强调**：闸用祈使/禁止句——非叙述性——命令句注意力权重更高
8. **关键规则放首/尾**（serial position）：批准门等放每条消息处理规则顶部
9. **减量提权**：长文机制细节从正文移走/指向文档——减总量提升剩余注意力；Markdown 表行不可换行，
   表行 >200 转 `- **State** → action` 条目对（词序保原）
10. **关键锚点多处重复**（不同措辞）：顶部总则 + 具体 flow 点 + Hard Rules；**视觉锚**：`>` 块引用 /
    加粗 / 独立行——关键行有结构性凸起

**C. 工程纪律（怎么改）**

11. **可判可测**：规则句写成可判定断言（能机械或明确判断违没违反）——"尽量/适当/合理"类模糊词须
    给出判定锚；真正自由裁量处显式声明裁量
12. **锚稳定**：被测试 fail-when-unchanged 锁定的锚句，改写 = 同批改断言（锚句变更永不静默）；锚句
    保持句式稳定不随手润色；保逐字整句不拆（核心纪律句族 + 行内引用整块保行）
13. **变更走批**：提示词内容变更 = 设计批评审 + 批准，不走"顺手改"；每文件头部注本槽位与消费方
    ——**变更流程界定（用户裁定 2026-09-10）**：提示词文件（src/prompts/*.md）= **设计文档性质**（给
    模型的规格文本，非代码）——变更走**设计文档流程**（架构师直接编写/修订 + 内容质量把关），**不走
    eng-coder 实现链**（纯文本无执行面——无审计/测试/L2 需求）；装配代码（setup.mjs/prompt-
    overlays.mjs 等）= 代码，工程模式实现链不变。对施工的映射：文本迁移/内容修订类 = 架构师直接做；
    锚测试/装配代码 = eng-coder 链
14. **语义与格式永不混批**：语义改动与格式重排永不混批（重排批"零语义改动——只断行/换行/换位/
    提权——不改任何一个字"铁律沿用；内联引用不切：token 模板/按钮文案/确认语整块保行）
15. **提示词不含维护者注**（用户裁定 2026-09-10）：提示词写给模型执行——只需规则本体。出处/日期/
    批次名/评审号/施工进度/变更史（如"语境（2026-09-09——某批）：…""（用户裁定 2026-09-10）"
    "（某批 A1 锚——施工③随迁落位）"）一律**进设计档不进提示词**——模型不需要知道内部项目管理词
    汇。例外：日期本身携带行为语义的（如语义生效边界）保语义去日期注。本纪律与 #2 单一权威源互为
    表里：维护者注的权威归宿 = 所属设计档

## 3. 装配逻辑

### 3.1 四槽位固定序（主装配链——主会话 + 常规子代理）

```
[1] 人格层 → [2] 公共层 → [3] 纪律层 → [4] 其他
```

- 每槽至多一份文件；未命中角色/模式的槽位跳过
- **人格先行**：身份定义永远先于行为规则
- **公共恒二**：common.md 位置固定——人格冲突不落入公共层
- **同槽位不重复**：一个槽位一份文件（同一层禁止两份文本并存）
- **同槽位复用**：同层多场景语义一致时共用同一份文件，不另立副本（变体差异归人格层覆写）

### 3.2 装配矩阵（目标态——每个场景一行，子代理不合并）

## 4. 内容归属判定规则（新增/修改提示词内容的分层判定法）

1. "模式/角色里你是谁、交付什么、边界在哪" → 人格层
2. "两模式逐句都要的协作基础" → 公共层
3. "该模式下怎么干活（流程/规则/工具观）" → 纪律层
4. 仅项目相关 → 项目层（cwd）；冲突判定：人格层 > 公共层（人格定义边界，公共层不得越界）

**判定法关键区分（2026-09-10 盘点沉淀）**：
- **公共层 = “两模式 + 全角色逐句需要”**——不是“多处出现”。反例：子代理共性（C3）重复 5 处但仍留人格层——因主会话不需要，而公共层不是放条件节的地方。
- **人格层 = 角色独特形态**——同一协作原则在不同角色有不同具体形态时（如系统接口语义 C8：各角色收到的提醒字段不同），归人格层各写各的，不强行抽象。
- **特殊域（consult/advisor）= 自包含注入**——不注入公共层，其内部重复不受公共层迁移影响（受控双源先例）。
