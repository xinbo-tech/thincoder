## 1. 总体目标

让**任意用户项目**（任意语言 / 目录布局 / 文档约定 / 有无 git）与本产品自研仓上，
工程模式全流程（需求 → 设计 → 评审 → 实现）都能正确工作：

- 不得假定项目约定（文档布局 / 命名 / 语言 / 构建 / 测试方式）；
- 凡需要项目约定处，由**项目自述或配置**提供；
- 缺失时**降级可见**——写进评审消息 / 工具反馈 / 同步结果，不得静默失效。

## 3. FR14 落实文本（推进档位交互契约）

工程模式的推进档位（auto / manual）是**用户可感知的交互契约**，定义如下：

- **两档**：**auto**（默认——每步完成即呈现、随即推进下一步）；**manual**（每步完成即呈现、**等待用户明确放行**再推进）。
- **切入 manual**：用户叫停 / 要亲自把关时切入——判据是**意图不是词表**（"停 / 先别 / 别急 / 等下 / 别自动"等表达均算）。
- **manual 下的行为**：继续回答与讨论、呈现当前结果；但**跨步动作停住**（spawn / 评审发起 / 推进落档 / digest 后动作都等用户点头）。
- **恢复 auto**：用户下一条明确指示（"可以 / 继续 / 开始"或具体下一步指令）即恢复；原状态不丢。
- **性质**：档位是**步与步之间的闸**，不是新状态；WAIT 前的讨论与呈现照常。

> 档位的运行面细节（提示词槽位、digest 机器信号、User stop 处理）已在工程模式纪律层提示词中生效；
> 本条需求的确立 = 把该契约**登记进需求层**（此前只活在提示词里）。
