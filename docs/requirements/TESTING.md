# 测试基建（TESTING）— 需求

> 板块：测试基建（分层纪律/库存治理/slow 门）。需求层文档（`docs/requirements/`）。
> 来源：2026-09-10 自 `../design/TESTING.md` 抽取需求陈述（§1 分层纪律 + slow 门——设计档保留机制细节）；2026-09-11 扩入测试生命周期与集成集（TEST-LIFECYCLE 批）；2026-09-12 扩入散文锚退役与禁令（PROSE-ANCHOR-RETIRE 批——§5）；2026-09-12 修正轮：§5.1 判据补充（C1-a–c：提示词句子不豁免 / 工具契约面保留 / 非句子对象保留）+ F17 增工具契约面。
> 状态：**现行**（分层纪律 + slow 门 + 测试生命周期/集成集 + 散文锚退役与禁令）。
> 设计+测试见 `../design/TESTING.md`。

## 1. 总体需求

一次代码改动的验证必须**按层收口**，避免"随便改一点就跑上千个测试"——浅改浅验、深改深验、链终一次全量。
验证成本的大头是重 IO 而非用例数量，因此分层按**耗时**而非目录切分。

测试体系同时按**寿命**组织：单元测试是开发期工具（为改对代码而写——用过即退役，批次收口逐条处置）；
集成测试是业务资产（业务设立 + 生产补入——常驻，承担发布门验收）。两类来源不重复覆盖（单元不属于验收面）。

| F14 | 双端实例化 | 场景目录在 CLI 与 VSC 两仓各自实例化（语义同源、各端原文自持、不做 byte 一致） |

## 3. 非功能性需求

| # | 维度 | 标准 |
|---|---|---|
| N1 | slow 门（分层执行） | **作用域 = 单元档（`test/` 顶层 `*.test.mjs`——快/全两层执行面内）**：需真实 fs / git 子进程 / 定时器 / 网络的测试（单用例 >500ms）用 `slow(name, fn)` 包装——快层自动 skip（可见 `↯ skipped`，不隐身），全量（`npm run test:full` / `THINCODER_TEST_FULL=1`）跑；集成档不在本门作用域（不得用 `slow()`——设计档 §4.3） |
| N2 | 零漂移 | 快层与全量共用同一套断言文件（不改名不挪目录）——同一断言两种执行面 |
| N3 | 防漏硬红 | 跑完机械检查「未标 slow 而超过拦截阈值」的用例，**逐条点名 + 非零退出**（腐化根因就是无人拦截） |
| N4 | 阈值缓冲 | 拦截阈值 **800ms** > 归册阈值 **500ms**（机器负载抖动不触红）；env `THINCODER_SLOW_GATE_MS` 可覆盖 |
| N5 | 快层并发上限 6 | `--test-concurrency=6`（4 核实测 29s → ~17-20s；**勿再调高**——c8 会把 400-500ms 中位带通胀过拦截线，打地鼠式误红）；`test:full` 不动（默认调度） |
| N6 | 阈值实测依据 | >500ms 的测试约占全量 CPU 的 **95%**，而 <5ms 的过半测试合计仅 376ms——**数量不是成本，重 IO 才是** |
| N7 | ②集与需求同步演进 | 需求发展/行为变化必须触发集成集评估（主 agent——不外包不自动）；集成集不得落后于需求（判据 = 每批 §6 处置行 ②半 有记录） |
| N8 | 最小可跑起步 | 首批集成集 = 场景最小集（三态齐全）；扩面只走两个入口（业务设立 ② / 生产收编 ③）——不预防性铺量 |
| N9 | 自动可跑 | 集成集必须可自动执行（发布门内跑——不依赖真实付费端点、不依赖人工操作） |

## 4. 范围边界（不做）

- 不用目录分层做**快/慢分层**（`test/**` 是唯一约定入口；同档门控让单文件调试与全量永远走同一断言）——集成集以 `test/integration/` 子目录分界属**生命周期**划分（①/②③），非执行层划分（见 F12）
- 不设独立测试角色（维护模型零新角色——职责随既有角色，见 §2.1）
- 集成集不调真实付费端点、不依赖人工操作（真端点 smoke 仍独立于所有层）
- 不维持存量测试库存（2026-09-07 起"按需加"）——本机制为"按需加"的产物补寿命与收口处置

## 5. 散文锚测试退役（PROSE-ANCHOR-RETIRE）

> 来源：用户 2026-09-12 裁定 R1–R5（批次档 `../batches/2026-09-12-PROSE-ANCHOR-RETIRE.md` §1）。
> 一句话：**读档断言「某句在场 / 缺席」的测试一律不做**——收益无实证（举不出该类锚抓到真实漂移的记录），成本可量化（改一字即红、失败信息零信息量、锚红后的动作永远是「把字改回去」）。
> 设计 + 逐条删除清单 = `../design/TESTING.md` §11。

### 5.1 判据（三条同时成立 = 散文锚）

| # | 条件 |
|---|---|
| ① | 断言对象是**非测试档**文本（`src/**` · `docs/**` · `AGENTS.md` · `README*` · 仓根 `*.md` / `*.json` · `package.json` · `scripts/**` · `bin/**` · `webview/**` · `locales/**`；VSC 侧另含兄弟仓 `../thincoder/**`）或其派生切片 |
| ② | 断言其**文本内容**在场 / 缺席 / 出现次数 / 相对顺序（`.includes` · 常量子串 `assert.match` · `.startsWith` · `.endsWith` · `.indexOf` · 文本计数） |
| ③ | 断言对象**不是**结构机检保留面所判的属性（保留面 = F17 封闭枚举） |

**载体判据（判据 ① 的落地口径）**：断言对象是**执行产物**（函数 / 工具返回值、子进程输出、渲染帧、测试自建临时域文件）或**结构 / 数值常量** → 不命中 ①；
经 `import` 取到的 src 静态文案字面量 → 命中 ①。

**判据补充（2026-09-12 修正轮——PA-A1 / PA-A3 裁定；判据 ① 的「实质」判法）**：

| # | 补充 | 内容 |
|---|---|---|
| C1-a | **提示词句子不豁免**（PA-A1） | **不问文本从哪来**（读盘 / 装配器或渲染出口的返回值 / 写入 `systemPrompt` 的装配结果），只问**断言的是否是提示词句子**——断言提示词句子（装配器传出的话语、注入块、降级句、槽文本，以及装配产物**与字面常量的全文相等 / 不等**）→ 命中 ①；**「不读文件」不是豁免理由** |
| C1-b | **工具契约面与工具返回文案保留**（PA-A3） | **模型实际收到的工具契约对象**（`tool.description` / 参数说明）与**工具返回 / 拒绝文案** → 契约守卫 / 行为输出，非文档散文锁 → 不命中 ①；读 `src/**` 源码档文本（含源码里的描述串）仍命中 ① |
| C1-c | **非句子对象保留**（载体判据原义） | 结构 / 数值 / 判定信号（槽文件表与集合成员、长度、警告清单与警告文案、旗位、退出码）→ 不命中 ① |

### 5.2 功能性需求

| # | 需求 | 说明 |
|---|---|---|
| F15 | 退役类别 | 散文锚 = §5.1 三条同时成立的断言；**一律不做**——含双端提示词镜像锚（`prompts-dual-source` / `prompts-mirror-anchors` / `prompts-async-guidance` 的大头；用户对「保留双端镜像锚」的建议明确否决）。 |
| F16 | 存量全删 | 已落地散文锚断言**全删**（无「保留待议」项）；CLI + VSC 两仓同批。 |
| F17 | 保留面（封闭枚举） | 结构机检一类**不删**：`doc-consistency` V1 / V2 / V3（引用可解析 / 计数相符 / §3 轮次行）· `check-ledger` L1–L3（指针可解析 / 组计数 / 六态取值）· `check-doc-width`（行宽）· `slow` 门（归册防漏）· **工具契约面**（工具 `description` 等发给模型的契约文案——契约守卫）。判据 = 断言**结构自洽**，非断言**句子在场**（判据 ① 的实质判法 = §5.1 C1-a–c）。 |
| F18 | 混装档只删锚断言 | 行为用例 / 结构机检 / slow 门**一律不动**；**不得整档删**（零误删）。 |
| F19 | 禁止新写 | 新增断言只允许**行为面**（业务可观察结果）与**结构机检面**；**禁止新写散文锚**。纪律落点 = 提示词双端测试纪律节（`discipline-engineering.md`）+ 本档 + 设计档。 |
| F20 | 双端同批 | VSC 仓同族同批处置——语义同源、各端独立实现、**不做 byte-identical、不加跨端同步依赖**。 |
| F21 | 清单制 + 对账 | 设计产出 = **逐条删除清单**（`档:行` + 用例名 + 归类依据），交父侧核销；**快层用例总数下降 == 清单整删条数**（可机判）。 |
| F22 | 点名项同批处置 | `test/ledger.test.mjs` T95（归属修订文本面）+ 设计档 `ENGINEERING-MODE.md` §3.1 AC75 / §3.2 T95 行随本批退役（形态见设计档 §11.5）。 |

### 5.3 非功能性需求

| # | 维度 | 标准 |

### 5.4 边界（不做）

- `check-ledger.mjs` / `check-doc-width.mjs` / `doc-consistency` V1–V3 的**语义与判据零改**（保留面不动）；
- 台账本体内容治理（归档移档等）· `slow` 门阈值与归册纪律 · 行为测试的增删改；
- **既有验收标准（AC）中的锚式判据**不随本批清理（本批射程 = 已落地测试断言 + F22 点名的两项）；新批次的 AC 判据按 F19 只写行为面 / 结构机检面。
