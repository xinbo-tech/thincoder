## 1. 总体需求

本端测试只在**系统行为 / 结构自洽**上红：读非测试档断言「某句在场 / 缺席」的散文锚断言一律不做；
存量全删、禁止新写；保留面（结构机检）不弱化。本档承载本端 F/N 条目与判据口径——
与 CLI 侧同标识条目（测试基建需求（CLI 仓）§5）语义同源、各端原文自持。

## 2. 判据（三条 + 判据补充 C1-a–d——判据 ① 的实质判法）

一条断言属**散文锚**（删），当且仅当三条同时成立：

① 断言对象是**非测试档**文本——一切非 `test/**` 的仓内文件（`src/**` · `docs/**` · `scripts/**` · `webview/**` ·
   `locales/**`〔资源文本保留——C1-d〕 · `package.json` · 仓根 `*.md` / `*.json` / `*.mjs` · `AGENTS.md` · `README*`；
   另含**兄弟仓**（CLI 仓））或其派生切片；
② 断言其**文本内容**在场 / 缺席 / 出现次数 / 相对顺序（`.includes` · 常量子串 `assert.match` · `.startsWith` /
   `.endsWith` / `.indexOf` · 文本计数 · 全文相等 / 不等）；
③ 断言对象**不是**结构机检保留面（F17 封闭枚举）所判属性。

**载体判据（判据 ① 的落地口径）**：断言对象是**执行产物**（函数 / 工具返回值、子进程输出、渲染帧、测试自建临时域文件）
或**结构 / 数值常量** → 不命中 ①；经 `import` 取到的 src 静态文案字面量 → 命中 ①。

**判据补充（PA-A1 / PA-A2 / PA-A3 裁定——与 CLI 侧同源、本端原文自持）**：

| # | 补充 | 内容 |
|---|---|---|
| C1-a | **提示词句子不豁免**（PA-A1） | 不问文本从哪来（读盘 / 装配器或渲染出口的返回值 / 写入 `systemPrompt` 的装配结果），只问断言的是否是提示词句子——是 → 命中 ①；**「不读文件」不是豁免理由** |
| C1-b | **工具契约面与工具返回文案保留**（PA-A3） | **模型实际收到的工具契约对象**（`tool.description` / `parameters` 说明）与**工具返回 / 拒绝文案** → 契约守卫 / 行为输出 → 保留；读 `src/**` 源码档文本仍命中 ① |
| C1-c | **非句子对象保留** | 结构 / 数值 / 判定信号（槽文件表与集合成员、长度、警告清单与警告文案、旗位、退出码）→ 保留 |
| C1-d | **locales 资源文本保留**（PA-A2） | `locales/**` 文本值 = **产品资源文案**（界面 / 本地化面）→ **不命中 ①**（保留、不进清单）；读非测试档**源码 / 文档文本**仍命中 ① |

## 3. 功能性需求（F15–F22）

- **F15 退役类别**：散文锚 = §2 三条同时成立的断言；**一律不做**——含本端提示词镜像锚
  （`prompts-mirror-anchors` / `prompts-async-guidance` 的大头；用户对「保留双端镜像锚」的建议明确否决）。
  范围边界：不涉行为断言、结构机检、slow 门。
- **F16 存量全删**：已落地散文锚断言**全删**（无「保留待议」项）——本端全量处置（含 PA-A1 追加面：
  装配器 / 渲染出口传出的提示词句子断言）。范围边界：对端同批处置、对端需求自持于对端档。
- **F17 保留面（封闭枚举）**：结构机检一类**不删**——`doc-consistency` V1/V2/V3 · `check-ledger` L1–L3 ·
  `check-doc-width` 行宽 · `slow` 门 · **工具契约面**。判据 = 断言**结构自洽**，非断言**句子在场**。
  本端执行面构成（端差登记）：`scripts/check-doc-width.mjs`（行宽 + 一致性 V1/V2/V3 单源）+
  `scripts/check-syntax.mjs` + `test/doc-consistency.test.mjs` + slow 门；**本端无 `check-ledger.mjs`**
  （台账机检住 CLI 仓——端差在册，见设计档 §8.2，不新造脚本）。
- **F18 混装档只删锚断言**：行为用例 / 结构机检 / slow 门**一律不动**；**不得整档删**（零误删）。
- **F19 禁止新写**：新增断言只允许**行为面**（业务可观察结果）与**结构机检面**；**禁止新写散文锚**。
  纪律落点 = 本端提示词（双源）测试纪律节 + 本档 + 设计档。范围边界：对端落点自持于对端档。
- **F20 双端同批**：对端（CLI）同族同批处置——**语义同源、各端独立实现、不做 byte-identical、
  不加跨端同步依赖**；对端条目自持于对端档。
- **F21 清单制 + 对账**：设计产出 = **逐条删除清单**（`档 + 用例名` + 归类依据），交父侧核销；
  **快层用例总数下降 == 清单整删条数**（可机判）。
- **F22 点名项同批处置**：本端无对应点名项（T95 / AC75 为 CLI 侧面）；本端清单条目口径同 F16 / F21。

## 4. 非功能性需求（N10–N12）

- **N10 可机判对账**：对账式：`用例总数(批后) = 用例总数(批前) − 清单整删条数`；
  计数口径 = 顶层 `test/*.test.mjs` 内 `test(` / `slow(` / `it(` 起始行计数（双端同口径——语义同源；
  对端口径自持）。本端基准 = 653 → 592。
- **N11 发布门不降**：删除后 `vscode:prepublish` 三环（lint → test:full → test:integration）全绿；
  结构机检（F17）不得因本次改动而弱化——本端 `scripts/check-doc-width.mjs` 判据面**零改**。
- **N12 零误删**：清单外断言零触碰；结构机检 / 行为用例 / slow 门零改动（删除集与保留集互斥且穷尽）。

## 5. 边界（不做）

- 保留面（V1–V3 / L1–L3 / 行宽 / slow 门）的**语义与判据改动**；
- 台账机检执行面新建（本端无 `check-ledger.mjs`——端差在册，不新造脚本）；
- 行为测试的增删改；新增测试档；本端登记制与两清单边界（`test/files.mjs` / `test/integration/files.mjs`）；
- 既有验收 AC-VT1–AC-VT7 的语义；
- 需求跨仓承载（本端需求住本端——各仓自持、禁止跨仓写需求）。
