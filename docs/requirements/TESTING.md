# 测试基建（TESTING）— 需求

> 板块：测试基建（分层纪律/库存治理/slow 门）。需求层文档（`docs/requirements/`）。
> 来源：2026-09-10 自 `../design/TESTING.md` 抽取需求陈述（§1 分层纪律 + slow 门——设计档保留机制细节）。
> 状态：**现行**（分层纪律 + slow 门仍生效）。
> 设计+测试见 `../design/TESTING.md`。

## 1. 总体需求

一次代码改动的验证必须**按层收口**，避免"随便改一点就跑上千个测试"——浅改浅验、深改深验、链终一次全量。
验证成本的大头是重 IO 而非用例数量，因此分层按**耗时**而非目录切分。

## 2. 功能性需求

| # | 需求 | 说明 |
|---|---|---|
| F1 | 四级分层 | L0（每修正轮：改动即时验证 + verify 声明）/ L0+（首次实现：语法 + 定向测试，秒级）/ L1（快层 `npm test`）/ L2（`test:full` 全量） |
| F2 | 首次实现只做 L0+ | **不做全量**——报告义务句："not full-suite verified — the parent-side L2 run is the only full-suite point." |
| F3 | L2 归属父侧 | 链末父侧终验恰一次/端，**不在 eng-coder 链内跑** |
| F4 | verify 不代跑 | verify 三层都只收模型的 `verification.status` 声明（passed / skipped+reason），不代跑任何测试 |
| F5 | 单文件调试可用 | `node --test test/xxx.test.mjs` 直达（不经过快层入口，无拦截） |

## 3. 非功能性需求

| # | 维度 | 标准 |
|---|---|---|
| N1 | slow 门（分层执行） | 需真实 fs / git 子进程 / 定时器 / 网络的测试（单用例 >500ms）用 `slow(name, fn)` 包装——快层自动 skip（可见 `↯ skipped`，不隐身），全量（`npm run test:full` / `THINCODER_TEST_FULL=1`）跑 |
| N2 | 零漂移 | 快层与全量共用同一套断言文件（不改名不挪目录）——同一断言两种执行面 |
| N3 | 防漏硬红 | 跑完机械检查「未标 slow 而超过拦截阈值」的用例，**逐条点名 + 非零退出**（腐化根因就是无人拦截） |
| N4 | 阈值缓冲 | 拦截阈值 **800ms** > 归册阈值 **500ms**（机器负载抖动不触红）；env `THINCODER_SLOW_GATE_MS` 可覆盖 |
| N5 | 快层并发上限 6 | `--test-concurrency=6`（4 核实测 29s → ~17-20s；**勿再调高**——c8 会把 400-500ms 中位带通胀过拦截线，打地鼠式误红）；`test:full` 不动（默认调度） |
| N6 | 阈值实测依据 | >500ms 的测试约占全量 CPU 的 **95%**，而 <5ms 的过半测试合计仅 376ms——**数量不是成本，重 IO 才是** |

## 4. 范围边界（不做）

- 不用目录分层（`test/**` 是唯一约定入口；改名 + 同名导出门控，让单文件调试与全量永远走同一断言）
- 不维持存量测试库存（2026-09-07 起"按需加"——测试随机制需要按需补）
