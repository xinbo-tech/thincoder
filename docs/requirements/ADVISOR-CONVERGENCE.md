# 评审收敛（ADVISOR-CONVERGENCE）— 需求

> 板块：评审收敛（advisor 审 → 修 → 复审循环的收敛保证）。需求层文档（`docs/requirements/`）。
> 来源：2026-09-10 自 `../design/ADVISOR-CONVERGENCE.md` 抽取需求陈述（§1 目标——设计档保留机制细节）。
> 状态：**现行**。
> 设计+测试见 `../design/ADVISOR-CONVERGENCE.md`；工程模式整体需求见 `ENGINEERING-MODE.md`（NFR2 收敛性）。

## 1. 总体需求

独立评审必须在"审查 → 修复 → 复审"循环中**收敛**：要么确认全部问题已修复（passed），
要么在**有限轮次内机械终止**。

> 历史病根（需求的来源）：advisor 反复执行、每轮全量扫描都报新问题、永不收敛（收敛约束只存在于 user 级
> 消息、system 权重压过 user）；以及复评引用旧文件状态、把已修复问题反复报回。

## 2. 功能性需求

| # | 需求 | 说明 |
|---|---|---|
| F1 | 轮次衰减 | system prompt 按轮次替换——ROUND1 全量、ROUND2 验 prior 为主、ROUND3+ **严格只验 prior** |
| F2 | 机械 cap | `MAX_ADVISOR_ROUNDS = 5`（仅代码评审）——第 6 次启动**机械终止、不消耗 LLM** |
| F3 | design 评审豁免 | design 评审不消耗该预算（cap 豁免——见工程模式 NFR2） |
| F4 | 会话隔离 | 每轮 fresh session（旧 read 数据物理不在上下文） |
| F5 | 证据机械校验 | host-verified citations 机械比对磁盘（模型引用的 file:line 逐条核） |
| F6 | 确定性状态 | 轮次/失效/重置全部由运行状态位决定，**不解析 LLM 输出** |

## 3. 非功能性需求

| # | 维度 | 标准 |
|---|---|---|
| N1 | 收敛保证 | 有限轮内必然终止（机械 cap）——不依赖模型自觉 |
| N2 | 评审对象稳定 | 评审对象由调用时显式传入的文档清单定义，不遍历 git diff（工程模式 FR2） |
| N3 | 触发范围克制 | 用户裁定：**不肆意扩大**评审触发范围——评审在既有流程节点触发，不为"多审几次"扩大 |

## 4. 范围边界（不做）

- 不做"每轮全量重扫"（F1 轮次衰减已取代——历史病根）
- 不做 LLM 输出解析来判定状态（F6：确定性状态位）
- 不在 design 评审上施加 cap（F3）

## 5. 待设计需求（2026-09-10 用户裁定——问题成立，待设计）

### 5.1 评审注入的路径不得硬编码项目约定

**问题（实证）**：`src/advisor/messages.mjs` 向 advisor 注入项目上下文时硬编码了路径约定：

| 注入面 | 硬编码 | 位置 |
|---|---|---|
| 文档地图 | `docs/README.md`（新）+ `docs/design/README.md`（旧 fallback） | `:245-254` |
| 项目方法论 | 项目根 `METHODOLOGY.md` | `:236`、`:349` |

根路径取 `guideRoot ?? agent.cwd`（=`injectProjectGuide` 从评审范围反查的项目根）——即**被评审项目**，
不是 ThinCoder 自身（此点无错）。

**错在哪**：ThinCoder 是通用 coding agent——用户项目的文档布局不由我们定。布局不同（`doc/`、
`documentation/`、根级单文件…）时探不到会**静默跳过**——"Document ownership"评审维度与方法论基准
**无声消失**，用户不可见、不可修。等于把自家仓库的布局烧进产品。

**待设计方向（不预设结果）**：① 配置项（`advisor.*` 指定地图/方法论路径）；② 由**项目自述**声明
（AGENTS.md 声明指针行——项目层本就是项目自己的口）；③ 保留约定探测作便利 fallback（当前候选列表）。
可组合。

**验收方向**：项目可用非默认布局启用这两个评审依据；未声明时**要么降级可见（写进评审报告）、要么可配**——
不得静默丢维度。
