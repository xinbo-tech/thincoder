## 1. 文档更新纪律（D1–D8——设计侧机制）

 写稿权唯一只是**必要条件**；反复栽的是**更新纪律缺位**。八条纪律的语义 = `requirements/ENGINEERING-MODE-V2.md` §13.1（需求侧权威——现列 D1–D7；**D8 为设计侧新增，需求侧同步 = 主 agent 域**）；本节给**机械面**与**细则**。

| # | 纪律 | 机械面 / 细则 |
|---|---|---|
| D1 | 写权矩阵 | 文档类 → 唯一作者（批次档 = 主 agent；需求档（项目需求 + 功能规格）= 主 agent；设计档（架构设计 + 模块设计）= eng-designer；提示词 = 主 agent 内容权 + eng-coder 落笔）——无机械门，靠角色契约与评审核验 |
| D2 | 单一权威源 | 一条机制只在一处详述，其余处只引用不重述（**模板同理**——批次档模板只在需求侧机制档 §1.12） |
| D3 | 计数·枚举纪律 | 「N 项/处/条」与列表**同时改**；机判 = **无**（V2 无机检器——v2 收敛撤除，§4.2.6）；本项归文本纪律面 + 评审核验 |
| D4 | 指针纪律 | 指针形态 = `文档:节`；行号只作 **as-of** 参考；禁“见上/见该节”式相对指针；**消费点代码坐标一律写自仓根完整路径**（细则见下方 D4 块）；机判 = **V5**（V1 无机检器——v2 收敛撤除，§4.2.6） |
| D5 | 冻结窗口 | 评审在途不改被审文档——**「在途」的下界定义 + 在途写入拦截**见 `design/ADVISOR-GUARDS.md` |
| D6 | 回读核对 | 任何写入后回读核实再报完成（写入静默失败、编辑吞标题均已实证） |
| D7 | 变更留痕 + 核销同步 | 每批核销跑**核销同步清单**（**每批批次档 §6 段槽位** = 核销同步清单执行位——**非** `design/BATCH-RECORD.md` §6〔后者 = VSC 端镜像〕；承小债批评审 #12）：角色表 / 状态行 / 计数 / 指针 / 变更记录 / 待办勾销（**含前批遗留核对**——条目已完成而挂靠批档未收口 ⇒ 兜底核销路径 = `design/BATCH-RECORD.md` §5.2）/ **台账可见面（收口行）** |
| D8 | **失效表达必删** | 现役规范面（功能点 / AC / 判据句 / 纪律句 / 边界 / 现状陈述）内表达一旦失效（被判否 / 对象消失 / 被取代）⇒ **删除**——不留 `~~划改~~`、「原记 X ⇒ 收正 Y」、「已作废 / 裁撤」挂尸；历史归**记录面**（变更记录 / 沿革 / 批档）。细则见下方 D8 块 |

**D8 细则（失效表达必删——2026-09-18 立）**：

- **判据**：**现役规范面** = 功能点 / AC / 判据句 / 纪律句 / 边界 / 现状陈述——其中一旦出现失效表达（设计被判否 · 对象消失 · 被新形态取代）⇒ **删除**；不留 `~~划改~~` · 不留「原记 X ⇒ 收正 Y」 · 不留「已作废 / 裁撤」挂尸。**删除后须扫该档与兄弟档引用**——引用悬空 ⇒ **同轮收正**（本次实证：删一条量表行 ⇒ 他处引用同轮悬空，机检报出）。
- **由来（当日实证）**：父侧读 `requirements/ENGINEERING-MODE-V2-SPEC-PROMPT-PIPELINE.md` 的 `~~单向生成机检~~ 裁撤（…）` 划改残留 ⇒ **把已被否掉的判据重新当成待办立批**（三轮空转 + 两次方法错误）。用户 2026-09-18 裁定：「**修订式表达很害人，失效的表达一定要删掉**」。
- **与既有纪律的挂接**：删除动作本身仍受 **D6**（写入后回读核实）与 **D7**（变更留痕）约束——被删内容的**历史去向 = 记录面**，不进现役面正文：该档**变更记录**留一行（日期 + 执行方 + 可 revert）即足。
- **两分判据（出处注 vs 退役挂尸）**：看表达**指向的对象是否仍存在**——指向在位对象（如「依据 X · 日期」「as-of 读数」）= **出处注**，属记录面，照留；指向已消失对象 = 退役挂尸，删。
- **记录面（保留零触）**：变更记录 / 不并项与历史沿革 / 逐批变更行 / 批档 / 台账——带日期即明示历史，删除反毁审计链。
- **机扫判据（豁免族）**：以下四类**不属失效表达**，机扫命中亦**不得删**——ⓐ 规则正文**自身的反例引用**（如 D8 内的 `~~划改~~` 示例）ⓑ markdown **语法描述**（描述渲染行为的标记字面）ⓒ **判据类目名**（如「退场注记」= 处置类别）ⓓ **归档台账**（`TODO-archive.md` 等记录面）。
- **需求侧同步**：本纪律为设计侧新增（`requirements/ENGINEERING-MODE-V2.md` §13.1 现列 D1–D7）——需求侧落笔 = 主 agent 域。

**D4 细则（消费点坐标完整路径形态——2026-09-20 立）**：

- **纪律句**：档内写**代码消费点坐标**（路径 + `:行号` 形态）⇒ 路径段一律用**自仓根完整路径**
  （例：`thincoder-core/provider/core.mjs:198`）；禁「核 / VSC / CLI」上下文内的裸相对段——
  即只写子系统内目录段 + 文件名、不带仓根段的那种写法。
- **成因（机检面实测，非推测）**：V5 存在性解析序 = 仓根 → 锚域根 → 本档目录 → 锚域前缀剥离
  \+ **唯一 basename 索引**；裸相对段的 basename 在仓内常**多个同名**（实测：`core.mjs` 2 个 ·
  `index.mjs` 6 个）⇒ 唯一索引失效、相对路径亦不解析 ⇒ **判悬空红**。完整路径两个解析入口均命中。
  反身实证：本细则初稿在**禁例句里写裸相对段例字**，自身即被机检抽为 3 条悬空 —— 该形态的触发面
  包括「作为反例出现」的场合（机检不区分引用与反例）⇒ 写反例请用中文描述，不写裸路径字面。
- **代价面**：坐标变长（行宽预算）；收益 = 锚机检一次绿 + 人读无歧义（裸段「哪个 index.mjs」不可判）。
- **实例登记（本细则立案实证）**：`docs/core/design/MODEL-SPECS.md` 设计轮首跑引入 **10 条悬空锚**
  （全由裸相对段构成）⇒ 按本形态改写仓根完整路径后 `OK(锚): 0`；逐条见 `docs/batches/2026-09-20-qwen-flash-specs.md` §2.6。
- **机判**：归 V5（锚存在性·路径/坐标类）——形态本身不另建机检器，违规以悬空红暴露。

## 2. 机械校验最小集（V1–V6）

**总口径**：校验必须**随 `npm test` 可跑（单入口内）**、**零假阳才能常驻**（「存量 / 入基线」**已废**——阈值 = 0；违规一律阻断）、**不得靠自然语言理解**（只做字符串/结构判）；语义一致性仍归评审。

| 校验 | 判什么 | 落点 |
|---|---|---|
| **V1** 段引用可解析 | 扫描域内 `X.md §N` / `文档:节` 引用——目标档存在**且**归一后编号在目标档标题里 | 文本纪律面（无对应机检器——v2 收敛撤除；§4.2.6） |
| **V2** 计数与列表一致 | 「N 项/处/条」声明与同节列表条数一致，不符即报 | 文本纪律面（无对应机检器——v2 收敛撤除；§4.2.6） |
| **V3** 批次档 §3 轮次行 | 已批准批次 §3 非空且含**工具写入的轮次行**（排骨架行）——判据与射程见 `design/BATCH-RECORD.md` §4.6 | 文本纪律面（无对应机检器——v2 收敛撤除；§4.2.6） |
| **V4** 跨仓形态合规 | 正文引用他仓文档的形态须在**封闭枚举 E1–E5** 内——枚举外即红 | 文本纪律面（无对应机检器——v2 收敛撤除；§4.2.6；判据全文 = `design/LEDGER-SELF-CONTAINED.md`） |
| **V5** 文档锚一致性 | 现行档内的事实锚（用例号 / 文件路径 / 符号）存在性——判据规格 = 本档 §4 | 独立档 `scripts/doc-check-anchors.mjs` |
| **V6** 编号引用可解析 | 档内家族编号（`F` / `N` / `D` / `AC` / `T`）**跨节 / 跨档引用**的被引处定义存在性——判据规格见本节 V6 块 | 常驻测试 `thincoder-cli/test/doc-fnum-refs.test.mjs`（已在位） |

**V1 跨仓边界（形态规范 B——检查器零改动）**：

- 问题：V1 按 **basename 在本仓扫描域**解析——跨仓引用（他仓档名 + `.md` + 节号形态）**当该 basename 不在本仓扫描域时**恒判 `unknown-doc`；**加仓前缀也无效**。
  **同名 basename 处置**：他仓档名与本仓某档同名 → V1 按其**本仓档**解析——可能 `no-section` 误报、甚至以**错档**节号通过。
- **契约（选定「形态规范」）**：检查器**零改动**（边界 ≠ 机制变更）；规范文本 = `docs/README.md` §3.7 规则表增一条：
  引用他仓文档**不得写 `X.md §N` 形态**——写「名称（仓别）§N」（如 `WEBVIEW（VSC 仓）§5`）：去 `.md` 后缀、去路径前缀（跨仓引用 = V1 域外）。
- **候选对比**：① V1 跨仓解析（需工作区双仓布局假设 + 双端双实现 + 新假阳面）**否决**——收益（罕见引用类的可验性）低于成本；② **形态规范**（零假阳 / 零代码 / 与在用实践一致）**选定**；③ 静默容忍（不判不报）**否决**——违零静默，且与 `unknown-doc` 真阳性不可机械区分。
- **后续选项（登记）**：跨仓引用规模增大、确需机验 → 走 ① 独立批（先定义他仓扫描根 + 双端镜像约定，不得硬编码）。

**V2 / V3 已有判据语义零改**（V3 见 `design/BATCH-RECORD.md`）。**V4** 见 `design/LEDGER-SELF-CONTAINED.md`。

**V6 编号引用可解析（批 9 CRITERIA-FACE · 条目 2——判据规格 = 本节）**：

- **纪律句（编号自持）**：档内编号家族（`F` / `N` / `D` / `AC` / `T` 类）**节内定义、节内引用**；跨节 / 跨档引用他处编号 ⇒ **去编号化**——改「指针（文档:节）+ 语义名」形态（D4 指针纪律 + D2 单一权威源）。
- **判据**：抽取形态 = 「`§<节号>` + 家族编号」与「`§<节号>` + 家族编号区间（`Fm–Fn`）」；定义面 = **被引节内**的编号定义位（粗体行首 `**Fm**` / 列表项首 `- **Fm` / 表格行首）；区间**逐号展开**判；集合差非空 ⇒ 报（档:行 + token）。
- **落点**：判据函数 + 常驻测试 `thincoder-cli/test/doc-fnum-refs.test.mjs`（**已在位**；夹具 = 正常 / 区间边界 / 悬空错误三例）；**首落报告态**（承 F4 先例——报告态先落、清账后收紧）。
- **本批判定面**：`requirements/ENGINEERING-MODE-V2.md` §13.4 面（集合差为空）；**全档 / 全仓扫描 = 后续批**（读数登记、不阻断本批）；无档名的跨档 `§N` 引用形态归后续批读数面。
- **与既有判据不重叠**：V1 只管「`X.md §N` 的档 / 节号存在性」（不判家族编号定义）；V5 不判编号引用（面不交——见 §4.2.6）。
- **判据句**：跨节引用他节编号而无定义 ⇒ 判**违规**；区间引用未逐号展开判 ⇒ 判**违规**（漏判面）。

## 3. 文档机制边界（表格行宽度豁免 + 拆分债 + 机检零落仓 + 坐标尾形态 + 文档行数规则废除 + 死指针 sweep 两分口径 + 死名/旧指针收正二轮 + 尺寸档登记（小债批） + 判据行工具形态（中文串））

### 3.1 条目 C：表格行宽度豁免（规范 + 机制双层）

**问题**：宽度规则（无 >300 字符单行）与 markdown **表格行不可折行**结构性冲突——多批评审 §3 发现表全部超宽（表格行为主力）。

**候选对比**：① **表格行豁免（规范 + 检查器同步）**——双层一致；**选定**。② 检查器单边跳过——规范仍禁、机制放行 = 规范-机制漂移，**否决**。③ 发现表非表格化——评审协议 / 提示词模板 / 既有 §3 结构全动，**否决**。

**契约**：

1. **机制**（宽度检查）：宽度扫描豁免表格行——谓词 = **表行形态**（行首可选空白 + `|` 起 + `|` 收），与 V2 同源；**单源化**（扫描函数内跳过 + 主流程改调用该函数，删除内联重复扫描——防两处规则漂移）。
2. **规范**：一致性检查的运行说明里落笔规则 1 的豁免句（**表格行豁免**：markdown 表格行结构性不可折行，超宽表格行不计入宽度检查——建议就近折行或表下补充，非阻断）。
3. **影响面**：豁免后宽度报告集按表格行数下降；**非表格超宽行照常报告**；V1/V2/V3 与基线**零接触**（宽度面无基线机制）。
4. **残余登记**：豁免谓词 = **裸表行形态判定**——代码围栏内、或其他 `|…|` 形态的 >300 行会被一并豁免（罕例——fail-open 方向）；不影响选型（规范侧以「建议就近折行」兜底）。

### 3.2 条目 D：两处拆分债

- **D-1 `thincoder-core/advisor/messages.mjs`（300 建议线外、500 硬限内）——不拆（显式理由 + 拆分计划登记）**：
  理由 = 本批零增厚；< 500 硬限；模块职责单一（advisor 消息装配）。
  **拆分计划（登记——不执行；触发 = 再度增厚）**：候选线 = 抽「项目上下文发现」组 → `thincoder-core/advisor/project-context.mjs`；import 面由 re-export 保持不变（既有导入点零改）。
- **D-2 超 500 硬限的测试档——拆分为两档**：迁出「主题连贯的一组用例」→ 新档；新档**头部自持**（imports + 助手 + 所需语料读取 + 常量）、**零跨档 import**；迁出用例**逐字搬移**（断言零改、零增、零删）；原档保留余例；**用例数守恒**；两档各 ≤500。
  否决备选：① 迁出「运行时组」——余档余量较小；② 不拆——违硬限（无豁免通道）。

### 3.3 档位结论

- 宽度检查档 = **存量贴线档**（300 建议线）——本批承诺**终态 ≤300**（净增受控）；落地以**批前 / 批后实测对表**记账；**若实测越线 → 拆分退路**：抽宽度扫描核心至独立档 + 扫描库分档（re-export 保持消费面零改），主档回 ≤300；触发即**停下报告**。
- **提示词面零碰**（文档机制边界只动规则 / 括注层面；提示词 = 产品代码）。

### 3.4 条目 E：机检器测试**零落仓**（并发免疫）

**问题**：机检测试把**夹具写进仓库扫描域**（探针档落在本域 `docs/` 扫描域内的固定路径）——同一套测试**并发两实例**（发版门 / 双实例协作）抢同一探针路径 ⇒ 一方读取抖动（探针被对方清掉）；被强杀时残留探针 = 一条**新增违规**（自伤）。

### 4.3 层 2 清账契约

- **顺序**：用例号 → 符号（窄形态）→ 路径。

- **处置三选**：① **现态改写**（改为现行号 / 现行档 / 现行符号）② **退场·已废注记 + 来源指针** ③ **订正**（引用确属笔误 → 改为正确引用）。
- **零代码面**：不改源码 / 测试实体（本批 = 文档面对账）；锚缺失若暴露**真实代码问题** → **停下上报**（不自行改码）。

### 4.4 层 3 防回潮 + 流程入规

**反查脚本（`thincoder-cli/scripts/doc-impact.mjs`）**：

- **接口**：`node thincoder-cli/scripts/doc-impact.mjs --base <ref> [--files a,b] [--json]`；退出码 **0**（非门禁——查询工具；git 降级亦 0——打印「反查跳过」行）；**用法错误（缺 `--base`）⇒ 2**（fail-loud）。
- **输入**：① 变更文件（相对基准的 name-only diff）② 变更符号（新增/删除行内标识符候选）。
- **输出**：① 变更面 ② 反查命中档清单（每档一行 + 命中词 + 命中数）③ 一行提示（建议录入批次档 §2 受影响文件表）。
- **实现形态（单源）**：纯函数（随 `npm test` 直驱可测）+ 薄 git 包装（子进程——`slow` 纯别名标注）。
- **时点与基准**：**实施轮开工前**跑一次（设计期无 diff）；基准 = **上一批收口点**——**不以 `HEAD` 为默认**；归属 = 主 agent；输出**不自动**写批次档。

**V5 常驻**：① 单入口面（随 `npm test` 生效）② 发布门链（`lint` → `npm test`）同入口生效。再出现即红（闸态）。

**语义巡检机制（机器判不了的那类）**：

| 要素 | 定义 |
|---|---|
| 对象 | **无锚语义句**（句中不含可判锚的事实句） |
| 周期 | ① **触发式**：某板块档发生**实质修订** → 该档随改巡检该档 ② **收口式**：批次收口时对**本批触碰档**逐档过一遍 |
| 归属 | **eng-designer**（**设计档**写稿面）；**需求档 = 主 agent**（**D1**） |
| 记录形态 | 批次档 §6 既有「遗留项」行内一行（**零新槽位**——不改模板） |
| 判据面 | **无机械判据（明示）**——不入机检；发现项经设计者修订后由评审核验 |

**跨仓批派单与写域**：跨仓面的批次——**每仓各起一轮实施**，各轮带**自己仓的批次档**；语义同源由**同一份简报**保证，**不做逐字一致**。
**写域纪律**：子代理**只写本仓**（含本仓批次档里自己那一段）；**写对端仓任何档 = 违规**；确需对端改动 → **停下上报**，由主 agent **另起对端仓一轮**。
反例在案：跨仓落修 = 反例——不得再犯（不因「顺手」「只有一行」「对端缺人」而代写）。

**提示词落笔面**：跨仓批派单三条 + 反查脚本一条入纪律层双副本（逐字文本归提示词落笔轮；**脚本名不写进提示词**——可移植性口径）。

### 4.6 边界（本层不做）

- **不动既有判据语义**：V1–V4 / L1–L4 / 宽度域 / 台账域——各自域零改；新增 V5 与它们**不重叠报行**。
- **不动 `_archive/`**：归档档不作现状依据，也不入扫描域。
- **不重写历史批档**（批次档 append-only）；V5 扫描域**不含批档**。
- **不改代码 / 测试语义**（含不改测试用例名——用例号锚缺失的处置只能走文档面：改写或注记）。
- **不承诺清零的两类**：① 无锚语义句（归巡检）② 符号宽形态命中（归报告 + 巡检选样）。
- **不入产品提示词**：V5 脚本名/命令字面属本仓工具面；只有通用行为条款入提示词。
- **不写对端仓任何档**（含提示词镜像 / 台账 / 批档）——对端一轮自行落笔。
- **已登记代价（假阴面）**：对端仓前缀**合规形态**——**对端可达但档缺失**时 ③ 不命中转 ④ 本仓同名 basename（≥1）⇒ **通过** ⇒ **缺档不报**（已知代价）；该面归语义巡检选样，**不得**以「通过」读作对端档案存在。
- **不动参照历史面正文**（`thincoder-cli/docs/**` · `thincoder-vscode/docs/**`）：**只读红线**（§1.20 层 0-2 判定句）——对该两树正文落笔 ⇒ 违规。
- **族为闭集（现役两族 = §4.2.9 / §4.2.10）**：新增标记形态 / 史实谓词 / 豁免锚类须走设计 + 评审。

- **不动 §1.19 既有编号**：正文编号 F1–F14 零改（本批只对**表行**去编号化）；**编号不复用**（退役编号不回收）。

## 7. 机检引擎（v2——M8 增量）

**定位**：v1 机检 = **三引擎 + 硬编码**（`check-doc-width*.mjs` 行宽+一致性 · `doc-anchors*.mjs` V5/VSC 双锚引擎 · `check-ledger*.mjs` 台账 L1–L4），各自硬编码本仓 `docs/` 路径、各自扫描源域、各自行宽阈值，带参照历史面豁免族 / 六档并入映射 / V3 历史常量等过度工程。v2 砍到**单引擎（锚 + 行宽）+ 声明面**，台账一致性由 SQLite schema 承接（check-ledger 作废）。

**四功能点**：

| # | 功能点 | 方案 |
|---|---|---|
| F1 | 单引擎 | 内核 = 锚检查（段引用可解析）+ 行宽检查（单行 > 阈值）；入口 = `scripts/doc-check.mjs`（合并三入口，同一 `main` 驱动 + 同一 `formatReport` 报告） |
| F2 | 声明面判据 | `scanDirs` / `lineWidth` / `anchors.domain` / `exemptions` / `anchors.exclude` 全读 manifest `checkConfig`——改 manifest 即改行为 |
| F3 | 砍六族过度工程 | 双锚引擎（V5/VSC 收敛为一套）· 三套源域（→ 单 `collectSourceDomain(checkConfig.scanDirs)`）· 三套行宽判据（→ 单 `checkConfig.lineWidth`）· 参照历史面豁免族（`REF_DOC_TREES`）· 六档并入映射（`MERGED_SCRIPTS`）· V3 历史常量（`v3Key`）——全部删除 |

**产物包内机检脚本的域取向（2026-09-18 · 批 VSC-MIRROR-RETIRE 裁定）**：

- **域语义（实装口径）**：`--domain <d>` ⇒ 被检域根 = `resolve(root, d)`、源域 = 该根下 `checkConfig.scanDirs`（= `docs`）——即**域根必须自身就是一个「持 `docs/` 的域根」**（`scripts/doc-check.mjs:58` · `scripts/doc-check-targets.mjs:35-43`）。
