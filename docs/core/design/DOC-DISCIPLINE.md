## 1. 文档更新纪律（D1–D7——设计侧机制）

写稿权唯一只是**必要条件**；反复栽的是**更新纪律缺位**。七条纪律的语义 = `requirements/ENGINEERING-MODE-MECHANISM.md` §1.15（需求侧权威）；本节给**机械面**与**细则**。

| # | 纪律 | 机械面 / 细则 |
|---|---|---|
| D1 | 写权矩阵 | 文档类 → 唯一作者（需求/设计 = eng-designer；批次档 = 主 agent；提示词 = 主 agent 内容权 + eng-coder 落笔）——无机械门，靠角色契约与评审核验 |
| D2 | 单一权威源 | 一条机制只在一处详述，其余处只引用不重述（**模板同理**——批次档模板只在需求侧机制档 §1.12） |
| D3 | 计数·枚举纪律 | 「N 项/处/条」与列表**同时改**；机判 = **V2** |
| D4 | 指针纪律 | 指针形态 = `文档:节`；行号只作 **as-of** 参考；禁“见上/见该节”式相对指针；机判 = **V1** + **V5** |
| D5 | 冻结窗口 | 评审在途不改被审文档——**「在途」的下界定义 + 在途写入拦截**见 `design/ADVISOR-GUARDS.md` |

| D7 | 变更留痕 + 核销同步 | 每批核销跑**核销同步清单**（批次档 §6 模板槽位）：角色表 / 状态行 / 计数 / 指针 / 变更记录 / 待办勾销 / **台账可见面（收口行）** |

## 2. 机械校验最小集（V1–V5）

**总口径**：校验必须**快层可跑**（`npm test` 内）、**零假阳才能常驻**（「存量 / 入基线」**已废**——阈值 = 0；违规一律阻断）、**不得靠自然语言理解**（只做字符串/结构判）；语义一致性仍归评审。

| 校验 | 判什么 | 落点 |
|---|---|---|
| **V1** 段引用可解析 | 扫描域内 `X.md §N` / `文档:节` 引用——目标档存在**且**归一后编号在目标档标题里 | 一致性检查（宽度档族） |
| **V2** 计数与列表一致 | 「N 项/处/条」声明与同节列表条数一致，不符即报 | 同上 |
| **V3** 批次档 §3 轮次行 | 已批准批次 §3 非空且含**工具写入的轮次行**（排骨架行）——判据与射程见 `design/BATCH-RECORD.md` §4.6 | 同上 |
| **V4** 跨仓形态合规 | 正文引用他仓文档的形态须在**封闭枚举 E1–E5** 内——枚举外即红 | 同上（判据全文 = `design/LEDGER-SELF-CONTAINED.md`） |
| **V5** 文档锚一致性 | 现行档内的事实锚（用例号 / 文件路径 / 符号）存在性——判据规格 = 本档 §4 | 独立档 `scripts/doc-anchors.mjs` |

**V1 跨仓边界（形态规范 B——检查器零改动）**：

- 问题：V1 按 **basename 在本仓扫描域**解析——跨仓引用（他仓档名 + `.md` + 节号形态）**当该 basename 不在本仓扫描域时**恒判 `unknown-doc`；**加仓前缀也无效**。
  **同名 basename 处置**：他仓档名与本仓某档同名 → V1 按其**本仓档**解析——可能 `no-section` 误报、甚至以**错档**节号通过。
- **契约（选定「形态规范」）**：检查器**零改动**（边界 ≠ 机制变更）；规范文本 = `docs/README.md` §3.7 规则表增一条：
  引用他仓文档**不得写 `X.md §N` 形态**——写「名称（仓别）§N」（如 `WEBVIEW（VSC 仓）§5`）：去 `.md` 后缀、去路径前缀（跨仓引用 = V1 域外）。
- **候选对比**：① V1 跨仓解析（需工作区双仓布局假设 + 双端双实现 + 新假阳面）**否决**——收益（罕见引用类的可验性）低于成本；② **形态规范**（零假阳 / 零代码 / 与在用实践一致）**选定**；③ 静默容忍（不判不报）**否决**——违零静默，且与 `unknown-doc` 真阳性不可机械区分。
- **后续选项（登记）**：跨仓引用规模增大、确需机验 → 走 ① 独立批（先定义他仓扫描根 + 双端镜像约定，不得硬编码）。

**V2 / V3 已有判据语义零改**（V3 见 `design/BATCH-RECORD.md`）。**V4** 见 `design/LEDGER-SELF-CONTAINED.md`。

## 3. 文档机制边界（表格行宽度豁免 + 拆分债）

### 3.1 条目 C：表格行宽度豁免（规范 + 机制双层）

**问题**：宽度规则（无 >300 字符单行）与 markdown **表格行不可折行**结构性冲突——多批评审 §3 发现表全部超宽（表格行为主力）。

**候选对比**：① **表格行豁免（规范 + 检查器同步）**——双层一致；**选定**。② 检查器单边跳过——规范仍禁、机制放行 = 规范-机制漂移，**否决**。③ 发现表非表格化——评审协议 / 提示词模板 / 既有 §3 结构全动，**否决**。

**契约**：

1. **机制**（宽度检查）：宽度扫描豁免表格行——谓词 = **表行形态**（行首可选空白 + `|` 起 + `|` 收），与 V2 同源；**单源化**（扫描函数内跳过 + 主流程改调用该函数，删除内联重复扫描——防两处规则漂移）。
2. **规范**：一致性检查的运行说明里落笔规则 1 的豁免句（**表格行豁免**：markdown 表格行结构性不可折行，超宽表格行不计入宽度检查——建议就近折行或表下补充，非阻断）。
3. **影响面**：豁免后宽度报告集按表格行数下降；**非表格超宽行照常报告**；V1/V2/V3 与基线**零接触**（宽度面无基线机制）。
4. **残余登记**：豁免谓词 = **裸表行形态判定**——代码围栏内、或其他 `|…|` 形态的 >300 行会被一并豁免（罕例——fail-open 方向）；不影响选型（规范侧以「建议就近折行」兜底）。

### 3.2 条目 D：两处拆分债

- **D-1 `thincoder-core/advisor/messages.mjs`（300 建议线外、500 硬限内）——不拆（显式理由 + 拆分计划登记）**：
  理由 = 本批零增厚；< 500 硬限；模块职责单一（advisor 消息装配）。
  **拆分计划（登记——不执行；触发 = 再度增厚）**：候选线 = 抽「项目上下文发现」组 → `thincoder-core/advisor/project-context.mjs`；import 面由 re-export 保持不变（既有导入点零改）。
- **D-2 超 500 硬限的测试档——拆分为两档**：迁出「主题连贯的一组用例」→ 新档；新档**头部自持**（imports + 助手 + 所需语料读取 + 常量）、**零跨档 import**；迁出用例**逐字搬移**（断言零改、零增、零删）；原档保留余例；**用例数守恒**；两档各 ≤500。
  否决备选：① 迁出「运行时组」——余档余量较小；② 不拆——违硬限（无豁免通道）。

### 3.3 档位结论

- 宽度检查档 = **存量贴线档**（300 建议线）——本批承诺**终态 ≤300**（净增受控）；落地以**批前 / 批后实测对表**记账；**若实测越线 → 拆分退路**：抽宽度扫描核心至独立档 + 扫描库分档（re-export 保持消费面零改），主档回 ≤300；触发即**停下报告**。
- **提示词面零碰**（文档机制边界只动规则 / 括注层面；提示词 = 产品代码）。

## 4. 文档↔实装对账（V5 判据规格 + 清账 + 防回潮）

### 4.1 问题与三层交付

设计/需求档的「事实句」落后于代码/测试现态——撞见即清 250+ 处，但**没有全量清单**（清的是撞见的，不是存在的）。病根四条 = `requirements/ENGINEERING-MODE-MECHANISM.md` §1.20。

| 层 | 交付 | 判据面 | 落点 |
|---|---|---|---|
| 1 机检器 | **V5「文档锚一致性」**（三锚）+ 全量清单 + 报告态/闸态两态 | 可机器判的事实锚 | `scripts/doc-anchors.mjs` + `thincoder-cli/test/doc-anchors.test.mjs` |
| 2 清账 | 逐条处置（现态改写 / 退场·已废注记 + 来源指针）+ 收紧 | 文档面（零代码/测试语义改动） | `docs/core/design/**` + `docs/core/requirements/**` |
| 3 防回潮 | 反查脚本 + V5 常驻 + 语义巡检 + 跨仓批派单与写域 | 机检面 + 人流程面 | `thincoder-cli/scripts/doc-impact.mjs` + 提示词层 + 批次流程 |

**方案选型（判定面）**：① 形态-only（判形态不判存在性）**否决**——等于不治；② 全树存在性裸口径**否决**——实测假阳为主（红一片 = 无人看 = 等于没有）；③ 声明式清单（人工允许/例外清单）**否决**——与本仓「**基线必须保持为空 / 不得再设存量通道**」同一裁定相抵；④ **坐标化判定**（② 的存在性内核 + 判定面收窄到「可证明为坐标的引用」）——**选定**。
**选定代价（如实列）**：④ 不覆盖「无坐标 / 无宿主声明的符号引用」——该类归 **V5-C 宽形态报告清单 + 语义巡检**（不阻断）；也不覆盖「设计计划未落地」类（用例号在测试树无宿主的计划面——**不属悬空**：其编号定义在本档用例表内，归测试生命周期 / §6 收口面）。

### 4.2 V5 判据规格

#### 4.2.1 锚抽取（逐条：正则 + 排除式）

判定单位 = **行**（fenced 块整块跳过——与 V1–V4 同口径）。三锚：

- **V5-A 路径 / 坐标锚（入闸）**：正则见下方围栏块。
  **射程** = ① 含 `/` 的路径形态，**或** ② 带行号坐标（`:NN`——含**行区间 `:N-M`**，整条参与抽取、不截断）——裸 basename 且无坐标者**不判**（它是文档互指 / 运行期档名 / 术语的常用写法，无坐标则不可定位）。
  **排除式（逐条 = 硬排除）**：① 占位 / 示意名与通配（token 含占位符号；末段裸名 ∈ 占位集 **含通用入口名类**，大小写不敏感——判据句 = 「夹具与示例档名」，射程 = 末段裸名）；② 运行期面（点目录开头）；③ 组合简写（一段内 ≥2 个扩展名段）；④ 命令字面与围栏（fenced 块整块 + 可执行行谓词，与 V4 射程豁免同源）；⑤ 已属他判据（`.md` token 后接 `§N` 归 V1；**对端仓直引的违规形态归 V4——V5 跳过**；**合规形态**（`路径（仓别）`）**不排除**——入存在性域判存在性）。
- **V5-B 用例号锚（入闸）**：正则见下方围栏块。
  形态注：① 裸 `T` 后 ≤1 字母且直接数字——`TLS12` / `TAB123` 类标识符**不入抽取**；② `T-` 前缀「字母块 1–5」形态**捕多段号完整形态**；③ 收尾 lookahead 排除后续字母/数字/连字符。
  排除式：① 带前缀的内部编号（`AC-` / `D-` / `F-` / `N-` 类——前导连字符即排除）；② 裸 `T<数>.<数>`（台账/条目号族——与用例号同形不同物）；③ 形态面收紧（见上）。
  存在性域 = **定义面**（不直接判测试树——见 4.2.2）。
- **V5-C 符号锚**：分两段（同一抽取面，两种判定）：
  - **窄形态（入闸）**：同一行内同时出现「反引号标识符」+「定义谓词」（闭枚举：定义于 / 定义在 / 声明于 / 声明在 / 生成点 / 定义处 / 唯一权威 / 导出）+「**唯一**宿主档坐标」三要素时，判该符号在宿主档文本存在。
  - **宽形态（报告态——不阻断）**：反引号标识符（≥5 字符、含大写或 `_`）在代码树的存在性——实测悬空面含大比例对端符号 / 库·平台 API / 退场叙述（假阳），**按 F2 硬条不入闸**，仅入报告清单（供语义巡检选样）。

```text
V5-A: /(?<![A-Za-z0-9_.\-\/])((?:[A-Za-z0-9_.\-]+\/)*[A-Za-z0-9_.\-]+\.(?:mjs|cjs|js|json|md|css|html|svg|yml|yaml|sh|ps1))(?::(\d+(?:-\d+)?))?(?![\w])/
V5-B: /(?<![A-Za-z0-9-])((?:T-[A-Z]{1,5}\d{1,3}(?:-\d{1,3})?|T-\d{1,3}|T[A-Z]?\d{1,3})[a-z]?(?:\.\d+)?)(?![A-Za-z0-9-])/
```

#### 4.2.2 存在性域

- **路径 / 坐标 / 窄符号宿主**：解析序 = ① 本仓根 → ② **本档所在目录**（档相对引用）→ ③ **对端仓根** → ④ **唯一 basename 索引**。
  - ③ 可达来源序：显式 `peerRoot` 参数（用例直驱入口）→ env `THINCODER_PEER_ROOT`（别名 `THINCODER_CLI_ROOT`；**自指防护** = 取值解析为本仓根即弃用）→ 工作区兄弟目录（仓族名枚举、跳过自身）。**仅合规形态**（`路径（仓别）`）入域——违规形态跳过。
  - ④ **本仓**同名命中口径：唯一 ⇒ 通过；多命中且带目录前缀 ⇒ 通过；多命中无目录前缀 / 零命中 ⇒ 报。仓前缀合规形态（③ 不命中、对端可达）同落此步——本仓同名命中（≥1）⇒ 通过（**缺档不报 = 已登记代价**，见 4.4）；本仓零同名 ⇒ 悬空报行。
- **代码树（符号宽/窄形态）**：`src` / `scripts` / `bin` / `test` 四树（两仓）。
- **用例号定义面**（三源任一命中即通过）：① 两仓测试树文本（含测试名内嵌号）；② **定义位**（表格首格 / 列表项首 / 粗体行首——全档全域）；③ **退役登记表**（表头含「用例名」的表格行任意格）。
- **降级（明示）**：对端仓不可达（单仓克隆）⇒ 解析序 ③ 不可用——**合规形态锚**记「**域外**」计入报告行（不阻断）；**不得**因对端缺失而静默放过或静默报红。域外行**只**来自合规形态——违规形态根本不入 V5 域（两态互斥，见 4.2.6）。

#### 4.2.3 注记识别（何种形态视为「已退场 / 已废」而通过）

- **粒度 = 判定行**（同行即通过；**不做跨行语义判**——防假阳）。
- **标记集（闭枚举，逐字）**：`已退场` · `已退役` · `已废` · `已废弃` · `已撤` · `已收窄` · `退场` · `退役` · `已删` · `已拆` · `已清空` · `已并入` · `归档` · `换名` · `改名` · `删除记录` · `未恢复`。
- **并档叙述形态**：`原…系`——旧编号系列的谱系括注（如「（原 T-L/T-F4/T-F5 系，…）」）；**判据句 = 谱系叙述不主张单号存在**；射程 = 叙述位（标题 / 括注）；判定粒度 = 判定行。
- **指针形态**：`源 = <file:line>` 或 `删除记录 = <指针>`（指针本体同受 V5-A 判定——注记不能拿一个不存在的指针当退场证据）。
- **可见面（防标记集滥用）**：每次运行报告「注记豁免条数」——标记膨胀即漂移信号。

#### 4.2.4 假阳类逐条排除（硬——F2 的落地面）

| # | 假阳类 | 排除式 |
|---|---|---|
| 1 | 设计档内部编号（`AC-` / `D-` / `F-` / `N-` 类） | V5-B 前导连字符排除 + 形态不含 `T` 前缀者不入抽取 |
| 2 | 库 / 浏览器 / 平台 API | V5-C 宽形态**不入闸**（仅报告）；窄形态需「定义谓词 + 宿主坐标」双证 |
| 3 | 提交哈希 | 形态排除（40 位 hex 不在三锚正则内） |
| 4 | 命令字面 / fenced 块（可执行坐标） | 围栏整块跳过 + 可执行行谓词 |

#### 4.2.5 报告态 → 阻断态（切换条件与阈值）

- **两态**：模块常量（初值 `false` = **报告态**；清账完成后翻 `true`）；CLI 参数可覆盖（反证与临时收紧/放宽用——翻转后两态仍可直驱）。

- **闸态语义**：命中计入违规集——`exit 1`；阈值 = **0**。
- **切换条件（收紧点）**：① 扫描域三锚命中 = **0**（层 2 清账完成）② 常量翻 `true` ③ 快层断言 as-of 与本态同步。三者齐备才收紧；**未清完不收紧**（不得提前设闸建红一片）。
- **测试稳定性**：判定函数接受**显式 `gate` 参数**（两态均可直驱）——用例与 AC 跨切换点零改。

### 4.3 层 2 清账契约

- **顺序**：用例号 → 符号（窄形态）→ 路径。
- **粒度与纪律**：逐档改完即 **D6 回读**；同行可判者不改语义、只改**现态陈述**；**不得**顺手重写整段（超出对账面）。
- **处置三选**：① **现态改写**（改为现行号 / 现行档 / 现行符号）② **退场·已废注记 + 来源指针** ③ **订正**（引用确属笔误 → 改为正确引用）。
- **零代码面**：不改源码 / 测试实体（本批 = 文档面对账）；锚缺失若暴露**真实代码问题** → **停下上报**（不自行改码）。
- **写域对接（动态清单 → `files` 声明）**：首跑清单中**每个命中档**逐档转为 file-level `files` 项（清单「档」列去重后逐行取用）；检查器档（常量翻转）另列一项——文件域 = 该集合（清单外的档不入）。
- **收紧**：清账完成即翻闸（4.2.5 三条件）——件随层 2 末轮。

### 4.4 层 3 防回潮 + 流程入规

**反查脚本（`thincoder-cli/scripts/doc-impact.mjs`）**：

- **接口**：`node thincoder-cli/scripts/doc-impact.mjs --base <ref> [--files a,b] [--json]`；退出码 **0**（非门禁——查询工具；git 降级亦 0——打印「反查跳过」行）；**用法错误（缺 `--base`）⇒ 2**（fail-loud）。
- **输入**：① 变更文件（相对基准的 name-only diff）② 变更符号（新增/删除行内标识符候选）。
- **输出**：① 变更面 ② 反查命中档清单（每档一行 + 命中词 + 命中数）③ 一行提示（建议录入批次档 §2 受影响文件表）。
- **实现形态（单源）**：纯函数（快层直驱可测）+ 薄 git 包装（子进程——`slow()` 归册）。
- **时点与基准**：**实施轮开工前**跑一次（设计期无 diff）；基准 = **上一批收口点**——**不以 `HEAD` 为默认**；归属 = 主 agent；输出**不自动**写批次档。

**V5 常驻**：① 快层面（随 `npm test` 生效）② 发布门链（`lint` → `test:full` → `test:integration`）经快层间接生效。再出现即红（闸态）。

**语义巡检机制（机器判不了的那类）**：

| 要素 | 定义 |
|---|---|
| 对象 | **无锚语义句**（句中不含可判锚的事实句） |
| 周期 | ① **触发式**：某板块档发生**实质修订** → 该档随改巡检该档 ② **收口式**：批次收口时对**本批触碰档**逐档过一遍 |
| 归属 | **eng-designer**（写稿面唯一作者——巡检发现的修正也归其修订） |
| 记录形态 | 批次档 §6 既有「遗留项」行内一行（**零新槽位**——不改模板） |
| 判据面 | **无机械判据（明示）**——不入机检；发现项经设计者修订后由评审核验 |

**跨仓批派单与写域**：跨仓面的批次——**每仓各起一轮实施**，各轮带**自己仓的批次档**；语义同源由**同一份简报**保证，**不做逐字一致**。
**写域纪律**：子代理**只写本仓**（含本仓批次档里自己那一段）；**写对端仓任何档 = 违规**；确需对端改动 → **停下上报**，由主 agent **另起对端仓一轮**。
反例在案：跨仓落修 = 反例——不得再犯（不因「顺手」「只有一行」「对端缺人」而代写）。

**提示词落笔面**：跨仓批派单三条 + 反查脚本一条入纪律层双副本（逐字文本归提示词落笔轮；**脚本名不写进提示词**——可移植性口径）。

### 4.6 边界（本层不做）

- **不动既有判据语义**：V1–V4 / L1–L4 / 宽度域 / 台账域——各自域零改；新增 V5 与它们**不重叠报行**。
- **不动 `_archive/`**：归档档不作现状依据，也不入扫描域。
- **不重写历史批档**（批次档 append-only）；V5 扫描域**不含批档**。
- **不改代码 / 测试语义**（含不改测试用例名——用例号锚缺失的处置只能走文档面：改写或注记）。
- **不承诺清零的两类**：① 无锚语义句（归巡检）② 符号宽形态命中（归报告 + 巡检选样）。
- **不入产品提示词**：V5 脚本名/命令字面属本仓工具面；只有通用行为条款入提示词。
- **不写对端仓任何档**（含提示词镜像 / 台账 / 批档）——对端一轮自行落笔。
- **已登记代价（假阴面）**：对端仓前缀**合规形态**——**对端可达但档缺失**时 ③ 不命中转 ④ 本仓同名 basename（≥1）⇒ **通过** ⇒ **缺档不报**（已知代价）；该面归语义巡检选样，**不得**以「通过」读作对端档案存在。
