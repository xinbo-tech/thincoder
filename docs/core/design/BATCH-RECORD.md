## 1. 载体机制（批次档三点）

**定位**：批次档 = 任务流转的核心依据——**全链路唯一贯穿的档**（起 → 派 → 验）。需求档管“现状是什么”（无批次概念）、设计档管“怎么做”（跨批次演进）；
**只有批次档有完整链条**：B1 讨论落档 → B3 输入 designer → B6 designer 追加 §2 → B9 评审判据基准 → B11 **§2 即任务书** → B13 验收对照 → 需求池核销证据。

**三点机制**：

1. **档不可缺、不可写歪**——它是外部记忆（agent 上下文会丢），缺件 = 全链路失准。
2. **路径不硬编码**——批次档位置由调用侧传入（`batchDoc` 参数），产品**不假定**用户项目形如本仓；错误消息里的 `docs/batches/<批>-<主题>.md` 是**提示文案**，**不参与路径判定、不是默认位置**（判定只看 `batchDoc` 传入值）。
3. **判据只到「参数在 + 路径可读」**——**不校验内容/措辞**（不做正则匹配状态词——脆且把措辞写死）；内容够不够由**执行者拒收**兑底（`requirements/ENGINEERING-MODE-V2.md` §8 依据缺失处置）。

## 2. batchDoc spawn 门禁

**门禁判据**：目标角色（`eng-coder` / `eng-designer`）spawn 时**必须**传 `batchDoc`；**没传即拒**；传了但**不可读**（不存在 / 非文件）亦拒（消息含路径与原因）。

| 面 | 契约 |
|---|---|
| 参数 schema | spawn 参数面新增 `batchDoc` 属性（否则参数无处传入）；模型面描述文案按**角色集**（eng-coder / eng-designer）参数化 |
| 角色域 | 门**只对 `NEEDS_BATCH_DOC = { eng-coder, eng-designer }` 生效**——其余角色（`explore` / `plan` / `coder`）**零变更**（不带 batchDoc 照常 spawn） |
| 校验落点 | **单一共用装配点 + 与 token 门同出口**（阻塞/异步两路命中同一校验函数；错误生命周期一致） |
| 路径解析 | 相对路径解析序（cwd → 项目根 → 基底）**单源 = §4.15**（`batch-paths.mjs`）——门判据仍「参数在 + 路径可读」，解析面与 append / create 同源（2026-09-25 批 · 台账 #287） |
| 注入 | 通过校验后 child 携带批次档绝对路径；**child 任务文本含一行 `Batch record (batchDoc): <abs>`**（同形镜像，无变体退路） |
| 受限变体 | 审计 / 勘察子代理的 `delete props` 清单**同步加 `batchDoc`**（不得透传给子代） |
| 越界文案 | 越界错误文案**带实际角色名**参数化（designer 越界时不误导为 eng-coder 专属措辞） |

**选型（决策点）**：校验落点取「共用装配点（token 门旁）」而非「execute 内」或「两处都查」——**A 与 B 覆盖等价**，A 胜在**单一共用装配点 + 与 token 门同出口**；C 冗余。
**判据级别**取「存在 + 可读」（iii）而非措辞正则或机器标记——(i) 把中文措辞写死进代码、模板一改就断；(ii) 给文档加机器字段 = 形状约束；(iii) 零脆弱，内容好坏由执行者拒收兜底。

**VSC 侧差异（P2 面——机制原则保留，实现坐标归 VSC 轮）**：VSC **无** CLI 的双路装配单点（阻塞 spawn 与异步 spawn 各自在册）——选型取「**两处各落 + 共享校验函数**」（否决「先造共享 spawn 等价点」：结构性重构，风险超出镜像范围；共享校验逻辑仍单份，语义不会漂）。

## 4. 批次档生命周期工具 `batch`（FR22 载体 + 生命周期扩权）

**目标**：六段机制要求「一段一作者」，但子代理**没有写批次档的手段**——现实是**父侧代写**，而代写 = 二次加工 = 失真源。`append`（原 `batch_segment` 语义原样迁移）给子代理一条**受控写入通道**：各写各段、写到准确位置、不留后门。
**生命周期扩权（2026-09-21 · 承 `docs/batches/2026-09-21-batch-lifecycle-tool.md` §1）**：批次档全生命周期（建 → 写 → 转 → 收）收进同一工具——**创建走有门通道**（骨架预齐 + 占位状态行含 gate 合法关键字 + 建档即过 gate），消「校验有工具、创建靠手感」的半截纪律。action 枚举 = `create`（建档，§4.11）/ `append`（段写入，本节全表）/ `status`（状态行流转，§4.12）/ `close`（收口冻结，§4.13）。

### 4.1 工具契约

| 契约 | 内容 |
|---|---|
| **append/status 无路径参数（子代理）** | 子代理（eng-designer / eng-coder / 评审）的 append / status 不接收目标路径；**目标批次档路径由 spawn 时注入**——**语法上就写不到别处**。两个有意破例（均绑 depth-0——D-BR17 / D-BR21）：create 有 `path`（主代理建新档必须指定位置）；depth-0 的 append / status 有可选 `path`（无 spawn 绑定、多批在飞——无 path 无从定位；缺省 = 在飞批唯一时取该批，复数时必传） |
| **段白名单（按身份）** | `eng-designer → §2` · `设计评审子代理 → §3` · `eng-coder → §5` · `主 agent → §1/§4/§6`（§1 方案行绑定——D-BR18）；**越段写入即拒**——「一段一作者」从纪律升为**机械事实** |
| **append-only** | append 只追加，不覆写、不删除已有段；**既有行字节不变**。status / close 是**状态行单行改写**（§4.12 / §4.13）——唯一豁免，域限状态行 |
| **来源戳（工具生成）** | 写入 §3 时由**工具**加盖 `### 轮次 N（评审子代理）`；N 只数**工具写入过的**轮次行（固定骨架行 `### 轮次与发现（…）` **不计**）；调用方自带同名标题被忽略 |
| **凭证剥除（工具做）** | 写入前过滤 token / designId 形态行——**模型可能忘，机械不能忘**；工具用**自有正则**（自有冒号态形态），**不复用**凭证巡检正则（后者要求参数名后接空白，匹配不到冒号态） |
| **fail-closed** | 目标段标题缺失 / 越段 / 骨架行冲突（写入文本含 `## §N` 标题形态）/ 超量（单次 text 超上限）/ **已收口档回改 / 状态行不可解析**（§4.9）⇒ **throw**；失败**明示报告「§× 未写入」**；回退父侧代写**必须打标** |
| **分段追加** | 超量拒收后拆成多次调用写同轮内容——**每次调用各成节、N 顺延**（档案按节记，分区诚实——无「不新盖戳」承诺） |
| **action 分发** | 单工具 `batch({action, ...})`——家法 = `subagent` / `memory` / `git` 形态；append 侧判定函数（段白名单 / 来源戳 / 凭证剥除 / 超量 / 冻结）逐一复用，零语义变（§4.11–§4.14 为新增 action 面） |

**段定位的骨架前提**：批次档骨架由 **create 一次预写**（`## §2` 等标题在档，§4.11）——工具按标题定位追加；标题缺失即 fail-closed（纠正动作 = 主代理 create 建档或补骨架；append **不自动补骨架**——create 是骨架唯一权威入口）。

### 4.2 档绑定（路径怎么到执行者手里）

- **eng-designer / eng-coder**：spawn 时 `batchDoc` 经门禁校验 → `child._batchDoc = <abs>`（§2）→ 工具取用。
- **设计评审**：`batchDoc` 作为 advisor 调用参数传入，沿**评审实例键**（`resolved.run.batchDoc`）传递到工具入口——**不用单值会话态**（异批次并发的设计评审各自正确落档，不得串档）。
- **不强制必传**：评审侧 `batchDoc` = **若传则须可读**——未传 ⇒ 工具**不挂载**、评审照常跑（零回归；无批次档的在途设计评审不受阻）。主 agent 侧纪律 = 有批次档在飞时必传。

**选型**：路径传递取「参数在工具入口 + **评审实例键**传递」而非「显式参数贯穿到评审执行体」——后者需改一个已贴档位硬顶的模块（+行即越线）；前者保留参数可拒可测，且实例键与正文同口径。
**工具形态**取「单工具 action 分发」而非「四工具并列」——一套挂载面 / 一条绑定通道覆盖全生命周期；append 的「无路径参数」仍把限制写在**语法**里（否决「通用 `write` + 路径白名单」：授权面大一档，白名单可绕/可扩大）。

### 4.3 工具挂载（三方，只读面不扩）

| 调用方 | 挂载落点 | 路径来源 |
|---|---|---|
| **设计评审** | 评审工具集构造：**仅当 `reviewType === "design"` 且 batchDoc 已绑定（可读）时**追加 `batch`（仅 append / status 可用——create / close 对评审身份拒）；代码评审分支**零变更**（零 git、只读不变）；测试缝保留 | 评审实例键（§4.2） |
| **eng-designer / eng-coder** | 家族单源 `thincoder-core/agent/family-tools.mjs` 挂载链（eng-coder = `[advisor, verify, batch, subagent]` · eng-designer = `[batch, subagent]`）：两分支各追加 `batch`（仅 append / status 可用） | `child._batchDoc`（spawn 时绑定） |
| **主 agent** | **depth-0 挂载 `batch`（2026-09-21 扩权——D-BR18）**：create / close 仅 depth-0 放行；§1/§4/§6 普通文档写**照旧零回归**（工具通道是新增、不替代） | create / close `path` 参数（工具无 spawn 绑定态）；depth-0 的 append / status 可选 `path` 参数（§4.1——缺省 = 在飞批唯一时取该批，复数时必传） |

### 4.4 §3 内容 = 评审结论全文

每轮追加附录节：**`### 轮次 N（评审子代理）`（标题由工具生成）+ 该轮发现表（逐字 markdown 表）+ VERDICT 行 + 计数**；多轮各自成节（append）。**逐字不转述**（父侧不得代润色/缩减）。
§3 写在**批次档**——**§3 段不在评审对象清单内**（B9 只含批次档 **§2**）；追加 §3 **不改变被审内容**，故与冻结窗口不冲突。
**承载面分工**：内容性（表全文 + VERDICT + 计数、逐字）由**提示词层**承载（grep 断言）；机械面 V3 只保证**底线**（§3 非空 + 含工具写入轮次行）——V3 不看内容，这是有意的（内容判定无法机判，强判会假阳）。

### 4.5 提示词侧

### 4.6 机械校验 V3（零假阳口径）

入文档一致性扫描族：**仅当批次档「§4 或 §6 有实质内容」时**（机器判据；**不引用 §1 的讨论状态词**）判「§3 **含工具写入的轮次行**（排除骨架行）」。**与建批形态解耦（2026-09-21）**：create 工具化建批不改变本判据——V3 对 create 建的档照常适用（骨架行 / 占位行不算实质内容，判据零变）。
**“有实质内容”的定义**：该段内**除骨架行/斜体占位行外**存在非空行。
在飞批次（尚未评审）**不报**（避免每批都假阳）；反证用例：构造已批准但 §3 空 → 必报。
**判据射程**：V3 只判**工具落地后**创建的批次档——该日及之前的批次档 §3 无工具写入通道（父侧代写），属**结构性历史事实**而非违规（原「存量入基线」处置由**射程排除**取代）。
**选型**：V3 范围取「仅 §4 或 §6 非空的批次」而非「全批」——后者对在飞批次必然假阳。V3 落点 = 既有宽度检查档或独立档（二选一——**实际落 = 留单档**）。

### 4.7 不变量（评审判据）

1. **代码评审只读保证不削弱**（零 git + 只读工具集）。
2. **凭证绝不落档**（工具级强制，不靠纪律）。
3. **父代理 §1/§4/§6 普通文档写语义不变**（工具通道为新增——主 agent 挂载只解锁 create/close 与 §1/§4/§6 append，既有写法零回归，D-BR18）。
4. **不静默兜底**（失败必可见 + 代写必打标）。
5. **来源戳不可伪造**（工具生成标题与 N）。
6. **并发隔离**：异批次并发的设计评审**各自正确落档**（实例键绑定），不得串档。
7. **depth-0 参数面**：主 agent 的 append / status 携可选 `path` 定位目标档（无 spawn 绑定态——D-BR21）；子代理语法不变（目标仍由 spawn 注入）。

### 4.9 状态行冻结拒写 + `docRoot.batches` 双基底（v2——M3 增量）

**写入路径新增两道机械门（`batch` append/status 写入前——符号名 = `batchTool.execute`；`batchSegmentTool` = 过渡别名，§4.14——fix 轮 #9）**：

1. **状态行解析（fail-closed）**：解析对象 = §1 段内 `**状态行**：` 前缀行（§1 边界 = 该行到下一 `## §` 标题；其他段内「状态行」字样不参与判定）；关键字判定：含 `已收口` → 冻结、含 `进行中` → 放行（emoji / 括号 / 日期后缀容忍）；缺失 / 两关键字皆不命中 → 拒（fail-closed：不可解析视为冻结——宁可误拒进行中档，不得放行回改已收口档）。
2. **冻结拒写**：`已收口` / 不可解析 → throw（错误消息区分「已收口档不回改」/「状态行不可解析或缺失」）——覆盖 `batch` append / status 通道；主 agent 对 §1/§4/§6 的普通文档写不经本工具，兑底 = 写纪律。

**落点接线（N3 可迁移）**：解析序与防嵌套**单源 = §4.15**（2026-09-25 批收正——`batch-paths.mjs`）。

### 4.15 相对路径解析序与防嵌套（台账 #287 · 2026-09-25 批）

**问题**：同一批次档路径串在不同动作 / 不同 cwd 下解析结果不同——create 只按基底解析（根相对串静默嵌套成 `docs/batches/docs/batches/…`）；append / status / close 与评审门按「cwd → 基底」解析（cwd ≠ 项目根时根相对串必 throw）；spawn 门只按 cwd 解析（单基底）。四处调用点 = 三条规则各解各的。

**契约（单源 = `agent-tools/batch-paths.mjs`；四处调用点全部经它——create / append·status·close / 评审门 / spawn 门）**。**矩阵 cwd 四形** = 项目根 / 项目内子目录 / 项目根的上级目录 / 非项目目录（无 manifest）——用例 BR-27–BR-35 以此四形为准：

1. **候选序（相对路径）**：① `resolve(cwd, p)` → ② `resolve(项目根, p)` → ③ 逐基底 `resolve(基底, p)`（**基底取值两段**：**声明面** = manifest `docRoot.batches`；**缺省回退默认值** = 声明面为空时 `resolve(docRootBase(cwd), "docs/batches")`（docRootBase = 项目根 ?? cwd））。
   **取面分野（基底腿）**：**create / 在飞扫描 / 锚定面**取「声明面 + 缺省回退」合体（`batchDocBases(cwd)`——恒非空）；**读面 ③ 腿只取声明面**（无 manifest ⇒ **无基底腿**——读面零回归）。
   **「项目根」取根单源** = `resolveProjectRoot(cwd) ?? resolve(cwd ?? ".")`（归属 ∨ 发现两段——`thincoder-core/manifest.mjs` `resolveProjectRoot`；`no-project` / 无 manifest ⇒ `resolve(cwd ?? ".")` 兜底；同式 = 库键式的同一子表达式，`design/LEDGER.md` §6.1 口径 2）。
   **单值**——基底可多根，项目根不受基底数影响（多基底不产生多项目根）。
2. **判据分野（唯一差异）**：**读面**选候选序中**首个可读文件**（判据仍「参数在 + 路径可读」逐字不变）；**create** 选候选序中**首个落在基底根内**者（新档不存在，可读性无判别力）。
3. **防嵌套（锚定规则）**：`p`（归一 `/`）以**任一基底的「项目根相对前缀」**（如 `docs/batches`）打头**且前缀后为路径段边界（`/` 或串尾）** ⇒ **只解析项目根形**（候选②，跳过 ①③）——已含基底相对前缀的串不再二次拼接；项目根形不落基底内 ⇒ fail-closed 带提示。**段边界例**：`docs/batches-old/<x>.md`（前缀同形、`-` 非段边界）⇒ **不锚定**，照候选序解析、不触发 fail-closed（BR-35）。
4. **零变面**：绝对路径照旧取用（create 仍过越基底判据）；「参数在 + 路径可读」判据句、冻结门、段白名单、错误文案（spawn 门逐字 / `resolveBatchDocPath` 逐字）全部零变。

**行为变更登记（有意收正）**：① create 收根相对串（原静默嵌套）；② create 在 cwd = 子目录 / 上级 时收 cwd 相对串（原嵌套）；③ 读面在 cwd ≠ 项目根时收根相对串（原 throw）；④ 读面不再命中「同前缀嵌套幽灵档」（防御性收窄）。其余当前成功路径逐字零变（读面候选序对既有命中为**追加**关系——**唯一序内边界 = ② 先于 ③**：`<项目根>/p` 与 `<基底>/p` 并存且皆可读 ⇒ 读面取 ②；该优先级即本条登记面）。

**fail-closed 新文案（逐字）**：`batch: create path is anchored at a batch base root but does not resolve under the declared docRoot.batches root(s) — refusing to nest it (fail-closed). Path: <raw>`

**射程**：create 的相对路径语义变更 = 对外可见行为变更（工具参数解析）——登记面 = 本性 + 批档 §2；不改工具参数 schema、不改判据句。

**边界**：不做 basename 搜索 / 全仓 glob（启发式找档）；前缀匹配只认**锚定面基底**（「声明面 + 缺省回退」合体——`batchDocBases`，条 1 取面分野）的相对前缀且**按路径段（段边界）判**（条 3；前缀不匹配者不做启发式改写——登记）；不做 UNC / URL 形路径语义扩展；不改 VSC 侧路径面（VSC 经核消费本解析序）。

**锚断言口径**：关键句进 **fail-when-unchanged** 家族（提示词内容断言）；**新增的 persona 文件必须进断言清单**，否则首行格式断言与表行宽断言**不覆盖它**（漏覆盖即漏防）。

### 5.1 批次档生命周期（界 / 护栏 / 闭合 / 接续 / 判定权）

**问题**：旧档 `docs/batches/2026-09-13-CORE-UNIFICATION.md`（≈6900 行）自代码面迁移一路用到文档面迁移 ⇒ ① 所有子代理在其上串行排队 ② 档过长使父侧注意力下降（漏项 / 误报的机制性根因）。
需求回指 = `requirements/ENGINEERING-MODE-V2.md` §13.6（批次档生命周期）；判据面 = 本档 §5.1。

**五类判据（七行）**：

| # | 判据 | 阈值 / 形态 | 越界动作 |
|---|---|---|---|
| L1 | **界**（一次实现轮） | 一批 = 一个交付目标 + 一组同批条目 + 一份批次档；命中任一即越界：① 交付目标变更（主题词变）② 阶段跨越 ③ 条目集变更（新增条目不属原批范围 / 原批条目已全部核销） | 另起新批新档（本批 §6 收口后闭合） |
| L2 | **护栏·长度** | 单档 **>1000 行** = 越界信号 | 必须另起新批；已写内容不回改 |

**本轮不加机检**（守护 = 双面逐字 + 评审核验 + 三机检零回归）；**阈值机检为候选扩展、不入本批**（登记：D-BR13）。判据与用例 BR-10 – BR-16（见 §4.8）；**L7 机检为候选扩展**（判据取值可数、机械可得——本轮不落，登记 §7 D-BR15）。

### 5.2 兜底核销路径（批未收口 / 条目失去挂靠——台账 #99）

**问题**：正常链路里条目的核销节点 = 挂靠批的 §6 收口（核销同步清单）；批**不再走正常收口路径**时该节点消失——条目已实质完成、批档却停在「进行中」（§4 / §6 无实质内容），核销既无触发点也无规则。
实例 = `docs/batches/2026-09-18-machine-check-closeout.md`（§5 全绿 · §4 空 · 无 §6 · 状态行永停进行中，而其条目 #48 / #51 已另行核销）。**本条的靶 = 条目侧的核销节点，不是给批档另开闭合口。**

**触发（任一命中）**：① 条目已实质完成，而挂靠批档停在「进行中」且 §4 / §6 无实质内容（不再有实现活动）；② 挂靠批已被拆 / 被取代（承载改由新批档或父侧直接执行）；③ 条目在挂靠批档之外完成（父侧直接执行 / 他批顺带涵盖），该档无对应 §5 记录。

**动作（主 agent）**：① **核销判据 = 结账依据**（不是挂靠批档的状态行）——先按迁移表推进到「待核销」，`evidence` 回写**结账依据**（批档路径 + 段 / 行坐标，或提交号 / 他批坐标）；② **批档面零旁路**——L4 闭合语义不变（§6 收口完成 ⇒ 状态行「已收口 <日期>」）：判定该批仍有后续价值 ⇒ 由主 agent 补写 §6（「兜底收口行」须记**未走 §4 用户批准**及其依据）后按 L4 闭合；判定不再收口 ⇒ 整档原样保留（外部记忆），**不得当活档引用**（新批 §1 前情指针注明未收口）。

**可达面（触发点在哪）**：现役批收口的**前批遗留核对**（核销同步清单「待办勾销」项逐条核）+ 台账事件面（`prompts/persona-engineering.md` 台账节「事件 → 动作」③ 批收口）。**不是**被卡批档自身的 §6——该清单只对该批可跑，对「批未收口」对象不可达。

## 6. VSC 端镜像（FR23——机制原则）

> **实现坐标（VSC 仓文件路径与行数）** = P2 产品面 ⇒ 归 VSC 轮；本档只落机制原则与锚面（选型理由与差异登记见 §7）。

### 6.1 总原则：语义同源·原文自持（N1）

两端**各自实现、不共用代码**；机制语义同源，**实现各写一份**。**镜像 ≠ 抄实现：抄的是契约与锚句**，适配的是落点（VSC 落点多处不同）。

### 6.2 镜像锚（逐字源钉死——多实现面纪律）

需逐字一致的段**不在本设计重述**（避免第三份副本），而以**逐字源为 CLI 侧文件:节**，实现面**照拷、禁自行解释**；差异只允许在路径/UI 引用处，且必须登记：

| 锚 # | 内容 | 逐字源 | VSC 宿主 |
|---|---|---|---|
| A1 | 六段 append-only·**一段一作者**声明句 + **子代理自写不经父侧转述** | 纪律层六段块 | VSC 同名档（**新增六段节**） |
| A2 | **写入手段句**（`batch({action:"append", segment, text})`——子代理 append/status 无路径参数 + 段白名单枚举；create / status / close 各附身份判据，depth-0 `path` 破例见 §4.1 / D-BR21） | 纪律层同块 | 同上 |
| A3 | **执行者拒收**·**澄清必经主 agent**·**三方条目一致** | coder / designer persona | 同名两档 |
| A4 | **D1–D7 文档更新纪律表** | 纪律层文档更新纪律节 | 同 A1 宿主 |
| A5 | **§3 写入指令句 + 适用面限定子串**（仅设计评审 / 工具已挂载） | 评审三档 | 同名三档 |
| A6 | **失败明示句** | 纪律层 + 评审三档 | 同 A1 宿主 + 三档 |
| A7 | **调用侧句**（有批次档在飞时发起设计评审必须传 `batchDoc`） | 纪律层发起评审节 | 同 A1 宿主 |
| A8 | **`batch` 工具描述文案**（action 枚举 / 段白名单枚举 / 子代理 append·status 无路径参数 + depth-0 可选 `path` 破例（D-BR21）/ append-only / 来源戳 / 剥凭证 / 失败明示） | 工具定义字符串 | 新增同名档（**断言口径 = 跨仓同文件 grep**） |
| A9 | **来源戳形态**（`### 轮次 N（评审子代理）`、N = §3 内该形态行计数 + 1、排骨架行） | 本档 §4.1 | 工具实现（**行为锚**——不进 grep 集合） |
| A10 | **V3 触发判据**（§4 或 §6 有实质内容；骨架/占位行不算） | 本档 §4.6 | 一致性检查实现（**行为锚**） |
| A11 | **spawn 样例行带 `batchDoc=`** | 纪律层 spawn 样例节 | 同 A1 宿主 |
| A12 | **主 agent 人格改述 + spawn eng-designer 调用链** | 主 agent persona | 双源同名两档 |

**判据**：**文本类锚**（A1–A8 / A11 / A12）在 VSC 侧宿主文件与 CLI 侧逐字相同（grep 断言；白名单枚举/参数名/状态词不得改写）；**A9 / A10 为行为锚**（宿主是工具/脚本代码），断言面 = 行为用例，**不进 grep 集合**。

### 6.3 提示词双源与端特有段

- 两端各自 `docs/core/design/prompts/` 中文权威镜像，与英文产品源**同名集合相等**。
- **端特有段处置**：某端独有的内容段**在其面原地保留**（不并入另一面布局）；镜像时**一并写入该端中文镜像**并**逐项登记差异表**（文件 + 段 + 来源），双源断言**覆盖端特有段存在性**（非仅锚句）。
- **跨仓节引用处置**：逐字拷入后按“路径/UI 引用处”豁免——能对上目标仓对应节的改写、对不上的改注「（CLI 侧）」，**逐项入镜像差异表**；一致性检查对**带注记的引用行豁免**（不报、不入基线）。该豁免为 VSC 侧独有语义（另一侧不变）。
- **定点改写**：仅**锚句宿主档**改，**其余档不动**——**不得拿一端的 src/prompts 整体覆盖**（会回退另一端特有内容）。

### 6.4 实现面拆分与不变量

**实现面拆分**：① **代码面**（门 / 角色 / 工具 / 装配 / 枚举 / 一致性检查 + 新用例档）② **提示词双源面**（拷贝 + 锚句宿主定点改 + 新建 + 锚句断言测试）——**文件域不相交 → 两个 eng-coder 并行**；锚句断言测试归面 ②（它拥有那些文件），面 ① 的测试只测代码行为。

**不变量**：① 代码评审纯只读不削弱 · ② 凭证绝不落档（工具级剥除）· ③ **语义同源·原文自持**（文本类锚逐字一致；行为锚由行为用例承载）· ④ 零回归 · ⑤ **验收不拿静态存在冒充生效**（必须重载扩展后实跑）· ⑥ **角色可 spawn**（断言下沉到运行期门——白名单/模式门/子代门全部通过才算落地）。

## 8. 边界（本档不做）

1. 不写实现代码（工具本体 / 门禁 / 装配 = eng-coder 写域）。
2. 不写提示词实体（内容权归主 agent）。
3. 不裁定 VSC 仓文件坐标（P2——归 VSC 轮；本档只给机制原则与锚面）。
4. 不重述需求侧模板与段作者表（D2——指针见档头）。
5. 不做批次档内容模板化（append 载荷自由正文——批次档是记录不是表单；模板只覆盖**骨架与占位**，§4.10）。
6. 不动 §1/§4/§6 主 agent 普通文档写语义（create / close 是**新增**有门通道，既有写法零回归）。
7. 需求档面（`requirements/`）零改动（需求笔归主 agent——若需同步收口由主代理裁量，上抛项见批档 §2）。
8. 不做批次档路径的启发式查找（basename 搜索 / 全仓 glob）——解析只认候选序与声明基底的相对前缀（§4.15 边界）。
