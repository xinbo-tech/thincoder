## 1. 载体机制（批次档三点）

**定位**：批次档 = 任务流转的核心依据——**全链路唯一贯穿的档**（起 → 派 → 验）。需求档管“现状是什么”（无批次概念）、设计档管“怎么做”（跨批次演进）；
**只有批次档有完整链条**：B1 讨论落档 → B3 输入 designer → B6 designer 追加 §2 → B9 评审判据基准 → B11 **§2 即任务书** → B13 验收对照 → 需求池核销证据。

**三点机制**：

1. **档不可缺、不可写歪**——它是外部记忆（agent 上下文会丢），缺件 = 全链路失准。
2. **路径不硬编码**——批次档位置由调用侧传入（`batchDoc` 参数），产品**不假定**用户项目形如本仓；错误消息里的 `docs/batches/<批>-<主题>.md` 是**提示文案**，**不参与路径判定、不是默认位置**（判定只看 `batchDoc` 传入值）。
3. **判据只到「参数在 + 路径可读」**（spawn 门；设计评审点火另加一道账链门——§4.2 必传条）——**不校验内容/措辞**（不做正则匹配状态词——脆且把措辞写死）；内容够不够由**执行者拒收**兑底（`docs/core/requirements/ENGINEERING-MODE-V2.md` §8 依据缺失处置）。

## 2. batchDoc spawn 门禁

**门禁判据**：目标角色（`eng-coder` / `eng-designer`）spawn 时**必须**传 `batchDoc`；**没传即拒**；传了但**不可读**（不存在 / 非文件）亦拒（消息含路径与原因）。

| 面 | 契约 |
|---|---|
| 参数 schema | spawn 参数面新增 `batchDoc` 属性（否则参数无处传入）；模型面描述文案 = **模式无关措辞**（两模式分支同列、不随会话模式变动——§4.16「描述面处置」） |
| 角色域 | 门**只对 `NEEDS_BATCH_DOC = { eng-coder, eng-designer }` 生效**——其余角色（`explore` / `plan`）**零变更**（不带 batchDoc 照常 spawn）；`coder`（普通模式）：门不生效、**可选**携 `batchDoc`（传则须可读——§4.16） |
| 校验落点 | **单一共用装配点 + 与 token 门同出口**（阻塞/异步两路命中同一校验函数；错误生命周期一致） |
| 路径解析 | 相对路径解析序（候选序 + 锚定防嵌套 + 基底自有项目根形）**单源 = §4.15**（`batch-paths.mjs`）——门判据仍「参数在 + 路径可读」，解析面与 append / create 同源（2026-09-25 批；2026-10-05 收正） |
| 注入 | 通过校验后 child 携带批次档绝对路径；**child 任务文本含一行 `Batch record (batchDoc): <abs>`**（同形镜像，无变体退路） |
| 受限变体 | 审计 / 勘察子代理的 `delete props` 清单**同步加 `batchDoc`**（不得透传给子代） |
| 越界文案 | 越界错误文案**带实际角色名**参数化（designer 越界时不误导为 eng-coder 专属措辞） |

**选型（决策点）**：校验落点取「共用装配点（token 门旁）」而非「execute 内」或「两处都查」——**A 与 B 覆盖等价**，A 胜在**单一共用装配点 + 与 token 门同出口**；C 冗余。
**判据级别**取「存在 + 可读」（iii）而非措辞正则或机器标记——(i) 把中文措辞写死进代码、模板一改就断；(ii) 给文档加机器字段 = 形状约束；(iii) 零脆弱，内容好坏由执行者拒收兜底。

**VSC 侧差异（P2 面——机制原则保留，实现坐标归 VSC 轮）**：VSC **无** CLI 的双路装配单点（阻塞 spawn 与异步 spawn 各自在册）——选型取「**两处各落 + 共享校验函数**」（共享校验逻辑仍单份，语义不会漂）。

## 4. 批次档生命周期工具 `batch`（FR22 载体 + 生命周期扩权）

**目标**：六段机制要求「一段一作者」，但子代理**没有写批次档的手段**——现实是**父侧代写**，而代写 = 二次加工 = 失真源。`append`（原 `batch_segment` 语义原样迁移）给子代理一条**受控写入通道**：各写各段、写到准确位置、不留后门。

**生命周期扩权（2026-09-21）**：批次档全生命周期（建 → 写 → 转 → 收）收进同一工具——**创建走有门通道**（骨架预齐 + 占位状态行含 gate 合法关键字 + 建档即过 gate），消「校验有工具、创建靠手感」的半截纪律。action 枚举 = `create`（建档，§4.11）/ `append`（段写入，本节全表）/ `status`（状态行流转，§4.12）/ `close`（收口冻结，§4.13）。

### 4.1 工具契约

| 契约 | 内容 |
|---|---|
| **append/status 无路径参数（子代理）** | 子代理（eng-designer / eng-coder / 评审）的 append / status 不接收目标路径；**目标批次档路径由 spawn 时注入**——**语法上就写不到别处**。两个有意破例（均绑 depth-0——D-BR17 / D-BR21）：create 有 `path`（主代理建新档必须指定位置）；depth-0 的 append / status 有可选 `path`（无 spawn 绑定、多批在飞——无 path 无从定位；缺省 = 在飞批唯一时取该批，复数时必传） |
| **段白名单（按身份 · 模式感知）** | 工程面（逐字不变）：`eng-designer → §2` · `设计评审子代理 → §3` · `eng-coder → §5` · `主 agent → §1/§4/§6`（§1 方案行绑定——D-BR18）；普通面（2026-10-09 新增——§4.16）：`主 agent → §1/§2/§4/§5/§6` · `coder（携绑定）→ §5`；**越段写入即拒**——「一段一作者」从纪律升为**机械事实**（`edit` 段域同表同判——段域一处单源） |
| **段内一个写面（作者改自己那一段）** | **六段各自只有一个作者**；作者对本段可 `append` 在段尾加内容、可 `edit` 就地改写既有行 / 删区间（判据与边界 = §4.19）——§2 与 §1/§3/§5/§6 **同一处置**，差别只在段的内容性质、不在写面。**非作者一概拒**（段白名单仍是机械事实）。**状态行单行改写**（status / close）是唯一被单独划出的行级写面（§4.12 / §4.13）；`append §3` 带打回裁定时由工具同笔把 `§3` 状态行重置为 `进行中（第 N 轮打回）`（判据 / 形态单源 = `docs/core/design/BATCH-LEDGER-REVIEW-UNIFY.md` §2.5） |
| **来源戳（工具生成）** | 写入 §3 时由**工具**加盖 `### 轮次 N（评审子代理）`；N 只数**工具写入过的**轮次行（固定骨架行 `### 轮次与发现（…）` **不计**）；调用方自带同名标题被忽略 |
| **凭证剥除（工具做）** | 写入前过滤 token / designId 形态行——**模型可能忘，机械不能忘**；工具用**自有正则**（自有冒号态形态），**不复用**凭证巡检正则（后者要求参数名后接空白，匹配不到冒号态）。**形态 = 三形**：① 闭括号形（`[DESIGN-TOKEN:…]`）② 键形（`designId:` + 值）③ 无标两段值形（`⟨uuid⟩:⟨epoch⟩`——Approved 后缀逐字携带）∥ **裸 uuid 不剥**（id 非凭证 ∥ 批侧无 token 上下文不可精确） |
| **fail-closed** | 目标段标题缺失 / 越段 / 骨架行冲突（写入文本含 `## §N` 标题形态）/ 超量（单次 text 超上限）/ 死占位残留拒（F11-C——判据 = `TOOLS.md` §6.20）/ **已收口档回改 / 状态行不可解析**（§4.9——**唯一例外 = 重开合取**：段 = §1 · depth-0 · 值关键词 = 进行中 · `note` 非空，§4.18-B）/ **`append §3` 无裁定行 ∥ 两者同携**（`R-G3`——判据单源 = `docs/core/design/BATCH-LEDGER-REVIEW-UNIFY.md` §2.6.1；`edit §3` **不在此判据内**——它改的是既有块内的字，裁定行闸只挂 `append`，§4.19） / **收口链未跑完**（§4.18-A——`close` ∥ `status` 写「已收口」）/ **`edit` 锚判据**（零命中 ∥ ≥2 命中 ∥ 锚越段界 ∥ 锚或替换触及状态行——§4.19）⇒ **throw**；失败**明示报告「§× 未写入」**；回退父侧代写**必须打标** |
| **文档机检门（2026-10-18）** | `append` ∥ `edit`（全部段，含 depth-0 与评审写 §3）⇒ 写盘前自动跑 `doc_check` 的 gate：`REFUSED` ⇒ throw（串含 verdict + 命中清单），档字节不变；`PASS` ⇒ 照写；`ERROR` ⇒ 写 + 回执明示。`close` ∥ `status` 值余核 =「已收口」⇒ 收口前同跑：`REFUSED` ∥ `ERROR` ⇒ throw（状态行不改）。范围 / 适用面 / 版本前置 = `docs/core/design/DOC-DISCIPLINE.md` §3.20「结构兜底」（本档不重述） |
| **分段追加** | 超量拒收后拆成多次调用写同轮内容——**每次调用各成节、N 顺延**（档案按节记，分区诚实——无「不新盖戳」承诺） |
| **action 分发** | 单工具 `batch({action, ...})`——家法 = `subagent` / `memory` / `git` 形态；append / edit 侧判定函数（段白名单 / 来源戳 / 凭证剥除 / 超量 / 冻结 / 机检门）逐一复用，零语义变（§4.11–§4.13 为新增 action 面） |

**段定位的骨架前提**：批次档骨架由 **create 一次预写**（`## §2` 等标题在档，§4.11）——工具按标题定位追加；标题缺失即 fail-closed（纠正动作 = 主代理 create 建档或补骨架；append **不自动补骨架**——create 是骨架唯一权威入口）。

### 4.2 档绑定（路径怎么到执行者手里）

- **eng-designer / eng-coder**：spawn 时 `batchDoc` 经门禁校验 → `child._batchDoc = <abs>`（§2）→ 工具取用。
- **coder（普通模式 · 2026-10-09——§4.16）**：spawn **可选**携 `batchDoc`（非强制——「spawn 强制 batchDoc」= 工程专属、不移植）；传则须可读（同评审面判据）⇒ `child._batchDoc = <abs>` 绑定 ⇒ §5 记录通道；未携 ⇒ 不绑定、照常 spawn。
- **设计评审**：`batchDoc` 作为 advisor 调用参数传入，沿**评审实例键**（`resolved.run.batchDoc`）传递到工具入口——**不用单值会话态**（异批次并发的设计评审各自正确落档，不得串档）。
- **必传（设计评审）**：`batchDoc` = **必填**——未传 ⇒ `advisor` 拒发（判据 / 拒文 = `docs/core/design/ADVISOR-GUARDS.md` §2 第 6 条）；传了则须可读（同一解析单源 `resolveBatchDocPath`，文案逐字）。
  **可读之外还要有账**：该档须有至少一行未决台账行的 `task_book` 指着它（同族第二道准入门——判据 / 判据来源 / 拒文 = 同档 §2 第 7 条）。`batch create` 与开行同一笔 ⇒ 正常链恒满足；门拒的三种可达径（行被撤 ∥ 核销后重开 ∥ 指针改挂）也在该条点名。**为什么必填**：评审签出的 token 靠关档消费收口，而关档认批归属——批外签发的授权没有第二个关闭者，只能等 TTL。`type="code"` 不携此参数，不受本门约束。
- **写面两道门（段维度 / 档维度——分层不重叠）**：段维度 = 身份 → 可写段白名单（`batch` 工具的绑定面）；档维度 = 目标档 ∈ 绑定档；
  **绑定档之外**的批次档文件此前无门 ⇒ `thincoder-core/agent/dispatch.mjs`（两端单源——端档已取核）落**批次档写门**——携绑定的子代理（工程角色 ∥ 普通面 coder——§4.16）直写他批档被拒、**自身批次伴随件**（非 `.md` · 同目录 · 词干族——2026-09-29 收窄）放行
  （判据 / 文案 / 边界 = `docs/core/design/AGENT-LOOP-SUBAGENT.md` §6.29.1——本档不重述）；主 agent（depth 0）不受该门约束。

**选型**：路径传递取「参数在工具入口 + **评审实例键**传递」而非「显式参数贯穿到评审执行体」——后者需改一个已贴档位硬顶的模块（+行即越线）；前者保留参数可拒可测，且实例键与正文同口径。
**工具形态**取「单工具 action 分发」而非「四工具并列」——一套挂载面 / 一条绑定通道覆盖全生命周期；append 的「无路径参数」仍把限制写在**语法**里。

| **coder（普通模式 · 2026-10-09——§4.16）** | coder 分支（`[parentChannelTool, ledgerReadTool, verifyTool, advisorTool]`）**携绑定追加 `batchTool(batchDoc)`**——未绑定不挂载（同评审面先例：工具不在表 = 语法面不可达） | `child._batchDoc`（spawn 可选绑定） |
| **主 agent** | **depth-0 挂载 `batch`（2026-09-21 扩权——D-BR18）**：create / close 仅 depth-0 放行；`append` / `edit` / `status` 的段域 = §1/§4/§6（§4.1 段白名单），**普通文档写照旧零回归**（工具通道是新增、不替代） | create / close `path` 参数（工具无 spawn 绑定态）；depth-0 的 append / status 可选 `path` 参数（§4.1——缺省 = 在飞批唯一时取该批，复数时必传） |

**评审面的写旁路 = 无（装配面实测）**：评审工具集 = 只读六件（`read` ∥ `glob` ∥ `grep` ∥ `ls` ∥ `lsp` ∥ 代码检索），设计评审绑本档时再追加 `batch`（append / edit / status）。

不含 `write` / `edit` / `bash` / `apply_patch` ⇒ 写批档的通道 = `batch` 的 `append` 与 `edit`（`create` / `close` 对评审身份拒）；`§3` 的裁定行闸挂在 `append` 通道上（`edit` 改的是既有块内的字，不要求裁定行——§4.19）：判据单源 = `docs/core/design/BATCH-LEDGER-REVIEW-UNIFY.md` §2.6.1。实现坐标 = `thincoder-core/advisor/loop.mjs` `advisorToolsFor`。

**动作可用面的判点（装配 ∥ 动作）**：

- **装配**（哪身份挂到哪个工具集）= 家族单源 `thincoder-core/agent/family-tools.mjs` 挂载链 ∥ 评审侧 `advisorToolsFor`。
- **动作可用面**（哪身份许哪个动作）= `batchTool.execute` 的 action 分派（`thincoder-core/agent-tools/batch.mjs`）：`case "create"` → `createBatchRecord` · `case "append"` → `appendBatchRecord` · `case "edit"` → `editBatchRecord` · `case "status"` → `statusBatchRecord` · `case "close"` → `closeBatchRecord`。
- **`create` 的首判** = `assertMainAgentOnly`（`thincoder-core/agent-tools/batch-ledger-bind.mjs`，注释逐字「main-agent-only 门（BR-19/BR-24）：create 仅 depth-0 放行（eng 子代理 / 评审皆拒）」）；`close` 的同一道门 = BR-24（§4.13）。
- **段域判** = `allowedSegment`。**上面括注里的「append / edit / status 可用」不是文案，就是这两处判据的读数。**

### 4.4 §3 内容 = 评审结论全文

每轮追加附录节：**`### 轮次 N（评审子代理）`（标题由工具生成）+ 该轮发现表（逐字 markdown 表）+ VERDICT 行 + 计数**；多轮各自成节（append）。**逐字不转述**（父侧不得代润色/缩减）。

§3 写在**批次档**——**§3 段不在评审对象清单内**（B9 只含批次档 **§2**）；追加 §3 **不改变被审内容**，故与冻结窗口不冲突。
**每一笔追加都自带裁定行**：`§3` 的追加若读成「无裁定行」∥「两者同携」，**写不进去**；判打回的一笔照写。

拒文逐字与可认形 = `docs/core/design/BATCH-LEDGER-REVIEW-UNIFY.md` §2.6.1 `R-G3`。中文结论形的尾句号两锚同判、可省可带；混合形不认。

这不是纪律，是拒面：裁定行只在评审的回复里、没进块正文时，`§5` 门会拒而唯一能补的人已经结算离场。

**承载面分工**：内容性（表全文 + VERDICT + 计数、逐字）由**提示词层**承载（grep 断言）；机械面 V3 只保证**底线**（§3 非空 + 含工具写入轮次行）——V3 不看内容，这是有意的（内容判定无法机判，强判会假阳）。

### 4.5 提示词侧

- **评审层三条提示词全覆盖**（round 1 + round 2 + round 3 档）：均指示评审者在报告之外**调工具把表与 VERDICT 写进批次档 §3**；

### 4.6 机械校验 V3（零假阳口径）

入文档一致性扫描族：**仅当批次档「§4 或 §6 有实质内容」时**（机器判据；**不引用 §1 的讨论状态词**）判「§3 **含工具写入的轮次行**（排除骨架行）」。**与建批形态解耦（2026-09-21）**：create 工具化建批不改变本判据——V3 对 create 建的档照常适用（骨架行 / 占位行不算实质内容，判据零变）。

**“有实质内容”的定义**：该段内**除骨架行/斜体占位行外**存在非空行。
在飞批次（尚未评审）**不报**（避免每批都假阳）；反证用例：构造已批准但 §3 空 → 必报。
**判据射程**：V3 只判**工具落地后**创建的批次档——该日及之前的批次档 §3 无工具写入通道（父侧代写），属**结构性历史事实**而非违规（原「存量入基线」处置由**射程排除**取代）。
**选型**：V3 范围取「仅 §4 或 §6 非空的批次」而非「全批」——后者对在飞批次必然假阳。V3 落点 = 既有宽度检查档或独立档（二选一——**实际落 = 留单档**）。

### 4.7 不变量（评审判据）

1. **代码评审只读保证不削弱**（零 git + 只读工具集）。
2. **凭证绝不落档**（工具级强制，不靠纪律）。
3. **父代理 §1/§4/§6 普通文档写语义不变**（工具通道为新增——主 agent 挂载只解锁 create/close 与 §1/§4/§6 的 append / edit，既有写法零回归，D-BR18）。
4. **不静默兜底**（失败必可见 + 代写必打标）。
5. **来源戳不可伪造**（工具生成标题与 N）。
6. **并发隔离**：异批次并发的设计评审**各自正确落档**（实例键绑定），不得串档。
7. **depth-0 参数面**：主 agent 的 append / status 携可选 `path` 定位目标档（无 spawn 绑定态——D-BR21）；子代理语法不变（目标仍由 spawn 注入）。

### 4.9 状态行冻结拒写 + `docRoot.batches` 双基底（v2——M3 增量）

**写入路径四道机械门（`batch` append/status/close 写入前——符号名 = `batchTool.execute`）**，序列 = ① 状态行解析 → ② 冻结拒写 → ③ 链完整性门（§4.18-A——落位 = 既有拒因之后、文档机检门之前）→ ④ 文档机检门：

1. **状态行解析（fail-closed）**：解析对象 = §1 段内 `**状态行**：` 前缀行（§1 边界 = 该行到下一 `## §` 标题；其他段内「状态行」字样不参与判定）；关键字判定：含 `已收口` → 冻结、含 `进行中` → 放行（emoji / 括号 / 日期后缀容忍）；缺失 / 两关键字皆不命中 → 拒（fail-closed：不可解析视为冻结——宁可误拒进行中档，不得放行回改已收口档）。
   **行尾形态无关**（LF ∥ CRLF ∥ 混排同判——`\r` 归行分隔、不归行内容；行切分 = `/\r?\n/`）。
2. **冻结拒写**：`已收口` / 不可解析 → throw（错误消息区分「已收口档不回改」/「状态行不可解析或缺失」）——覆盖 `batch` append / status / edit 通道；**唯一例外 = 重开合取**（§4.18-B：段 = §1 · depth-0 · 值关键词 = 进行中 · `note` 非空 ⇒ 放行并追加 §1 追记行；非合取一律走本拒写，串逐字零变）；主 agent 对 §1/§4/§6 的普通文档写不经本工具，兑底 = 写纪律。
3. **链完整性门（2026-10-18 · 收口前置——§4.18-A）**：`close` ∥ `status` 写 §1「已收口」两路在写盘前同过 `assertCloseoutChainComplete(src)`——§2 / §3 / §4 / §6 各段须有内容（每一批都要有设计、评审、批准——段内不得声明不适用）；§5 段号豁免；不满足 ⇒ throw 并点名缺段。门位 = 门 ② 之后、门 ④ 之前（链未跑完先报结构缺口，不先跑机检）。判据逐段 / 声明形 / 三拒串 = §4.18-A（本条不重述）。
4. **文档机检门（2026-10-18 · 结构兜底）**：`append` ∥ `edit`（全部段）、`status` 值「已收口」、`close` 各路在写盘前跑 `doc_check` 的 gate——`REFUSED` ⇒ 拒（append / edit 面档字节不变；close / status 面状态行不改）；`ERROR` ⇒ append / edit 放行 + 回执明示 ∥ close / status 拒（fail-closed）。契约 = §4.1 行 + `docs/core/design/DOC-DISCIPLINE.md` §3.20「结构兜底」；门位在既有拒因**之后**、写盘**之前**（零回归）。**判集分两类**：**段长类**（段落过长 / 行过长）判本次写入的文本——`append` 判追加文、`edit` 判 `newText`；**锚类**（`档缺` / `节缺` / `引缺`）+ 骨架 / 占位 / 状态行判**整档**——引用完整性是档级属性，改一处不能只看新文。`close` 面整档照判（既有 fail-closed 不变）。

收口两路（`close` ∥ `status` 值「已收口」）另过 **§4.13 单测档零留存门**——判序已定：本门位在 ③ 链完整性门**之后**、④ 文档机检门**之前**（判序单源 = `thincoder-core/agent-tools/batch-closeout.mjs:80` 的 `assertCloseoutGates`：① 链门 → ② `§3` 状态词臂 → ③ 本门 → ④ 机检门）；本清单只登记全路径门，本门的判据与拒面 = `docs/core/design/TESTING.md` §3.5。

**在途性真值 = 批次档状态行自身**（本档 ① 冻结门读它）。

**落点接线（N3 可迁移）**：解析序与防嵌套**单源 = §4.15**（2026-09-25 批收正——`batch-paths.mjs`）。
`resolveBatchDocPath(cwd, given)` = 该解析序的**读面形态**（首个可读文件胜；不可读 → throw，fail-closed 不变）。

manifest `docRoot.batches` 复判（M1 缺键 → M1 默认值 fallback；注入缝 = `configureBatchSegment`）= 解析序内**基底分支**。
`batch` append/status 行内解析改复用该函数（门禁单源——AC-M3-1 拒面与落点接线同一函数）。

**边界（本增量不做）**：不做评审本身（M6）；不做**完整批次档模板定义**（**骨架块 = §4.10 本档**；需求侧 = 指针与同步位——2026-09-20 收正，承 §4.10〔父侧直接执行 · 可 revert〕）；不做批边界判定（判定权归主 agent）；不机械拦截前情指针形态（F5 判据归属 = 主 agent 写纪律 + M8 锚检查）。与 D5 冻结窗口（M4）**不同窗口**（评审在途 vs 已收口），不重叠、不互相替代。

### 4.10 批次档骨架（create 模板单源落位）

**判据句**：`batch` append 按标题定位追加 ⇒ 骨架由 **create 一次预写**（§4.11）；标题缺失即 fail-closed（§4.1——append 不自动补骨架）。**状态行必居 §1 段内**——解析域 = §1 段内 `**状态行**：` 前缀行至下一 `## §` 标题（§4.9）；只置档头 = 不可解析 ⇒ 拒写。

**骨架（create 模板的行为规格——代码单源 = `agent-tools/batch-skeleton.mjs` 的 `batchSkeleton()`（KD-4 拆分后；`batch.mjs` 持 schema ∕ 分发）；红线 = 模板只覆盖骨架与占位，不模板化内容）**：

```text
# <日期> · <主题>
> 六段，一段一作者：§1 讨论（主 agent）· §2 批次任务与设计（eng-designer）· §3 设计评审（评审子代理）· §4 用户批准（主 agent）· §5 实施记录（eng-coder）· §6 验证与收口（父代理）。
> 每段只有一个作者：作者的段可 `append` 加内容、可就地改（`edit`，§4.19）；非作者一概拒。
> 编制：主 agent · <日期> · 来源 = <来源实参>。
> 台账 = <编号实参 | #<编号>>（<板块实参 | <板块>> · 归批）。前情 = <旧档指针 | 无（独立批）>。
## §1 讨论（主 agent）
**状态行**：🔄 进行中（…）
<§1 模板占位：本批条目 / 关键判据 / 授权口径>
## §2 批次任务与设计（eng-designer）
**状态行**：（eng-designer 写入时更新）
<§2 模板占位：本批条目（覆盖） / 设计档落点 / 机制设计 / 受影响文件与测试 / 验收对照 / 关键决策 / 上抛项>
## §3 设计评审（评审子代理）
## §4 用户批准（主 agent）
## §5 实施记录（eng-coder）
## §6 验证与收口（父代理）
```

**档头两句（写面与分权的承载位）**：第一句 = 六段 + 一段一作者（A1 族锚句形态）；第二句 = 作者对自己的段有两个动作——`append` 加内容 ∥ `edit` 就地改（§4.19）。新增档逐字取形。

**存量档档头按在不在跑分两判**：档头那句是给**当下的人**读的操作说明，不是决策证据——所以判据不是「存量 / 非存量」，是**这本档还在不在跑**。

- **状态行 = `进行中`（在飞）⇒ 随正**：作者现在就照着档头读；留着旧句，他就以为自己那一段只能追加，改不动的死锁当场回来（`#2021`）。随正形 = 两句形（§4.10 骨架块第二、三行）。
- **状态行 = `已收口`（冻结）⇒ 一字不动**：那是冻在那一轮执行里的账，改了就等于说那一轮是按新规则跑的，而它不是。

  判据不落在工具行为上，落在两次读数上：本档档头逐字 = §4.10 骨架块第二、三行；一本 `已收口` 夹具档同形操作 ⇒ 改前改后逐字节相同。

**§1 段体内的「已定决定」行约定（2026-10-19 · FR34 · 格式归属登记）**：§1 段体允许一类标记行——形 = `- **已定决定**：<决定> · 用户原话：「<逐字>」 · 时间：<YYYY-MM-DD HH:MM>`（行首标记 `- **已定决定**：` 固定）。

### 4.13 `close`——收口冻结（仅主 agent）

**参数**：`path`（目标批次档——同 depth-0 append/status 取值规则，见 §4.1 / D-BR21）。
**动作**：§1 段内状态行 →「已收口 <YYYY-MM-DD>」；此后该档 append / status 全拒（冻结判据唯一真值 = §1 行——与 §4.9 一致，零语义变；**唯一例外 = 重开合取**，§4.18-B）。**文档机检门**：§6 非空门之后、状态行改写之前跑 gate——`REFUSED` ∥ `ERROR` ⇒ throw（不落「已收口」；§4.9 ④）。

**身份判据**：仅 depth-0 放行。**不替代**：台账核销事务 / 前批遗留核对（收口链主面仍是 §6 写入 + 台账动作——close 只收**机械收口**：状态行 + 冻结；不代写 §6 内容）。
**收口前置（本批）**：写盘前过**链完整性门**（§4.18-A）——§6 非空判据在本门内、口径单源（`sectionContentState`）；**§6 为唯一缺段时拒串逐字不变**（不降级）。

**收口前置（本批单测档）**：两路收口（`close` ∥ `status` 写 §1「已收口」）另过本批批内单测档门——**登记位与门序单源 = §4.9 门清单末行**（本档只此一处登记，本条为纯指针）；判据、拒面与实现 = `docs/core/design/TESTING.md` §3.5。

**收口重锚（本批未落行——自动）**：收口**两路**（`close` ∥ `status` 写 §1「已收口」）**同调单源 `reanchorOnClose`、零二写**——两路的**全部拒因通过、§1 状态行改写落盘之后**调 `ledgerReanchorBatch`（`docs/core/design/LEDGER.md` §7.1）。

判据 ∥ 取行全集 ∥ `cwd` 基准 ∥ 复启句 ∥ 幂等 ∥ 失败语义 ∥ 次序 = `docs/core/design/LEDGER.md` §6.2（本条不重述）；收口被拒 ⇒ **台账零写**；一次收口只出一份 `[ledger reanchor]` 清单（`batch` 一次调用只分派一个 action——两路不同拍）。

**本档特有面**：回执逐行点名（`#<id> <status> <title>` → `条件`）∧ 失败因（返回形 `failed` 项）并入同一回执；冻结照常完成；无未落行 ⇒ 无该段。**重锚 ≠ 核销**（不改 `status`——核销仍走台账写命令）。

**收口时点的其它动作**：同一次 close 上还挂出口清单（只读——`docs/core/design/LEDGER.md` §3.7 ③）；批量结算则是 `ledger(close)` 携 `batch` 的显式调用，**不在** close 径。三者共存口径（先后 ∥ 幂等 ∥ 冲突裁决）= `docs/core/design/LEDGER.md` §6.2「收口三动作边界」。


### 4.15 相对路径解析序与防嵌套（2026-09-25 批）

**契约（本面参数与落位判据单源 = `agent-tools/batch-paths.mjs`；四处调用点全部经它——create / append·status·close / 评审门 / spawn 门）**；候选序算法单源 = `docs/core/design/PATH-RESOLUTION.md` §2.2。**矩阵 cwd 四形** = 项目根 / 项目内子目录 / 项目根的上级目录 / 非项目目录（无 manifest）——用例 BR-27–BR-35 以此四形为准。

   本面追加的第三级基底**取值两段**：**声明面** = manifest `docRoot.batches`；**缺省回退默认值** = 声明面为空时 `resolve(docRootBase(cwd), "docs/batches")`（docRootBase = 项目根 ?? cwd）。**create 面候选序与收窄**见条 2 / 条 6。

   **取面分野（基底分支）**：**create / 在飞扫描 / 锚定面**取「声明面 + 缺省回退」合体（`batchDocBases(cwd)`——恒非空）；**读面 ③ 分支只取声明面**（无 manifest ⇒ **无基底分支**——读面零回归）。

   **「项目根」取根单源** = `resolveProjectRoot(cwd) ?? resolve(cwd ?? ".")`（归属形单源——`thincoder-core/manifest-discovery.mjs` 的 `owningProject`（经 `manifest.mjs` 转口）取根臂 = 仅归属命中；发现读数只供 `workspace` 报明、不进 `root`；调用方 `?? resolve(cwd ?? ".")` 兜底；同式 = 库键式的同一子表达式，`docs/core/design/LEDGER.md` §6.1 口径 2）；

**多根工作区锚**（`projectRootView` 报 `workspace`——下辖有已注册项目，1 ∥ ≥2 同判）⇒ 专用条 5（不静默回退）。
   **单值**——基底可多根，项目根不受基底数影响（多基底不产生多项目根）。
2. **判据分野（唯一差异）**：**读面**选候选序中**首个可读文件**（判据仍「参数在 + 路径可读」逐字不变）；**create** 选候选序中**首个落在基底根内**者（新档不存在，可读性无判别力）。
   **create 候选序补全（#942——逐候选判据 = 条 6）**：锚定分支后依次 = ① cwd 形 → ② 项目根形 → ③ 逐基底**自有项目根**形 → ④ **基底相对形（限单段文件名）**。
3. **防嵌套（锚定规则）**：`p`（归一 `/`）以**任一基底的「项目根相对前缀」**（如 `docs/batches`）打头**且前缀后为路径段边界（`/` 或串尾）** ⇒ **只解析项目根形**（候选②，跳过 ①③）——已含基底相对前缀的串不再二次拼接；项目根形不落基底内 ⇒ fail-closed 带提示。**前缀可判限定**：基底不落 cwd 项目根下（跨仓 ∥ 声明面他仓基底）时前缀**不可判** ⇒ **不锚定**——其无仓前缀形见条 6③（BR-43）。
   **段边界例**：`docs/batches-old/<x>.md`（前缀同形、`-` 非段边界）⇒ **不锚定**（不触发锚定分支文案，BR-32 射程不变）；照候选序解析，create 多段串无落点 ⇒ 通用 fail-closed 拒（BR-35 收正——不静默建嵌套树）。
4. **零变面**：绝对路径照旧取用（create 仍过越基底判据）；「参数在 + 路径可读」判据句、冻结门、段白名单、错误文案（spawn 门逐字 / `resolveBatchDocPath` 逐字）全部零变。
5. **多根工作区锚检查（多项目并存 = 常态——2026-10-02 · #828；2026-10-15 · 2026-10-25 收正）**：会话锚不归属任何项目（`projectRootView(锚).state === 'workspace'`——下辖有已注册项目，1 ∥ ≥2 同判）⇒ **不静默回退锚基底**。
   create：目标**所属项目**（`owningProject`——用点路径 → 最近带档祖先）∈ 锚下辖项目集 ⇒ 基底 = 该项目声明面（落其基底内；越出 ⇒ 既有 fail-closed）；无所属 ⇒ **报明事实 + 可执行下一步**（下辖项目全列 + 显式路径指引——如 `thincoder/docs/batches/<x>.md`；**文案 = 逐字——见下**；**不得写 `ambiguous` / 「锚歧义」**——2026-10-15 收正）。

   读面：候选追加各候选项目的项目根形 ∥ 声明基底形（仍取首个可读——**候选间次序单源** = 候选**按名排序**（同 `discoverProjects` / `projectView` 契约），并集**保序**）。在飞扫描 / 写门基底集：候选项目基底**并集**（唯一在飞批照取 / ≥2 照列）。

   **`ok`（锚有项目）∥ `none`（空目录 ∥ 锚自身为裸仓——`.git` 无档且下辖无已注册项目）两态零改**（#827 ⑤ 语义保持——跨仓 create 照拒）；锚下辖有项目（带档者 ≥1 ∥ 零带档时裸仓 ≥1）即 `workspace` ⇒ 条 5 报明（无「子格」之分）。

6. **基底自有项目根形与基底相对形收窄（#942 残留收正——2026-10-05 批）**：create 在锚定分支 / ①② 形后补两形、并收窄基底相对形（条 2 候选序补全的判据）。**判据 = 无仓前缀相对形 ⇒ 正确落点或显式拒——不得静默建嵌套树**；回执（create `batch: created <abs>`）随落点取值——落点收正即回执不再照写错路径（拒面无回执）。
   - **③ 基底自有项目根形**：逐基底 `resolve(owningProject(基底), p)`（`owningProject` 不可判者跳过）——落基底内且**恰一落点** ⇒ 收（已含任一基底自有项目根相对前缀的串**不再二次拼接**）；**落点 ≥2 ⇒ 显式拒**（列候选落点——不静默取首个）。收正面 = 基底不落 cwd 项目根下（跨仓 ∥ 声明面他仓基底）时 `docs/batches/<x>.md` 原静默嵌 `<基底>/docs/batches/docs/batches/…`。
   - **④ 基底相对形（限单段文件名）**：归一后**单段**（不含路径分隔）者照收（`<x>.md` ⇒ `<基底>/<x>.md`——回归零变）；**多段串不收**（基底相对读法会二次拼接出 `<基底>/<多段串>` 嵌套树）——各候选无落点 ⇒ 通用 fail-closed 拒（`outsideBasesError` 文案逐字）。

⑤ **工作区锚**（2026-10-02 收正 · 2026-10-15 措辞收正）：create 原静默落锚基底 ⇒ 按目标所属项目落 / 无所属报明 + 下一步（去 ambiguity 字样——「锚下并存多项目 = 常态」）；⑥ 读面 ∥ 在飞 ∥ 写门基底集在多档锚下补**候选并集**（原「基底外」漏检 / 漏扫 ⇒ 覆盖）。

⑦ **#942 收正**（2026-10-05——见条 6）：基底不落 cwd 项目根下时 `docs/batches/<x>.md` 由「静默嵌套」改「落基底自有项目根」；多段相对串无落点由「静默嵌套」改「通用 fail-closed 拒」（BR-35 形随此收正）；基底相对形由「任意段」收窄「单段文件名」。
其余当前成功路径逐字零变（读面候选序对既有命中为**追加**关系——**唯一序内边界 = ② 先于 ③**：`<项目根>/p` 与 `<基底>/p` 并存且皆可读 ⇒ 读面取 ②；该优先级即本条登记面）。

**fail-closed 新文案（逐字）**：`batch: create path is anchored at a batch base root but does not resolve under the declared docRoot.batches root(s) — refusing to nest it (fail-closed). Path: <raw>`

### 4.18 收口前置（链完整性门）与重开路径（带审计）

**来源**：用户 2026-10-18 18:47「这个冻结门不能一直存在问题啊！」+ 18:48「修」。实证 = 五本批次档在收尾链（§2/§3/§4）全空时被 `status` 标「已收口」并永久冻结（补记被拒、解冻被拒）。病根 = 冻结门只保护「已收口的账不被改写」，不拦「链没跑完就收口」，也不承认标错。

**A · 收口前置（closeout chain gate）**

- **两个收口入口同门**：`close`（§4.13）与 `status` 写 §1「已收口」——写盘前都过 `assertCloseoutChainComplete(src)`。
- **门位**：既有拒因（冻结门 ∥ 段白名单）之后、**文档机检门**（§4.9 ④）之前——即 §4.9 门清单的**第 ③ 道**；链未跑完先报结构缺口，不先跑机检（两者均在写盘前）。
- **判据（逐段）**：判 §2 / §3 / §4 / §6 四段，每段须满足二者之一：
  ① **有内容**——段体内至少一行不属于：空行 ∥ 标题行（`^#{1,6}\s`）∥ `**状态行**：` 行 ∥ `<§N 模板占位：…>` 行 ∥ 「不适用」声明行；
  ② **声明一律拒**——§1 段体内出现 `> 不适用：§N —— <理由>` 即拒（判据 = `malformedInapplicableLine`，拒串 = `inapplicableDeclarationError`）：§2 / §3 / §4 / §6 每段必须带自己的内容（设计 / 评审 / 批准 / 验证）。
  **§5 不判**（段号豁免）。
- **判据口径单源**：`sectionContentState(src, seg)` → `content` ∥ `empty`（`not-applicable` 随声明机制退役已删；住 `batch-skeleton.mjs`——判据字面与骨架共址）。§6 旧判据 `sectionSixHasContent` 改为 `sectionContentState(src, 6) === "content"`——**同一 predicate、无第二套**；口径收紧一处（「有标题无正文」由「非空」改判「空」）。
- **「空」的三实测形（本会话五本）**：① 段体零行（`## §4` 段头紧接下一段头）；② 只有 `**状态行**：…` + `<§2 模板占位：…>` 两行；③ 只有子标题（`### …`）而正文零行。三者皆判 `empty`。
- **为什么一句声明也不行**：一声「本批无设计 / 无批准」就能把批结了账，而它由主 agent 在自己段里写；对照之下 `§3` 状态行只有绑本档的评审实例写得进。**写得进去的人不同，门的重量就不同**——用户 2026-11-02 16:17 / 16:24 两裁。`malformedInapplicableLine` 留作这条已退役路的痕迹检测：`§1` 里还写它的人当场被拒，而不是静默当作没写。
- **拒串**：`inapplicableDeclarationError` 逐字回违规行（「声明已停用——§2 / §3 / §4 / §6 各段必须带内容」）。
- **拒绝串（逐字——全在代码块内，逐字照抄）**：

```text
链门（缺段非仅 §6 时）：
batch: 收口链未跑完（closeout chain gate）— close refuses: the record's closeout chain has not run, and closing would freeze it that way. Missing: <§2 / §3 …>. - **判据不做的事**：不判内容质量（§2 写「见某档」也算有内容——门问的是「这一步跑没跑、没跑有没有说」，不是编辑审稿）；不判 §1（主 agent 自述段不设前置）；不判台账行状态（收口链 ≠ 核销）。
```

**B · 重开路径（带审计的逆向流转）**

- **触发（合取）**：目标段 = §1 · depth-0（主 agent）· 门态 = `closed` · 写入值关键词 = 进行中 · 理由（`note`）非空。

- **理由校验（重开专用，不用 `assertStatusNote`）**：单行 + 非空；**允许携状态词表关键字**——理由最自然的写法常是「误标已收口」，而括注零命中的规则防的是「括注被 gate 读成冻结」（追记行不是状态行形态，不参与 gate 判读）。

- **追加位置 = §1 段体尾部**（下一 `## §` 段头之前 ∥ 文末），直接接在段体末行之后，**不额外插空行**——与下条机检形「行数 +1」一致。为什么不在状态行下方插入：§1 向下生长，尾部追加 = 时间序；且「只追加」在实现上可判（前缀不动、仅尾部增长）。

### 4.19 段内就地改（`edit` · 作者改自己那一段）

**判据句**：批档六段，一段一作者。**作者对自己那一段有完整的写面**：`append` 在段尾加内容，`edit` 就地改写既有行 / 删区间。段与段之间仍是机械分权——非作者一概拒。

**依据**：用户 2026-11-03 05:41 原话「我个人觉得没必要限制 append-only，应该都允许修改，append-only 这个有过度设计的嫌疑。」

**现场（不是假想的边界）**：`#2021` 里父侧改了需求档一句 ⇒ 实施席在批档 §5 引那句的一行成了死引文（`引缺`）。三条路全断：
`edit §5` 逐字回「edit is not yours to run」；`append` 补一行说明，机检命中的仍是原来那行、`REFUSED` 照旧；`close` 面 fail-closed。
**「被引文档会变」是常态（父侧同一晚也在改需求档），append-only 把这个常态变成本档永久收不了口。**

**代价（如实写下）**：证据面那层「字面不可改写」没有了。事后复原当时怎么想的，靠两处——**git**（旧字节逐字可查）与**收口对账**（§7 D-BR37 两半）。这是本批明知的代价，不是遗漏。

**改写语义（`edit`）**：锚定区间替换。`oldText` 在**目标段段体内**出现**恰一次** ⇒ 就地替换为 `newText`；`newText` 为空串 = **删除该区间**（作废判据退场的主要动作）。

**不做整段替换**：段体可能超 `MAX_TEXT_CHARS`（20000——`thincoder-core/agent-tools/batch.mjs` 实读）。整段替换要模型把全文重发一遍，缺一段就是静默丢内容。

**实测**（`docs/batches/*.md` 全 **283** 本带 §2 的档，逐本读段体字符数——本轮复测）：**56 本（约两成）的 §2 超过 20000 字符**；最大一本 = `docs/batches/2026-10-15-doc-ref-direction-cleanup.md`，其 §2 **128,888 字符 ≈ 上限的 6.4 倍**。

**不做模糊匹配**：一次近似改写 = 一次没人看见的错改。**匹配 = 逐字节，含行尾**：`\r\n` 档上的 LF 锚零命中 ⇒ 拒（安全方向，不会误改）。

| 面 | 契约 |
|---|---|
| 参数 | `segment`（须 ∈ 调用者写域——§4.1 段白名单，与 `append` 同一张表）+ `oldText` + `newText`；`path` 仅 depth-0（D-BR21），子代理无路径参数（目标 = spawn 绑定） |
| 段域 | **= 同模式 `append` 白名单**（一处单源，两动作读同一张表）：工程面 `eng-designer → §2` · `eng-coder → §5` · 评审 → `§3` · depth-0 → `§1/§4/§6`；普通面 depth-0 → `§1/§2/§4/§5/§6` · coder（携绑定）→ `§5` · 评审 → `§3` |

| 冻结 | 已收口档 ⇒ 拒（§4.9 门 ②，串逐字同 `append`——六段同判）；修 = 重开径（§4.18-B）或另起新批 |
| 段序门 | **不跑 §5 段序门**（`assertSectionFiveGate`）：门护的是「实施记录不得先于评审通过」，而 `edit` 须有既有锚（零命中即拒）⇒ 它写不出原本不存在的内容，造不出「先实施」；反过来在 §3 进行中时把 §5 的旧行拒掉，正是本批要消的死锁 |

| 文档机检门 | 与 `append` **同一个门、同一种阻断面**，**判集按命中类分两套**：**段长类**（段落过长 · 行过长）= `pending`，即本次写进来的文本（`append` = 追加文；`edit` = `newText`）——一条早先就在的超长段不再拦该段的无关改动；**锚类**（`档缺` · `节缺` · `引缺`）+ 骨架 / 占位 / 状态行 = **整档**（引用完整性是档级属性，改一处不能只看新文）。`REFUSED` ⇒ 拒（零字节落盘）· `ERROR` ⇒ 写 + 回执明示（`docs/core/design/DOC-DISCIPLINE.md` §3.20） |

**`append` 与 `edit` 的分工（不重叠）**：`append` 在段尾加内容（后来的决定、补充的条目）；`edit` 改既有的字（既有行已不成立）。一条判据收口：**读者只该有一种读法**——被 `edit` 换掉的旧行必须删掉，不留「以本段为准」指针；新旧并存就是本条要消掉的那个翻车形。

**就地改的射程（判据，不是提醒）**：

- **只改本批自己的档**——目标 = 调用方绑定的那一本（子代理）∥ depth-0 的 `path` / 在飞批（主 agent）。他批档 ⇒ 拒（§4.2 写面两道门 + `thincoder-core/agent/write-gate.mjs` 跨批档门）。
- **已收口档六段一律不改**——那一轮的账已经结过；照那一轮之外的新规则改它，账里就出现一件从没跑过的事。「在飞档头随正 ∥ 已收口一字不动」（§4.10）是同一件事的另一端。要改 ⇒ 重开径（带追记行，§4.18-B）或另起新批。
- **只改自己的段，不改状态行**——状态行有单一写者 `status`（§4.12）；六段共六条状态行，编辑面碰不到任何一条。
- **对账两个方向都要看**——§2 可改之后，`§2 ↔ §5` 的对账能被「改齐」；现在 §5 也由实施者可改，方向变成双向。判据不变（D7 收口对账读的是两处记录的当前值），保证从「字面不可改写」降为「git 可复原 + 收口时两处对得上」。

**两模式同判**：普通面 §2 / §5 = 主 agent 的设计席与实施席（§4.16），`edit` 段域 = 同模式 `append` 白名单。两模式走同一个判定函数，差别只在约束强度。

**`edit` 是受认可的通道，不是唯一通道**：携绑定的子代理本就能用文件工具直写自己绑的档（`thincoder-core/agent/write-gate.mjs` 的批次档写门里那一行 `if (targetKey === boundKey) continue // 写自己绑定的档 = 正常面`），主 agent 的普通文档写也不经本工具（§4.2）。

所以本动作不给出一条「唯一」路径，它给出一条**更省事的**路径：只需锚 + 替换文（几个字到几行），不必重发整段；段域、冻结门、剥凭证、来源戳、机检门由工具一并判。**旁路仍在**（用文件工具直写本档别人段，无机械面）——处置 = **登记即终局**（§7 D-BR36）：不补门、不另裁。

**改写不追认既有记录——取收口对账，不取改时拦截（判据 + 理由）**：

- **不取「§5 非空 ⇒ `edit §2` 拒」**：实施开始后改 §2 是**正当且常见**的（设计变更传播：实施到一半发现设计有问题，先改设计再改 §2，见 `thincoder-core/prompts/persona-engineering.md` 的设计变更传播句）——拦住它等于把正路关掉，写者只好绕去文件工具直写（旁路本来就在）。
- **不取「追记行落段内」**：留痕行若落在段内，就是往**那一段的记录**里塞第二种读法——「§2 收口时只须一种读法」当场失效；对证据面同理（在证据里加一行「改了什么」，读的人要读两层）。留痕不住段内。
- **取什么**：改动本身在 **git** 里（旧字节逐字可查，这正是「历史住 git、不住文档」的既有纪律），而「记录与实施是否一致」在**收口对账**（D7）时判。判的时点从「改的那一刻」挪到「收口那一刻」，判的对象 = 两处记录是否对得上（机检与人都可读）：

  - **§2 ↔ 设计档**：§2 引用的判据 / 计数是否仍与所属设计节一致（D7 清单项 = `§2 ↔ design-doc reconciliation`，差异记 §6）。
  - **§2 ↔ §5（实施记录）**：§2 改过的判据与 §5 记下的实现是否还对得上。**对得上 = 澄清，照此收口**（实施开始后改 §2 是正当且常见的：设计变更传播、口径补清）；**对不上 = 洗账的形**——§5 记着另一套实现而 §2 已改成与设计一致，此时差异记 §6，不许再改 §2 收场。反方向同理：§5 被改成与 §2 一致而实施没变，也在收口对账里看（判据单源 = §7 D-BR37）。

| 锚 ≥2 命中 | **有场景 · 构造型复现（最小两步）**：① 取一句在本档机制表与验收表各出现一次的短判据；② 以它为 `oldText` 调 `edit` ⇒ 命中两处（放行则删一处会连另一处一起删） | 拒并列出命中行号 = 让写者把锚加长到唯一 |

| `newText` 引入状态行 | **有场景 · 构造型复现（最小两步）**：① 取目标段段体内任一行作锚；② `newText` 携一条 `**状态行**：` 行传进去 ⇒ 抛状态行拒串 | 状态行只有一个写者（`status`）；新引入的那条会接管该段状态行的写入（§4.12） |
| `edit §3` 的戳行 | **有场景 · 构造型复现（最小两步）**：① 设计评审以 §3 段内任一行作锚；② `newText` 携 `### 轮次 N（评审子代理）` 传进去 ⇒ 该行被丢弃，其余文本落盘 | 戳行由工具生成是既有不变量（§4.7 不变量 5）——若能写进戳，轮次 N 与「谁是作者」当场可伪造 |

**三条不变量型拒面的拒文仍带（理由）**：空锚、「引入状态行」、§3 戳行三条都按不变式拒，拒文照旧带、仍进工具描述面——空锚会被「恰一次」判成可写而插在段首，新引入的状态行会让该段出现第二个写者，写进来的戳让轮次 N 与作者可伪造。fail-closed 的代价是一次误拒，误拒的写者当场看见原因；静默放行的代价是事后才发现状态行被谁改过。

**新落点的三问（名字 ∥ 位置 ∥ 归谁）**：

- **动作名 `edit`**：`existing: thincoder-core/agent-tools/batch.mjs` 的 action 分发表 · name: `"batch"`（五动作 `create` / `append` / `edit` / `status` / `close`）· consumers: eng-designer / eng-coder / 设计评审（`family-tools.mjs` 挂载）∥ 主 agent（depth-0）。内置 `edit` 工具（文件区间替换）已占这个名字，取同名 = 用读者已有的直觉（改既有内容），不另造词。本批不新增动作、不新增参数——改的是段域常量与拒串。
- **锚参数 `oldText` / `newText`**：`existing: 同档` 的 `append` 载荷参 `text` · name: `"text"`——两名是它的旧 / 新两半，同族命名。**偏离** = 内置 `edit` 工具的 `old_string` / `new_string`，理由 = 本工具自己那一半已叫 `text`，同一个工具里两套名字会逼模型记两套。
- **回执串** `batch: edited §<N> of the batch record — replaced <M> characters with <K>.`：`existing: 同档` 的 `batch: created <abs>` ∥ `batch_segment: appended …` 家族形，逐字对齐。

**骨架保护的既有缺口（本批不改，登记理由）**：`batch.mjs` 的判据是 `/^## §\d/m`，`##  §4`（两个空格）不被它命中。**机器面无影响**——同族定位判据同形（`sectionHeaderRe`，三处共用），两空格那行对它们都不是段头，落在段体里当普通文本。

**唯一后果 = 人读那一行会以为是段界**。不收紧的理由：收紧要同时改三处定位判据（否则写进去的行就成了真段头）——那是段定位机制，不在本批边界内。

### 5.2 条目在别处完成（结账依据写 `evidence`，核销节点仍是挂靠批收口）

条目的核销节点 = 挂靠批的 §6 收口，且该批须走完全链——核销门 `assertCloseOutProof` ② 要求批档 `§1` = 已收口，③ 要求 `§3` 状态行 = `评审通过`。**本条只讲「核销时说什么」，不讲「什么时候可以不核销」。**

**触发**：条目在挂靠批档之外完成（父侧直接执行 / 他批顺带涵盖），该档无对应的 §5 记录。

**动作（主 agent）**：把**结账依据**写进该行 `evidence`（批档路径 + 段 / 行坐标，或提交号 / 他批坐标）——它证明的是「这件事做完了」，不是「可以不收口」。**核销前提不变**：挂靠批仍须走完全链收口，核销门才放行。

**挂靠批已被拆 / 被取代**：承载改由新批档 ⇒ 行改挂新批档，由新批的收口承担；判据不变。

**停在「进行中」的挂靠批**：要不要收口由主 agent 判——要收口就补齐 §2 / §3 / §4 / §6 后按 L4 闭合；不收口则整档原样保留（外部记忆），**不得当活档引用**（新批 §1 前情指针注明未收口），它的行也就核销不了（核销门 ② 如实拒，不另设豁免）。

**可达面（触发点在哪）**：现役批收口的**前批遗留核对**（核销同步清单「待办勾销」项逐条核）+ 台账事件面（`thincoder-core/prompts/persona-engineering.md` 台账节「事件 → 动作」③ 批收口）。**不是**被卡批档自身的 §6——该清单只对该批可跑，对「批未收口」对象不可达。

### 5.3 §6 收口要求与五前置（修正轮落地 ∕ 搁置清单回核 ∕ 暂缓批复核 ∕ 文档机检门 ∕ 用户文档面同拍——2026-09-29 ∥ 2026-10-04 ∥ 2026-10-18）

**§6 收口要求（成文）**：§6 = 父代理段的核销同步执行位（槽位枚举权威 = `docs/core/design/DOC-DISCIPLINE.md` D7 行）——收口时逐项：角色表 / 状态行 / 计数 / 指针 / 待办勾销（含前批遗留核对——兜底 = §5.2）/ **修正轮落地前置** / **搁置清单回核** / **暂缓批复核** / **文档机检门**（收口前——口径 = `docs/core/design/DOC-DISCIPLINE.md` §3.20「交付时点强制」；无文档改动记「文档机检门：无文档改动」一行）/ **用户文档面同拍** / 台账可见面（收口行）。

- **修正轮落地前置**：**实施后修正轮须先于本批 close 落地并经核验**——存在未 settle 修正轮 ⇒ 不 close。已冻结档的漏记 ⇒ **并入下一活档 §6**（冻结档不回改——L4）。
- **搁置清单回核（程序级收口）**：一个程序（多批）末批的 §6 须加「搁置清单回核」——逐条核设计档登记 ∕ 搁置项（§10 类）：已兑现 ∥ 未兑现转新批。
- **暂缓批复核（暂缓必须可复启）**：跑暂缓批扫描（命令 = §5.1 L8 细节块）——暂缓批逐条对复核条件：已满足 ⇒ 复启（清标记 + 复启动作）；对象消失 ⇒ 定去留（收口 ∕ 撤并）；无暂缓批 ⇒ §6 记一行「暂缓批复核：无」。
- **文档机检门（2026-10-18——用户四轮裁定）**：批准 / 核销 / close 之前，父侧对**本轮文档档集**跑 `doc_check(mode:"gate", docs:[...])`（清单与判集 = `docs/core/design/DOC-DISCIPLINE.md` §3.20「② 的范围」——本档不重述）——首行 `DOC-CHECK GATE: PASS` 才算 §6 可落；
  `REFUSED` ⇒ **不提交批准、不核销、不 close、不改台账**，按面打回作者同轮修、复跑到 `PASS`；`ERROR` ⇒ **同判**（无 `PASS` 即未见通过——先修声明面 ∥ 指名项目根再复跑）；命中项**不转台账**（当场修，不挂账）。

  **结构面 = `batch` 工具两机械点**（`close` ∥ `status` 值「已收口」自动跑，不过即拒——口径 = `docs/core/design/DOC-DISCIPLINE.md` §3.20「结构兜底」）；父侧协议跑仍是**权威范围面**（`<批起 sha>` 只由父侧**写入**——门读 §1 的记入行，写入义务 = 本节「`<批起 sha>` 记入行」条）。
- **`<批起 sha>` 记入行（父侧义务）**：批开时父侧在批档 §1 记一行 `批起 sha = <sha>`（形态 = 行内首个 40 位十六进制串；取行与判集单源 = `docs/core/design/DOC-DISCIPLINE.md` §3.20「② 的范围」）；无该行 ⇒ 门走「只认触达账 + 回执明示『基 sha 未定』」，回执不静默。
- **用户文档面同拍（用户 2026-10-04「更及时的文档」升级批）**：本批触及**用户可感**能力（新增 ∥ 改变用户可见行为）⇒ 收口前按**板块设计档「用户文档面」节**逐面对照
  （面清单与义务语义单源——当前实例 = `docs/cli/design/ACP-CLIENT.md` §14：必更 / 随核对、落入方式、豁免面均详述于该节）。兜底分支（通用槽自持）：① 板块设计档无该节 ⇒ 记一行「用户文档面：面清单未立」（不得静默跳过）；
  ② 「用户可感」由收口轮判定，存疑 ⇒ 逐面对照兜底；③ 无涉面 ⇒ §6 记一行「用户文档面同拍：无」。

## 6. VSC 端镜像（FR23——机制原则）

> **实现坐标（VSC 仓文件路径与行数）** = P2 产品面 ⇒ 归 VSC 轮；本档只落机制原则与锚检查（选型理由与差异登记见 §7）。

### 6.1 总原则：语义同源·原文自持（N1）

两端**各自实现、不共用代码**；机制语义同源，**实现各写一份**。**镜像 ≠ 抄实现：抄的是契约与锚句**，适配的是落点（VSC 落点多处不同）。

### 6.2 镜像锚（逐字源钉死——多实现面纪律）

需逐字一致的段**不在本设计重述**（避免第三份副本），而以**逐字源为 CLI 侧文件:节**，实现面**照拷、禁自行解释**；差异只允许在路径/UI 引用处，且必须登记：

| 锚 # | 内容 | 逐字源 | VSC 宿主 |
|---|---|---|---|
| A1 | 六段**一段一作者**声明句 + 写面句（作者可 `append` 加内容 ∥ 可 `edit` 就地改自己那一段）+ **子代理自写不经父侧转述** | 纪律层六段块 | VSC 同名档（**新增六段节**） |
| A2 | **写入手段句**（`batch({action:"append", segment, text})` ∥ `batch({action:"edit", segment, oldText, newText})`——子代理 append/edit/status 无路径参数 + 段白名单枚举；create / status / close 各附身份判据，depth-0 `path` 破例见 §4.1 / D-BR21） | 纪律层同块 | 同上 |
| A3 | **执行者拒收**·**澄清必经主 agent**·**三方条目一致** | coder / designer persona | 同名两档 |
| A4 | **D1–D7 文档更新纪律表** | 纪律层文档更新纪律节 | 同 A1 宿主 |

| A8 | **`batch` 工具描述文案**（action 枚举五动作 / 段白名单枚举 / 子代理 append·status·edit 无路径参数 + depth-0 可选 `path` 破例（D-BR21）/ 写面一句（作者可 `edit` 自己段）/ 来源戳 / 剥凭证 / 失败明示） | 工具定义字符串 | 新增同名档（**断言口径 = 跨仓同文件 grep**） |

### 6.3 提示词面与端特有段

- **跨仓节引用处置**：逐字拷入后按“路径/UI 引用处”豁免——能对上目标仓对应节的改写、对不上的改注「（CLI 侧）」，**逐项登记**；一致性检查对**带注记的引用行豁免**（不报、不入基线）。该豁免为 VSC 侧独有语义。
- **定点改写**：仅**锚句宿主档**改，**其余档不动**——**不得拿一端的 src/prompts 整体覆盖**（会回退另一端特有内容）。

### 6.4 实现面拆分与不变量

**实现面拆分**：① **代码面**（门 / 角色 / 工具 / 装配 / 枚举 / 一致性检查 + 新用例文件）② **提示词面**（锚句宿主定点改 + 新建 + 锚句断言测试）——**文件域不相交 → 两个 eng-coder 并行**；锚句断言测试归面 ②（它拥有那些文件），面 ① 的测试只测代码行为。

**不变量**：① 代码评审纯只读不削弱 · ② 凭证绝不落档（工具级剥除）· ③ **语义同源·原文自持**（文本类锚逐字一致；行为锚由行为用例承载）· ④ 零回归 · ⑤ **验收不拿静态存在冒充生效**（必须重载扩展后实跑）· ⑥ **角色可 spawn**（断言下沉到运行期门——白名单/模式门/子代门全部通过才算落地）。

## 8. 边界（本档不做）

1. 不写实现代码（工具本体 / 门禁 / 装配 = eng-coder 写域）。
2. 不写提示词实体（内容依据 = 机制文档，落笔 = eng-coder）。
3. 不裁定 VSC 仓文件坐标（P2——归 VSC 轮；本档只给机制原则与锚检查）。
4. 不重述需求侧模板与段作者表（D2——指针见档头）。
5. 不做批次档内容模板化（append 载荷自由正文——批次档是记录不是表单；模板只覆盖**骨架与占位**，§4.10）。
6. 不动 §1/§4/§6 主 agent 普通文档写语义（create / close 是**新增**有门通道，既有写法零回归）。
7. 需求档面（`requirements/`）零改动（需求笔归主 agent——若需同步收口由主代理裁量）。
8. 不做批次档路径的启发式查找（basename 搜索 / 全仓 glob）——解析只认候选序、锚定规则与基底自有项目根形（§4.15 条 1 / 条 3 / 条 6 边界）。
9. 不做暂缓批的机械写锁 ∕ 新提示面产品码（暂缓 = 调度陈述——gate 词汇零扩；扫描器 ∕ 提醒器不做；例检 = §5.1 L8 + 既有清单槽位）。
10. 不新增工程机械门到普通面（设计令牌 ∥ spawn 强制 `batchDoc` ∥ 写文件门禁——三者在普通面**不新增**；第三门名统一「写文件门禁」——权威措辞 = `docs/core/design/ADVISOR-CONVERGENCE.md:378`）
——普通面作者缝 = 纪律 + 可选绑定（§4.16）；**携批次档绑定的实施子代理随绑定受既有批次档写门**（containment——非新增门；§4.16 ∥ `AGENT-LOOP-SUBAGENT.md` §6.29.1）。
    **同句的另一半**：设计评审的 `batchDoc` 参数契约收严（未携即拒发）**不在此列**——评审工具只有一套，模式不改变它的参数契约；spawn 强制 `batchDoc` 仍为工程专属（需求面同句 = `docs/core/requirements/NORMAL-MODE.md` §5.6）。
11. 不做档头台账行的多**物理行**形态（多编号仍居单行——§4.10）：多物理行会破「档头结构行」单行契约与占位残留判定域（`TOOLS.md` §6.20）——不做。
12. 不做台账行本体（`docs/core/design/LEDGER.md` 写域）；**收径（收口重锚——`close` ∥ `status` 写 §1「已收口」两路，同一单源）例外 = 允许写台账行**——仅「本批未落行 ⇒ `trigger=条件` + 复启句」一处（`docs/core/design/LEDGER.md` §6.2）；**其余报警 / 读数面仍只读只报**（不代核销、不代改其它字段——核销仍走台账写命令）。
13. 不做链门的自动修复（§4.18-A）：门只拒 + 点名缺段 + 给声明形——补内容 / 声明 / 重开是主 agent 的判断（门不代写任何段）；不判收口内容质量；不做 batch 写面互斥锁（锁 = 新机制，另议）；「重开」不做成第三个状态词；不手工编辑已冻结档（修法 = 重开径 + 收尾链）。
14. 不做段体整段替换（`edit` = 锚定区间替换；整段替换另有超量与丢内容风险——§4.19）。
15. 不做「改写追认既有记录」的**改时拦截**（`edit` 只改自己那一段，别人的段零触）——判据落在收口对账的 §2 ↔ §5 半项上（§4.19「改写不追认既有记录」∥ §7 D-BR37）：改过的判据与 §5 记下的实现对得上 = 澄清，对不上 = 差异记 §6、不改 §2 收场。
16. 不做段级文件写门（拦「用文件工具直写本档别人段」）——现有两道机械门覆盖「写别批」「用工具写别段」，第三方向登记为候选扩展（D-BR36）。
