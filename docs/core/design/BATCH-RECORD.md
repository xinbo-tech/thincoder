## 1. 载体机制（批次档三点）

**定位**：批次档 = 任务流转的核心依据——**全链路唯一贯穿的档**（起 → 派 → 验）。需求档管“现状是什么”（无批次概念）、设计档管“怎么做”（跨批次演进）；
**只有批次档有完整链条**：B1 讨论落档 → B3 输入 designer → B6 designer 追加 §2 → B9 评审判据基准 → B11 **§2 即任务书** → B13 验收对照 → 需求池核销证据。

**三点机制**：

1. **档不可缺、不可写歪**——它是外部记忆（agent 上下文会丢），缺件 = 全链路失准。
2. **路径不硬编码**——批次档位置由调用侧传入（`batchDoc` 参数），产品**不假定**用户项目形如本仓；错误消息里的 `docs/batches/<批>-<主题>.md` 是**提示文案**，**不参与路径判定、不是默认位置**（判定只看 `batchDoc` 传入值）。
3. **判据只到「参数在 + 路径可读」**——**不校验内容/措辞**（不做正则匹配状态词——脆且把措辞写死）；内容够不够由**执行者拒收**兑底（`docs/core/requirements/ENGINEERING-MODE-V2.md` §8 依据缺失处置）。

## 2. batchDoc spawn 门禁

**门禁判据**：目标角色（`eng-coder` / `eng-designer`）spawn 时**必须**传 `batchDoc`；**没传即拒**；传了但**不可读**（不存在 / 非文件）亦拒（消息含路径与原因）。

| 面 | 契约 |
|---|---|
| 参数 schema | spawn 参数面新增 `batchDoc` 属性（否则参数无处传入）；模型面描述文案 = **模式无关措辞**（两模式分支同列、不随会话模式变动——§4.16「描述面处置」） |
| 角色域 | 门**只对 `NEEDS_BATCH_DOC = { eng-coder, eng-designer }` 生效**——其余角色（`explore` / `plan`）**零变更**（不带 batchDoc 照常 spawn）；`coder`（普通模式）：门不生效、**可选**携 `batchDoc`（传则须可读——§4.16） |
| 校验落点 | **单一共用装配点 + 与 token 门同出口**（阻塞/异步两路命中同一校验函数；错误生命周期一致） |
| 路径解析 | 相对路径解析序（候选序 + 锚定防嵌套 + 基底自有项目根形）**单源 = §4.15**（`batch-paths.mjs`）——门判据仍「参数在 + 路径可读」，解析面与 append / create 同源（2026-09-25 批；2026-10-05 收正） |
| 注入 | 通过校验后 child 携带批次档绝对路径；**child 任务文本含一行 `Batch record (batchDoc): <abs>`**（同形镜像，无变体退路） |
| 受限变体 | 审计 / 勘察子代理的 `delete props` 清单**同步加 `batchDoc`**（不得透传给子代） |
| 越界文案 | 越界错误文案**带实际角色名**参数化（designer 越界时不误导为 eng-coder 专属措辞） |

**选型（决策点）**：校验落点取「共用装配点（token 门旁）」而非「execute 内」或「两处都查」——**A 与 B 覆盖等价**，A 胜在**单一共用装配点 + 与 token 门同出口**；C 冗余。
**判据级别**取「存在 + 可读」（iii）而非措辞正则或机器标记——(i) 把中文措辞写死进代码、模板一改就断；(ii) 给文档加机器字段 = 形状约束；(iii) 零脆弱，内容好坏由执行者拒收兜底。

**VSC 侧差异（P2 面——机制原则保留，实现坐标归 VSC 轮）**：VSC **无** CLI 的双路装配单点（阻塞 spawn 与异步 spawn 各自在册）——选型取「**两处各落 + 共享校验函数**」（共享校验逻辑仍单份，语义不会漂）。

## 4. 批次档生命周期工具 `batch`（FR22 载体 + 生命周期扩权）

**目标**：六段机制要求「一段一作者」，但子代理**没有写批次档的手段**——现实是**父侧代写**，而代写 = 二次加工 = 失真源。`append`（原 `batch_segment` 语义原样迁移）给子代理一条**受控写入通道**：各写各段、写到准确位置、不留后门。

**生命周期扩权（2026-09-21）**：批次档全生命周期（建 → 写 → 转 → 收）收进同一工具——**创建走有门通道**（骨架预齐 + 占位状态行含 gate 合法关键字 + 建档即过 gate），消「校验有工具、创建靠手感」的半截纪律。action 枚举 = `create`（建档，§4.11）/ `append`（段写入，本节全表）/ `status`（状态行流转，§4.12）/ `close`（收口冻结，§4.13）。

### 4.1 工具契约

| 契约 | 内容 |
|---|---|
| **append/status 无路径参数（子代理）** | 子代理（eng-designer / eng-coder / 评审）的 append / status 不接收目标路径；**目标批次档路径由 spawn 时注入**——**语法上就写不到别处**。两个有意破例（均绑 depth-0——D-BR17 / D-BR21）：create 有 `path`（主代理建新档必须指定位置）；depth-0 的 append / status 有可选 `path`（无 spawn 绑定、多批在飞——无 path 无从定位；缺省 = 在飞批唯一时取该批，复数时必传） |
| **段白名单（按身份 · 模式感知）** | 工程面（逐字不变）：`eng-designer → §2` · `设计评审子代理 → §3` · `eng-coder → §5` · `主 agent → §1/§4/§6`（§1 方案行绑定——D-BR18）；普通面（2026-10-09 新增——§4.16）：`主 agent → §1/§2/§4/§5/§6` · `coder（携绑定）→ §5`；**越段写入即拒**——「一段一作者」从纪律升为**机械事实** |
| **append-only** | append 只追加，不覆写、不删除已有段；**既有行字节不变**。status / close 是**状态行单行改写**（§4.12 / §4.13）——唯一豁免，域限状态行 |
| **来源戳（工具生成）** | 写入 §3 时由**工具**加盖 `### 轮次 N（评审子代理）`；N 只数**工具写入过的**轮次行（固定骨架行 `### 轮次与发现（…）` **不计**）；调用方自带同名标题被忽略 |
| **凭证剥除（工具做）** | 写入前过滤 token / designId 形态行——**模型可能忘，机械不能忘**；工具用**自有正则**（自有冒号态形态），**不复用**凭证巡检正则（后者要求参数名后接空白，匹配不到冒号态）。**形态 = 三形**：① 闭括号形（`[DESIGN-TOKEN:…]`）② 键形（`designId:` + 值）③ 无标两段值形（`⟨uuid⟩:⟨epoch⟩`——Approved 后缀逐字携带）∥ **裸 uuid 不剥**（id 非凭证 ∥ 批侧无 token 上下文不可精确） |
| **fail-closed** | 目标段标题缺失 / 越段 / 骨架行冲突（写入文本含 `## §N` 标题形态）/ 超量（单次 text 超上限）/ 死占位残留拒（F11-C——判据 = `TOOLS.md` §6.20）/ **已收口档回改 / 状态行不可解析**（§4.9——**唯一例外 = 重开合取**：段 = §1 · depth-0 · 值关键词 = 进行中 · `note` 非空，§4.18-B）/ **收口链未跑完**（§4.18-A——`close` ∥ `status` 写「已收口」）⇒ **throw**；失败**明示报告「§× 未写入」**；回退父侧代写**必须打标** |
| **文档机检门（2026-10-18）** | append 写 §2 / §5（子代理身份）⇒ 写盘前自动跑 `doc_check` 的 gate：`REFUSED` ⇒ throw（串含 verdict + 命中清单），档字节不变；`PASS` ⇒ 照写；`ERROR` ⇒ 写 + 回执明示。`close` ∥ `status` 值余核 =「已收口」⇒ 收口前同跑：`REFUSED` ∥ `ERROR` ⇒ throw（状态行不改）。范围 / 适用面 / 版本前置 = `docs/core/design/DOC-DISCIPLINE.md` §3.20「结构兜底」（本档不重述） |
| **分段追加** | 超量拒收后拆成多次调用写同轮内容——**每次调用各成节、N 顺延**（档案按节记，分区诚实——无「不新盖戳」承诺） |
| **action 分发** | 单工具 `batch({action, ...})`——家法 = `subagent` / `memory` / `git` 形态；append 侧判定函数（段白名单 / 来源戳 / 凭证剥除 / 超量 / 冻结）逐一复用，零语义变（§4.11–§4.13 为新增 action 面） |

**段定位的骨架前提**：批次档骨架由 **create 一次预写**（`## §2` 等标题在档，§4.11）——工具按标题定位追加；标题缺失即 fail-closed（纠正动作 = 主代理 create 建档或补骨架；append **不自动补骨架**——create 是骨架唯一权威入口）。

### 4.2 档绑定（路径怎么到执行者手里）

- **eng-designer / eng-coder**：spawn 时 `batchDoc` 经门禁校验 → `child._batchDoc = <abs>`（§2）→ 工具取用。
- **coder（普通模式 · 2026-10-09——§4.16）**：spawn **可选**携 `batchDoc`（非强制——「spawn 强制 batchDoc」= 工程专属、不移植）；传则须可读（同评审面判据）⇒ `child._batchDoc = <abs>` 绑定 ⇒ §5 记录通道；未携 ⇒ 不绑定、照常 spawn。
- **设计评审**：`batchDoc` 作为 advisor 调用参数传入，沿**评审实例键**（`resolved.run.batchDoc`）传递到工具入口——**不用单值会话态**（异批次并发的设计评审各自正确落档，不得串档）。
- **不强制必传**：评审侧 `batchDoc` = **若传则须可读**——未传 ⇒ 工具**不挂载**、评审照常跑（零回归；无批次档的在途设计评审不受阻）。主 agent 侧纪律 = 有批次档在飞时必传。
- **写面两道门（段维度 / 档维度——分层不重叠）**：段维度 = 身份 → 可写段白名单（`batch` 工具的绑定面）；档维度 = 目标档 ∈ 绑定档；
  **绑定档之外**的批次档文件此前无门 ⇒ `thincoder-core/agent/dispatch.mjs`（两端单源——端档已取核）落**批次档写门**——携绑定的子代理（工程角色 ∥ 普通面 coder——§4.16）直写他批档被拒、**自身批次伴随件**（非 `.md` · 同目录 · 词干族——2026-09-29 收窄）放行
  （判据 / 文案 / 边界 = `docs/core/design/AGENT-LOOP-SUBAGENT.md` §6.29.1——本档不重述）；主 agent（depth 0）不受该门约束。

**选型**：路径传递取「参数在工具入口 + **评审实例键**传递」而非「显式参数贯穿到评审执行体」——后者需改一个已贴档位硬顶的模块（+行即越线）；前者保留参数可拒可测，且实例键与正文同口径。
**工具形态**取「单工具 action 分发」而非「四工具并列」——一套挂载面 / 一条绑定通道覆盖全生命周期；append 的「无路径参数」仍把限制写在**语法**里。

### 4.4 §3 内容 = 评审结论全文

每轮追加附录节：**`### 轮次 N（评审子代理）`（标题由工具生成）+ 该轮发现表（逐字 markdown 表）+ VERDICT 行 + 计数**；多轮各自成节（append）。**逐字不转述**（父侧不得代润色/缩减）。

§3 写在**批次档**——**§3 段不在评审对象清单内**（B9 只含批次档 **§2**）；追加 §3 **不改变被审内容**，故与冻结窗口不冲突。
**承载面分工**：内容性（表全文 + VERDICT + 计数、逐字）由**提示词层**承载（grep 断言）；机械面 V3 只保证**底线**（§3 非空 + 含工具写入轮次行）——V3 不看内容，这是有意的（内容判定无法机判，强判会假阳）。

### 4.6 机械校验 V3（零假阳口径）

入文档一致性扫描族：**仅当批次档「§4 或 §6 有实质内容」时**（机器判据；**不引用 §1 的讨论状态词**）判「§3 **含工具写入的轮次行**（排除骨架行）」。**与建批形态解耦（2026-09-21）**：create 工具化建批不改变本判据——V3 对 create 建的档照常适用（骨架行 / 占位行不算实质内容，判据零变）。

**“有实质内容”的定义**：该段内**除骨架行/斜体占位行外**存在非空行。
在飞批次（尚未评审）**不报**（避免每批都假阳）；反证用例：构造已批准但 §3 空 → 必报。
**判据射程**：V3 只判**工具落地后**创建的批次档——该日及之前的批次档 §3 无工具写入通道（父侧代写），属**结构性历史事实**而非违规（原「存量入基线」处置由**射程排除**取代）。
**选型**：V3 范围取「仅 §4 或 §6 非空的批次」而非「全批」——后者对在飞批次必然假阳。V3 落点 = 既有宽度检查档或独立档（二选一——**实际落 = 留单档**）。

### 4.7 不变量（评审判据）

1. **代码评审只读保证不削弱**（零 git + 只读工具集）。
2. **凭证绝不落档**（工具级强制，不靠纪律）。
3. **父代理 §1/§4/§6 普通文档写语义不变**（工具通道为新增——主 agent 挂载只解锁 create/close 与 §1/§4/§6 append，既有写法零回归，D-BR18）。
4. **不静默兜底**（失败必可见 + 代写必打标）。
5. **来源戳不可伪造**（工具生成标题与 N）。
6. **并发隔离**：异批次并发的设计评审**各自正确落档**（实例键绑定），不得串档。

### 4.9 状态行冻结拒写 + `docRoot.batches` 双基底（v2——M3 增量）

**写入路径四道机械门（`batch` append/status/close 写入前——符号名 = `batchTool.execute`）**，序列 = ① 状态行解析 → ② 冻结拒写 → ③ 链完整性门（§4.18-A——落位 = 既有拒因之后、文档机检门之前）→ ④ 文档机检门：

1. **状态行解析（fail-closed）**：解析对象 = §1 段内 `**状态行**：` 前缀行（§1 边界 = 该行到下一 `## §` 标题；其他段内「状态行」字样不参与判定）；关键字判定：含 `已收口` → 冻结、含 `进行中` → 放行（emoji / 括号 / 日期后缀容忍）；缺失 / 两关键字皆不命中 → 拒（fail-closed：不可解析视为冻结——宁可误拒进行中档，不得放行回改已收口档）。
   **行尾形态无关**（LF ∥ CRLF ∥ 混排同判——`\r` 归行分隔、不归行内容；行切分 = `/\r?\n/`）。

3. **链完整性门（2026-10-18 · 收口前置——§4.18-A）**：`close` ∥ `status` 写 §1「已收口」两路在写盘前同过 `assertCloseoutChainComplete(src)`——§2 / §3 / §4 / §6 各段须有内容，或经 §1 声明不适用（仅 §2/§3/§4 可声明；§5 段号豁免、§6 不可声明）；不满足 ⇒ throw 并点名缺段。门位 = 门 ② 之后、门 ④ 之前（链未跑完先报结构缺口，不先跑机检）。判据逐段 / 声明形 / 三拒串 = §4.18-A（本条不重述）。

### 4.13 `close`——收口冻结（仅主 agent）

**参数**：`path`（目标批次档——同 depth-0 append/status 取值规则，见 §4.1 / D-BR21）。
**动作**：§1 段内状态行 →「已收口 <YYYY-MM-DD>」；此后该档 append / status 全拒（冻结判据唯一真值 = §1 行——与 §4.9 一致，零语义变；**唯一例外 = 重开合取**，§4.18-B）。**文档机检门**：§6 非空门之后、状态行改写之前跑 gate——`REFUSED` ∥ `ERROR` ⇒ throw（不落「已收口」；§4.9 ④）。

**收口前置（本批）**：写盘前过**链完整性门**（§4.18-A）——§6 非空判据在本门内、口径单源（`sectionContentState`）；**§6 为唯一缺段时拒串逐字不变**（不降级）。

**收口重锚（本批未落行——自动）**：收口**两路**（`close` ∥ `status` 写 §1「已收口」）**同调单源 `reanchorOnClose`、零二写**——两路的**全部拒因通过、§1 状态行改写落盘之后**调 `ledgerReanchorBatch`（`docs/core/design/LEDGER.md` §7.1）。

**本档特有面**：回执逐行点名（`#<id> <status> <title>` → `条件`）∧ 失败因（返回形 `failed` 项）并入同一回执；冻结照常完成；无未落行 ⇒ 无该段。**重锚 ≠ 核销**（不改 `status`——核销仍走台账写命令）。

### 4.15 相对路径解析序与防嵌套（2026-09-25 批）

**契约（单源 = `agent-tools/batch-paths.mjs`；四处调用点全部经它——create / append·status·close / 评审门 / spawn 门）**。**矩阵 cwd 四形** = 项目根 / 项目内子目录 / 项目根的上级目录 / 非项目目录（无 manifest）——用例 BR-27–BR-35 以此四形为准。

**末形再分两判**：多根工作区锚（`projectRootView` 报 `workspace`——直接子目录带档 ≥1 ∥ 零带档时下辖裸仓 ≥1）⇒ 条 5 报明；`none`（空目录 ∥ 锚自身为裸仓——`.git` 无档且下辖无已注册项目）⇒ 兜底 `resolve(cwd)`：

1. **候选序（相对路径）**：① `resolve(cwd, p)` → ② `resolve(项目根, p)` → ③ 逐基底 `resolve(基底, p)`（**create 面候选序与收窄**见条 2 / 条 6；**基底取值两段**：**声明面** = manifest `docRoot.batches`；**缺省回退默认值** = 声明面为空时 `resolve(docRootBase(cwd), "docs/batches")`（docRootBase = 项目根 ?? cwd））。
   **取面分野（基底分支）**：**create / 在飞扫描 / 锚定面**取「声明面 + 缺省回退」合体（`batchDocBases(cwd)`——恒非空）；**读面 ③ 分支只取声明面**（无 manifest ⇒ **无基底分支**——读面零回归）。

   **「项目根」取根单源** = `resolveProjectRoot(cwd) ?? resolve(cwd ?? ".")`（归属形单源——`thincoder-core/manifest-discovery.mjs` 的 `owningProject`（经 `manifest.mjs` 转口）取根臂 = 仅归属命中；发现读数只供 `workspace` 报明、不进 `root`；调用方 `?? resolve(cwd ?? ".")` 兜底；同式 = 库键式的同一子表达式，`docs/core/design/LEDGER.md` §6.1 口径 2）；

**多根工作区锚**（`projectRootView` 报 `workspace`——下辖有已注册项目，1 ∥ ≥2 同判）⇒ 专用条 5（不静默回退）。
   **单值**——基底可多根，项目根不受基底数影响（多基底不产生多项目根）。

  - **写在 §1（不写进该段）**：工程模式主 agent 的 append 域 = §1/§4/§6（§4.16）——它写不进 §2（designer 段）与 §3（评审段），而「声明不适用」恰恰发生在 designer / 评审本轮不跑时 ⇒ 段内声明形在需要的场合不可写；§1 = 轮次性质的自述面，声明住这里 = 把「哪些步骤没跑、为什么」写在记录自己的开口处。
  - **形不合 ⇒ 拒**（不静默当作无声明）：行首匹配 `^>\s*不适用` 却不满足完整形（缺 `——` / 缺理由 / § 号 ∉ {2,3,4}）⇒ 拒并逐字回该行。
- **拒绝串（逐字——全在代码块内，逐字照抄）**：

```text
链门（缺段非仅 §6 时）：
batch: 收口链未跑完（closeout chain gate）— close refuses: the record's closeout chain has not run, and closing would freeze it that way. Missing: <§2 / §3 …>. 声明形不合：
batch: 「不适用」声明形不合（malformed inapplicability declaration）— one line per section: `> 不适用：§N —— <reason>` with a non-empty reason, §N ∈ {2,3,4} (§5 needs no declaration; §6 is never declarable). Offending line: <该行原文>. Nothing was written.

```

- **判据不做的事**：不判内容质量（§2 写「见某档」也算有内容——门问的是「这一步跑没跑、没跑有没有说」，不是编辑审稿）；不判 §1（主 agent 自述段不设前置）；不判台账行状态（收口链 ≠ 核销）。

**B · 重开路径（带审计的逆向流转）**

- **触发（合取）**：目标段 = §1 · depth-0（主 agent）· 门态 = `closed` · 写入值关键词 = 进行中 · 理由（`note`）非空。
- **非触发面逐字零变**：子代理 / 评审对任意段 status（含 §1）⇒「已收口档不回改」；depth-0 对冻结档再写「已收口」⇒ 同串；状态行不可解析 ⇒「状态行不可解析或缺失」（**不可重开**——不可解析档的修法 = 主 agent 普通文档写，不借重开）。
- **理由载体 = 复用 `note`（零新参）**：note 的定义已是「这次状态行流转的散文说明」，重开理由正是它；新参 `reason` 会造第二个散文载体，且工具还要决定哪个落哪。**本路径上 note 不进状态行括注**（一处理由一个家 = 追记行）。
- **理由校验（重开专用，不用 `assertStatusNote`）**：单行 + 非空；**允许携状态词表关键字**——理由最自然的写法常是「误标已收口」，而括注零命中的规则防的是「括注被 gate 读成冻结」（追记行不是状态行形态，不参与 gate 判读）。

- **机读位形态（单源）**：暂缓落笔 = §1 状态行 note 位（既有面——`batch status` 的 `note` 字段落行内括注），形态 = `进行中（暂缓 · 复核条件 = <条件句>）`；
  判据三合取：① 行含「进行中」（暂缓 ≠ 冻结——gate §4.9 ∕ `findInFlightBatch` 全零变）；
  ② note 以「暂缓」起头、`·` 后接「复核条件 = 」句；③ 单行 · 状态词表零命中（既有 note 校验——条件句勿含「设计完成」等词表关键字，改写）。
  复启 = 同工具写 `value:"进行中"` 不带 note（括注清空）；§1 段内另记「复启」行（既有实践）；普通编辑径同形（§1 归主 agent）。
- **扫描（例检枚举——cwd = 仓根）**：

```text
node -e "const fs=require('fs');const r=[];for(const f of fs.readdirSync('docs/batches',{recursive:true}))if(f.endsWith('.md')){const m=fs.readFileSync('docs/batches/'+f,'utf8').match(/^\*\*状态行\*\*：.*$/m);if(m&&m[0].includes('暂缓'))r.push(f)}console.log(r.join(' ')||'(空=无暂缓批)')"
```

  判据 = 首个 `**状态行**：` 行含「暂缓」（骨架序 = §1 居首）；输出 = 暂缓批清单——**提示面**（穷尽性 ∕ 异常形态由人读兜底；条件判读 = 语义面，不机判）。
- **例检钩三落点**：① **收口轮**——核销同步清单槽位「暂缓批复核」（§5.3；无暂缓批 ⇒ §6 记一行「暂缓批复核：无」）；
  ② **会话启动**——engineering 会话开工先跑扫描；③ **条件事件**——条件指涉事件落地（报告 ∕ 交付入档、批收口、用户裁定）逐条对。
  逐条判定：已满足 ⇒ 复启（清标记 + 复启动作）；对象消失 ⇒ 定去留（收口 ∕ 撤并）。②③ = 纪律句，落点 = 提示词面（内容依据 = 机制文档，落笔 = eng-coder）。
- **与台账关系**：暂缓不改台账行状态——挂靠行保持 `在途`（六态零扩）；暂缓纪律 = `evidence` 补一行指针「暂缓 · 复核条件见 §1 状态行」（条件文本单源 = 本档 §1；`docs/core/design/LEDGER.md` §5）；复启 ∕ 核销照既有通道。
- **已知边界**：条件判读不机械化（语义面——「不得靠自然语言理解」机检铁律）；扫描取首个状态行口径；异常档由人读兜底。

### 5.2 兜底核销路径（批未收口 / 条目失去挂靠）

正常链路里条目的核销节点 = 挂靠批的 §6 收口（核销同步清单）。**本条的靶 = 条目侧的核销节点，不是给批档另开闭合口。**

**触发（任一命中）**：① 条目已实质完成，而挂靠批档停在「进行中」且 §4 / §6 无实质内容（不再有实现活动）；② 挂靠批已被拆 / 被取代（承载改由新批档或父侧直接执行）；③ 条目在挂靠批档之外完成（父侧直接执行 / 他批顺带涵盖），该档无对应 §5 记录。

**动作（主 agent）**：① **核销判据 = 结账依据**（不是挂靠批档的状态行）——先按迁移表推进到「待核销」，`evidence` 回写**结账依据**（批档路径 + 段 / 行坐标，或提交号 / 他批坐标）；② **批档面零旁路**——L4 闭合语义不变（链门 §4.18-A 过 ⇒ 状态行「已收口 <日期>」）：判定该批仍有后续价值 ⇒ 由主 agent 补写 §6（「兜底收口行」须记**未走 §4 用户批准**及其依据）后按 L4 闭合；判定不再收口 ⇒ 整档原样保留（外部记忆），**不得当活档引用**（新批 §1 前情指针注明未收口）。

**可达面（触发点在哪）**：现役批收口的**前批遗留核对**（核销同步清单「待办勾销」项逐条核）+ 台账事件面（`thincoder-core/prompts/persona-engineering.md` 台账节「事件 → 动作」③ 批收口）。**不是**被卡批档自身的 §6——该清单只对该批可跑，对「批未收口」对象不可达。

### 5.3 §6 收口要求与五前置（修正轮落地 ∕ 搁置清单回核 ∕ 暂缓批复核 ∕ 文档机检门 ∕ 用户文档面同拍——2026-09-29 ∥ 2026-10-04 ∥ 2026-10-18）

**§6 收口要求（成文）**：§6 = 父代理段的核销同步执行位（槽位枚举权威 = `docs/core/design/DOC-DISCIPLINE.md` D7 行）——收口时逐项：角色表 / 状态行 / 计数 / 指针 / 待办勾销（含前批遗留核对——兜底 = §5.2）/ **修正轮落地前置** / **搁置清单回核** / **暂缓批复核** / **文档机检门**（收口前——口径 = `docs/core/design/DOC-DISCIPLINE.md` §3.20「交付时点强制」；无文档改动记「文档机检门：无文档改动」一行）/ **用户文档面同拍** / 台账可见面（收口行）。

- **修正轮落地前置**：**实施后修正轮须先于本批 close 落地并经核验**——存在未 settle 修正轮 ⇒ 不 close。已冻结档的漏记 ⇒ **并入下一活档 §6**（冻结档不回改——L4）。
- **搁置清单回核（程序级收口）**：一个程序（多批）末批的 §6 须加「搁置清单回核」——逐条核设计档登记 ∕ 搁置项（§10 类）：已兑现 ∥ 未兑现转新批。
- **暂缓批复核（暂缓必须可复启）**：跑暂缓批扫描（命令 = §5.1 L8 细节块）——暂缓批逐条对复核条件：已满足 ⇒ 复启（清标记 + 复启动作）；对象消失 ⇒ 定去留（收口 ∕ 撤并）；无暂缓批 ⇒ §6 记一行「暂缓批复核：无」。
- **文档机检门（2026-10-18——用户四轮裁定）**：批准 / 核销 / close 之前，父侧对**本轮文档档集**跑 `doc_check(mode:"gate", docs:[...])`（清单与判集 = `docs/core/design/DOC-DISCIPLINE.md` §3.20「② 的范围」——本档不重述）——首行 `DOC-CHECK GATE: PASS` 才算 §6 可落；
  `REFUSED` ⇒ **不提交批准、不核销、不 close、不改台账**，按面打回作者同轮修、复跑到 `PASS`；`ERROR` ⇒ **同判**（无 `PASS` 即未见通过——先修声明面 ∥ 指名项目根再复跑）；命中项**不转台账**（当场修，不挂账）。

  **结构面 = `batch` 工具两机械点**（`close` ∥ `status` 值「已收口」自动跑，不过即拒——口径 = `docs/core/design/DOC-DISCIPLINE.md` §3.20「结构兜底」）；父侧协议跑仍是**权威范围面**（`<批起 sha>` 只由父侧**写入**——门读 §1 的记入行，写入义务 = 本节「`<批起 sha>` 记入行」条）。
- **`<批起 sha>` 记入行（父侧义务）**：批开时父侧在批档 §1 记一行 `批起 sha = <sha>`（形态 = 行内首个 40 位十六进制串；取行与判集单源 = `docs/core/design/DOC-DISCIPLINE.md` §3.20「② 的范围」）；无该行 ⇒ 门走「只认触达账 + 回执明示『基 sha 未定』」，回执不静默。
- **用户文档面同拍（用户 2026-10-04「更及时的文档」升级批）**：本批触及**用户可感**能力（新增 ∥ 改变用户可见行为）⇒ 收口前按**板块设计档「用户文档面」节**逐面对照
  （面清单与义务语义单源——当前实例 = `docs/cli/design/ACP-CLIENT.md` §14：必更 / 随核对、落入方式、豁免面均详述于该节）。兜底分支（通用槽自持）：① 板块设计档无该节 ⇒ 记一行「用户文档面：面清单未立」（不得静默跳过）；
  ② 「用户可感」由收口轮判定，存疑 ⇒ 逐面对照兜底；③ 无涉面 ⇒ §6 记一行「用户文档面同拍：无」。

## 6. VSC 端镜像（FR23——机制原则）

> **实现坐标（VSC 仓文件路径与行数）** = P2 产品面 ⇒ 归 VSC 轮；本档只落机制原则与锚检查（选型理由与差异登记见 §7）。

### 6.1 总原则：语义同源·原文自持（N1）

两端**各自实现、不共用代码**；机制语义同源，**实现各写一份**。**镜像 ≠ 抄实现：抄的是契约与锚句**，适配的是落点（VSC 落点多处不同）。

### 6.2 镜像锚（逐字源钉死——多实现面纪律）

需逐字一致的段**不在本设计重述**（避免第三份副本），而以**逐字源为 CLI 侧文件:节**，实现面**照拷、禁自行解释**；差异只允许在路径/UI 引用处，且必须登记：

| 锚 # | 内容 | 逐字源 | VSC 宿主 |
|---|---|---|---|
| A1 | 六段 append-only·**一段一作者**声明句 + **子代理自写不经父侧转述** | 纪律层六段块 | VSC 同名档（**新增六段节**） |

### 6.3 提示词面与端特有段

- **跨仓节引用处置**：逐字拷入后按“路径/UI 引用处”豁免——能对上目标仓对应节的改写、对不上的改注「（CLI 侧）」，**逐项登记**；一致性检查对**带注记的引用行豁免**（不报、不入基线）。该豁免为 VSC 侧独有语义。
- **定点改写**：仅**锚句宿主档**改，**其余档不动**——**不得拿一端的 src/prompts 整体覆盖**（会回退另一端特有内容）。

### 6.4 实现面拆分与不变量

**实现面拆分**：① **代码面**（门 / 角色 / 工具 / 装配 / 枚举 / 一致性检查 + 新用例文件）② **提示词面**（锚句宿主定点改 + 新建 + 锚句断言测试）——**文件域不相交 → 两个 eng-coder 并行**；锚句断言测试归面 ②（它拥有那些文件），面 ① 的测试只测代码行为。

**不变量**：① 代码评审纯只读不削弱 · ② 凭证绝不落档（工具级剥除）· ③ **语义同源·原文自持**（文本类锚逐字一致；行为锚由行为用例承载）· ④ 零回归 · ⑤ **验收不拿静态存在冒充生效**（必须重载扩展后实跑）· ⑥ **角色可 spawn**（断言下沉到运行期门——白名单/模式门/子代门全部通过才算落地）。

## 8. 边界（本档不做）

1. 不写实现代码（工具本体 / 门禁 / 装配 = eng-coder 写域）。
2. 不写提示词实体（内容依据 = 机制文档，落笔 = eng-coder）。
3. 不裁定 VSC 仓文件坐标（P2——归 VSC 轮；本档只给机制原则与锚检查）。
4. 不重述需求侧模板与段作者表（D2——指针见档头）。
5. 不做批次档内容模板化（append 载荷自由正文——批次档是记录不是表单；模板只覆盖**骨架与占位**，§4.10）。
6. 不动 §1/§4/§6 主 agent 普通文档写语义（create / close 是**新增**有门通道，既有写法零回归）。
7. 需求档面（`requirements/`）零改动（需求笔归主 agent——若需同步收口由主代理裁量）。
8. 不做批次档路径的启发式查找（basename 搜索 / 全仓 glob）——解析只认候选序、锚定规则与基底自有项目根形（§4.15 条 1 / 条 3 / 条 6 边界）。
9. 不做暂缓批的机械写锁 ∕ 新提示面产品码（暂缓 = 调度陈述——gate 词汇零扩；扫描器 ∕ 提醒器不做；例检 = §5.1 L8 + 既有清单槽位）。
10. 不新增工程机械门到普通面（设计令牌 ∥ spawn 强制 `batchDoc` ∥ 写文件门禁——三者在普通面**不新增**；第三门名统一「写文件门禁」——权威措辞 = `docs/core/design/ADVISOR-CONVERGENCE.md:378`）
——普通面作者缝 = 纪律 + 可选绑定（§4.16）；**携批次档绑定的实施子代理随绑定受既有批次档写门**（containment——非新增门；§4.16 ∥ `AGENT-LOOP-SUBAGENT.md` §6.29.1）。
11. 不做档头台账行的多**物理行**形态（多编号仍居单行——§4.10）：多物理行会破「档头结构行」单行契约与占位残留判定域（`TOOLS.md` §6.20）——不做。
12. 不做台账行本体（`docs/core/design/LEDGER.md` 写域）；**收径（收口重锚——`close` ∥ `status` 写 §1「已收口」两路，同一单源）例外 = 允许写台账行**——仅「本批未落行 ⇒ `trigger=条件` + 复启句」一处（`docs/core/design/LEDGER.md` §6.2）；**其余报警 / 读数面仍只读只报**（不代核销、不代改其它字段——核销仍走台账写命令）。
13. 不做链门的自动修复（§4.18-A）：门只拒 + 点名缺段 + 给声明形——补内容 / 声明 / 重开是主 agent 的判断（门不代写任何段）；不判收口内容质量；不做 batch 写面互斥锁（锁 = 新机制，另议）；「重开」不做成第三个状态词；不手工编辑已冻结档（修法 = 重开径 + 收尾链）。
