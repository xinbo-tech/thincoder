> **本档 = 悬空锚 / 行宽存量清账的计划面**。
> **判据权威（D2 单一权威源）**：锚判据句住 `docs/core/design/DOC-DISCIPLINE.md` §4（V5 判据规格）、引擎落点住同档 §7——**本档不重述判据句**，只落「族 → 修法 → 归属轮」。

## 1. 问题与目标态

问题 = 机检锚检查**闸态常红**（阈值 0）⇒「新增即红」的防回潮信号失效（红一片 = 无人看）；行宽 1 行同欠。**本档两线均已收口**（判据面批 #40 ∥ B / C 轮 #26 核销）——理由、证据与候选见 §3-Q1 / §3-Q3 / §3-Q5 / §8 发现 1–5。

判据项 = `scanDirs` / `lineWidth` / `anchors.domain` / `anchors.exclude` / `exemptions`（定义面住 `docs/core/design/DOC-DISCIPLINE.md` §7）。

**勘察结论（定全局的一句话）**：三类的体量主体**不是文档罗嗦**，而是**两仓合并 → 核统一**迁移留下的三类结构性残差；三类**处置人不同**：

| 类 | 性质 | 处置轮 |
|---|---|---|
| ① 判据伪影 | 文档文本正确，抽取式 / 存在性面判错（P1 / S1 / B1） | 判据面批 #40（**已核销**） |
| ② 迁移期引文 / 待裁定 | 文本有意保留旧址名、判据无对应族；或宿主取错、单元测试档已删（P5 / P7 / S2 / B2 / B3） | **B + S2 轮**（逐条订正）· **C 轮**（机制裁定后——§3-Q5）——**已收口**（#26 核销） |
| ③ 可文档侧闭合 | 缺仓前缀 / 改名落点 / 占位形态（P2 / P3 / P4） | **A 列子批** |

## 2. 三分归类（各族逐条处置）

### 2.1 三族（引擎判类，逐字）

| 族 | 形态 |
|---|---|
| 用例号 | `T-…` / `T<数>` 形态（右界强制），在册判据未命中 |
| 路径/坐标 | 路径 token（含 `/` 或带行号坐标），存在性判据未命中 |
| 符号·窄 | 反引号标识符 + 定义谓词 + 恰一宿主坐标；宿主文本不含该名 |

### 2.2 路径族细分（六分 · 判据逐字 · 修法 · 归属轮）

| # | 判据（机判 · 逐字） | 修法（枚举单源 = §3-Q1） | 归属轮 |
|---|---|---|---|
| P1 | token 以 `.js` 收尾，且**同行原文含**同名 `.json` 串 | 无文档侧修法——判据（见 §8 发现 2） | 判据 |
| P2 | token 以 `modules/` 开头 | **改指**：按反向退役表 / 转正注记映射改落转正档（或补全归档落点——可解析性证据见 §3-Q4）；两分支皆空 ⇒ **去路径段**（保留档名、去 `modules/` 段；判据见 §3-Q1） | A 列子批 |
| P3 | token 命中占位 / 示例形（末段裸名 ∈ `x` `y` `z` `foo` `path` `to` `file` `your*` `example` `placeholder`，或路径含此类段） | **归一占位形态**（元字符形 `<>`，抽取式排除式①既有射程） | A 列子批 |
| P4 | 去掉 P1–P3 后，token 的**尾段精确匹配全仓唯一** | **改指**：补仓前缀 / 补中段，命中该唯一落点 | A 列子批（须上下文核验，见 §3-Q2） |
| P5 | 尾段精确匹配命中 **≥2**（同名多落点） | **订正**：按同行 / 同表仓别声明裁定落点后改指 | 待裁定 |
| P7 | 零落点 | **现态改写 / 订正**；无现态落点可指者 ⇒ **停下上报**（可能是真缺陷）。退场族 N1–N6 真值依据成立者（= C 面 C3 子集 · §3-Q6）按**订正**计——退场注记是订正的一种形态，不是另一类处置 | 待裁定 |

**为什么只留这一条判据**：一条「带日期 / 带旧值词的行可以不判」的许可，等于告诉写档的人把现状写成带日期的形状就不会被追——而写「某日实读 = N」比写「判时实读」省事；旧读数一旦被检索到，检索不带「这是历史」的标签，读者会照它办。所以判据只问一件事：这一行有没有现态落点可指。

## 3. 设计问题的定案（六项）

### Q1 三分归类与各族修法（§1.2 #1）

**定案**：归类见 §2（族 → 判据 → 修法 → 归属轮）；修法**六项**按下表分配——**「加锚」明示否决**（无「应存在而缺失」的落点：全部落点都是迁移改名 / 删除，补建档 = 越界造档）。

| 修法 | 适用族 | 判据（改完怎么算过） |
|---|---|---|
| 改指真实落点 | P2 · P4 ·（P5 裁定后） | 复跑该条转绿（存在性判据命中） |
| 去路径段（保留档名 · 去 `modules/` 段） | P2 余项：**无转正落点且无归档副本**者（落点 = `docs/core/design/MANIFEST.md:3`） | token 降为纯文件名 ⇒ 不再产锚（引擎判据 `scripts/doc-check-anchors.mjs:126`「纯文件名不显式锚定」）；复跑该条转绿 |
| 删（改述去锚 / 占位归一） | P3 | 该行不再产锚（抽取式排除或形态不再命中） |
| 加锚 | —— | 否决（见上） |
| 坐标出 span（改指**伴随纪律** · 防符号面激活） | 改指落点行 · **新写 / 改述行**（行内含坐标路径者） | 坐标自路径 token 移出（空格 / 独立反引号对）⇒ 带坐标 token 数归零、符号·窄不激活（`scripts/doc-check-anchors.mjs` `:139-140`）；复跑**清单外新增 = 0**；**新写 / 改述行同判** |

**代价（如实列）**：① 改指 = 需上下文核验（P4 中同行无仓别词者，须看同表列头）；② 改述去锚 = 历史指针精度下降。

### Q2 修复机制：逐档手工 vs 机械批量（§1.2 #2）

**定案 = 分层，按「语义含量」切片**（不作二选一）：

| 层 | 面 | 手段 | 硬约束 |
|---|---|---|---|
| L1 机械面 | P3 占位归一 · P4 前缀补齐 | **候选清单落盘（不改档）+ 逐条留痕（该轮记账位）**：脚本只做「token → 补齐形态」映射表（零语义字符串替换），**不直接改档**；改动作由 edit 逐条执行。**脚本落点 = execute 内联（不落仓）**；确需落盘者落工作树外临时域，**不入 `scripts/**`**（AC-4 硬边界） | 每条改动须在该轮记账位留「file:line → 旧 token → 新 token → 复跑读数」；脚本仅作候选生成，须**显式声明**（承文档纪律：语义内容禁 scripted 批量改写） |
| L2 语义面 | P2 modules 改指 · P5 / P7 逐条订正 · **S2 宿主订正** | 逐档手工（每档改完 D6 回读） | **承 `docs/core/design/DOC-DISCIPLINE.md:521` §4.3**（粒度与纪律 + 处置三选）——本档不重述；**§3-Q1 修法枚举（六项）= §4.3 三选的批内细化**（映射：改指真实落点 ≡ ① 现态改写 + ③ 订正 · 去路径段 与 删（改述去锚 / 占位归一） ≡ ① 的改述形态 · 「加锚」= 批内新增候选、已否决 · **坐标出 span** = 批内**伴随纪律**——非存量锚处置，防改指激活新锚）；**冲突处以 §4.3 为准** |
| L3 判据 | P1 / S1 / B1 | **零改**（禁触判据本体） | 转发现清单（§8）上报 |
| L4 行宽 | 见 Q3 子批 D | 重新组织语言重写 | 提示词面 = 产品代码面 ⇒ 落笔 = eng-coder（内容依据 = 机制文档） |

**P4 前置换算（防「改指错仓」）**：补齐前须核**同行 / 同表列头**的仓别声明（CLI / VSC / 核）；**核不出仓别者降级为待裁定**（宁可留红，不得猜）。

| 面 | 裁定建议 | 依据 |

**`_archive` 可解析性（引擎证据 · 只读取证；评审轮 1 #7）**：

- **解析序不经 `SKIP_DIRS`**：`resolveFile`（`scripts/doc-check-anchors.mjs:158-164`）按仓根 → 锚域根 → 本档目录 → 前缀剥离给候选，命中判据 = `isFile`（同档 `scripts/doc-check-anchors.mjs:62` = `statSync(p).isFile()`）——无目录排除面。
- **`SKIP_DIRS` 的作用面**（同档 `scripts/doc-check-anchors.mjs:54` / `:65-71`）= `walk()`，只喂 basename 索引与用例索引；源域排除另在 `scripts/doc-check-targets.mjs:20-32`（扫描面，非解析面）。
- **实证**：docs/core/requirements/METHODOLOGY.md:100 指 thincoder-cli/docs/design/_archive/METHODOLOGY.md ⇒ 复跑**未入悬空清单**——该档非唯一 basename ⇒ 只能由解析序命中。
- **与三处反向读法不冲突**：`docs/core/design/DOC-DISCIPLINE.md:162` / `docs/core/design/DOC-DISCIPLINE.md:467` / `docs/core/design/DOC-DISCIPLINE.md:575` 锁的是**扫描面**（源域 exclude）与**现状依据面**（归档档不作现状依据）——解析面另属。
- **结论**：P2 修法分支「补全归档落点」与 §3-Q5 适用前提③ **成立、保留**；边界用例见 §6 U11。

## 7. 边界（本设计不做）

- **不改判据本体**：`scripts/doc-check*.mjs` 三档零改（= 修债不是改判据）。
- **不建新档 / 不补锚**：「加锚」修法已否决——无「应存在而缺失」的落点。
- **不写代码面**：`thincoder-core/**` · `thincoder-cli/**` · `thincoder-vscode/**`（含代码注释里的死指针）零触；暴露真实代码问题 ⇒ 停下上报。
- **不写冻结批档 / `_archive/**` / 参照树正文**：不追溯、不代写对端。
- **不做无锚语义巡检**（机器判不了的那类，归 DOC-DISCIPLINE §4.4 巡检机制）。
- **不承诺全 0**：全 0 需余量全清——判据面（#40 已核销）+ B / S2 / C 三面逐条订正（两线均已收口：#40 ∕ #26 核销），见 §1。
- **零 UI 面（纯文档面）——无未决项**：设计档「UI / 交互决策」槽位 = 空集（无界面 / 无交互 / 无未决项）。
