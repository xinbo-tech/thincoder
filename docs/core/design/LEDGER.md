# 台账机制（LEDGER）· 设计

> 板块：工程模式 / 台账——**需求池指针台账（FR18 载体面）** + **台账提醒与可见面（FR24 载体面）**。
> 需求层指针 = `requirements/ENGINEERING-MODE-MECHANISM.md` §1.13（需求池产品机制：条目形态 / 状态机 / 两池分组 / 触发与老化 / 职责分工）· §1.18（FR24 提醒与可见面）。
> 兄弟档：`design/LEDGER-SELF-CONTAINED.md`（**L4「本仓可解析」判据 + 形态合规 V4 + 例外判据**）· `design/DOC-DISCIPLINE.md`（V1–V5 族）· `design/BATCH-RECORD.md`（批次档 §6 模板槽位）。
> 落点：检查器 = 仓根 `scripts/check-ledger.mjs`（本仓自用工具面——**不入产品提示词**）；显示面单源模块 = `thincoder-core/ledger.mjs`。

## 1. 机制目标与范围

需求池的诉求：**一眼看出“哪条需求落地了没有”**，无需遍历文档。现状的病不是“条目少”而是**条目与任务书脱钩**——没有指针，条目只是备忘；有指针，点开即见任务书 §2 与验收结论。

**可见面**的诉求：台账只有两个读面——形态机检（面向维护者）与审计清单（慢层、手动跑）；**没有任何主动可见面**，未决项静默积压。
本档立三层可见面——**状态行标记**（常驻两数）· **明细行三面**（启动 / 收口 / 变化，落会话流）· **显示端状态栏增量**；**有可动作项才出声**（零噪音）；数字与形态**单源**。

**范围**：条目契约 / 状态机 / 分组计数 / 归档触发老化 / 机检 L1–L3 / 显示面（CLI TUI + VSC 状态栏与 chat 流）+ 收口行。

## 2. 条目契约

**两种锚形态**（需求池 / 技术待办）与铁律「不展开任务细节」= `requirements/ENGINEERING-MODE-MECHANISM.md` §1.13（D2——本节不重述），本节只落**可机判的增量**：

- **「一行一条」升级为硬约束**：**需求池组**条目正文**不得超过 1 行**，续行即违规——机检 L3① 判。
  依据：台账的可用性全在“一行一条”，多行即回退成长条垃圾场。
  **适用范围（钉死）**：该硬约束的**机检面 = 需求池组**；技术组条目的机判面是**锚形态**（指针 + `file:line` 证据行——L3②③），**不判行数/长度**（长度与症状措辞属语义面——“不得靠自然语言理解”机判）。两池共用同一**铁律**。
- **技术待办 (b) 形态纳入机检**：文本权威 = `requirements/ENGINEERING-MODE-MECHANISM.md` §1.13；本批只把「证据行」钉成可判形态（`file:line` 正则——L3②），症状 / 归属语义留给评审。

## 3. 状态机（六态）

**状态机表本体（6 行）= `requirements/ENGINEERING-MODE-MECHANISM.md` §1.13**——本节不重述（D2），只记机制侧口径：

- 各态对任务书指针的要求（必填 / 可挂 / 保留）随表住需求档；机检只取其中「**在途 / 待核销 = 必填**」一条做断言，其余态**只判单行形态**——机判面与需求文本对齐，不另立口径。
- **归档两态**：已核销 / 已废弃 = **归档态**——勾销后移出活文件；**活文件不判其入口形态**（活文件零 `- [x]`——L3⑤）。
- **状态取值面**：活文件内实为**未决四态**（待讨论 / 待设计 / 在途 / 待核销）；`status=` 机外取值**不再入基线**——违规照报（阈值 = 0），并在**收拢时就近归一**。

## 4. 两池分组与计数

- **两池不混**：需求池收**用户需求点**；技术待办另组分列。**分组是归属判定**——错组 = 后续状态推进认错对象。
- **组计数口径（钉死——机检 L2 与验收共用同一口径）**：**组** = 行首 `##` 级标题（档标题不计入）；**条目** = 行首顶格未决条目行。组标题声明的「N 条」必须等于组内**未决**实条目数（D3）。
- **分组识别（钉死结构依据）**：`##` 组标题**含「需求池」→ 需求池组**；**含「技术」→ 技术组**；**两标记都不含的 `##` 组不判 L3③**（仍受 L2 计数与 L3① 约束）。
- **归档**：`status=已核销` / `已废弃` 的条目**勾销后整体移入同仓归档档**；条目连同其冻结指针入归档档，**活文件只留未决**；活组计数 = 未决数。
- **数字口径**：本档与批次记录里的散文字数一律为 **as-of 实测**，不构成契约；**验收以检查器重算值为准**。

## 5. 归档 / 触发 / 老化

| 面 | 契约 |
|---|---|
| **归档** | 已核销 / 已废弃条目勾销后**整体移入同仓归档档**（与已完成清单同口径）；活文件只留未决（L3⑤）；组计数 = 未决数。归档档最小形态：一行标题 + 来源注 + 原样迁入行（保留勾销锚、status、冻结指针）；**不入机检扫描域** |
| **触发字段** | 形态三枚举：`触发=归批（<批名/批号>）` / `触发=条件（<条件句>）` / `触发=认账不排期`（合法选项，区别于遗忘）。**无 `触发=` 场** → 审计面「待处置」（默认归集；**不判 L3 红**——处置要人判）；取值非三枚举 → **L3⑥ 红**。赋值归主 agent |
| **老化报告（审计模式）** | 入口 = 检查器 `--audit`；输出「**待处置清单**」= 技术组全部无触发条目（逐条 `档:行号` + 摘要），**行龄超 N 天**者标「老化」。**N 默认 30 天**；行龄 = 条目行最近变更时间（建议 `git blame` 行级；非 git / 不可判定 → 标「年龄未知」照列、不判老化——零假阳降级）。**不自动删 / 不改任何文件**；退出码 **0**（报告不阻断） |
| **归属与落笔** | 物理落笔（两仓台账 / 归档档）= **主 agent**；台账档**不入任何子代理 `files`**；运行面头部行口径 = 主 agent 落笔 |

## 6. 台账机检契约（L1–L3）

**检查什么**（三项，逐项独立可判）：

| 号 | 检查 | 判据 |
|---|---|---|
| **L1** | **指针可解析** | 条目内引用的 `<档>.md §X` 须过三条子判据（①归一 ②basename 唯一 ③可解析） |
| **L2** | **计数一致（D3）** | 组标题声明的「（N 条）」== 组内**未决**实条目数 |
| **L3** | **形态合规（只判形态）** | ①需求池组条目均为**单行** ②技术**组**条目含 `file:line` 的**正则形态** ③条目锚形态与**所在组标题**结构一致 ④`status=` 取值落在六态内 ⑤**活文件勾销锚零命中** ⑥**技术条目 `触发=` 取值合法**（无触发 = 审计面非红） |

**L1 子判据**：① **归一**：`§X` ↔ 标题编号 `X` 视为同一节（标题不含 `§` 字样，字面比对必假阳）；② **basename 唯一**：只写 basename 时仓内同名档必须唯一，多义**必须带目录前缀**；③ **可解析**：档存在 **且** 归一后编号可在该档标题里找到。

**L3 的豁免与分组识别（零假阳所需）**：

- **非必填态豁免**：待讨论写 `—`、待设计「可挂」、技术项无归属档写 `—`——该类槽位**只判单行形态**（L3①），**不判** ③ 的锚齐备。
- **分组识别**：见 §4（含「需求池」/「技术」标记的组才判 L3③）。
- **status 枚举豁免**：非必填态槽位写 `—`、**无 `status=` 场**的条目豁免 L3④；机外取值不再入基线（违规照报）。
- **归档态与触发字段豁免**：已核销 / 已废弃条目不在活文件（不另判 L3④）；需求池组无 `触发=` 场；技术组**无触发** → 审计「待处置」（非 L3⑥）。

**机判与评审的分界**：症状措辞是否属实、条目归属是否真是技术项、指针指得对不对——**一律不机判**（「不得靠自然语言理解」）。上表三项**只判可判的形态**；语义面留评审。

**输入 / 输出 / 失败信息形态**：

- **输入**：仓根路径 + 目标台账档清单。
- **输出（绿）**：`OK: <档>` 一行 + 退出码 0。
- **输出（红）**：每违规一行，形态 = `<档>:<行号> [L1|L2|L3] <症状> — 期望 <…> · 实得 <…>`；末尾汇总；退出码 **1**。
- **退出码**：**0 = 全绿 / 1 = 有红**（fail-closed；异常退出不得伪装成绿）。
- **审计模式**：见 §5。
- **扫描域**：**仅活台账档**（显式清单，不做目录递归发现）。**明确不含**设计档（宽度/一致性扫描域）——两扫描域**互不侵入**。
- **基线与存量**：机检基线**必须保持为空**——**违规一律阻断**（「存量分流 / 入基线」已废——阈值 = 0）；非空基线 ⇒ FAIL + 固定句。基线键**稳定、不含行号**。
- **反证要求**：用例须含「合成坏台账必报红」（防“永远绿的空转脚本”）。

**实现细节**（解析正则 / 行扫描算法 / 基线文件格式 / 报表排版）**由实现阶段确定**——本节只钉**契约**。
**归属面**：脚本住**本仓** `scripts/`（本仓局部工具，**不进产品提示词**）；提示词面零命中该脚本名。

**L4（本仓可解析）与形态合规 V4** = `design/LEDGER-SELF-CONTAINED.md`（跨仓登记的机检面——与本节的 L1–L3 正交）。

### 7.2 口径契约

- **计数 / 老化 / 阈值 / 可动作**：见 `requirements/ENGINEERING-MODE-MECHANISM.md` §1.18（D2——本节不重述）。
- **明细行集** = `{current} ∪ {可动作项目}`（发现序：current 在前，其余按目录名升序）；同项去重。
- **条目键派生**（去重档 `aged` 集元素）：键 = 条目行**归一化文本**——去行首条目前缀 + 去首尾空白 + 连续空白折叠为单空格。
  **位置无关**（跨行位移 / 同档他条编辑稳定）；**自身文本变更**（含 status 推进）= 键变 → 按新条目计（最坏一次重报——与坏档降级同级，非缺陷级）；两端同规则（去重档跨端共享——一端写的键另一端须逐字认得）。
- **变化检测（去重）**——状态档每台账一项 `{aged:[条目键…], threshold:bool}`：
  - 老化事件：`agedNow − aged(档)` 非空 → 一行（标题取新增者）；**送达后** `aged := agedNow`（自清）。
  - 阈值事件：`thresholdNow && !threshold(档)` → 一行；**送达后** `threshold := thresholdNow`（跌回 false 即重置——再达阈 = 新事件）。
  - **送达门**：仅当行真正落入会话流成功后才写档；未送达不记。
- **去重档 schema**：`{"version":1,"ledgers":{"<台账绝对路径·正斜杠>":{"aged":[…],"threshold":false,"updatedAt":<ms>}}}`；缺失 / 坏 JSON → 空态；UTF-8；写临时档 + rename（防撕裂）。
- **行龄未知**（非 git / 未跟踪）→ 不计老化（零假阳降级）。
- **性能**：技术组无「无触发候选条目」的项目**不跑 git**；有候选 → 每台账恰一次全档 blame（非逐行）。

### 7.3 行文本逐字契约（三面同文——CLI / 对端 / 收口行同一 formatter）

| # | 形态 | 逐字模板 | 色 / 态 |
|---|---|---|---|
| L1 状态标记 | 单行 | `台账 <pool>·<tech>`（例 `台账 4·32`） | `aged>0` → 警示色；否则默认 |
| L2 明细行 | 每项目一行 | `台账 <名>：需求池 <pool> · 技术待办 <tech>（老化 <aged>）` +（阈值时）` — 可开批` | 该项目 `actionable` → 警示色；否则 dim |
| L3 变化行·老化 | 每事件一行 | `台账变化：<名> 老化首次越线 <n> 条（超 30 天未处置）：<t1>；<t2>；<t3>`（标题 = 条目首段粗体；**无粗体段 → 回退 = 归一化文本前 20 字**；>3 条时第三项后接 `；…`） | 警示色 |
| L4 变化行·阈值 | 每事件一行 | `台账变化：<名> 需求池达阈值（<pool> 条）— 可开批` | 警示色 |

- `<名>` = 项目根目录 basename；数字 = 十进制整数；`<aged>` **恒显**（含 0——自证已检查）。
- **收口行输出** = L2 行序列（**行集 = 族行**——`discoverFamily` 的 projects 全体逐项目一行，含不可动作同级）；族空时输出 `台账：未发现台账（docs/TODO.md）。`（**仅命令面**——运行时面静默）。
- **状态行位置**：状态段簇**尾**（键位组前）——状态类信息同簇；受右截优先级与既有状态段一致。备选「行尾」被否决：窄终端下键位段已先被截——标记会落在可视区外。

### 7.4 CLI 挂载

| 点 | 接线 | 行为 |
|---|---|---|
| TUI 主档 | 状态加台账槽（marker / warn / scannedAt）；启动流程后调显示面启动；清理钩子调 dispose | 启动扫描 + 周期 |
| 显示面胶水档（新档） | 首扫（不抢首帧）→ push 变化行 / 启动行 → 写状态槽；周期定时（`unref()`）；回合处理期间跳过本轮（git 子进程不打断回合帧） | 三面发射 + 状态位 |
| 渲染档 | 状态段簇尾插 L1；空标记零注入（半态逐字节等价纪律） | 常驻标记 |

- **启动行**：首扫**任一项目可动作**（老化 >0 或阈值）→ push 明细行集 L2 行（每项目一行）；**不可动作 → 会话流零行**（常驻标记不受此门约束）；同扫若出变化行 → **先变化行、后明细行**。
- **周期扫描**：仅检测到**新**变化时 push（L3 / L4）；状态槽每次刷新重写。
- headless（对话 / ACP 入口）**零改动**——入口不落任何台账面。

### 7.5 对端挂载（状态栏 + chat 流 + tooltip）

| 点 | 接线 | 行为 |
|---|---|---|
| 显示面胶水档（新档） | init / refresh / pushStartup / dispose | 扫描 + item 更新 + 投递 |
| 面板主档 | 初始化状态栏时并立 item（右侧对齐、低优先级） | item 建立 + 周期注册 |
| 面板消息档 | webview 就绪分支加启动行投递——每次 webview 创建一次 | 启动行投递 |
| 项目切换档 | 换项目回调尾加刷新 | 换项目即时刷新 |
| webview 聊天脚本 | 新消息类型 `ledgerNotice` → 渲染 | 流内行 |
| webview 行渲染档（新档） | 逐行 `<div class="ledger-line [warn]">` append 到消息容器（宿主渲染档已贴硬限 → 独立新档） | 渲染 |
| webview 样式档 | `.ledger-line` 样式（弱化小字；`.warn` 警示色） | 视觉 |

- item 形态：`text = L1`；`tooltip = MarkdownString(明细行集 L2 行)`；**无 `command`**（点击面板否决在案）；无台账 → 隐藏。
- 消息载荷：`{type:"ledgerNotice", lines:[{text, warn:bool}]}`（端内自有投递通道——与 CLI 各自实现，语义同源）。
- **启动行投递门 = 同 §7.4**（任一项目可动作才投递；不可动作零投递）。
- **自验前置**：源码改动**需重载扩展才生效**——终局自验 = 重载后在含台账工作区看到 item / 启动行。

### 7.6 收口行（命令面 + 清单槽位 + 提示词逐字）

- **命令面**：`node scripts/check-ledger.mjs --summary [--root <dir>]`——输出 = L2 行序列；**只读**（不写档、不改台账）；退出码 0。
  **命令字面（含脚本名）只落本档 / 批次档 §6 模板——不入提示词**（可移植性口径）。

  > 7. **D7 变更留痕 + 核销同步** — 每批核销跑**核销同步清单**（批次档 §6）：角色表 / 状态行 / 计数 / 指针 / 变更记录 / 待办勾销 / **台账可见面（收口行）**。
  >    收口行 = 台账 `--summary` 汇总面的输出（有汇总面的仓直接跑；无则按同口径汇总输出）——保留在会话流。

  （各端原文自持；锚断言 = 固定子串 `台账可见面（收口行）` 与 `--summary`——**两锚即全部断言面**、**不含脚本名**。）
- **可移植性**：用户项目无该脚本 → 收口行由主 agent 按同口径汇总输出——不阻断工作流。

### 7.8 不变量

1. **无台账 → 零输出零标记**（空态零噪音）。
2. **台账档只读**——本机制唯一写面 = 去重档（且仅在送达后写）。
3. **数字单源**——显示数字全部出自单源模块；L2 行在 CLI / 对端 / 收口行三面同 formatter。
4. **L1–L3 机检语义零改**（既有用例零改全绿为证）。
5. **不新增工具 / 命令 / 快捷键面**；headless 零新增输出。
6. **变化行送达门**——未送达不记账。

## 9. 边界（本档不做）

- 不做：新命令 / 触发字段回填 + 机检强制 / 点击展开面板 / 状态行合计 / 多行 / 多根铺开（**否决在案，不得复活**）。
- 不做：台账内容治理（归档 / 移档 / 勾销——收口划扫职责）；台账档写入（唯一写面 = 去重档）。
- 不改：L1–L3 语义（只新增只读 `--summary` 面与共享解析消费）；headless 面；既有台账用例。
- 不做：跨进程缓存 / 全工作区深扫 / 文件监听 / 任何网络面。
- 不写实现代码（脚本 / 显示面 / 检查器 = eng-coder 写域）；不写提示词实体（内容权归主 agent）。
- **同级枚举上限（成本有界——确定性退化）**：同级枚举限 `MAX_SIBLING_SCAN`——父目录目录项数超限 → 该层候选判**空集**（不取部分结果），退化 **current-only**；current 缺 → 继续向上求候选。
  **裁定句**：「项目集 = current + 同级含台账者」不设语义上限，**成本有界优先**——上限只约束枚举规模，不改「含台账者」判据本身。
