# 台账自持（LEDGER-SELF-CONTAINED）· 设计

> 板块：工程模式 / 文档体系自持——**各仓记各仓的**：台账射程、批次档同规、文档体系自持、机检闸 L4 与形态合规 V4、例外判据。
> 需求层指针 = `docs/core/requirements/ENGINEERING-MODE-V2.md` §13.4（各仓自持 FR25 · F1–F14 / N1–N4）。
> 兄弟档：`docs/core/design/LEDGER.md`（台账条目契约 · L1–L3 机检 · 可见面）· `docs/core/design/DOC-DISCIPLINE.md`（**V1–V6** 族）· `docs/core/design/BATCH-RECORD.md`（批次档载体）。
> 判据指针：两轴面与 V1 跨仓边界的关系 = `docs/core/design/DOC-DISCIPLINE.md` §2；正文引用形态规范落 `docs/core/design/DOC-SYSTEM.md` §7（交叉引用形态与机检判据）。

## 1. 定位

本机制立三样东西：

| # | 面 | 内容 | 对应需求 |
|---|---|---|---|
| 1 | **射程规则** | 台账 / 批次档 / 需求档只收本仓条目，禁跨仓指针 | FR25 F1 · F2 · F6 |
| 2 | **行为纪律** | 上述约束落**提示词层**（代理运行期实际读到的纪律），不只落文档层 | FR25 F5 · F7 · F8 |
| 3 | **机械闸** | 台账条目的证据 / 指针路径须**在本仓内可解析**，fail-closed | FR25 F6 |

**定位边界**：不改既有 L1–L3 判据语义；不改宽度 / 一致性检查既有判据；不做事故的平台侧处置（远端缓存与克隆副本回收——组织层面事项）。

**两轴并列（不留两套口径）**：

| 轴 | 管什么 | 判据 | 落点 |
|---|---|---|---|
| **轴一：条目 / 归属** | 台账条目、批次档范围、需求归属 | **本仓可解析**（路径形态必须在本仓根内可解析） | 机检 **L4** + 提示词「文档与台账自持」节 |
| **轴二：正文引用形态** | 文档正文里引用他仓文档 | **既有 V1 跨仓边界**（「名称（仓别）§N」= 显式域外；带 `.md` 形态 → 判 `unknown-doc`） | `docs/core/design/DOC-SYSTEM.md` §7 + 一致性检查段引用面 |

**一句话**：**正文可以指他仓（规范形态），条目与归属不行。**

## 2. 架构 / 接口 / 数据流契约

### 2.1 台账条目契约（L4 的输入面）

条目内的**路径形态**分两类，均入 L4 判据：

| 形态 | 正则锚 | L4 要求 |
|---|---|---|
| 指针 `<档>.md` / `<档>.md §N` | 既有段引用正则 | 以**本仓根 + 台账目录**为基根可解析到档；不可解析 → `[L4]` |
| 证据 `<path>.ext:<line>` | 既有证据正则 | 取 `:` 前路径段，须在**本仓根**内为文件；不可解析 → `[L4]` |

**不入判据**（零假阳面）：无路径的散文（对位声明、镜像登记、机制叙述）；「名称（仓别）§N」规范形态（无路径）；组标题 / 表头行。

> **收紧**：「散文里的对端提及不入 L4 判据」**不等于无约束**——允许形态为**封闭枚举 E1–E5**（§4.1）；枚举外形态（携 `.md` / 路径前缀 / 裸节号）由检查器 **V4** 判红（**声明源前缀形除外**——§4.1 声明源条）。L4 管条目位（轴一），V4 管正文形态（轴二）。

### 2.2 跨端互引形态规范（两侧记录互引）

两侧批次档 / 台账之间的互引，按**轴二**规范形态书写：`名称（仓别）§N`。

- 例：一侧批档引用另一侧记录写 `LEDGER-SELF-CONTAINED（CLI 仓）§6`——**去 `.md` 后缀、去路径前缀**。
- **范围**：本形态自新档起生效——两侧设计档 / 需求档自身的跨端引用同循（收敛面 = 新档 + 两侧记录面；存量档按 §4.3 处置）。

### 2.3 数据流

```text
台账条目（docs/TODO.md）
  └─ 路径形态 ─┬─ 指针 X.md §N   ─→ 基根=(本仓根, 台账目录) → 不可解析 ⇒ [L4]
               └─ 证据 p.ext:N   ─→ 基根=(本仓根)          → 不可解析 ⇒ [L4]
  └─ 基线分流（test/fixtures/ledger-baseline.json）
       ├─ 新增 ⇒ 阻断（退出码 1）
       └─ 存量 ⇒ 不得再作为常驻合法态（「入基线」已废——阈值 = 0）
```

## 3. 机检补强：L4「本仓可解析」

- **L4① 指针路径**：条目内 `<档>.md` / `<档>.md §N` 形态 → 解析基根 = **本仓根 + 台账目录**（不含工作区根、不含兄弟仓）→ 不可解析 ⇒ `[L4]`。
- **L4② 证据路径**：条目内 `<path>.ext:<line>` 形态 → 路径段须在**本仓根**内为文件 → 不可解析 ⇒ `[L4]`。
- **L4② 完整判序（全匹配：同一行 / 条目内多处证据逐处判）**：
  1. **跨仓形态硬判**（兄弟仓目录名前缀 / `..` 逃逸 / 仓根外绝对路径）⇒ `[L4]`（fail-closed——**不回退 basename**）；**声明源前缀命中 = 除外**（L4③——声明的公共仓可引）；
  2. 全路径本仓根直接解析 ⇒ 通过；
  3. **外仓前缀排除（收紧）**：相对路径含目录前缀、全路径本仓不可解析时——前缀首段须为本仓根**现存条目**；不现存 ⇒ **跨仓形态** ⇒ `[L4]`（**不回退 basename**——防「外仓前缀 + 仓内唯一 basename」假阴面）；省略 / 陈旧前缀的**仓内**引用不在此列；
  4. 文档行坐标（`.md` + 行号）⇒ 同名 `.md` 仓内 ≥1 ⇒ 通过（0 ⇒ `[L4]`）；
  5. 仓内定位（裸 basename / 陈旧前缀——首段现存）⇒ basename 仓内唯一 ⇒ 通过；0 / ≥2 ⇒ `[L4]`（不可定位 / 多义）。
- **L4③ 声明源（有界例外）**：指针 / 证据路径段**首段 = 项目声明的公共仓目录名**（`index.publicRepos`）⇒ 于该声明根解析余段（值形 ∥ 解析单一定义 = `declaredPublicRoots`——`DOC-DISCIPLINE.md` §4.2.2 ⑥）——**可核 ⇒ 通过**；**未声明**的仓外形态照旧 `[L4]`（fail-closed 零松——步 1 硬判在未声明时原样生效）。
  声明根缺位 ⇒ 引用不可核——**写门侧照旧拒**（写面 = 存在性要求，严；文档侧「未核」报告态 = `DOC-DISCIPLINE.md` §4.2.5——两面分列）。

**为何现有 L3② 会漏掉事故形态**：L3② 只判「含 `file:line` 正则形态」——不判**该路径能否在本仓解析**；跨仓路径形态在语法上完全合法 ⇒ 形态判据不报。

**与既有 L1–L3 的关系**：L4 与 L1–L3 **正交**（形态面不同）；同一行可同时报 L1 与 L4（两侧判据不同，可接受）。
**fail-closed 与零假阳**：新规则对本仓合法内容**零命中**（无路径散文 / 「名称（仓别）§N」规范形态不入判据）；违规一律阻断（阈值 = 0）。
**对端仓机检落点**：对端**自持自己的台账检查器**——**与判据一致**（各仓自持 + 多实现面纪律「各端独立实现、语义同源」）；检查器默认台账清单**不含对端仓台账**（否则即跨仓扫描面 = 与 F1 同病）。

## 4. 例外判据（先例不构成例外依据）

> **机制含义**：「**用先例破规则是模型骨子里的训练**」——**规则的有效性不能依赖模型的自觉**：凡「看得见的旧形态 / 登记在案的存量」都会被下一个 agent 当依据，**用先例免掉判断**。
> 故「先例 / 存量 / 已落形态」**不构成偏离规则的依据**；**例外的唯一依据是判据句（可机判）**。

### 4.1 叙述性提及 → 封闭形态枚举（判据 = 检查器 V4）

**收紧判据**：叙述性提及**不再是概括豁免**——允许形态**仅限 E1–E5**；**凡携 `.md` 后缀 / 路径前缀 / 裸节号（未附「名称（仓别）」的 `§N`）者一律改归 B 类**，逐条规范形态化；**声明源前缀形除外**（「声明仓目录名 + 仓内相对路径」= 合法可核坐标——§4.1 声明源条；射程 = 声明公共仓）。

| # | 允许形态 | 语义 | 机判表达式（逐行；枚举内 = 通过） |
|---|---|---|---|
| E1 | `名称（仓别）§N` | 引用他仓板块档 | `[A-Za-z0-9_\-]+（[^（）]{1,12}仓）\s*§\s*\d+(?:\.\d+)*` |
| E2 | `名称（仓别）` | 无节号（迁移档名 / 台账 / 目录 / 板块档泛指） | `[A-Za-z0-9_\-]+（[^（）]{1,12}仓）` 且**其后不接** `§` |
| E3 | `路径（仓别）` | 实施面文件坐标（保留相对路径与后缀） | `[A-Za-z0-9_\-]+(?:/[A-Za-z0-9_\-.]+)+（[^（）]{1,12}仓）` |
| E4 | 裸仓名（仅仓别词 / 仓目录名） | 不携档名 / 节号 / 路径 | 仓别词命中，且同一 token 不携 `.md` / `/` / `§` |
| E5 | 纯语义提及（对端 / 另一端 / 多端镜像 等） | 不携任何坐标 | 该行**零** `.md` 后缀、**零** `/` 路径段、**零** `§` 节号 |

**判红规则（枚举外即红——检查器 V4「跨仓形态合规」，fail-closed）**：同一行内「**对端仓指标**」与下列任一**枚举外坐标**共现 ⇒ 违规（退出码 1）：

- ① 档名 + 文档后缀（`.md`）——**带对端坐标 / 仓标触发者判**；**无对端坐标的裸档名（`X.md §N`）不入 V4**（归 V1 面——两判据不重复报同一行）；
- ② 跨仓路径前缀（兄弟仓目录名 + `/`）——**以 `.md` 副本为限**（非 `.md` 路径不入）；
- ③ **裸节号**——`§N` 未紧附于「名称（仓别）」；**实装 = 紧邻形态**；孤立 `§N` 无对端指标（触发条件不可判）不入；
- ④ 仓目录名直引——由 ① 前段承载（仓目录名 + `/` + `.md`），同属 ② 的 `.md` 射程界。

**声明源前缀命中 = 除外**——路径 token 首段 = 项目声明的公共仓目录名（`index.publicRepos`）者，先按声明源判（于声明根解析——**合法可核坐标**；§4.1 声明源条 ∥ 解析序 = `DOC-DISCIPLINE.md` §4.2.2 ⑥）：**不计入 ①–④ 的枚举外坐标**；其余 token 照判。

**射程豁免（硬）**：**fenced 代码块整块跳过**；**行内命令**（码段含命令链 / 命令词）· **搜索模式串**（码段含正则片段）⇒ **整行不判**（可执行坐标——证据与命令保字面）。

**引述（旧形态对照）不是允许形态**：审计对照所需的旧形态以**断开书写**呈现（用反引号切断档名后缀与节号的连续形态），令判据不命中；**连续书写即命中**。这是**表现协议**、不是豁免。

**声明源形（合法可核坐标）**：**声明公共仓**（项目 manifest `index.publicRepos`）之文档 / 记录引用，合法形 = **「声明仓目录名 + 仓内相对路径」**（形 = 声明仓名 + 仓内路径两者相拼；证据面可携 `:N` 坐标）——**入解析、可机核**。

解析序 = `DOC-DISCIPLINE.md` §4.2.2 ⑥；三态 = 在场可核 ∥ 缺位未核列报 ∥ 未声明照旧。
**记录面有界例外**：台账 / 批档 / 需求档 / 设计档的「仓外指针禁止」为**声明源**开——**可引**（同形、可核）；**登记与归属面零松**；**未声明**的仓外形态（携 `.md` / 路径前缀）**照旧禁**（E 枚举外即红——V4）。**声明 ≠ 豁免标记**：声明源 = 解析源（无行级标记参与），不得与注记 / 标记族互代。

### 4.2 实施面文件坐标 → 机判式（并说明为何不是「跨仓登记」）

- **坐标形态（机判）**：`路径（仓别）`——**去仓目录前缀、保留相对路径与 `.md` 后缀**；坐标**仅限实施面语境**（受影响文件表 / 落点表 / `files` 声明 / grep 面）。
- **为何不是「跨仓登记」**：**坐标 = 说清该批动哪个文件**；**登记 = 把对端的需求 / 记录搬进本仓**（台账条目、批次档范围、需求归属）。前者是对**该批实施面**的指认；后者是**内容搬迁**。判据：坐标行**不带节号、不在条目位**；一旦进入条目位即改名换姓为跨仓登记 ⇒ 违规（轴一，L4 射程）。

### 4.3 「存量 / 入基线」已废（阈值 = 0）

- 两侧文档一致性基线**已清零**且**必须保持为空**：**新增违规一律红**；**「存量豁免 / 入基线」不得再设（阈值 = 0）**；**基线非空即 FAIL**（检查器 fail-closed 分支）。
- **历史语义保留、形态必须规范化**——「存量」不再是合法态；残留 = 先例源。

## 5. 提示词面（行为纪律落点）

### 5.1 「多实现面纪律」节（通用化后形态）

同一机制落多个实现面（多个端 / 多种语言 / 多个平台 / 同源镜像文档）时：

1. **各面独立实现，语义同源**——各实现面各自的文本以其面原文为准；不做逐字硬一致、不加面间同步依赖；一致由同源设计 + 各面独立语义锚断言守。
2. **不以面间产物回改（对齐经同源设计）**——不以任一实现面实际产物为准回改其他面；**本条只描述实现形态，不构成差异保留依据**（端差处置见第 6 条）。
3. **差异如实上报**——落地中发现同源设计缺陷 → 停下报告（设计档修正 + 重新评审），不静默偏离。
4. **面特有段各面保留**——某一实现面独有的内容段在其面原地保留，不并入其他面布局；**面特有段 = 非机制面内容；本条不构成机制面差异保留依据**（机制面端差处置见第 6 条）。
5. **一式多份设计的核验职责**——同一机制跨多个实现面产出一式多份设计时，各面设计独立成文；**主 agent 有义务核验各份逻辑是否一致**（核验四维 = 裁定同源 / 判据同一 / 边界同形 / 差异显式登记；静默差异 = 漂移）；核验时点 = 各面设计均落档后、**评审前预检**内执行；核验结论连同差异表随「设计就绪待评审」一并报用户。
6. **端差处置（默认与例外）**——**端差默认 = 消**：机制面差异 ⇒ 归单一权威源实现 / 各面对齐同一口径；**用户可见端差 = 缺陷**（须消除——归对齐批）；**唯一例外 = 宿主能力面**（仅单侧宿主能力可承载 ∕ 不可承载所制约的差异），**须实证**；**「登记后保留」形不判合格**——差异登记面只记录**已裁的宿主能力例外项**，✗ 非未决差项的兜底处置；**本纪律不构成差异保留依据**。

> **通用化要求**：条文**不得绑死本产品两端**（不得以本产品术语作示例、不得夹维护者注）。

### 5.2 新节「文档与台账自持」（各仓记各仓的）

1. **台账射程**：台账（需求池 / 技术待办）只收本仓条目——禁登记本项目之外的事项；**跨仓指针同样禁止**——不在本仓台账里指向他仓的档、路径或证据。
2. **批次档同规**：批次档各仓记各仓的——本仓批次档只登记本仓范围（含本仓的受影响文件与验收）。
3. **文档体系各仓自持**：需求档 / 设计档 / 批次档 / 台账一律各仓自持、只写本仓；本仓需求必须住在本仓——不得把他仓需求写进本仓文档。
4. **缺的层必须补齐**：本仓缺失的文档层就地补建——不得以「另一仓已有」「避免重复」为由省略本仓文档。
5. **台账头部自持**：台账头部只引用本仓路径与节号——不引用他仓路径。

> **行为面增量（公共仓读取）**：item 1「跨仓指针同样禁止」为**声明源**开有界例外（声明公共仓可引——声明源前缀形、可核；机制 = §3 L4③ ∥ §4.1 声明源形条）；提示词落地与逐字 = `PROMPT-SYSTEM.md` §6.15（D2——本档不复制）。

### 5.3 新节「规则与例外」（先例不构成例外依据）

```md
## 规则与例外（先例不构成例外依据）
1. **例外的唯一依据是判据句**：任何「以前也这样 / 已落形态 / 他批先例 / 存量在案」都不构成偏离规则的依据——
   例外只能由**可机判的判据句**给出；找不到判据句时，**按规则办，或停下上报**，不得以先例为由放行。
2. **残留即示范**：设计档 / 需求档 / 批次档 / 台账 / 变更记录中的残留即示范——合规形态必须显示为合规形态
   （判据枚举外的形态一律修掉，不得「保留原样」）；历史语义可保留，**形态必须规范**；
   **「存量豁免 / 入基线」不得再设**——存量不是合法态。
3. **例外须带消解期**：任何登记在案的例外必须写明**消解路径与到期条件**——没有到期条件的例外 = 永久先例。
```

**措辞纪律（同 §5.1）**：条文可执行、**零维护者注**（不写日期 / 批号 / 评审号 / 档内引用）；零本产品术语绑死；行宽 ≤300 字符。

### 5.4 勘察 checklist 通用化

勘察 checklist 第 ④ 项由「核双端对位面」改写为「**核多实现面镜像面（多端 / 多种语言 / 多个平台同源镜像）**」。

### 5.5 normal 模式覆盖范围结论（逐处判定）

| 条款 | 工程模式 | normal 模式 | 判据 |
|---|---|---|---|
| 台账射程（§5.2 条 1） | 适用（机械拦） | **适用**（同一规则；本面的机检属工程侧 L4，普通侧靠纪律） | 台账是**两模式同一套规则**，差别只在**约束强度**（工程 = 机制，普通 = 自觉）——判据 = `docs/core/requirements/NORMAL-MODE.md` §5.6 |
| 批次档同规（条 2） | 适用 | **适用** | 文档体系对全模式同一（批次档 = 任务的流转承载物）；差别 = 是否强流程约束——工程模式以结构强制、normal 以纪律与工具 |
| 文档体系自持（条 3） | 适用 | **适用** | normal 也写文档（有「文档先行 / 文档归属」节） |
| 缺的层补齐（条 4） | 适用 | **适用** | 同条 3 |
| 账链（批档须挂未决行） | 适用（机械拦：设计评审点火门） | **适用**（**同一道机械门**） | 见下「账链例外」——本面是两模式同判的机械门，不是纪律面 |
| 台账头部自持（条 5） | 适用（机械拦） | **适用**（同一规则；普通侧靠纪律） | 台账两模式都在（`batch create` 模式无关、与开行同一笔）⇒ 头部规则无「无台账面」可言 |
| 例外判据（§5.3 条 1–3） | 适用 | **适用** | 三条管的是「规则与例外」本身（判据句唯一 ∥ 残留即示范 ∥ 例外带消解期），不是某一模式的专属机制——普通模式同样会用先例免规则，同样要这三条收住；「工程侧承担」不能当普通侧免掉这三条的理由 |

→ **落点结论**：条 1–5 两模式**同一套规则**；落到 normal 纪律档的是条 2 / 条 3 / 条 4（§5.6 表第 4–5 行），条 1 / 条 5 普通侧不另设落地句（规则照旧适用）——**规则同一，不代表每一条都要另写一句**。差别只在约束强度：工程侧对射程另有 L4 机检与写门，普通侧靠纪律。**账链不在这个差别里**（见下）。

**账链例外（两模式同一道机械门）**：批档必须挂着未决台账行——这一条两模式跑同一道门、同一判据、同一拒文，代码零模式分支（机制单源 = `docs/core/design/ADVISOR-GUARDS.md` §2 第 7 条）。

判据逐字 = `docs/core/requirements/NORMAL-MODE.md` §5.6 范围边界：「**评审工具的发起判据（参数契约 + 账链）两模式同判，不在此列**」——本面正是那句里的「账链」。

「普通模式在射程这一面没有机检」不得读成「普通模式没有这条规则」，也不得读成「普通模式的账不用有人挂」：前者是约束强度，后两者是把规则删了。

## 7. 边界（本档不做）

- 不改既有 L1–L3 判据语义；不改宽度 / 一致性检查既有判据。
- 不改归档档的**非对端条目**（对端面条目按处置清单走）。
- 不做 `src/**` / `test/**` 实体写入（拆分实施归 coder；形态清零 = 文档面）。
- 不写检查器 V4 实现的判据之外语义；不写提示词实体（内容依据 = 机制文档，落笔 = eng-coder）。
- 不做台账物理落笔 / 状态推进（归主 agent）；不做事故平台侧处置（远端缓存 / 克隆副本回收）。
- 不写对端仓任何档（含批次档 / 台账 / 设计档）——对端一轮自行落笔。
- **不建 `docs/guides/` 层**（本端接入 / 使用面分别住地图与 UI 设计档、发布面住发布设计档）；**触发 = 出现首个「面向用户的操作指南」主题（非机制设计）时建层并在地图登记**。
