# CLI 自动验证面（E2E-HARNESS）· 设计

> 板块：测试基建——**端到端 harness**：以真子进程驱动 CLI 真入口，覆盖 **ACP 协议会话面**与**伪 TTY + 管道的交互命令面**；TUI 渲染留人工真机。
> 需求层指针 = `requirements/TESTING.md` §6（F23–F28 / N13–N18）。
> 兄弟档：`design/TESTING.md`（分层纪律 / 生命周期 / 集成集承载与执行契约——本档 §「接入」节只挂指针不重述）。
> 硬约束（实核已定）：**不引入原生模块**——Node 内置 `node:tty` 只能探测 / 包装、**不能创建 pty**（无 TTY 下创建读流抛 `ERR_TTY_INIT_FAILED`）；本机原生构建链不可用 ⇒ 外部 pty 方案一路不可行。

## 1. 问题与现状

- **缺环（本面要补的）**：CLI 的 TTY 依赖面在真无 TTY 环境不可自动验证——**四处** stdin 守卫
  （`thincoder-cli/src/cli/permission.mjs:35` · `thincoder-cli/src/cli/distill-command.mjs:40` · `thincoder-cli/bin/thincoder.mjs:157` · `thincoder-cli/src/tui/index.mjs:74`）在管道环境恒走降级分支 ⇒ 交互路径（权限 y/n 等）**现只能人工**；
  前三处 = 人机问答面（接缝目标——§4）；末一处 = TUI 接管硬门（保持直读——豁免）。
  ACP 协议面亦无进程级全链用例——既有 ACP 测试为 in-process 面（假 notify / request 捕获，零子进程），集成集内 ACP 零命中（设计轮 grep 实核）。
- **已有基础（复用面）**：真进程驱动先例 = `thincoder-cli/test/integration/config-provider-routing.test.mjs`（伪 HOME + 真入口子进程 + 本地 mock）；脚本化 provider = `thincoder-cli/test/helpers/mock-llm.mjs`（SSE 端点，含工具调用步——零改复用，**多轮步进原生支持**：按脚本数组逐请求步进，两步脚本即本档用例所需）。
- **本面不做**：TUI 渲染 / 画布（人工真机）；真端点上云（smoke 独立在册）。

## 2. 方案选型对比

判据：① 目标契合（真进程全链）② 覆盖面（协议 / 会话 vs 命令 / 交互）③ 零 TTY 可行 ④ 确定性（脚本化 provider / 无外网）⑤ 零新增依赖 ⑥ 成本（驱动件与维护面）⑦ 与既有验证链接口（走既有集成集）。

| # | 候选 | 判据逐项评估 | 结论 |
|---|---|---|---|
| 1 | ACP 驱动单用 | ①✓ 真子进程跑 ACP 面 ②半（协议 / 会话 / 权限往返齐；本地命令面与本地 y/n 提示不在协议内）③–⑤✓ ⑥低 | 否决（单用）——覆盖漏面 = 命令行与本地交互分支 |
| 2 | 伪 isTTY + 管道单用 | ①✓ ②半（命令面 / 本地权限 y/n 齐；协议面与结构化会话断言缺——对话路径断言仅 stdout 文本）③–⑤✓ ⑥低 | 否决（单用）——覆盖漏面 = 协议 / 会话面 |
| 3 | **两者并用** | ①✓ ②✓（并集：ACP 担会话 / 协议面 + 伪 TTY 担命令 / 交互面）③–⑤✓ ⑥中 | **选定** |
| 4 | PTY 方案（原生模块） | ③✗ ⑤✗（原生模块） | 否决——硬约束排除 |
| 5 | 模块级 in-process 直驱（现状形态） | ①✗ | 否决——不满足「真 CLI 起来」目标 |

## 4. 与四处 TTY 守卫的关系（机制裁定：注入缝）

| 守卫 | 语义 | 处置 | 理由 |
|---|---|---|---|
| `thincoder-cli/src/cli/permission.mjs:35` | 「stdin 能否承担人机问答（y/n）」 | **接缝**（改经谓词） | 问答流可被管道喂答——伪 TTY 的正当目标面 |
| `thincoder-cli/src/cli/distill-command.mjs:40` | 「能否进交互式向导」 | **接缝** | 同类问答面（降级分支保留为对照组） |
| `thincoder-cli/bin/thincoder.mjs:157` | 「（无 key 时）能否进交互式配置向导」 | **接缝** | 与前一守卫字面同族（同一“缺 key → 起向导”判定）；向导本体 = 管道可喂答形态（`thincoder-cli/src/cli/setup-wizard.mjs` 头注即以管道输入为支持场景） |
| `thincoder-cli/src/tui/index.mjs:74` | 「能否接管终端（raw mode / 尺寸）」 | **不接缝**（保持真 TTY 硬门） | 伪 TTY 下 raw mode / 尺寸不存在 = 不可发生态；TUI 渲染面留人工真机——以结构机检锚定 |

**机制裁定**：前三守卫改经**单谓词**（新档拟名 `stdinIsTTY()`——env 门 `THINCODER_TEST_FAKE_TTY=1` 覆盖为真；缺省 = 原语义），TUI 守卫保持直读、零接缝。

**「注入缝」优先于「脚本自行伪造属性」——建议与理由**：

1. **仓内既有约定**：env 门测试缝是既定工艺（崩溃注入 / TUI 激活 / 清理输出 / 全量开关 / 慢门阈值同族）；**属性伪造作测试缝工艺无先例**——仓内唯一同手法 = 启动黑屏手工 repro 脚本的一次性取巧，非测试套件内缝工艺。
2. **语义诚实**：守卫问的是「能否交互」（策略判定），非「stdin 是不是终端」（传输事实）——谓词把判定收成命名单点、契约显式。
3. **可机检（fail-closed）**：直读枚举可写死为 {谓词档 1 处 + TUI 守卫 1 处（豁免）}——新增直读即红；属性伪造面无可检之物。
4. **入口路径全继承**：env 天然随 spawn 链下传；预载旗标须逐 spawn 接线（漏加 = 静默走真分支、无红）。
5. **失败面收窄**：伪造属性让「无 TTY 却 isTTY=true」扩散到一切读点（含未来新增——静默误入交互分支）；缝只影响经谓词的判定。

**实核登记（可行性面——不构成否决理由）**：管道 stdin 下 `process.stdin.isTTY` = `undefined`（基线）；管道下赋值 = 真生效；预载赋值 = 真生效；无 TTY 下创建读流 = 抛错（pty 路线排除）⇒ 两机制今天**都可行**——否决属性伪造 = **设计面裁量**（上列 1–5）。

**结构机检（实现轮落测试，fail-closed）**：扫描域 = 仓内代码档（产品源码 / 入口 / 测试 / 脚本 / 仓根脚本）；`docs/**` 引述文本不入。
改动后 stdin 直读枚举 = {谓词档：1 处；TUI 守卫档：1 处（豁免）}；三守卫经谓词、零直读；谓词缺省（无 env）= 原语义（行为用例对照：无 env + 管道 ⇒ 权限路径仍走降级）。
**排除口径（非直读用法——不计入枚举，防误红）**：① 属性写点（手工 repro 脚本的属性伪造写点——其文本不含直读形态，直读扫描天然不命中）；② 文档面引述与扫描器自身文件。

## 5. 接入点与分层关系

- **落点 = 集成集**——单层 glob 自动收揽；发布门第三步骤已接线 ⇒ **零 runner / 零脚本 / 零包配置改动**。
- **慢用例归册语义**：harness 用例 = 重 IO 面（真子进程 + 网络回环 mock）——归册落点 = **集成层**（而非快层 + `slow()` 标记）：集成档不在慢门执行面、**不得用 `slow()`**（`design/TESTING.md` 红线）；快层与全量目标集合 = 顶层单层 glob ⇒ 集成档天然不进——**集合零变**。
- **与既有集成档分工（不重复纪律）**：既有集成档各有其面（配置选路 · 普通工具流 · TUI 基本盘 · 会话恢复 · 子代理生命周期 · commit / verify 关口 · 工程模式链）；本面新增 = **补两处未覆盖面**：① ACP 协议面进程级全链；② TTY 依赖的交互路径——非既有档改写镜像。

## 10. 边界与待裁项

**边界（不做）**：TUI 渲染（人工真机）· pty / 原生模块 · 真付费端点 · 对端对位（后续裁定）· 快层 / 分层机制改动 · 不引入新入口 / 脚本。

**待裁 / 未决（实现轮前须定或随轮登记）**：
