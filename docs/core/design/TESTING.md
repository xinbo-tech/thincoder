## 1. 分层纪律（L0 / L1 / L2）与 slow 门

### 1.1 分层纪律

分层纪律把一次代码改动的验证拆成三级，级级向上收口，避免“随便改一点就跑上千个测试”：

| 层 | 时机 | 内容 | 谁跑 |
|---|---|---|---|
| **L0+** | 首次实现 | 语法检查 + 定向相关测试（秒级） | eng-coder |
| **L1** | 升级路径 | 快层 `npm test`（slow 层跳过） | eng-coder（仅定向测试空映射 / 触主干时显式升级到本层） |
| **L2** | 链终态 | `test:full` 全量（含 slow 真设备测试） | 父侧收口恰一次/端 |
| **L0** | 每个修正轮 | 改动即时验证 + verify 声明 | eng-coder |

- **首次实现 = L0+，不做全量**——报告义务句逐字：“not full-suite verified — the parent-side L2 run is the only full-suite point.”
- **L1 = 快层**：无链上阶段默认跑；仅当定向测试空映射（无测试文件的板块）或改动触主干 / 入口文件时，显式升级到 L1。**本链永不跑全量**。
- **L2 = 全量**：链末父侧终验恰一次/端，不在 eng-coder 链内跑。
- verify 三层都只收模型的 `verification.status` 声明（passed / skipped+reason），**不代跑任何测试**（verify 语义 = `design/VERIFY-REDESIGN.md`）。

### 1.2 slow 门机制

`slow(name, fn)`——需要真实 fs / git 子进程 / 定时器 / 网络的测试（单用例 >500ms）用它包装：

- **默认快层自动 skip**（runner 输出可见 `↯ skipped`，不隐身）；
- **全量**（`test:full` 或 env `THINCODER_TEST_FULL=1`）跑全量——发版 / CI / 排查时用；
- 快层与全量共用同一套断言文件（不改名不挪目录），零漂移。

**为什么不用目录分层**：`test/**` 是唯一约定入口；同文件改名 + 同名导出门控，让 `node --test test/xxx.test.mjs` 单文件调试跑法（高频）与全量永远走同一断言。
阈值依据实测：>500ms 的测试约占全量 CPU 的 **95%**，而 <5ms 的过半测试合计仅 376ms——**数量不是成本，重 IO 才是**。

**防漏拦截**：

- 快层入口挂慢门 reporter；跑完后机械检查「未标 slow 而超过拦截阈值」的用例，发现即**逐条点名 + 非零退出**（硬红防腐化）。
- **拦截阈值 800ms > 归册阈值 500ms**（阈值缓冲——机器负载抖动不触红）；env `THINCODER_SLOW_GATE_MS` 覆盖（供机制自验）。
- 注册表比对省略（恒等式）：快层里 slow 用例全 skip，「通过且超阈」⇔「未归册」。
- 快层并发 6（`--test-concurrency=6`——**勿再调高**：并发过高会把 400–500ms 中位带通胀过拦截线，打地鼠式误红）；全量不动（默认调度）。

**归册补登**：快层慢门点名的存量用例（真实装配实测 > 拦截线）→ 自普通注册改 `slow(` 归册（**归册不是删除**——快层 skip、全量跑）。归册判据 = 慢门实测点名（不预判；同档其余用例若被后续快层点名，同法归册）。**判定句**：该用例经 `slow(` 注册；快层 skip 可见、全量执行通过；`npm test` 零超阈拦截。

**分层入口**：

| 脚本 | 入口 | 用途 |
|---|---|---|
| `npm test` | `thincoder-cli/test/run-fast.mjs` | 快层（slow 跳过 + 防漏拦截） |
| `npm run test:full` | `thincoder-cli/test/run-full.mjs` | 全量（设 env 后 `node --test`） |
| `npm run test:integration` | `thincoder-cli/test/run-integration.mjs` | 集成集（发布门第三步骤） |
| 手工 | `node --test test/xxx.test.mjs` | 单文件调试（不经过快层入口，无拦截） |

## 2. 测试库存治理（按需加）

存量测试库存已清零，转入**按需加**政策：

- **测试不强制配给每次改动**；机制需要时（新增/重构有明确行为契约要锁）再补用例；
- 补的测试若 >500ms 重 IO，用 `slow()` 归册，进全量层（归册不是删除）；
- 红线：拆分 / 迁移类重构保证**断言数不减**（逐字迁移保真）；存量清理轮走**删除清单制**（逐条列明 + 父侧核销，差额 = 清单数，不再是“不减”）。

当前仓库的测试 = 按需补的少量用例 + 真端点 smoke：快层 / 全量脚本照常可用（机制不动）；冒烟测试不在任何一层，手工跑（花真 API 钱）。

## 3. 测试生命周期（三层来源）

> 术语辨异：**来源层**（①②③——测试的出身与寿命）与**验证层级**（L0/L0+/L1/L2——一次改动何时跑什么）是**两个正交轴**，勿混。

### 3.1 三层来源与寿命

| 层 | 落地物 | 来源 | 寿命 / 去处 |
|---|---|---|---|
| ① 单元（开发期） | `test/` 顶层各档 | 每批开发过程（批次档 §2 列着） | 批次收口逐条处置：**默认退役**（删除）；业务可观察且未覆盖 → 转②③ |
| ② 集成·业务 | `test/integration/` 常驻档 | 业务场景设立（开发期不产） | 常驻 + 发布门 |
| ③ 集成·生产 | `test/integration/` 常驻档 | 实际运行常出的问题补入 | 常驻（越用越准） |

- **退役台账零新增**：① 档的来源票据 = 批次档 §2 文件表 / §5 交付表 + 对端登记差分——处置行直接引用，不建新台账。
- **防误退三判定**（扫①执行时逐档判）：镜像 ≠ 冗余（两仓无跨仓 import）· 归档 ≠ 机制死（调用点全活）· 一致性检查器 = 唯一执行面（删 = 文档门停跑）。

### 3.2 处置判据（退 / 转四问）

1. 业务可观察？（结果 = 用户可感知行为 / 产物——非内部结构形状）
2. ②③ 未覆盖？（同语义场景不在集成集）
3. 可稳定驱动？（脚本化 provider / 真实临时环境——不靠人工）
4. 以上全满足 → **转**（改写成业务语气场景——断言只写业务可观察结果、不保留事故形态）；否则 → **退**（删除）。

### 3.3 批次档 §6 处置行契约（双半）与同步面

「测试处置」行落在批次档 §6 核销同步清单（槽位枚举权威 = `requirements/ENGINEERING-MODE-MECHANISM.md` §1.12）。行内容两半：

| 半 | 内容 | 对账面 |
|---|---|---|
| ① 本批单元档处置 | 逐条：`退 <档名>` / `转 <档名> → 集成场景 <场景名>`；本批零单元档 → `本批零单元档——无处置` | 批次档 §2 / §5 清单（逐条可对） |
| ② 集成影响核 | `新增 <场景>` / `修订 <场景>` / `无` | 主 agent 评估结论（F10——不外包不自动） |

- **执行人** = 主 agent（§6 作者）；① 落手（删档 / 改写）= eng-coder（维护小批 / 随触碰批——删除清单制，逐条列明 + 父侧核销）。
- **同步面（落笔清单）**：`requirements/ENGINEERING-MODE-MECHANISM.md` §1.12 模板槽位行 + §1.15 D7 行（eng-designer 修订）· 工程纪律档双副本的 D7 枚举（主 agent 内容权 + eng-coder 落笔）· 对端双源同款两文件。
- **落笔时机** = **无冻结窗口冲突时**（父侧排程）。

### 3.4 演进评估与 ③ 收编

- **触发**（主 agent 逐批核）：需求批次收口 / 行为变化（用户报“实际运行的常出问题”）/ 发布前。
- **评估动作**（不外包、不自动）：对触发来源逐条问——是否触及既有场景族语义？是否新增“常出问题”值得常驻？→ 需变则出条目（形态 = §6 处置行 ②半 或需求池指针），交 eng-designer 定形、eng-coder 落。
- **③ 收编**：真问题处理后——用户 → 主 agent 登记（落点 = 需求池条目或随 §6 行——不新增簿记）→ 转②（判据 = §3.2）。

## 4. 集成集：承载、执行与发布门

### 4.1 承载选型

判据：① 扫①边界机械性（处置台账可判）② 既有入口约定与单文件调试 ③ 快 / 全两层零混入（无配置漂移）④ helpers / fixtures 复用成本 ⑤ 端内清单制适配 ⑥ 双端镜像成本。

| # | 候选 | 判据逐项评估 | 结论 |
|---|---|---|---|
| 1 | **[`test/integration/`] 子目录** | ①域界 = 目录界（扫①只碰顶层测试档——机械可判）②同根（单文件直达）③单层 glob / 显式清单天然不含（零改）④同树复用⑤对端另立集成清单（登记制同性质）⑥双端同名同位 | **选定** |
| 2 | 仓根平级目录 | ①域界同样清晰 ②第二测试根——“`test/**` 唯一入口”惯例破得更彻底 ③天然不含 ④helpers 跨树引用 ⑤同 1 ⑥双端多一套根约定 | 否决 |
| 3 | `test/` 内标签分族 | ①两类寿命混域——扫①删除清单须逐档甄别；标签漏标 = 误退 / 漏退（处置靠“记得标”）②同域 ③“全量”语义被污染；slow 门与集成门两套 skip 叠加 | 否决 |

**对照 slow 门**：该注针对**快 / 慢同一断言双执行面**（防漂移）；①/②③ 是**不同断言集的不同寿命**——没有“防漂移”要保护，反而制造“处置边界靠自觉”的失稳点。隔离靠**域界**（机械可判），不靠**标记**（靠记得）。

### 4.2 runner 选型

取「**新入口 `run-integration.mjs`**」：语义单一（集成集执行面）；不挂慢门（不适用——不在快层）；退出码 / 摘要形态独立；发布门接线单点。
否决「复用快层 runner 指向集成集」：真实分界 = 其挂载慢门（超阈未归册即红）与消费方语义——集成档 >800ms 必被拦或需 skip 特判；两个消费方（`npm test` / 发布门）语义混淆。

### 4.3 接口契约（双端）

| 项 | 本端（CLI） | 对端（同构） |
|---|---|---|
| 目录 | `test/integration/` | `test/integration/` |
| 文件命名 | `<场景名>.test.mjs` | 同 |
| 目标集合 | 单层 glob `test/integration/*.test.mjs`（沿本仓 runner 惯例） | 显式清单（沿对端“登记即跑”惯例） |
| 入口 | `thincoder-cli/test/run-integration.mjs`（npm script `test:integration`——启动器形态沿全量入口） | 同款 |
| env 门 | 无（执行面 = 入口本身）；集成档**不得**用 `slow()`（无快层执行面） | 同 |
| 发布门接线 | `thincoder-cli/scripts/release-check.mjs` 步骤 +1（lint → test:full → test:integration；失败详情提取沿现有形态） | 对端 prepublish 同构 |
| 不变量 | 快层 / 全量目标集合零变（单层 glob 天然排除集成档）；单文件调试直达不经门 | 同（显式清单天然排除） |

- 裸 `node --test`（无参）非本仓入口（各入口均显式目标）——不设防线。
- 执行顺序：集成集运行面**独立于 L0/L1/L2 任一层**——只在发布门与手工入口跑（链上开发期纪律零变）。

### 4.4 双端镜像策略

- 场景目录 = **共享语义源**；两仓**各自实例化**（语义同源、各端原文自持、不做字节一致）。
- **驱动手段允许各端不同**：本端 = 真子进程 / 模块直驱 + 脚本化 provider；对端 = 扩展模块 + 宿主 mock / DOM 环境——**判据语义对齐、宿主各自**。
- 实现面互不追赶（不以任一端产物回改另一端）；差异如实登记。

### 4.5 覆盖划分（不重复纪律）

- ① 可断言实现内部（开发自证自由度高）；②③ **只断言业务可观察结果**——允许读状态文件 / 产物验证结果，不锁私有结构形状。
- **判定探针（口径内）**：verify 关口的机械判定旗位属口径内判定探针——以其判定值断言“放行 / 打回”业务结果，不视为“锁私有结构形状”；机验不改挂输出串（文案随模型措辞漂移；探针 = 机械判定信号本身，更稳）。
- 禁止同断言双持；②③ 不做 ① 的机械改写（“同样的测试做两遍没有意义”）。
- 处置判据（§3.2）即该纪律在收口时的执行面。

## 5. 首批集成用例表（场景 + 种子）

> 结构：每场景三态（正常 / 边界 / 错误）+ 输入 / 驱动 + 预期输出（判据）+ 机验手段。

| 场景 | 三态（判据摘要） |
|---|---|
| ① **普通模式完整工具流**（需求点名必选） | 正常：真 agent 循环 + 脚本化 provider + 临时工作区（读档 → 改档 → 校验 → verify 通过）——目标文件被改 + verify 认定通过 + 报告含验证声明；边界：纯文档浅改（改 `.md`）→ 快路径放行（不要求验证声明）；错误：代码改动 + 验证状态失败 → verify 打回（不得声称完成） |

| ③ 子代理生命周期 | 正常：真调度器 spawn 异步 + 脚本化 provider → 结算（报告送达父侧、池清、id 递增）；边界：两 spawn 文件域交叠 → 第二个排队，首清后自动启动（不手串行）；错误：运行中取消 → 池释放、终态干净、无孤儿进程 |
| ④ 会话恢复 / 中断续跑 | 正常：真会话文件（HOME 重定向）——写入含计数会话 → 重载（计数不重置、历史完整）；边界：中断半程落盘 → 恢复（已知前缀保留、无重复帧）；错误：损坏 / 缺失会话档 → 干净回退（新会话、不崩溃、退出码正常） |
| ⑤ TUI / 面板基本盘 | 正常：真 state + 按键处理（输入 → 提交 → 送达 agent 循环；渲染面更新）；边界：审批 / 提问面（权限请求 → 面板响应 → 回调结果正确）；错误：退出键 → 清理锁序；接管标志复位；零退出帧 |
| ⑥ commit / 验证关口 | 正常：真 git 临时仓 + 他批已暂存 → commit 路径（只提交列文件；他批暂存不混入不丢失）；边界：验证跳过带理由 / 不带理由（带理由放行 + 标记；无理由拒绝）；错误：验证失败 → 拒绝 |
| ⑦ 配置装载与 provider 选路 | 正常：HOME 重定向 + 真 config → 子进程启动（请求抵达选中 provider 的本地 mock——model / baseURL 匹配）；边界：指定不存在的 provider 名 → 明确报错（不静默落第一个）；错误：坏配置 → 软失败引导（不崩溃；退出码 + 可读文案） |
| 种子组（③层首收编——生产反馈） | 生产问题按 §3.4 收编，改写成业务语气场景（断言只写业务可观察结果）；既有单测档不因收编移除——其寿命按扫①口径 |

## 6. 散文锚退役（PROSE-ANCHOR-RETIRE）

### 6.1 判据（执行版）与口径裁定

**判据三条**（同时成立即散文锚）：① 断言对象是**非测试档文本**或其派生切片；② 断言其**文本内容**在场 / 缺席 / 出现次数 / 相对顺序；③ 断言对象**不是**结构机检保留面所判属性。

**口径裁定（分类的唯一执行口径）**：

| # | 裁定 | 说明 |
|---|---|---|
| C1 | 载体判据 | 按**被断言文本的载体**判，不按 needle 原产地判。断言对象 = **执行产物**（函数 / 工具返回值、子进程输出、渲染帧、测试自建临时域文件）或**结构 / 数值常量** → 不命中 ①（保留）；直接读非测试档所得文本，或经 `import` 取到的源码静态文案字面量 → 命中 ① |
| C2 | 非测试档边界 | **一切非测试档的仓内文件**：产品树 `src/**` · `docs/**` · `scripts/**` · `bin/**` · `webview/**` · `locales/**` · `package.json` · 仓根 `*.md` / `*.json` / `*.mjs` · `AGENTS.md` · `README*` |
| C3 | 保留面 = 封闭枚举 | 结构机检封闭枚举所判属性（段引用 / 计数 / 批次档轮次行 / 台账判据 / 行宽 / 归册 / **工具契约面**）。对非测试档文本的**出现次数 / 相对顺序 / 位置**断言**不属**该枚举 → 按散文锚处置 |
| C4 | 存在性断言保留 | 文件存在性断言不属「文本在场 / 缺席」→ 判据 ② 不成立 → 保留 |
| C5 | 测试档自身保留 | 断言读的是 `test/**`（含登记清单 / helpers / fixtures / 测试内常量）→ 判据 ① 不成立 → 保留 |

**判据补充（C1 的实质判法）**：

| # | 补充 | 说明 |
|---|---|---|
| C1-a | **提示词句子不豁免** | 载体判据按**实质**判——**不问文本从哪来**（读盘 / 装配器或渲染出口的返回值 / 写入 system prompt 的装配结果），只问**断言的是否是提示词句子**：断言提示词句子（含装配器传出的话语、注入块、降级句、槽文本，以及装配产物**与字面常量的全文相等 / 不等**）→ 命中 ①——**「不读文件」不是豁免理由** |
| C1-b | **工具契约面与工具返回文案保留** | **模型实际收到的工具契约对象**（工具 `description` / 参数说明）与**工具返回 / 拒绝文案** → 契约守卫 / 行为输出，非文档散文锁 → 保留。注：读源码档文本（含源码里的描述串）仍命中 ① |
| C1-c | **非句子对象保留** | 结构 / 数值 / 判定信号（槽文件表与集合成员、长度、警告清单与警告文案、旗位、退出码）→ 保留 |
| C1-d | **locales 资源文本保留** | `locales/**` 文本值 = **产品资源文案**（界面 / 本地化面——产品面）→ **不命中 ①**（保留、不进清单）；读非测试档**源码 / 文档文本**仍命中 ① |

**归类三值**：`整删`（该用例全部断言均为散文锚——删后无内容残留）/ `段删`（夹锚断言——只删锚断言行，行为断言保留）/ `保留`（无锚断言；**不进清单**）。

### 6.2 方案选型与清单制

| # | 候选 | 判据逐项评估 | 结论 |
|---|---|---|---|
| 1 | 按档删（锚档整档删除） | 零误删：✗（粗筛锚档含混装档——会连带删行为用例） | 否决（违「混装档只删锚断言、不得整档删」） |
| 2 | **逐条删除清单制**（逐条列档 + 用例名 + 行号，父侧核销） | 零误删：✓；对账：✓（用例总数下降 == 整删条数，机判）；沿既有纪律：✓（存量清理轮走删除清单制）；键控：✓（档 + 用例名，行号 only as-of） | **选定** |
| 3 | 目录 / 标签门控（读档断言族打标签，跳层不跑） | 对账：✗（标签计数与「用例总数」口径脱钩）；退役性：✗（断言仍驻留 = 未退役） | 否决 |

**清单制**：产出 = **逐条删除清单**（`档:行` + 用例名 + 归类依据），交父侧核销；**清单外断言零触碰**；**对账式**：`用例总数(批后) = 用例总数(批前) − 清单整删条数`（计数口径 = 快层执行面内 `test(` / `slow(` / `it(` 起始行计数）。
**零误删**：结构机检 / 行为用例 / slow 门**零改动**（删除集与保留集互斥且穷尽）。
**点名项同批处置**：跨板块被点名的文本面断言随本批退役（形态 = 就地退役注记，保号）。

### 6.3 禁令（禁止新写）

新增断言**只允许**：**行为面**（业务可观察结果）与**结构机检面**；**禁止新写散文锚**。
纪律落点 = 本仓提示词测试纪律节（双源）+ 需求档 + 本档；对端落点自持于对端档。
**相容口径（与端到端 harness 的关系）**：子进程输出 / 协议帧 / 工具返回文案等**执行产物**类断言**不命中**判据 ① ⇒ 非散文锚、属允许的行为面。

### 6.4 边界

- 检查器**语义与判据零改**（保留面不动）。
- 台账本体内容治理 · slow 门阈值与归册纪律 · 行为测试的增删改——均不在本机制射程。
- **既有验收标准（AC）中的锚式判据**不随本机制清理（射程 = 已落地测试断言 + 点名项）；新批次的 AC 判据按禁令只写行为面 / 结构机检面。
