## 1. 问题与定位

**问题**：工程模式全链（设计 → 评审 → 批准 → 实施）对**细节面**改动（视觉 ∥ 文案 ∥ 参数 ∥ 既有交互细部）成本畸高——现场走查的分钟级迭代被压成逐笔全链；放开直改则文档滞后与射程放大失控（试运行实证 = 射程放大被斥）。

**定位 = 受控旁路**：为四步硬流程在细节面开一条**条件严格、代价明确**的旁路——

- **条件面（准入）**：路由五问全过（fail-closed——拿不准一律全链）；
- **代价面（闭合）**：每轮次收尾**跑一次全链**（设计形式化 → 独立评审 → 修复（若有）→ 批准 → 收口核销）——旁路 ≠ 取消，收尾全链 = 对四步的补课；**收尾未落 ⇒ 不许核销**；
- **记账面**：轮次 = 批档一本 + 台账行逐笔——批档 ∥ 台账机制**复用，零新增机制**。

**设计原则**：① 落提示词层（内建机制，非会话级裁定）；② 零机械门（判断面纪律——承「为臆想的失败逐点加限制 = 反模式」）；③ 产品码零触（纯提示词文本 + 设计档面）；④ 两界原则（提示词正文运行时可解析——零文档引用）。

## 2. 机制设计（逐项定形）

### 2.1 路由判据（F-LC1）与量级阈值

五问全过才走；任一不过 ⇒ 全链（fail-closed——宁可重，不可偷渡）：

| # | 问 | 判据 |
|---|---|---|
| ① | 触面 | 落细节面闭合枚举：视觉 ∥ 文案 ∥ 参数（阈值 ∥ 默认值 ∥ 长度）∥ 既有交互细部（顺序 ∥ 位置 ∥ 键位 ∥ 提示语）；枚举扩面 = 新需求 |
| ② | 行为 | 不产生新行为路径（新分支 ∥ 新状态 ∥ 新流程 ∥ 新机制 ⇒ 出局） |
| ③ | 契约 | 不碰接口 ∥ 通道协议 ∥ 数据结构 ∥ 持久化 ∥ 跨端对位语义 ∥ 安全面 |
| ④ | 体量 | 射程小——单面内 ∥ 无连带；**量级阈值 = ≤15 档**（超 ⇒ 出局；定形依据 = §7 K2） |
| ⑤ | 拿不准 | 拿不准 ⇒ 全链 |

**行使面**：路由 = 主 agent 逐笔判定、随交底公开（用户可否决/改判）；子代理不路由、不援引本通道。
**通道外清单**（触界即停、上抛、回全链）：新机制 ∥ 新流程 ∥ 接口契约 ∥ 数据结构 ∥ 持久化 ∥ 跨端语义 ∥ 安全面 ∥ 体量超标。

### 2.2 交底（F-LC2）

- 每笔开工前**一句话交底**（固定格式；带**判据半句**——哪条判据过 ∥ 没过）：
  - 轻通道笔：「**本笔 = 轻通道**（细节面）｜改：__｜射程：__｜回退 = 可 revert」
  - 全链笔：「**本笔 = 全链**（触：__）｜设计 → 评审 → 批准」
- **交底即行**（非阻塞——分钟级；用户改判 ⇒ 即时停/校）；**用户一票改判**（轻通道 ⇄ 全链 双向可改）；
- **中途越界 ⇒ 停笔重交底**（禁偷渡）。
- 本机制无 UI 组件面；交互面 = 交底句（已定形，见上）。

### 2.3 记录在档（F-LC3 前半 ∥ F-LC4）

- 每个轻通道轮次开**一本批档**——逐笔收录 §1（交底 ∥ 改动 ∥ 走查 ∥ 定版——父侧笔）；
- 台账行逐笔照常（逐笔行可随收口核销）；
- **轮次界 = 收口**：收口后新笔另起新轮新档（承批次档生命周期「条目集变更 ⇒ 另起新批」规则）。

### 2.4 收尾一次全链（F-LC3 后半 ∥「必要测试」判据）

触发 = 用户说「收口」∥ 轮末自然停顿（父侧提请）。序列（一次跑全）：

1. **设计**——已落改动形式化 + 文档一致化方案（eng-designer 笔——落轮次批档 §2）；
2. **评审**——独立（落码 ∥ 记录 ∥ 文档对账——落 §3）；
3. **修复**（若有）——按变更面分流落笔；
4. **批准**（§4）；
5. **收口核销**（§6——含必要测试 + 收口测试行）。

**「必要测试」判据（定形）**：① 改动面定向核读（视觉 ∥ 交互细部笔 = 真机走查实测读数——走查即验收读数本）；② 触及可执行行为面的笔 = 批内单元件（随轻通道批档存 · 实施者写与跑）+ 复跑读数；③ 集成面零增补（承测试纪律）；④ 收口测试行照报。

### 2.5 核销挂接（核销前置）

- 轮次行：在途 → **收尾全链 pass** → 待核销 → 已核销（两步迁移照常——**机制本体零动**；前置 = 纪律句，非机械门）；
- **收尾未落 ⇒ 不许核销**（批档 ∥ 轮次行挂住——防「文档滞后永久化」）；判定句 = 「收尾未落而核销」= 0 例（台账查询可核）。

### 2.7 落地形（直改—走查—定版）

- **执行者 = 父侧直改**（分钟级回路；eng-coder 因 token 门无法承接无设计笔——`thincoder-core/agent-tools/subagent-spawn.mjs` 门禁）；改完实跑走查、报读数；
- 逐笔期文档随动 = 可选（若落须按变更面与打标纪律）；**文档一致化 = 收尾全链的必做面**（评审对账项）；
- 走查读数须取无缓存干扰的真实渲染（试运行教训——机制面不落具体刷新技巧，交项目面处理）。

## 5. 边界（本机制不做）

- 不做：边界外内容走通道 ∥ 免收口 ∥ 以本机制替代全链（机制自身 ∥ 大改仍全链）。
- 机制本面：零机械门 ∥ 产品码零触 ∥ 批档 ∥ 台账机制本体零动（纯复用）∥ 子代理零新义务。
- 提示词面：不改写既有条款（铁律 ∥ 分流 ∥ 确认门——例外入机制块载明）；零文档引用（两界原则）。
