## 1. 问题与定位

**问题**：工程模式全链（设计 → 评审 → 批准 → 实施）对**细节面**改动（视觉 ∥ 文案 ∥ 参数 ∥ 既有交互细部）成本畸高——现场走查的分钟级迭代被压成逐笔全链；放开直改则文档滞后与射程放大失控（试运行实证 = 射程放大被斥）。

**定位 = 受控旁路**：为四步硬流程在细节面 ∥ 收敛面开一条**条件明确、代价明确**的旁路——

- **条件面（准入）**：三样清单命中（细节 / 美工 ∥ 缺陷修复——是缺陷就走 ∥ 走查当场）+ 一句边界（新机制 ∥ 大改 ⇒ 全链）——误准入交**收尾全链**兜底（判据收口 · 2026-10-02）；
- **代价面（闭合）**：每轮次收尾**跑一次全链**（设计形式化 → 独立评审 → 修复（若有）→ 批准 → 收口核销）——旁路 ≠ 取消，收尾全链 = 对四步的补课；**收尾未落 ⇒ 不许核销**；
- **记账面**：轮次 = 批档一本 + 台账行逐笔——批档 ∥ 台账机制**复用，零新增机制**。

**设计原则**：① 落提示词层（内建机制，非会话级裁定）；② 零机械门（判断面纪律——承「为臆想的失败逐点加限制 = 反模式」）；③ 产品码零触（纯提示词文本 + 设计档面）；④ 两界原则（提示词正文运行时可解析——零文档引用）。

**判据收口定形（2026-10-02）**：准入 = **三样清单 + 一句边界**（命中即走——定形记录 = §7 K15）；**误准入交收尾全链兜底**——收口时被形式化 ∥ 评审捕获。**核销面 = 机制重心**：挂账 → 收尾全链 → 核销不漏 = 第一优先级（门槛让路给「不漏」）；启动即挂账（账前笔后）照常。

## 2. 机制设计（逐项定形）

### 2.1 准入（F-LC1——三样清单 + 一句边界 · 2026-10-02 判据收口）

**该走的三样**（正面清单——命中即走；免「设计 → 评审 → 批准」全链——直改 → 实时走查 → 定版）：

1. **细节 / 美工**——视觉 ∥ 文案 ∥ 参数（阈值 ∥ 默认值 ∥ 长度）∥ 既有交互细部（顺序 ∥ 位置 ∥ 键位 ∥ 提示语）；

2. **缺陷修复**——**是缺陷就走**（实现与已有出处相抵：需求 ∥ 设计 ∥ 记录 ∥ 用户当场的话——工作 = 让实现回到出处，非新增语义）；

3. **走查当场点名**的问题——按前两样归（细节类默认直行；行为类 = 缺陷修复）。

**一句边界**：**新机制 ∥ 大改 ⇒ 全链**。其余交由**收尾全链兜底**——误准入在收口时被形式化 ∥ 评审捕获（门槛让路给「不漏」——§2.3 重心句）。

**附则**：诊断 / 探针 = 零链面（只读 + 临时区，免归类）；性能观察类 = 无结构变更 ∧ 前后读数可证；**轻通道笔 = 主 agent 直改**（交底自带「可 revert」；大修复照旧派舱 eng-coder）。

**判定句**：抽查任一笔，路由结论可由「三样清单 + 一句边界」复核（判定依据可回放）；「触界内容走轻通道」的记录 = 0 例（收尾全链为兜底闸）。
**行使面**：路由 = 主 agent 逐笔判定、随交底公开（用户可否决/改判）；子代理不路由、不援引本通道。

### 2.2 交底（F-LC2）

- 每笔开工前**一句话交底**（固定格式；带**判据半句**——**命中三样①②③ ∥ 附则·性能观察**）：
  - 轻通道笔：「**本笔 = 轻通道**（细节面 ∥ 收敛面·缺陷修复 ∥ 收敛面·性能观察）｜改：__｜射程：__｜回退 = 可 revert」
  - 全链笔：「**本笔 = 全链**（触：__）｜设计 → 评审 → 批准」
- **交底即行**（非阻塞——分钟级；用户改判 ⇒ 即时停/校）；**用户一票改判**（轻通道 ⇄ 全链 双向可改）；
- **中途越界 ⇒ 停笔重交底**（禁偷渡）；**诊断/探针（零链面）不产笔 ∥ 免交底**——只读 + 临时区、产品面零改（经产品面改动 ⇒ 按三样清单 + 一句边界判）。
- 本机制无 UI 组件面；交互面 = 交底句（已定形，见上）。

### 2.3 记录在档（F-LC3 前半 ∥ F-LC4）

- **本面 = 机制重心**（2026-10-02 22:55 裁）：门槛可降，**挂账 → 收尾全链 → 核销不漏 = 第一优先级**。
- 每个轻通道轮次开**一本批档**——逐笔收录 §1（交底 ∥ 改动 ∥ 走查 ∥ 定版——父侧笔）；
- **启动即挂账（2026-10-02 扩容）**：开轮（首笔开工**之前**）立即两件——① 建轮次批档（先建——写门校验 `task_book` 指针所指档存在）；② 建轮次台账行（title 携「收尾链待跑」；`board` = 轮所在面；`task_book` = 轮次批档路径；`evidence` 记轮性质 + 钩句「收尾未落 ⇒ 不许核销」）。
- 行随开轮**连步至在途**（待讨论 → 待设计 → 在途——既有迁移表；在途必携指针 = 既有写门；携 executor = 跨会话接手判活面）——在途不可跳核销（既有源态判）= 钩的机械半幅；**账在前、笔在后——无账之笔 = 不成立**。
- 台账行逐笔照常（逐笔行可随收口核销）；
- **轮次界 = 收口**：收口前的新笔 = 本轮续笔（同轮记录）；收口后新笔另起新轮新档（承批次档生命周期「条目集变更 ⇒ 另起新批」规则）。

### 2.4 收尾一次全链（F-LC3 后半 ∥「必要测试」判据）

**触发面（时点清单——提请义务在父侧：用户未必知道需收口）**：用户说「收口」∥ 自然停顿（动作链已跑完、无下一动作在飞）∥ 话题转换（未收口而对话离题——离题前提请）∥ 收束信号（用户表达收束意图——意图为准非词表）。
提请形 = 一句、不追催（用户示意继续 ⇒ 随行——义务保留，下一时点再提请）；要素 = 轮次 ∥ 笔数 ∥ 欠的步 ∥ 一票即跑（回「收口」即跑全链）。

**跨会话接手（防亡链）**：会话启动（与「暂缓批先复核」同拍）⇒ 扫未收口轻通道轮次（轮级行未核销 ∥ 批档状态行非「已收口」）——见 ⇒ 先接手提请（要素同上）；用户一票 ⇒ 接手跑收尾全链。

序列（一次跑全）：

1. **设计**——已落改动形式化 + 文档一致化方案（eng-designer 笔——落轮次批档 §2）；
2. **评审**——独立（落码 ∥ 记录 ∥ 文档对账——落 §3）；
3. **修复**（若有）——按变更面分流落笔；
4. **批准**（§4）；
5. **收口核销**（§6——含必要测试 + 收口测试行）。

**「必要测试」判据（定形）**：① 改动面定向核读（视觉 ∥ 交互细部笔 = 真机走查实测读数——走查即验收读数本）；② 触及可执行行为面的笔 = 批内单元件（随轻通道批档存 · 实施者写与跑）+ 复跑读数；③ 集成面零增补（承测试纪律）；④ 收口测试行照报。

**收敛面笔（判据收口定形）**：其「必要测试」= **先红后绿的复现对 ∥ 读数前后对**——笔时捕获、§1 录、收口核（记录面件——不作入口条件）；不另立批内件义务（可执行面的复现脚本〔如有〕随批档存）。

**收敛面笔逐笔形式化模板（收尾轮 §2 设计面）**：逐笔一行——类 ∥ 出处（目标行为坐标：`file:line` ∥ 用户原话）∥ 相抵/读数（红态 ∥ 绿态；性能笔 = 前读数 ∥ 后读数）∥ 落地（改动 `file:line`）∥ 文档一致化去向（出处 = 需求/设计档 ⇒ 实现向档对齐、档零改〔坐标随动除外〕；出处 = 当场的话/记录 ⇒ 收口落档；无文档面 ⇒ 记「无需」）。

### 2.5 核销挂接（核销前置）

- 轮次行：在途 → **收尾全链 pass** → 待核销 → 已核销（两步迁移照常——**机制本体零动**；前置 = 纪律句，非机械门）；
- **收尾未落 ⇒ 不许核销**（批档 ∥ 轮次行挂住——防「文档滞后永久化」）；判定句 = 「收尾未落而核销」= 0 例（台账查询可核）。
- **行自开轮在盘**（启动即挂账——§2.3）：轮次行自开轮在途；未核销轮级行 = 跨会话接手扫描对象（与批档状态行同源）；收口链 pass ⇒ 两步迁移照常。

## 5. 边界（本机制不做）

- 不做：边界外内容走通道 ∥ 免收口 ∥ 以本机制替代全链（机制自身 ∥ 大改仍全链）。
- 机制本面：零机械门 ∥ 产品码零触 ∥ 批档 ∥ 台账机制本体零动（纯复用——启动即挂账 = 既有迁移表/写门连步）∥ 子代理零新义务。
- 提示词面：铁律 ∥ 分流表 ∥ 确认与批准门不改写（例外入机制块载明）；工程工具面直改硬约束 = 两条（判据收口定形）；零文档引用（两界原则）。
