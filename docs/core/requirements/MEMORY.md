## 1. 总体定位

记忆系统 = 三层记忆（`personal` / `project` / `team`）的存取 **+** 代码 / 文档索引 **+** 嵌入面。
CLI 侧住 `thincoder-cli/src/memory/**`（8 档）与 `memory.mjs` 转口；VSC 侧住 `thincoder-vscode/src/memory.mjs` + `memory-tool.mjs`。
本板块对本子系统的要求 = 该面归一为**核内单一实现**，方向 = **CLI 语义**（承用户裁定 A12 / A13）。

> 面清单与逐面裁决（分类 / 端差处置 / 前提校验 / 归属段）→ `docs/core/design/MEMORY.md` §1–§2（不复制）。

## 2. 功能性需求

### 2.1 本子系统条目

- **【回填】** 记忆面**归一方向 = CLI 语义**（`node:sqlite` 的 `DatabaseSync` + FTS5；库为唯一载体），VSC 侧改接线、**不保留降级路径**；分叉前提（「VS Code 内置 Node 不支持 sqlite」）**已失效** ⇒ 直接归一，不作选边拉锯。
  来源 = 工作流档 §1.2 第 6 条（承用户 2026-09-13 裁定 **A12**「记忆系统要向 cli 端统一」· **A13**「旧版用户升一下级不会死的」）。
- **【回填】** 既有记忆数据以**一次性导入器**承接（VSC `personal` 层 `.md` + 遗留 `.json` → CLI `entries`）；`modelPrefs`（住 VS Code 状态、无文件系统载体）**不迁**。
  来源 = 设计档 `MEMORY.md` §3.1 A2（用户 2026-09-13「全部按建议」批量批准；该行为父侧代选、已披露）。
- **【回填】** VSC **引擎下限随之抬升**（`node:sqlite` 需 Node ≥ 22.13）；下限值属对外契约变更 ⇒ **经真机实测确认后定值并提交用户过目**；配套运行时护栏 = `activate()` 自检 + 明确提示（**不崩**）。
  来源 = 工作流档 §3 N7（承 A8 残余 / A13）。
