# Function Spec · M2 台账（SQLite）

> 模块划分权威源 = `docs/core/design/ENGINEERING-MODE-V2.md` §2.2（M2）

## ① 模块目标

**SQLite 单表**台账——待办总账的单一权威源：六态 CHECK 机械锁死、COUNT 单源计数、收口事务保证原子。

## ② 功能点

1. **items 表 schema**（单表 + status 枚举，归档 = 状态子集）：

   | 字段 | 说明 |
   |---|---|
   | `id` | INTEGER PRIMARY KEY |
   | `kind` | TEXT NOT NULL CHECK(kind IN ('requirement','tech_todo')) |
   | `status` | TEXT NOT NULL CHECK(status IN ('待讨论','待设计','在途','待核销','已核销','已废弃')) |
   | `title` | NOT NULL——需求句 / 待办句（一行一条，不展开细节） |
   | `board` | 归属板块 |
   | `req_doc` | 需求档指针（需求类：`<档> §X`） |
   | `task_book` | 任务书指针（在途 / 待核销必填） |
   | `evidence` | `file:line` + 症状（技术类最小证据行） |
   | `trigger` | CHECK(trigger IN ('归批','条件','认账不排期') OR NULL) |
   | `executor` | 执行者归属：`sessionId` 文本；**在途写入 / 离开在途清除**——状态翻「在途」时记当前会话；离开「在途」（→ 待核销 / → 已废弃）与撤回（任意态 → 已废弃）时清空；核销路径（勾销 / 追认）零触碰；可空（老数据 / 历史行 NULL） |
   | 时间戳 | `created_at` · `updated_at` · `closed_at` |

2. **六态状态机**：待讨论 → 待设计 → 在途 → 待核销 → 已核销（勾销入归档）；任意态 → 已废弃（撤回 / 批次废弃）。
   **核销只一条边**：已核销的唯一来源 = 待核销（勾销）；`在途 → 已核销` 不可跳。
   待讨论 / 待设计 的行若已落地，走法 = 先 `update` 到在途（认领）→ 待核销 → 勾销。撤回（任意态 → 已废弃）与 `ledger`（action=update）的迁移表不变。
3. **查询命令**（只读，全角色可见）。
4. **写命令**（仅主 agent 装配）。
5. **归档 = 软删除语义**：已核销 / 已废弃 = 状态值，不物理删行。
6. **计数单源**：`SELECT COUNT(*) WHERE status IN (未决四态)`。
7. **落点**：项目级 `ledger.db`（不进 git）。
8. **执行者归属**：多实例并存下，在途条目记「谁在做」——
   - **写入**：状态迁移进入「在途」时，写当前会话 `sessionId` 到 `executor`；离开「在途」（→ 待核销 / → 已废弃）即**清除**（置 NULL）。
   - **可见面**：`/ledger` 查询与状态行显示执行者；`executor` 非空时**判活展示**——属主进程活着 ⇒ 正常显示；已死 ⇒ 显示「（属主已死 &lt;n&gt;，可接手）」（L2 尾段形态）；进程探测失败 ⇒ 保守显示（不显示死亡，防误判——D-MI10 不对称沿用）。
   - **存储零新建**：字段挂在既有 items 单表（台账库本就按项目根共享）——不建平行存储（MULTI-INSTANCE-COLLAB N-MI1 吻合）。

9. **库键归一与跨端一致**：库键 = `sha1(normalizeCwd(项目根绝对路径))[:16]`——
   - **归一步** = `session-slots.mjs` `normalizeCwd`（Windows 盘符统一大写；跨端契约同 session / checkpoint / traces / peers）；`resolve()` 既有规范化覆盖分隔符 / 点段 / 去尾斜杠；**非盘符段不折叠**（POSIX 大小写敏感——同 `MEMORY.md` §6.11「不做」）；`realpath` / 别名路径不做。
   - **不变性**：CLI 侧（盘符本大写）键零变；VSC 侧（`uri.fsPath` 小写盘符）并入同键 ⇒ **两端同库**。
   - **存量面**：变体键合并迁移（`thincoder ledger migrate --dry-run|--confirm`：备份 → 单事务迁入（id 重发）→ 事务内读回 → 源回收 `ledger-trash` 不删）· 残档审计（`thincoder ledger audit`：只读逐库定性 + 处置建议；只报告零动作）。

10. **变体键库首跑检测提示**：存量变体键库不再无声搁浅——
   - **检测**：启动（CLI 主入口）时对**当前项目根**计算其键的盘符变体（沿 `ledger-migrate.mjs` `legacyKeyVariants` 语义——检测面零新建哈希式）——变体键库在盘 ⇒ 判定成立（主库在否均提示——数据只在变体库时更属搁浅）；无 ⇒ 零动作零输出。
   - **提示**：判定成立 ⇒ 单行明示（文案单源 = i18n 键；内文含收正路径 `thincoder ledger audit` ∥ `migrate`）；**每进程至多一次**。
   - **降级**：检测全径失败（IO ∥ 目录不可读等）⇒ 静默——绝不阻塞 / 绝不中断启动。
11. **核销机检（F-LX4）**：凡写入 `已核销` 的语句，写库前先校验三件，缺一即拒并报明缺哪件：
    - **批档在盘**：行的 `task_book` 指向的档存在；
    - **批档已收口**：该档 `§1` 状态行 = `已收口`；
    - **凭证在册**：该批档在 design token 槽的**批次归属**中有记录（`design-slots` 的 `batch` 列反查）。
    **为什么**：改动与文档失步是常态——代码改了而设计档没跟（本门保留：例外通道取消后它仍是唯一挡得住这个形状的机械点）。

    **收口全链是把两者拉回同步的唯一动作**：eng-designer 把代码现态写回设计档 → 设计评审 → 批准。

    而设计评审通过才签发 `designToken`，签发时还会记下它属于哪份批档——**有 token 就是全链跑过的凭证**。旧闸只认标题里一个自贴自删的标记，等于自己给自己发通行证。
    **边界**：只对**新增**核销生效，存量已核销行不回改；归属判据沿用现有 `batchAbsPath`（评审文档集恰含一份批档；多份 ∥ 不含 = 无归属 = 拒）——不新增输入；不改「收尾链待跑」现有机械牙（它管开笔前，本项管核销时）。

## ③ 边界（不做什么）

- 不做 manifest（M1，只互指咬合）；不做批次档（M3）；不做 checklist（M7 废除，语义由本模块六态承接）。
- 不做项目归档档搬迁（`docs/TODO-archive.md` 是项目文档约定，不在本模块）。
- **首跑检测（F-LX3）不做**：不做变体库自动迁移 / 自动删除（只提示；收正 = 用户显式跑 `thincoder ledger migrate`）∥ 不做桌面 / VSC 启动面提示（CLI 主入口为限）。
- 不承载细节展开（台账条目一行一条——细节进需求档 / 批次档）。
