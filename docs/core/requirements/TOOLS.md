## 1. 总体定位

工具系统 = 工具实现面（`src/tools/*.mjs` + `src/agent-tools/*.mjs`）**+** 工具描述面（`src/tools/*.md`，文本行本体归提示词面）**+** 注册表（`agent-tools.mjs` / `cli/make-agent.mjs` ↔ VSC `thincoder-vscode/src/agent-tools/index.mjs`）**+** 单端独有实现。
本档只收**实现面与工具行为契约**（工具描述文本与槽位提示词的行本体住提示词面子系统档）。
本板块对本子系统的要求 = 对称面归一为**核内单一实现**；工具可见输出 / 回话面的归一变更**保留兼容并逐条登记**。

> 面清单与逐面裁决（分类 / 端差处置 / 前提校验 / 归属段）→ `docs/core/design/TOOLS.md` §1–§2（不复制）。

### 4.5 工具输出上限系（TOOL-OUTPUT-LIMITS——旧专题需求档并入）

> 来源 = `thincoder-cli/docs/requirements/TOOL-OUTPUT-LIMITS.md`（现行机制专题档）；设计面 = `docs/core/design/TOOL-OUTPUT-LIMITS.md`（本档只收需求条目）。与 §4.3 N5 的关系：N5 = 资源上限条目；本节 = 超长输出**落盘阈值与预览形态**（两轴并存）。

**总体目标**：工具输出「超长落盘」阈值 = **64K（65536 字符）**，落盘时的内联 preview 采用**保头保尾**构成，并让显示层全链路对齐 64K——减少大输出（尤其 advisor 评审、读大文件、grep 大仓库）被过早落盘 / 截断的频率。

**功能需求**：

- **FR1 · 64K 阈值**：工具输出 ≤65536 字符**不落盘**、直接进上下文；>65536 才落盘并返回 preview + 文件路径。
- **FR2 · 预览保头保尾**：preview 构成 = **头 16K + 中间省略注 + 尾 48K**，总长 ≤ 65536（预算：tail = 65536 − head − noteLen；两端均经 UTF-16 安全切片防代理对切开）。
- **FR3 · advisor 同宽（头尾双保）**：advisor 评审循环里读到的工具结果放宽到 64K——超限结果**头尾双保**（尾部结论 / 裁决不被切）；截断 = 头行 ~60% + 中段省略注 + 尾行余预算（+ offset 续读提示）。
- **FR4 · 失败路径同口径**：落盘失败回退路径同用双端切片（头 + 省略注 + 尾，无路径提示），不残留头截断。
- **FR5 · 行为兼容**：落盘机制、文件路径指引、写时自清理全部保留，仅阈值与 preview 构成变化。

### 4.7 TTY 驱动能力（TTY-DRIVE——新能力条目）

> **本子节 = 新增需求**（非并入——§4.1–§4.6 = 并入面）；**编号系 = 本子节自有**（U1–U4 · N1–N5——与 §4.1 的 F 系、§4.3 的 N 系、§4.5 的 FR/N 系并列，不互指）。
> **来源** = 用户需求层重定；用户原话：「我们是需要用 thincoder 去驱动一个终端环境测试某个程序，只是碰巧这次我们是在开发 thincoder」。
> **前身** = 旧「CLI 自动验证」条目（主轴倒置——其改判与逐条处置见 `TESTING.md` §6）。
> **关联在册**（指针，不展开）：`docs/TODO.md`「`bash` 工具需要异步 / 后台执行」（同族：agent 驱动长驻 / 交互进程；并轮与否由用户定）。
> **前身需求池条目** = `docs/TODO.md`「CLI 自动验证（端到端 harness）」——该条目主轴同样待改判（台账侧处置归主 agent；本档只登记）。

**总体目标（为谁解决什么问题）**：agent 能在**无人工、无真实交互终端**的环境里驱动**需要 TTY 的程序**
（跑起来 → 发输入 → 读回屏幕 → 按输出判定 + 取退出码），使「**测试一个终端程序**」可由 agent 自动完成。
thincoder 自身的 CLI / TUI **不定义**本能力——它只是其中一个被驱动对象。

**功能需求（用户故事 U1–U4）**：

| # | 用户故事 | 说明（判据方向——判据句归设计轮） |
|---|---|---|
| **U1** | 作为 coding agent，我想要把目标程序**跑在真 TTY 里**（非管道、非属性伪造），以便需要终端的程序能真正进入交互形态 | 被驱动进程对自身 stdin / stdout 的终端判定为真（**真终端**——不是属性伪造 / 伪 TTY）；管道形态下走降级分支不算达成 |
| **U2** | 作为 coding agent，我想要向被驱动程序**发输入**（文本 / 按键 / 控制序列）并**读回屏幕**，以便驱动交互流程并观察其响应 | 输入含普通文本、单键、控制序列（方向键 / Ctrl 组合）；读回 = 屏幕内容（可见文本；光标 / 尺寸等面按设计轮定形） |
| **U3** | 作为 coding agent，我想要**按输出判定并取退出码**，以便把「程序行为对不对」写成可自动执行的判据 | 断言 = 屏幕内容 + 退出码（+ 需要时 stdout / stderr 分流）；挂死不得表现为「静默等待」——须能被硬超时收束为失败 |
| **U4** | 作为 coding agent，我想要用**同一能力**驱动 thincoder 自身的 CLI / TUI，以便本仓库的终端程序也纳入自动验证 | **本条的一个用例，非需求本身**——能力不得只对本仓 CLI 生效（对象泛化：任意需要 TTY 的程序） |

**非功能候选（N1–N5——口径待设计轮定；本档只登记维度与标准方向）**：

| # | 维度 | 标准（候选） |
|---|---|---|
| **N1** | 宿主零 TTY 可跑 | 能力使用者（agent 会话）**无 TTY** 时全部用例仍可跑并全绿——TTY 由能力自造（取代旧形态：以伪属性骗过守卫） |
| **N2** | 确定性 | 被驱动对象的非确定性来源（模型 / 网络 / 时钟）一律走**脚本化替身**（零外网 / 零付费端点）；隔离 HOME 与 cwd；用例间零共享状态；重复执行结果一致 |
| **N3** | 硬超时保底 | 每用例有硬超时（挂死 = 失败，不永挂）且超时给**可读失败句**；数值口径待设计轮定（旧面参照值 ≤30s / 档 ≤3 分钟） |
| **N4** | 失败可诊断 | 失败输出含现场：退出码 + 屏幕 / 输出尾段 + 已发送的输入序列；无静默挂起 |
| **N5** | 分层归属 | 重 IO 用例（真子进程 / 终端通道 / 网络回环）归**集成层**：不进单入口（`npm test`）、不用 `slow()`、发布门执行（承 `TESTING.md` §6.2） |

**范围边界（不做）**：

- **不做伪 TTY 形态的能力本体**——属性伪造（把 `process.stdin.isTTY` 赋成真值）与产品侧「注入缝」不是本能力的达成方式（U1 要求真终端；伪 TTY 下 raw mode / 终端尺寸不存在）。
- **不做终端仿真器的完整语义**（终端能力全集 / 逐像素渲染仿真）——读回屏幕只到「按输出判定」所需；具体到哪一层归设计轮裁决。
- **不做主观体验判定**（界面观感 / 交互顺不顺手）——人工面；自动绿不得被读成体验已被验收。
- **不做真实付费端点 / 外网依赖**（承 N2）。
- **不新开执行边界**——沿用 §4.3 N1 的信任模型 + 审批门控 + 快照防线。
- **不代立两端验证的设立口径**——能力归属 = 工具系统（统一面）；各端验证用例是否同期设立属另批裁定。

**§4.3 N3 边（条件判值）**：工具面形态取「并入 `bash`」⇒ 须为交互态另定超时 / 生命周期口径——长驻 / 交互程序两次输入之间可远超 120s，且同步 `bash` 会挂住调用方回合；取「新工具」⇒ §4.3 N3 不动。

### 4.8 SSH 会话工具（SSH-SESSION——新能力条目）

> **本子节 = 新增需求**（**编号系 = 本子节自有（S / NS）**——与 §4.1 F 系、§4.5 FR 系、§4.7 U 系平列，不互指）。
> **来源** = 用户「用 thincoder 做网络管理」讨论定形（原话链：「我想用thincoder来做一些网络管理方面的工作，我觉得应该给他提供一个可以多次往返的ssh连接工具，你觉得有意义吗？」∥「凭据怎么录入呢？你连接时弹个用户名密码输入窗口？」∥「可以啊，这个应该是可以建立连接以后多次对话循环配置的吧？」∥「可以，跑吧！」）。
> **关联在册（指针，不展开）**：§4.7 TTY-DRIVE（同族机制——PTY 驱动；本条同样需要真 TTY（PTY），但落点在**远端**——由本机 ssh 客户端 `-tt` 分配，本地侧无需真 PTY）；服务端管理面「主机凭据弹窗 + exec」（**异面先例**——凭据弹窗零回显纪律同源，对象 = 服务器代管主机，非本机直连面）。

**总体目标（为谁解决什么问题）**：agent（与人）能从本机直连**远端主机 / 网络设备**，在**一条会话里多次往返**地发命令、读回输出、按输出继续下一步——覆盖交换机 / 路由器那类**只有交互式终端**、没有一次性 exec 的环境（网络管理面的主对象）。

**功能需求（用户故事 S1–S5——判据方向，判据句归设计轮）**：

| # | 用户故事 | 说明（判据方向） |
|---|---|---|
| **S1** | 作为 agent，我想要**建立一条到远端主机 / 设备的 SSH 会话**（密钥 / ssh-agent 优先；需要密码时走结构化输入窗），以便我不必为每条命令重连一次 | 连接复用本机 ssh 配置（known_hosts / config / agent）；密码入口 = 结构化弹窗（值零入对话 / 零入模型上下文——见 NS4） |
| **S2** | 作为 agent，我想要在**同一条会话里多次往返**：发 → 读回 → 再发下一条，直到关会话 | 会话状态（cwd / 环境变量 / 设备模式如 `configure terminal`）在往返间保持；会话 = 长命连接 |
| **S3** | 作为 agent，我想要驱动**交互式设备流程**（登录提示 / enable / 确认 y/n / `--More--` 分页），以便网络设备能真正配下去 | **远端**真 TTY（PTY——由本机 ssh 客户端 `-tt` 分配，本地侧无需）；按提示符 / 静默判定「该我发了」；非全屏终端仿真（见边界） |
| **S4** | 作为 agent，我想要**读回输出并据此继续**，以便把网络管理的多步操作用一段工作流完成 | 输出回进对话（量有帽）；回合之间会话**保活至显式关闭或闲置超时**（口径归设计轮） |
| **S5** | 作为用户，我想要**随时插话改方向** | 会话工作流由 agent 跑或用户看着跑——两种都行（输出实时可见） |
| **S6** | 作为用户，我想要**装过密钥的主机再也不弹窗**，以便不必每次手输 | 密钥优先（本机 ssh 配置 / agent / `identityFile`）；该主机密钥可用 ⇒ **零弹窗** ∧ **保存件零读取**（A 案） |
| **S7** | 作为用户，我想要在密码机上**首次输完就能保存**，之后静默复用 | 保存 = 可选（勾选）；存储 = **系统级加密件**（Windows DPAPI 等——仅用户域 ∥ 明文零落盘）；再连 **零弹窗**；解密失败 / 档损坏 / 条目被拒 ⇒ **回落弹窗**（不 brick）；改口令 ⇒ 覆盖（last-write-wins） |
| **S8** | 作为用户，我想要**看得见已存了哪些（值不出现）并删得掉**，以便我随时收回授权 | 清单 = 只读、值零出现；删除（`forget`）= 写操作、过既有审批门；删除后该主机回落弹窗 |
| **S9** | 作为 agent，我想要**可指定主机身份**（用户名 / 密钥路径），以便连非默认账户 | `connect identityFile=…` 生效并落记录；再连复用 |

**非功能（NS1–NS5——口径待设计轮定）**：

| # | 维度 | 标准（候选） |
|---|---|---|
| **NS1** | 零第三方运行时依赖（现行承诺） | **已裁**（用户——零原生件：远端 PTY 经 `ssh -tt` 分配、本地侧无需原生件；裁决表见下） |
| **NS2** | 不卡死 | 每条命令 / 每次读回有硬超时兜底；设备不吐提示符 ⇒ 可读失败句（非静默挂起）；输出量有帽 |
| **NS3** | 破坏性动作先确认 | 危险命令（`reload` 类）走既有「破坏性动作先确认」纪律（落点归设计轮） |
| **NS4** | 凭据零入上下文 | 密码从结构化弹窗直接喂 ssh 进程——不进消息行 / 不进模型上下文 / 不进会话记录；输入以遮蔽形式显示 |
| **NS5** | 宿主层 | 会话机制的宿主层（核工具——三端共有）归设计轮 |
| **NS6** | 凭证安全面 | 保存件 = 系统级加密（DPAPI 或等价）且仅用户域；**值零进 argv / env / 日志 / 仓**；解密失败 / 档损坏 / 条目被拒 ⇒ 回落窗（不 brick）；残余风险如实披露（本机被攻破 / 登录态被夺 ⇒ 可解） |
| **NS7** | 多端同源 | 三端（CLI / VSC / 桌面）**共一保存档**；端差仅渲染（勾选面文案），行为同源 |

**范围边界（不做）**：

- **不做全屏终端仿真**（vim / emacs 这类全屏 TUI 不伺候）——输出面 = 文本流；判据 = 不做逐屏刷新渲染。
- **凭据托管 = A+B 已裁**（用户 2026-10-17 00:43「可以，A+B」）：**A 密钥优先**（能装密钥的主机装密钥 ⇒ 零秘密、不出窗）+ **B 加密凭证库**（密码存**系统级加密件**——值零进日志 / 仓；解密失败 / 档损坏 / 条目被拒 ⇒ **回落弹窗**，不 brick）。
  **平台**：沿裁决 3（三平台实现面全覆盖 ∥ 实机验证仅 Windows）——Windows 后端 = DPAPI ✓；Linux / mac 后端 = 实施轮按资料落（macOS `security` 值经 argv 一点与「值不进 argv」纪律相抵 ⇒ 实施轮定案）。密钥事务仍归本机 ssh 配置 / agent。
- **不做文件传输**（scp / sftp）与**隧道管理**（`-L`/`-R` 的动态增删）——**后一刀（在册候选，非「不做」）**。
- **工具本体不与用户问答**（§4.2 F5 同判）——会话输入由 agent 或用户经对话面提供。

**待定项裁决（用户三裁在表）**：

| # | 待定项 | 裁决（用户三裁） | 影响面 |
|---|---|---|---|
| 1 | **PTY 依赖政策** | **已裁 = 零原生件**（原话「我支持方案1」） | 选定代价在册：残余风险 = 平台 askpass 支持逐平台验（网查版本面成立——OpenSSH ≥8.4；实机腿待补）∥ 提示符判定为文本启发式 |
| 2 | **「记住密码」** | **已裁 = A+B**（用户 2026-10-17 00:42「做个保存凭证的功能吧」+ 00:43「可以，A+B」——密钥优先 ∥ 密码存系统级加密件） | 静态秘密 = 加密态（DPAPI）且**仅用户域**；明文零落盘 ∥ 值零进 argv / env / 日志 / 仓；fail-soft 回落窗；落点与形态 = 设计 `docs/core/design/TOOLS.md` §6.22 |
| 3 | **跨平台口径** | **已裁 = 三平台实现面全覆盖 + 验证口径收窄**（原话「三个平台要都能用，但是不用都验证，windows验证过就行了，其他平台按资料实现，等用户反馈就是了」） | 实现按文档跨平台；实机腿 = 仅 Windows；mac / Linux = 文档面 + 用户反馈迭代 |

**验收方向**：① 一条会话内 ≥2 次往返且状态保持（cwd / 模式）；② 密钥机零弹窗直连；③ 密码机走弹窗且密码零入对话 / 上下文（机检：对话记录 / 消息面无密码字面）；④ 交互式流程（提示符 / 确认）可走通；⑤ 超时兜底：设备不响应 ⇒ 可读失败、不挂死；⑥ 存过密码的主机再连 ⇒ **零弹窗**；解密失败腿 ⇒ 回落弹窗、不崩；⑦ 删除面生效后 ⇒ 回落弹窗。

### 4.9 网络工具 DeepSeek 后端（WEB-BACKEND-DEEPSEEK——新能力条目）

> **本子节 = 新增需求**（**编号系 = 本子节自有（W / NW）**——与 §4.1 F 系、§4.5 FR 系、§4.7 U 系、§4.8 S 系平列，不互指）。
> **来源** = 用户 2026-10-17 19:05「search fetch要接啊」＋ 19:11「我觉得还是复用方便，我希望配了deepseek预置provider的用户能够零改动自动接入」＋ 19:12「行」。
> **上游事实**（官方 API 实读 2026-10-17）：`POST https://api.deepseek.com/v1/tools/search`——`query` ≤128 字（支持 `site:` ∥ `lang:` ∥ `after:` / `before:` ∥ 引号运算符）· `count` 1–50 · `need_content` 缺省 false；
> 结果 = `summary`（600–800 字，给模型读）∥ `snippet` ∥ `date` ∥ `authority` 0–4（**`-1` = 未知**——官方 Search API Reference「0 to 4 (-1 means unknown)」，2026-10-17 实读）∥ `rerank_score` 0–3。`POST /v1/tools/fetch`——`url` ⇒ `{title, content = Markdown}`。
> 认证 = 既有 DeepSeek API key；计费 = **按成功请求 $0.75 / 千次**（失败 / 空结果不计，`count` 不影响单价）；限速 = 各 5 QPS（账号级）。
> **关联在册（指针，不展开）**：设计 §6.10（`websearch` 配置面历史）· `CONFIG.md` §6.2 / §6.3（配置键名录 ∥ `${env:VAR}` 消费侧解析）· §4.2 F6（后端选择面契约）。

**总体目标（为谁解决什么问题）**：让 `websearch` / `fetch` 可直接消费 DeepSeek 官方搜索 / 抓取能力（结构化结果带权威度 ∥ 日期 ∥ 长摘要；抓取返回 Markdown），
**配了 DeepSeek 预置渠道的用户零配置自动获得**——同时保持无该渠道用户的行为逐字不变。

**功能需求（用户故事 W1–W6——判据方向，判据句归设计轮）**：

| # | 用户故事 | 说明（判据方向） |
