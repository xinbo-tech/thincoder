# Function Spec · M9 提示词双面流程

> 模块划分权威源 = `docs/core/design/ENGINEERING-MODE-V2.md` §2.2（M9）

## ① 模块目标

提示词**双面流程**：模板 = **中文审核面**（用户审核用）、落地档 = **英文运行面**（国外模型运行用）——改模板（中文）→ 翻译生成落地（英文）；生成 = 翻译，不是 cp。

## ② 功能点

1. **更新流程**：先改模板（`docRoot.design` + `/prompts`——本仓经 manifest 声明覆盖后 = `docs/core/design/prompts/`）→ 再翻译生成落地（`promptsLanding`——本仓 = `thincoder-core/prompts/`）。
2. **落点读声明面**：模板 = `docRoot.design` + `/prompts` 推导；落地 = manifest 顶层平级键 `promptsLanding`（落地是代码仓路径、不入 docRoot 文档体系）。
3. **提示词内不得要求「列候选对比」**（该纪律已废）。
4. **兑底 = 收口核对清单（非机检门 · 用户 2026-09-17 裁定）**：模板改动后，收口时**人工核对四项**——① 落地档已同步（新增 / 删除 / 改写逐档）② 两面档名集合相等（模板 15 ⇄ 落地 15）③ 核包提示词测试全绿（`node --test` 于核目录）④ 收口记录一行（「模板 → 落地 已同步」）。**不挂机检**（同上裁定）；**未裁项** = 是否另加机检（保持不挂，除另行裁定）。

## ③ 边界（不做什么）

- 不做提示词**内容权**（提示词内容 = 主 agent 内容权 + coder 落笔）。
- 不做需求档 / 设计档。
