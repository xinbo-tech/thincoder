# Function Spec · M4 写权门禁

> 模块划分权威源 = `docs/core/design/ENGINEERING-MODE-V2.md` §2.2（M4）

## ① 模块目标

把**写权矩阵**从「靠提示词自觉」落成**机械门禁**：谁能写什么，由结构拦——没有 token 写不了产品代码，评审在途改不了被审文档，台账 / manifest 非主 agent 写不了。

## ② 功能点

1. **token 门**（继承 v1）：eng-coder 写产品代码需**活 designToken**；无活槽 → 拒（fail-closed）。
2. **D5 冻结窗口**：设计评审在途，被审文件集（设计档 + 批次档）**零写入**——写入即拒 / 本轮结算为陈旧（不发 token）。在途下界 = 报告送达（digest 注入 / 回合尾 collect）或取消·中止——「子进程退出」不是窗口边界。
3. **声明面读取**：评审对象清单 / 被审文件路径从 `manifest docRoot` 取，**去硬编码 `docs/`**。
4. **装配承接**：台账 / manifest 写命令装配点在 M1（manifest 写门）+ M2（台账写命令）的实现里（非主 agent → 拒），M4 只承接拦截验证，不重复实现。

5. **修 ≠ 绕**：分流（变更面）与门禁不一致 → 停下上报（非静默放行）。

## ③ 边界（不做什么）

- 不做 token 签发（M6）；不做评审判据（advisor）。
- 不重写 v1 门禁本体（继承 + 声明面微调）。
- 不做语义写权判断（「谁写需求谁写设计」不可机判——落提示词层 + 互锁兜底）。

## ④ 验收（逐条可机判）

| # | 判据 | 方式 |
|---|---|---|
| AC-M4-1 | 无活 token 写产品代码 → 拒 | 清槽后写 → 期望拒 |
| AC-M4-2 | 冻结窗口内写被审文档 → 拒 / 结算为陈旧 | 评审在途写被审档 → 期望拒 |
| AC-M4-3 | 评审对象 / 被审文件路径读 `docRoot`（非硬编码 `docs/`） | grep 硬编码路径 |
| AC-M4-4 | 台账 / manifest 写命令非主 agent → 拒——**验证随 M1/M2 批**（装配点在 M1/M2，M4 只承接） | 非主 agent 写 → 期望拒 |
| AC-M4-5 | 修 ≠ 绕：分流（变更面）与门禁不一致 → 停下上报（非静默放行） | 构造不一致场景 |

## ⑤ 依赖

- **上游**：M1（`docRoot`）· M6（活槽判据）。
- **下游**：M5（spawn 门读活 token）。
