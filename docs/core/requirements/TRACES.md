### 2.3 启动 / 运行面：清理不得全量线性扫描（2026-09-21 用户报「启动的时间好长」同批 · 台账 #173）

**【用户报】** `cleanupTraces` 现实现 = 逐日目录 × 逐文件串行 `stat`（+ 过期 unlink）⇒ ① 启动时后台扫描风暴；② 一次性命令（`--version`）印出后进程挂 **12.5s** 等事件循环排空；③ `recordChatTrace` 每写一条轨迹又全扫一遍。存量基线（实读）：**15,610** 个 `.jsonl`（4 个日目录：6,609 / 1,979 / 5,574 / 1,394）。

- **F-SL3（清理面性能边界）**：① 清理须有**目录级判据**（整日目录过期 ⇒ 整删，免逐文件 stat）；② 每写 prune **须节流**（同窗多次写 ⇒ 至多一次扫描）；③ 存量一次性清理可执行。判定句：`--version` 类一次性命令印出后 ≤0.5s 退出（对照 12.5s）；同窗 3 连写 ⇒ 扫描 ≤1 次；存量清理后 `.jsonl` 总量回落。
- **边界**：不改「完整落盘 + prune」策略裁决本身 · 不动保留期内轨迹 · 两端默认开关零改 · 不改字段 / 目录命名形态。
- **验收**：同 SESSION §2.4 读数口径 + 本档判定句；三端测试全绿。
