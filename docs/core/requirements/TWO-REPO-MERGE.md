# 两仓合并（TWO-REPO-MERGE）· 统一面 · 需求

> 板块 = **两仓合并**（CLI 与 VSC 两产品收入单一 git 仓、各占子目录——跨仓机制全线退役）。
> **架构级机制档**——功能性需求以机制约束规格句表述（承文档规范：架构级机制档可以机制目标与约束替代逐条用户故事）。
> **配对设计档 = `docs/core/design/TWO-REPO-MERGE.md`（统一面）**。

## 1. 总体需求

ThinCoder 曾以**两个独立 git 仓**分头维护：CLI 仓与 VSC 扩展仓。

两产品在**概念层**镜像同一套机制（会话、上下文压缩、工具系统、评审收敛、工程模式……），却在**实现层**各自持有一份。

为了让两份实现不漂移，工程体系被迫长出一整套**跨仓机制**：跨仓引用形态判据、对端仓根发现、缺仓 / 域外口径、自指 fail-closed 防护、
端差登记、各仓自持纪律、每仓一轮的评审与实施节奏、提示词双副本。这些机制不产出任何产品价值，却对每一轮改动持续征税。

**本板块目标**：两产品收入**一个 git 仓**、各占一个子目录，使「他仓」这个范畴从根上消失——跨仓机制不是被「改好」，
而是**失去存在前提**，整线退役。这是**机制面**的收益，非代码面；结构搬迁，不是重写。

## 2. 功能性需求（phase 1 交付行为）

| 编号 | 规格句 | 范围边界（明确不做） |
|---|---|---|
| **F1** | 合并仓为**单一 git 仓**，CLI 与 VSC 两产品分居**顶层两个子目录**，子目录名沿用现有仓名 | 不做两产品文件级混合；不合并 `src/**` 实现 |
| **F2** | 两产品**独立构建、独立发布**——npm 包走 npm 链、vsix 走 Marketplace / Open VSX 链，互不触发 | 不做统一发布脚本；不改包名 / 版本号策略 |
| **F3** | VSC 仓的 **git 提交历史并入**合并仓，历史可追溯 | 不追平提交粒度；不重写 CLI 历史 |
| **F4** | 跨仓机制**全线退役**：对端发现 / 跨仓形态判据 / 域外口径 / 自指防护 / 端差登记 / 每仓一轮 / 禁跨仓 import / 提示词**跨仓机制层**（对端发现 / 自指防护 / 跨仓逐字断言） | **不是「改好」而是删除**——失去适用对象的判据一律删，不保留空转。**注记**：本行「提示词双副本」**整条退役**——提示词 = 单副本 `thincoder-core/prompts/`（承 2026-10-18 取消镜像裁定）；产品 `src/prompts/` 与两产品产品树下的提示词档目录均已退役 / 归档 |
| **F5** | 文档、机检脚本、台账、提示词**单仓化**：不再有「本仓 / 他仓」键，扫描域为合并仓全域 | 不改文档三层结构；不改台账状态机；不改板块划分。**收窄注记**：「不再有『本仓 / 他仓』键」分两层兑付——**判据 / 机检**即期（跨仓判据删除；全域扫描由 CI 全域调用承载）；**存量注记面**按设计档 D10 **停新增 · 留痕档冻结 · 现行档随触碰改写**——全量清零不属本批 |
| **F6** | 旧 VSC 仓**归档不删除**——保留只读可达，Marketplace 元数据 `repository` 仍指向它 | 不清空远端；不删 tag |
| **F7** | **产品运行行为零改动**——本次为结构搬迁，非功能变更 | 不碰运行逻辑；不改配置格式；不改 CLI 命令面 |

## 3. 非功能性需求

| 编号 | 标准 | 判据 |
|---|---|---|
| **N1** | **零行为回归** | 两产品各自集成测试集合并后全绿；共享用户级运行期状态（用户级配置 · 检查点目录（按 cwd 哈希分桶）· 日志目录）行为不变——**不涉迁移、无需验证**（cwd 键旁注见下） |
| **N2** | **历史可追溯** | VSC 侧并入的提交逐个可达；跨目录搬迁的 `blame` 不掉线（必要时用合并感知写法——设计档给命令形态） |
| **N3** | **迁移可验证** | 迁移前后文件清单逐条对账（数量 + 内容哈希）；两仓各自的机检不退化 |
| **N4** | **可回滚** | 每一步有回滚点：搬迁前后各留快照，任一步可退回，不产生不可逆数据损失 |
| **N5** | **发布链不断** | 合并当日两产品的发布路径均可照常完成 |
| **N6** | **本板块两档自身可机检** | 需求档 + 设计档纳入扫描域后不引文档机检红——不制造文档格式债 |

> **N1 旁注（cwd 键本地状态）**：合并后 CLI 产品目录变深一层（`<ws>/thincoder/thincoder-cli`）——以 cwd 为键的本机状态（检查点 / 日志）在该目录下**重新开账**；**产品运行行为不受影响**，此项**不属产品行为回归**。

## 4. 范围边界与既有需求的关系

- 与 **「各仓自持」**（需求层条款：文档体系各仓自持 / 需求层必须在本仓有档）的关系 = **同一病根的两种解法**：隔离（各记各的）→ 消灭（根本无仓可分）。
  本板块落地后，「各仓自持」条款失去对象，随之退役；二者**非叠加关系**。
- 与 **「跨仓内容纪律」** 无冲突：内容纪律（正文可指他仓、条目与归属不带跨仓指针）在本板块落地后**自然收窄**为仓内规范，条款本体留存。
- **条款住址**：两族条款住 CLI 产品树需求档 `thincoder-cli/docs/_archive/requirements/ENGINEERING-MODE.md`（CLI 侧**未迁**）与 VSC 侧同名档（未迁）——**先例不构成例外依据**为其中一条。
- **不属本板块**：phase 2（核心统一）——演进通道 = `docs/core/design/CORE-UNIFICATION.md`（设计）/ `docs/core/requirements/CORE-UNIFICATION.md`（需求）。
