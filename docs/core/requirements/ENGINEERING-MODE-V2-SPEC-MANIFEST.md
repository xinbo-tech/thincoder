# Function Spec · M1 项目状态档 manifest

> 模块划分权威源 = `docs/core/design/ENGINEERING-MODE-V2.md` §2.2（M1）

## ① 模块目标

为工程模式提供**项目状态账**——一个纯机器状态的 JSON 声明档，被开发项目用它申明「我是什么阶段、文档放哪、机检怎么判」。

一次声明，多处读取：文档体系落点（`docRoot`）、代码路径段（`codePaths`）、索引面（`index`）、情境旋钮（`phase`）全部从这一处取，机制不硬编码任何本仓路径。

## ② 功能点

1. **schema 定义**（**五键**）：`version` · `phase` · `docRoot` · `codePaths` · `index`——每一键都描述**这个项目自身**；产品内部事（提示词落地路径 / 机检配置 / 评审者配置）不挂在用户项目上。
2. **读 / 写 / 校验器**（`thincoder-core/manifest.mjs`）——机制代码在核，操作对象 = 被开发项目**项目根**（git 仓根 **或** 带档目录——**git 非前提**）的 `PROJECT-MANIFEST.json`（数据档）。
   - **项目根解析 = 按用点解析**：**会话不绑定项目**——任何需要项目参数的动作（机检域 / 文档落点 / 台账归属 / 批次归属 / phase 情境）取**目标路径所属项目**的档（**归属 = 最近祖先** ✗ 嵌套时子优于根——见 §⑥）；多项目并存 = 正常态。
   - **发现规则**（纯向下不向上 ✗ 一层不递归 ✗ **git 非前提**；**梯 ①–④ 只认「已存在」信号——全新目录（无 git 无档）必走 ⑤**）：
     ① **锚自身带档 ⇒ 锚是项目**（manifest = 项目标记 ✗ 与 git 解耦——已初始化的非 git 项目同认）；
     ② 锚自身含 `.git`（未带档）⇒ 锚是仓根（缺档 ⇒ 建档机会）；
     ③ 否则看**直接子目录一层**：**带档目录优先**（恰一 ⇒ 命中；≥2 ⇒ 列候选不猜）；
     ④ 零个带档时才看含 `.git` 的裸仓（恰一 ⇒ 命中项（缺档 ⇒ 建档机会）；≥2 ⇒ 列候选不猜）；
     ⑤ 均无 ⇒ 无项目 ⇒ **走建档流**（按用点协助在**会话锚（cwd）**建 manifest ✗ 默认落点 = 锚 ✗ 可显式指定 ✗ 轻动作 ⇒ 当场成为项目 ✗ 不砖死）。
3. **缺档处置（按用点）**（**会话权威值**口径——槽优先 + config 回退；普通会话＝**装配钩子零 manifest I/O**）：
   - 需要项目参数的动作发现**目标项目缺档** → 该动作报明并走**协助建档**：**项目落地 = 建 manifest（轻动作）** ✗ 落点 = 会话锚（cwd）（可显式指定）✗ 仓内缺档现状静默建档保持。
   - **`git init` = 可选增强**（用户要版本管理时提供 ✗ 经确认）✗ **非工程模式入场券**。
   - **任何情况不砖死**——会话照常起 ✗ 按动作报明 ✗ 不整会话死。
4. **缺键 fallback**：manifest 存在但缺某键 → 用默认值（便利 fallback，不拒绝）。
5. **写门**：唯一作者 = 主 agent（非主 agent 写 → 拒）。
6. **`docRoot` 值形态（多根数组 + `null`）**：值可以是非空字符串、非空数组，或 `null`。`null` 表示「本面没有」，是合法值；此时解析为空、键留着不被默认值顶回来。数组仍是完整声明，不与默认合并。空字符串、空数组、混合数组仍然拒绝，不静默通过。多根数组与 `null` 均为合法值。
7. **agent 工具面**：主 agent 对 manifest 的**全键读写**出口。现状 = 机制代码在场但无出口——装配侧内部调用之外，agent 侧唯一写点 = 工程模式翻转对缺档锚建默认档。五项：
   - **读**：现档 + 校验态（`ok` / `missingKeys` / `unknownKeys` / `errors` / 缺档报明）——`readManifest` 语义；
   - **建**：缺档 ⇒ 建默认档（`initManifest`；默认档 = `DEFAULT_MANIFEST`）；
   - **写**：**五键逐节点**可改——`version` / `phase` / `docRoot.*`（五子键）/ `codePaths` / `index.*`（四子键）/ 另含台账指针面；落盘前经 `validateManifest`（非法 ⇒ 拒 + 盘零变，fail-closed 照旧）；已退役三键（`promptsLanding` / `checkConfig` / `advisor`）写入时静默剥离，读面不报、不上界面；
   - **目标面**：显式目标目录参数（缺省 = 会话锚 / 按用点解析语义——歧义不猜、多候选列报）；
   - **权限面**：写面（`init` / `write`）只挂**主 agent**（沿写门不变）；读面（`read`）子代理另有**只读变体**（同名工具、`action` 枚举只剩 `read`，写动作 schema 级不可达 + execute 入口再拒一次）。子代理写面两道防线不动（写动作不在其装配 + `files` 域拒）。

## ③ 边界（不做什么）

- 不做台账（M2）；不做机检（M8）；不做批次档写入（M3）。
- 不替被开发项目创建目录；不做交互式初始化问答（初始化流程归两端壳面，本模块只提供读写校验）。
- 不承载「待裁 / 决策」类内容（manifest 是纯机器状态，决策进文档）。
- **agent 工具面**：单目标逐次调用——不做批量自动发现；不做 CLI 子命令（人面另议）；不替代既有装配侧调用点（翻转 ∥ 情境行 ∥ 钩子照旧零动）。

- **上游**：无（基础模块）。

## ⑥ 解析模型与作用定位（按用点解析）

**作用三身份**：① **项目状态账**（`phase` 存档 ⇒ 情境行注入）；② **声明面**（`docRoot` / `index`——一次声明多处读取，机制不硬编码本仓路径）；
③ **项目标记与管理单元凭证**（**每个项目（= 带 manifest 的目录）一份** ⇒ 在场 = 该项目已纳入工程模式管理（**项目侧管理声明** = 模式 ON 准入判据的**输入**）——✗ **不是模式状态载体**（模式状态 = **会话级**，住会话槽——见 `docs/core/design/SESSION.md`）；✗ git 非前提——非 git 目录同样可是项目）。

**它不是什么**：✗ 决策记录（决策进文档 ✗ 待裁进台账）；✗ 任务台账（现**五键**）；✗ 用户 / 工具偏好（模型、凭据、**工程模式开关**住 `config.json` + 会话槽——不在档里）。

**解析模型（核心）**：**会话不绑定项目** ✗ 无「启动选定 / 记住一个项目」✗ 参数**按用点解析**——动作作用于哪个项目的路径，就取那个项目的档（多项目并存 = 正常态 ✗ 工作目录下多仓 = 正常操作）。

**归属形（嵌套/重叠时以谁为准）**：目标路径 ⇒ 自其自身（文件则其所在目录）沿**祖先链**上溯，取**最近**带档目录——**上溯以会话锚为界，越界即停**（界外不挂项目；起点本身在锚外 ⇒ 无项目）。**上溯 = 子目录归到自己的项目根**（正常通路：`thincoder-core` 归 `thincoder`）；**发现梯纯向下**（只看直接子目录一层）——两者分离，容器锚不会被挂到外层项目上。**发现不参与取根**：容器锚下带档子目录再多再少，本动作的项目根仍是 `null`（报明），不择子目录。嵌套合法：子项目自身带档 ⇒ 各自其主。祖链无档 ⇒ 无项目（⇒ 按用点报明 / 建档流）。

**发现规则**：纯向下不向上（向上由 git 自身语义兜底）✗ 一层不递归（更深的项目以其自身为锚进入）✗ **git 非前提**（锚自我带档 ⇒ 锚 ✗ manifest = 项目标记）✗ 子仓判据带优先级（带档优先 ⇒「恰一命中」语义零回归）✗ 多候选 = 列候选不猜。

**建档规则**：**每个项目（= 带 manifest 的目录）一份** ✓ 多项目各建各的（允许并存 ✗ 含非 git 目录）✗ 建档 = 显式 / 用到时动作（✗ 不静默批量 ✗ 不预建）✗ **`git init` = 可选增强**（经确认提供 ✗ 非入场券）。

**不砖死（不变量）**：任何目录会话可起（含无项目目录）；需要项目参数而当前无项目的 ⇒ **该动作报明**（✗ 不整会话死）。

**两端同形**：CLI / VSC 同一套解析与发现（端差默认 = 消）。
