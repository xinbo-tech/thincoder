## 1. 总体定位

提示词系统 = **运行期面**（槽位提示词 `src/prompts/*.md` 15 档 + 工具描述 `src/tools/*.md` 25 档 + 槽位加载面）**+** **中文设计档**（两产品 `docs/design/prompts/**`，供人读、**非运行期**）。

本板块对本子系统的要求 = 提示词**并入核、核内唯一副本**，两端从核加载。

### 4.4 提示词编写纪律（旧 §2.7——15 条：A 内容性 / B 表达性 / C 工程纪律）

**A. 内容性纪律（写什么 / 放哪）**

1. **层归属先行**：每句内容先过 §4.6 判定法定槽位——放错层的句子一律不写；同槽不重复、同槽复用。
2. **单一权威源**：同一规则只在一处详述——其他位置至多一行指针（"per discipline-xxx"），不复制正文。
3. **人格不越层**：人格层只写身份 / 边界 / 交付物；流程和规则绝不混入人格层；反之纪律层不重宣言身份。
4. **双端语义同源**：双语端文件按多实现面纪律——各端原文自持、互不追赶、端特有段原地保留、差异如实上报。

**B. 表达性纪律（怎么写——继承注意力优化原则）**

5. **优先级排序**：最高优先规则（听用户的闸 / 批准门 / 叫停）放文件最前部。
6. **规则独立成短句 + 加粗关键词**：关键指令一行一条，加粗触发词；标题独占一行。
7. **命令句 + 否定强调**：闸用祈使 / 禁止句——命令句注意力权重更高。
8. **关键规则放首 / 尾**（serial position）。
9. **减量提权**：长文机制细节从正文移走 / 指向文档；Markdown 表行不可换行，表行 >200 转 `- **State** → action` 条目对（词序保原）。
10. **关键锚点多处重复**（不同措辞）；**视觉锚**：`>` 块引用 / 加粗 / 独立行。

**C. 工程纪律（怎么改）**

11. **可判可测**：规则句写成可判定断言——"尽量 / 适当 / 合理"类模糊词须给判定锚；真正自由裁量处显式声明裁量。
12. **句式稳定**（原「锚稳定」——2026-09-12 改述；断言联动已随散文锚退役批废除，`docs/core/design/TESTING.md` §5）：关键句保持**句式稳定、不随手润色**；核心纪律句族与行内引用**整块保行、逐字整句不拆**。**不落测试断言**（散文锚一律不做）。
13. **变更走批**：提示词内容变更 = 设计批评审 + 批准，不走「顺手改」；**变更流程界定（用户裁定 2026-09-10）**：提示词文件**仍是产品代码**（FR1 口径不变）——**内容权 = 主 agent**（逐字文本由它定，它就是设计的一部分）；**落笔走正常链**（设计评审 → 用户批准 → eng-coder）。「不经设计流程」指**不经 eng-designer 的需求 / 设计档流程**（提示词是产品方针，非设计方案）——**不**指绕过门禁。装配代码（`thincoder-core/prompt-overlays.mjs` 等）= 代码，工程模式实现链不变。
14. **语义与格式永不混批**：重排批「零语义改动——只断行 / 换行 / 换位 / 提权——不改任何一个字」铁律沿用；内联引用不切（token 模板 / 按钮文案 / 确认语整块保行）。
15. **提示词不含维护者注**（用户裁定 2026-09-10）：出处 / 日期 / 批次名 / 评审号 / 施工进度 / 变更史一律**进设计档不进提示词**。例外：日期本身携带行为语义的（如语义生效边界）保语义去日期注。本纪律与 #2 单一权威源互为表里。

### 4.5 装配逻辑（旧 §3）

**四槽位固定序（主装配链——主会话 + 常规子代理）**：`[1] 人格层 → [2] 公共层 → [3] 纪律层 → [4] 其他`。

- 每槽至多一份文件；未命中角色 / 模式的槽位跳过；**人格先行**；**公共恒二**；**同槽位不重复**（同一层禁止两份文本并存）；**同槽位复用**（同层多场景语义一致时共用同一份文件）。

### 4.6 内容归属判定规则（旧 §4——新增 / 修改提示词内容的分层判定法）

1. 「模式 / 角色里你是谁、交付什么、边界在哪」→ 人格层；
2. 「两模式逐句都要的协作基础」→ 公共层；
3. 「该模式下怎么干活（流程 / 规则 / 工具观）」→ 纪律层；
4. 仅项目相关 → 项目层（cwd）；冲突判定：人格层 > 公共层（人格定义边界，公共层不得越界）。

**关键区分（2026-09-10 盘点沉淀）**：**公共层 = 两模式 + 全角色逐句需要**——不是「多处出现」（反例：子代理共性 C3 重复 5 处但仍留人格层）；**人格层 = 角色独特形态**（如 C8 各角色收到的提醒字段不同——归人格层各写各的）；**特殊域（consult / advisor）= 自包含注入**——不注入公共层，其内部重复不受公共层迁移影响（受控双源在案形态）。
