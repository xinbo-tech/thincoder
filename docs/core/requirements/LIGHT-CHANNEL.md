## 1. 模块目标

让工程模式下的**细节调整**（细节面 ∥ 收敛面——扩容见 §2.1b）保持分钟级体验（免走设计 → 评审 → 批准全链），同时以「定版收口」兜住文档与测试（防"快捷"变"脱缰"）——**内建为机制**，不靠每会话临场裁定。

## 2. 功能性需求

### 2.1 F-LC1 路由判据（逐笔 · fail-closed）

**五问，任一不过 ⇒ 全链（设计 → 评审 → 批准 → 实施）；全过 ⇒ 轻通道候选。**

1. **触面问**：改动落在细节面吗？细节面（闭合枚举）= 视觉 ∥ 文案 ∥ 参数（阈值 ∥ 默认值 ∥ 长度）∥ 既有交互细部（顺序 ∥ 位置 ∥ 键位 ∥ 提示语）；枚举扩面 = 新需求。
2. **行为问**：不产生新行为路径吗？（新分支 ∥ 新状态 ∥ 新流程 ∥ 新机制 ⇒ 出局。）
3. **契约问**：不碰接口 ∥ 通道协议 ∥ 数据结构 ∥ 持久化 ∥ 跨端对位语义 ∥ 安全面吗？
4. **体量问**：射程小吗？（单面内 ∥ 无连带；量级阈值设计定形，超 ⇒ 出局。）
5. **拿不准 ⇒ 全链**（宁可重，不可偷渡）。

**判定句**：抽查任一笔，路由结论可由五问逐条复核（判定依据可回放）；「触界内容走轻通道」的记录 = 0 例。
**边界**：判据由主 agent 逐笔判定并**随交底公开**（F-LC2）；用户可当场复核。

### 2.1b F-LC1b 收敛面准入（扩容 · 2026-10-02）

**两类准入**：A 类 = 新增面（五问，§2.1 原判据，**不动摇**）；B 类 = **收敛面**——目标行为**已有出处**（需求 ∥ 设计 ∥ 记录 ∥ 用户当场的话），工作 = **让实现与之相符**（非新增语义）。B 类逐条如下（用户 15:39 扩容令：可明确识别的需快速反馈类，如 debug）：

1. **缺陷修复**（debug）——准入五条，全过才走：㈠ **目标行为有出处**且现实现与之相抵（「说好的 vs 实际」可指认）；㈡ **手段不新增**（不碰接口 ∥ **通道协议** ∥ 数据结构 ∥ 持久化 ∥ 跨端语义 ∥ 安全面——六件与 §2.1 A-③ 对齐）；
 ㈢ **先红后绿**（先复现、后修复验证——拿不出红绿两态 ⇒ 未定位到根因 ⇒ 全链）；㈣ **根因判读过闸**——根因 = 实现错误；**指向设计缺陷 ∥ 结构缺陷 ⇒ 停笔转全链**（铁律二面：错结构就地修 = 全链的活）；㈤ 射程 ≤15 档 · 单链 · 可 revert。
2. **诊断/探针 = 零链面**——定位 ∥ 复现 ∥ 置探针 ∥ 读数据（只读 + `.thincoder/tmp/` 面，产品面零改）免归类犹豫；一经产品面改动 ⇒ 回本表逐条判。
3. **走查修复循环（明示轻通道 · 用户 2026-10-02 16:48 裁）**——用户走查当场点名的问题：**细节类（外观 ∥ 交互细部 ∥ 文案 ∥ 参数）明确走轻通道**（**默认直行——不再逐笔纠结归类**；交底即行照旧）；行为类 ⇒ 按本条 1 判（缺陷修复五条）；一触越界 ⇒ 停笔重交底（转全链）。
4. **性能/效率点修（观察类——先跑 1–2 笔再定正式准入）**——准入拟 = 无结构变更 ∧ 前后读数可证；否则「顺手优化」= 口子。

**动手面（用户 15:42 裁）**：B 类 = **主 agent 直改**（≤15 档单点——交底自带「可 revert」）；大修复照旧派舱（eng-coder）。**守线不动的**：新行为/新机制/新接口 ⇒ 五问 fail-closed 照旧；「试试 X」类新功能草图 ⇒ 全链；**「怎么修」有争议/多方案待选 ⇒ 设计问题 ⇒ 全链**；铁律边界（结构/跨面/契约）一触即转全链（转 = 停笔重交底，无痛）。

### 2.2 F-LC2 路由前置知情（用户怎么知道走哪条）

- **每笔开工前一句话交底**（固定格式）：
  - 轻通道笔：「**本笔 = 轻通道**（细节面 ∥ 收敛面·缺陷修复 ∥ 收敛面·性能观察）｜改：\_\_｜射程：\_\_｜回退 = 可 revert」
  - 全链笔：「**本笔 = 全链**（触：\_\_）｜设计 → 评审 → 批准」
- 交底**带判据半句**（哪条判据过 ∥ 没过）——用户当场可复核；
- **用户一票改判**：轻通道 ⇄ 全链 双向可改（用户说了算）；
- **中途越界 ⇒ 停笔重交底**：干到一半发现超出边界 ⇒ 立刻停、报、重新归类——禁止在轻通道里偷渡边界外内容。

**判定句**：会话记录抽查——轻通道笔开工前必见交底句（含路由 ∥ 射程 ∥ 回退 ∥ 判据半句）；无一笔越界未报。

### 2.3 F-LC3 记录在档 + 收尾一次全链（核销前置）

- **记录在档**：每个轻通道轮次开一本**批档**（轻通道批档）——逐笔落档（交底 ∥ 改动 ∥ 走查 ∥ 定版——父侧笔）；台账行逐笔照常。
- **启动即挂账（扩容 · 2026-10-02 · 用户 15:42 裁）**：轻通道轮次**启动即挂账**——开轮（首笔开工**之前**）立即：① 建轮次批档；② 建轮次台账行（携「收尾未落 ⇒ 不许核销」钩）。**账在前、笔在后——无账之笔 = 不成立**；确保收尾全链永不因遗忘而漏。
- **轮次界 = 收口（2026-10-02 入文）**：收口前的新笔 = 本轮续笔（同轮记录）；**收口后新笔另起新轮新档**（承批次档生命周期「条目集变更 ⇒ 另起新批」）。
- **收尾一次全链**（触发 = 用户说「收口」∥ **提醒时点：自然停顿 ∥ 话题转换 ∥ 收束信号——父侧提请义务；跨会话接手：新会话见未收口轮次 ⇒ 接手提请**）：全链跑一次——**设计**（已落改动形式化 + 文档一致化方案）→ **评审**（独立：落码 ∥ 记录 ∥ 文档对账）→ **修复**（若有）→ **批准** → **收口核销**（含必要测试）。
- **收尾全链未落 ⇒ 不许核销**（批档 ∥ 轮次台账行挂住——防「文档滞后永久化」）。
- 迭代速度不变——直改 ∥ 走查照旧分钟级，全链只在收尾一次。

**判定句**：任一轮次：存在完整「逐笔入档 → 收尾全链（含评审）→ 核销」记录；「收尾未落而核销」= 0 例；在途轮次的收口提请（提醒 ∥ 接手）可抽查；**续笔归属可抽查**（收口前新笔同轮 ∥ 收口后另起新轮新档）。

### 2.4 F-LC4 记账

- 轻通道轮次 = **批档一本**（记录在档）+ 台账行逐笔；全链笔 = 批档（常规链）——**批档机制复用，零新增机制**。
- 核销对接：轮次台账行随收尾全链通过后核销；逐笔行亦可随收口核销。

**判定句**：每轮次有批档且逐笔可回看；核销面可追溯到批档。

## 3. 边界（明确不做）

- **不做**：边界外内容走通道 ∥ 免收口 ∥ 以本机制替代全链（机制自身 ∥ 大改仍全链）。
- **通道外清单**（触界即停、上抛、回全链）：新机制 ∥ 新流程 ∥ 接口契约 ∥ 数据结构 ∥ 持久化 ∥ 跨端语义 ∥ 安全面 ∥ 体量超标。
