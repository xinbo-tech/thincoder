## 1. 总体定位

verify 是**语言无关、框架无关、项目无关**的通用编程 agent 收尾门禁。不内置任何语言 / 测试 / 模块逻辑，
不替模型执行验证，只做**机械门禁判定**——要求**模型声明验证状态**，据此放行 / 打回。通用工具不 hardcode 项目私有结构。

## 2. 功能性需求（用户故事）

| # | 用户故事 | 验收语义 |
|---|---|---|
| **F1** | 作为 coding agent，我希望 verify 接受我的验证状态声明（是否已跑 + 结果），以便它对任何项目通用、不锁语言 | 声明 `passed` → 放行；`failed` → 打回 |
| **F2** | 作为 coding agent，我希望声明「跳过验证」时能放行（须给理由） | `skipped` + 理由 → 放行；`skipped` 无理由 / 无声明 / 非法声明 → 打回 |
| **F3** | 作为 coding agent，我希望被 verify 打回时知道这类改动该怎么做验证 | 打回消息列出变更文件，并指向项目 `AGENTS.md`（自然语言描述），由模型自决补什么验证 |
| **F4** | 作为使用者，我希望纯文档改动不被无谓拦截 | doc-only 快路径：变更全为文档 → 直接放行（显式 `failed` 声明仍被尊重） |
| **F5** | 作为使用者，我希望收尾检查信息可见但不越权 | 变更文件报告、任务清单 / 自审清单、编辑器诊断（VS Code）作为**提示**呈现——从不作为门禁 |

## 3. 非功能性需求

| # | 维度 | 标准 |
|---|---|---|
| **N1** | 零语言假设 | 无强制语言特定执行；可选语法提示仅在改动为 JS/MJS 且 node 存在时作软提示——不进门禁、不阻断 |
| **N2** | 不执行验证 | 验证命令由模型（读 `AGENTS.md` 自然语言后）自行执行——verify 只验收状态声明 |
| **N3** | 机械检查保留 | doc-only 快路径、任务 / 清单报告仍做（通用收尾）；结果只作提示 |
| **N4** | 可测试 | 五态声明分支 + 快路径 + 软提示由用例断言；登记入测试清单 |

## 4. 范围边界（不做）

- 不内置语言 / 框架 / 项目私有逻辑（N1——通用工具不 hardcode 项目私有结构）。
- 不替模型执行验证（N2——verify 只验收状态声明）。
- 提示面（诊断 / 清单）不作门禁（F5）。
