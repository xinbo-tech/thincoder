# 文档体系（DOC-SYSTEM）· 需求

> 板块 = **文档体系**——`docs/` 的**落点规划（core / CLI / VSC 三部分）** · 命名规则 · 归属判据 · 交叉引用形态 · 机检面的引擎 / 路由表切分。
> 设计档 = `docs/core/design/DOC-SYSTEM.md`（方案选型 / 接口契约 / 受影响文件 / 关键决策 / 验收回指 / 用例表 / 边界）。
> 建档：2026-09-14（**用户 2026-09-14 直接指名的设计任务**——「你现在这个需求和设计的目录显然也还没有为 core/cli/vscode 三部分做好规划，将来一开始整文档，肯定是一锅粥。」）。
> **本批只做规划，不执行迁移**：不改两产品树里任一档的物理位置、不改机检脚本、不改提示词文件、不写产品树。
> **判据权威分层（D2 单一权威源）**：工作流机制（批次档六段 / 需求池状态机 / 台账条目形态 / 文档自持边界）= `ENGINEERING-MODE`；
> 锚判据全文 = `ENGINEERING-MODE` §2.32.3（CLI 锚）· `DOC-CODE-RECONCILE` §4（VSC 锚）——本板块只给**切分与修法**，不重述判据全文。
> **本档只收本仓事项**（各仓记各仓：本板块的规划对象 = 本仓 `docs/` 与两产品树的产品级文档）。

## 1. 总体需求

**为谁解决什么问题**：为 thinCoder 合并仓建立 **core / CLI / VSC 三部分**的文档落点秩序。
合并仓已含一核两壳（`thincoder-core/` · `thincoder-cli/` · `thincoder-vscode/`），而 `docs/` 下的需求 / 设计目录
仍是一条**不分部分的平铺清单**（根层 16 + 16 板块档，无部分轴）；两产品树里另压着大量未迁的旧档。
不先定落点，则「开始整文档」时必然出现四类失控：**同名不同物** · **归属争议** · **跨部分引用不可解析** · **机检域拍不准**。

**范围边界（明确不做）**：本批零搬迁（两产品树任一档的路径不变）；零代码（机检脚本不改）；零提示词改动；零 commit。

## 2. 功能性需求（FR1–FR8）

| # | 需求（用户故事） | 验收面（可机判 / 可逐条核） |
|---|---|---|
| **FR1** | 作为**文档维护者**，我想要 `docs/` 下 core / CLI / VSC 三部分各有明确的需求 / 设计落点（含跨部分共享面），以便新档一落就有位置、不必现场争论 | 完整目录树 + 现有 16+16 板块档与提示词正本的**去向** |
| **FR2** | 作为**文档维护者**，我想要一套**可机判的命名规则**，以便「同名不同物」不再出现（已实证发生） | 命名规则 + 方案对比（≥2 候选 · 含否决理由） |
| **FR3** | 作为**文档维护者**，我想要**可判定的归属判据句**，以便任一新档 / 旧档一眼归类 | 判据句 + 现有产品树文档的**初分类** |
| **FR4** | 作为**文档维护者**，我想要跨部分引用的**统一形态**且机检**能解析**它，以便引用不靠人工记忆 | 引用形态规范 + 机检判据（现按域根解析，跨部分引用会判红） |
| **FR5** | 作为**项目负责人**，我想要本规划与既有四条裁定（基准层 / 参照历史 / 提示词正本 / 逐档随批迁）逐条自洽，以便不产生两套矛盾口径 | 四条逐条自洽说明（有冲突即指出并给修法） |
| **FR6** | 作为**产品维护者**，我想要机检的「**普适引擎**（该进产品）」与「**本仓路由表**（该可声明）」切开，并给射程修法，以便换一个项目时这套检查开箱可用 | 逐族切分（含行数估算）+ 射程修法（外部参照面域声明） |
| **FR7** | 作为**文档维护者**，我想要两处**悬空文档锚**被收正（`docs/core/design/CORE-UNIFICATION.md` 两行），以便根域机检回到悬空 0 | 实修 + 三机检读数（域一悬空 0） |
| **FR8** | 作为**主 agent**，我想要**台账两池判据**的落点与文本（需求池 / 技术待办），以便新条目不再靠临场判断 | 落点与文本（台账头部文本 + 提示词层落点）——**本批只出文本，不代写台账** |

## 3. 非功能性需求（N1–N4）

| # | 标准 | 度量方式 |
|---|---|---|
| **N1** | **可机判**：命名规则 / 归属判据 / 引用形态三条都必须是**判据句**（可写进机检谓词），不是「注意一下」类表述 | 逐条给出判据句 + 机检落点（脚本 / 判据节） |
| **N2** | **零假阳优先**：任何新增判据不得制造「红一片」——判据不精确即等于没有（承 DOC-CODE-RECONCILE §4.7 判据） | 外部参照面等新判据须给出**零报样例** |
| **N3** | **格式合规**：本板块新增 / 改动的档必须过仓根三机检（`doc-anchors` · `check-doc-width` · `check-ledger`）exit 0，零悬空锚 | 三机检原样读数随批次档 §2 落档 |
| **N4** | **可回退**：本批落笔只含文档（设计 / 需求 / 地图指针 / 批次档），**零代码零迁移** ⇒ 全部改动为可 `git revert` 的纯文本 | `git status` 自证改动集 |
