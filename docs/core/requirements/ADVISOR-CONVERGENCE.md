## 1. 总体定位

独立评审必须在「审查 → 修复 → 复审」循环中**收敛**：要么确认全部问题已修复（passed），要么在**有限轮次内机械终止**。

> 历史病根（需求的来源）：advisor 反复执行、每轮全量扫描都报新问题、永不收敛（收敛约束只存在于 user 级消息、system 权重压过 user）；以及复评引用旧文件状态、把已修复问题反复报回。

## 2. 功能性需求（F1–F17）

### 2.1 收敛本体（旧 §2）

| # | 需求 | 说明 |
|---|---|---|
| F1 | 轮次衰减 | system prompt 按轮次替换——ROUND1 全量、ROUND2 验 prior 为主、ROUND3+ **严格只验 prior** |
| F2 | 机械 cap | **仅代码评审**：第 6 次启动**机械终止、不消耗 LLM**（该实例轮次 ≥ 5 直接返回终止消息） |
| F3 | design 评审豁免 | design 评审不消耗该预算（cap 豁免——轮次继续递增，豁免的只是「第 6 次拒绝」这一轴） |

| F10 | 既成实践追溯 | 规则生效前的并行实践按**新老划断**留痕：不回填冻结批次档；追溯说明落当时设计档变更记录 | 不改写任何已冻结批次档正文 |

### 2.3 评审 / 凭证链边缘守卫（旧 §7）

> 归属边界：本节只承载评审**链的守卫与可观测性**；评审的语义判据（什么算 pass / changes-required）、凭证机制本体（槽 / TTL / 门禁 / consume）、提示词面均不属本节。

| # | 需求 | 说明 | 范围边界（不做） |
|---|---|---|---|
| F11 | 未完成即不签发 | 评审以宿主截断尾收尾时，无论评审文本是否回显 token，**设计凭证一律不签发**；报告携带「评审未完成——token 未签发」提示 + 原因 + 恢复指引，且报告内零未注册 token 字面 | 不改 pass / changes-required 语义判据；不改凭证槽 / TTL / 门禁 / consume 机制 |
| F12 | 凭证信号必达 | 设计评审请求内**必须**携带与本次签发 token 精确对应的 `## Approval Signal`：构建面缺则补齐；启动面补不上则**拒绝启动**并可见报错——不得发出「请回显一个不存在的 token」的请求 | 不改评审侧提示词；无 token 的设计评审（直接调用方）语义 = 拒绝启动，不静默放行 |
| F13 | 信号全程在位 | 评审上下文压缩（宿主 local compaction）后，本次评审的机械锚——评审对象声明 / 文档清单 / Approval Signal——**必须仍在**上下文中 | 不承诺重内容（项目指南 / 方法论 / 文档地图）压缩后仍在；不改压缩触发阈值 |
| F14 | 引用解析按声明范围补全 | `[host-verified]` 引文校验的路径解析候选 = cwd + 评审对象声明范围派生根（声明文件所在目录 / 声明仓根）；「文件存在 ∧ 目标行含引文内容 ∧ 围栏内」三条件全中才算命中 | 不改引文抽取正则与路径围栏；不改「不匹配不能支撑打回」语义；不引入 basename 全局扫描 / 模糊匹配 |
| F15 | 超时 / 预算守卫 | 评审墙钟预算 = **硬墙**（单次模型请求同受其约束）+ 预算见底前**一次性机械提示**促其收敛产出 + 超时收尾报告携带机读统计（预算 / 轮次 / 工具数 / 是否已产出文本）与可执行恢复指引 | 不改 `agent.advisor.timeoutMs` 语义（仍 = 整场预算，默认 600s）；不自动重跑 / 不自动拆范围；不改评审提示词语义 |
| F16 | 同族一致性 | 以宿主截断尾收尾的**代码**评审不得再被计为「评审已覆盖」（完成守卫的失败判定与 design 面共用同一谓词） | 不改完成守卫公式本体；不改 cap 语义 |
| F17 | 冻结窗口边界（在途下界） | 评审「在途」的下界落机制权威面：窗口 = **点火（启动受理）→ 结算**（陈旧判定读取时刻）；父侧可观察下界 = **报告送达或取消 · 中止**——「子进程退出 ≠ 安全」为显式反例。窗口内被审文件集（含批次档）父侧**零写入**；机制面**拦截**设计评审在途写（可见拒绝 + 逃生门 = 先 cancel、改动集齐后重发） | 不改 `reviewIsStale` / 记账 / 结算本体；不拦**代码评审**（stale / guard 重推保留）；bash / file_ops 不覆盖（登记）；批次档不豁免 |

## 5. 待设计需求（旧 §5——2026-09-10 用户裁定：问题成立，待设计）

### 5.1 评审注入的路径不得硬编码项目约定

**问题（实证）**：`thincoder-core/advisor/messages.mjs` 向 advisor 注入项目上下文时硬编码了路径约定：

| 注入面 | 硬编码 | 位置（来源档坐标，仅供定位） |
|---|---|---|
| 文档地图 | `docs/README.md`（新）+ `docs/design/README.md`（旧 fallback） | `:245-254` |
| 项目方法论 | 项目根 `METHODOLOGY.md` | `:236`、`:349` |

根路径取 `guideRoot ?? agent.cwd`（= `injectProjectGuide` 从评审范围反查的项目根）——即**被评审项目**，不是 ThinCoder 自身（此点无错）。

**错在哪**：ThinCoder 是通用 coding agent——用户项目的文档布局不由我们定。布局不同（`doc/`、`documentation/`、根级单文件…）时探不到会**静默跳过**——「Document ownership」评审维度与方法论基准**无声消失**，用户不可见、不可修。等于把自家仓库的布局烧进产品。

**待设计方向（不预设结果）**：① 配置项（`advisor.*` 指定地图 / 方法论路径）；② 由**项目自述**声明（AGENTS.md 声明指针行——项目层本就是项目自己的口）；③ 保留约定探测作便利 fallback（当前候选列表）。可组合。

**验收方向**：项目可用非默认布局启用这两个评审依据；未声明时**要么降级可见（写进评审报告）、要么可配**——不得静默丢维度。

## 6. 并入面：上下文预算与失败护栏（旧 §10 / §12）

### 6.1 评审上下文预算跟随模型窗口（旧 §10）

> 来源：用户报告评审实例死于 `Advisor: context window limit reached (120225 tokens)`；根因 = 评审循环的上下文上限是 128K 时代遗留的固定常量，而现行主力模型窗口为 1M。归属边界：本节只承载**评审循环上下文预算的派生**；评审语义判据 / 凭证机制 / 超时预算 / 压缩算法本体均不属本节。

**总体需求**：评审循环的上下文预算必须**由本次评审所用模型的实际窗口派生**：大窗口模型（1M）不得被小窗口时代的固定上限提前判死；预算的两档（压缩触发 / 判死线）均为窗口的**比例式**；未知模型回退保守默认规格。预算只是**宿主机自限线**——不替代服务端窗口约束，也不改变既有判定族语义。

| # | 需求（说明 + 判定句） | 范围边界（不做） |
|---|---|---|
| F27 | 预算派生（评审上下文——双端同源）：判死线 = `floor(模型窗口 × 0.8)`、压缩触发 = 判死线 × 0.8；窗口取 `providerSpec`（模型规格表 × provider 级 `context` 覆盖）。**判定句**：① 1M 窗口模型在 ~197K tokens 上下文下**不再**以 `context_limit` 收尾；② 128K / 未知模型在同量上下文下仍以截断尾收尾；③ provider 级 `context` 覆盖**双向**改变判定结果 | 不改压缩算法本体（本地裁剪 + 定锚重挂）、不改判定族与尾文案（逐字）、不改 `estimateTokens` 估算式；不新增 advisor 专用配置项（窗口覆盖沿用既有 `providers[].context`——单一真值源） |

**非功能**：N19 零回归 + 可机判（判定族 / 尾文案 / 提示词 / 既有比例关系语义零改；派生为**纯函数**（无 I/O、无状态）；每条验收可机判）。
**登记面**：`estimateTokens` 低保真估算（`chars/4` 扁平式——CJK 内容低估）——修正另批（登记）；大上下文带来的延迟与额度消耗属**模型选择后果**（登记；不另设闸）。

### 6.2 评审失败护栏：同一 doc-set 连续未完成即停（旧 §12）

> 来源：用户裁定「同一 doc-set 连续 N 次 incomplete 即停并出结论」。归属边界：本节只承载**设计评审的失败计数护栏**；cap 语义本体、判定族谓词与尾文案全部**零改**——护栏只新增一条「连续未产出可用结算即停」的失败轴。

**总体需求**：design 评审的 cap 豁免消除了「轮次上限」，但**机械失败**路径没有上界：宿主截断（判死）与陈旧（stale）结算都不签发凭证 → 门禁不解锁 → **必然重评** → 同一 doc-set 可无限重评、无出口。需求：**同一 doc-set 连续 N 次未产出可用结算 ⇒ 机械停止该 doc-set 的 design 评审发起，并产出结论**——停止可见、结论可执行；正常收敛路径（pass / changes-required）零影响。

| # | 需求（说明 + 判定句） | 范围边界（不做） |
|---|---|---|
| F28 | **连续未完成护栏（N = 3）**：同一 doc-set 的 design 评审**连续 3 次未产出可用结算** ⇒ 后续发起被拒（工具层预检 + 直调防线两级；**零 LLM 调用**、不耗轮次、不置「评审已覆盖」）。计数类 = 宿主截断尾五 kind + 陈旧结算 + 凭证落盘失败 + 无报告结算；可用判决落定 ⇒ 计数复位。判定句：① 连续 3 次未产出后第 4 次同集发起返回护栏结论串且零 chat 调用；② 1–2 次同形态仍正常发起；③ 任一可用判决落定后计数归零；④ 停止按 **doc-set 键**判定（次序无关、路径写法归一）；⑤ 计数载体 = **会话级内存**（不落盘、不进 session 文件）；停止在该会话内不可自解除 | 不改凭证签发 / 作废语义；不改 cap（design 豁免**保留**——两轴叠加，非替代）；不改评审语义判据 / 谓词 / 尾文案；不对代码评审生效；不做自动重跑 / 自动缩范围 |
| F29 | **停止产物 = 结论（表）**：护栏拒绝返回结论文本——稳定前缀 + 停止的 doc-set 清单 + 失败尝试表（逐次 kind + 人读说明）+ 三个选项（接受现状 / 改变或缩小范围后重跑 / 新会话重置）；全文**零凭证值**。判定句：结论串稳定前缀逐字；含尝试表（表头 + 每行 kind）；含三选项；凭证值扫描零命中 | 不改 cap 消息文案；不列未决问题（cap 面职责）；不自动执行任何恢复动作（发起权在父代理 / 用户） |
