## 1. 总体需求

一次代码改动的验证必须**按层收口**，避免“随便改一点就跑上千个测试”——浅改浅验、深改深验、链终一次全量。
验证成本的大头是重 IO 而非用例数量，因此分层按**耗时**而非目录切分。

测试体系同时按**寿命**组织：单元测试是开发期工具（为改对代码而写——用过即退役，批次收口逐条处置）；
集成测试是业务资产（业务设立 + 生产补入——常驻，承担发布门验收）。两类来源不重复覆盖（单元不属于验收面）。

## 3. 非功能性需求

| # | 维度 | 标准 |
|---|---|---|
| N1 | slow 标注（纯别名） | **作用域 = 单元档（`test/` 顶层 `*.test.mjs`）**：需真实 fs / git 子进程 / 定时器 / 网络的测试（单用例 >500ms）用 `slow(name, fn)` 包装——`slow` = **纯别名（全量跑，无 skip）**；集成档不在本门作用域（不得用 `slow()`——见 `design/TESTING.md` 集成集接口契约） |
| N2 | 零漂移 | 定向与全量共用同一套断言文件（不改名不挪目录）——同一断言两种执行面 |
| N3 | 标注纪律 | 单元档内单跑 >500ms 的用例须标 `slow()`（归册线 = N4） |
| N4 | 阈值口径（归册线） | 归册线 **500ms**（单跑实测） |
| N5 | 并发上限 6 | `--test-concurrency=6`（**勿再调高**——并发过高会让中位带通胀，打地鼠式误红） |
| N6 | 阈值实测依据 | >500ms 的测试约占全量 CPU 的 **95%**，而 <5ms 的过半测试合计仅 376ms——**数量不是成本，重 IO 才是** |
| N7 | ②集与需求同步演进 | 需求发展/行为变化必须触发集成集评估（主 agent——不外包不自动）；集成集不得落后于需求（判据 = 每批 §6 处置行 ②半 有记录） |
| N8 | 最小可跑起步 | 首批集成集 = 场景最小集（三态齐全）；扩面只走两个入口（业务设立 ② / 生产收编 ③）——不预防性铺量 |
| N9 | 自动可跑 | 集成集必须可自动执行（发布门内跑——不依赖真实付费端点、不依赖人工操作） |

**归册补登**：单元档内单跑 >500ms 的用例（真实装配）按 N1 标注 `slow()`——归册不是删除。
**判定句**：`npm test`（单入口）全绿。

## 4. 范围边界（不做）

- 不用目录分层做**执行层划分**（`test/**` 是唯一约定入口；同档门控让单文件调试与全量永远走同一断言）——集成集以 `test/integration/` 子目录分界属**生命周期**划分（①/②③），非执行层划分（见 F12）
- 不设独立测试角色（维护模型零新角色——职责随既有角色，见 §2.1）
- 集成集不调真实付费端点、不依赖人工操作（真端点 smoke 仍独立于所有层）
- 不维持存量测试库存（“按需加”）——本机制为“按需加”的产物补寿命与收口处置

## 5. 散文锚测试退役（PROSE-ANCHOR-RETIRE）

> 一句话：**读档断言「某句在场 / 缺席」的测试一律不做**——收益无实证（举不出该类锚抓到真实漂移的记录），成本可量化（改一字即红、失败信息零信息量、锚红后的动作永远是「把字改回去」）。
> 设计 + 逐条删除清单 = `design/TESTING.md`。
> 双端语义同源：本档 F15–F22 / N10–N12 与对端档同标识、语义同源、各端原文自持（不做 byte-identical）——对端条目自持于对端档，本档不代写对端规。

### 5.1 判据（三条同时成立 = 散文锚）

| # | 条件 |
|---|---|
| ① | 断言对象是**非测试档**文本（`thincoder-core/**` · `thincoder-cli/src/**` · `docs/**` · `AGENTS.md` · `README*` · 仓根 `*.md` / `*.json` · `scripts/**` · `bin/**` · `webview/**` · `locales/**`〔资源文本保留——C1-d〕）或其派生切片 |
| ② | 断言其**文本内容**在场 / 缺席 / 出现次数 / 相对顺序（`.includes` · 常量子串 `assert.match` · `.startsWith` · `.endsWith` · `.indexOf` · 文本计数） |
| ③ | 断言对象**不是**结构机检保留面所判的属性（保留面 = F17 封闭枚举） |

**载体判据（判据 ① 的落地口径）**：断言对象是**执行产物**（函数 / 工具返回值、子进程输出、渲染帧、测试自建临时域文件）或**结构 / 数值常量** → 不命中 ①；经 `import` 取到的源码静态文案字面量 → 命中 ①。

**判据补充（判据 ① 的「实质」判法）**：

| # | 补充 | 内容 |
|---|---|---|
| C1-a | **提示词句子不豁免** | **不问文本从哪来**（读盘 / 装配器或渲染出口的返回值 / 写入 `systemPrompt` 的装配结果），只问**断言的是否是提示词句子**——断言提示词句子 → 命中 ①；**「不读文件」不是豁免理由** |
| C1-b | **工具契约面与工具返回文案保留** | **模型实际收到的工具契约对象**（`tool.description` / 参数说明）与**工具返回 / 拒绝文案** → 契约守卫 / 行为输出 → 不命中 ①；读源码档文本（含源码里的描述串）仍命中 ① |
| C1-c | **非句子对象保留** | 结构 / 数值 / 判定信号（槽文件表与集合成员、长度、警告清单与警告文案、旗位、退出码）→ 不命中 ① |
| C1-d | **locales 资源文本保留** | `locales/**` 文本值 = **产品资源文案**（界面 / 本地化面）→ **不命中 ①**（保留、不进清单）；读非测试档**源码 / 文档文本**仍命中 ① |

### 5.4 边界（不做）

- `scripts/doc-check.mjs` / `scripts/doc-check-width.mjs` / 文档锚 V1–V3 的**语义与判据零改**（保留面不动）；

### 6.2 方法学条目（改判后仍成立——任何 harness 适用）

> 口径：本节持有**验证面方法学**；**能力面**（真 TTY / 发输入 / 判输出 / 取退出码）住 `TOOLS.md` §4.7（D2 单一权威源——不重述）。

**改判后仍成立 9 条**：

| # | 条目（改判后表述） | 判据 / 标准 |
|---|---|---|
| F23 | 真子进程驱动（非模块级直驱） | 验证路径不 import 业务模块——驱动对象 = 真进程（对象泛化：任意终端程序） |
| F26 | 覆盖边界写死 | 「能测 / 不测」逐条列明（承 §6.3）；自动绿**不得**被误读为未测面已被验证 |
| F27 | 确定性 | 被驱动对象的非确定性来源（模型 / 网络 / 时钟）走脚本化替身（零外网 / 零付费端点）；隔离 HOME 与 cwd；重复执行结果一致 |
| F28 | 接入集成集（发布门） | 端到端重 IO 用例住集成层（`test/integration/` 类落点），由发布门第三步骤执行——不新增入口 / 不加脚本 / 不动单入口执行集 |
| N14 | 宿主零 TTY 可跑 | 全部用例在**无 TTY 的宿主**（开发 / 评审会话即此类）可跑并全绿——不要求宿主有真终端、不要求人工操作 |
| N15 | 确定性（标准面） | 零外网 / 零付费端点；用例间零共享状态；重复执行结果一致 |
| N16 | 运行时长 | 单用例硬超时（超时 = 失败 · 失败句可读）；档级墙钟目标由首发实测校准（不得拖垮发布门；旧值 ≤30s / 档 ≤3 分钟仅作参照） |
| N17 | 失败可诊断 | 断言失败输出含现场（退出码 / 屏幕或输出尾段 / 输入序列）；无静默挂起 |
| N18 | 分层关系 | 属集成集（②③ 寿命面）：不进单入口执行集（`npm test` 目标集合零变）· 不用 `slow()` · 仅在集成入口与发布门跑；集成集既有纪律零改 |

### 6.3 范围边界（不做）

- **不做伪 TTY / 属性伪造形态**（U1 要求真终端；伪 TTY 下 raw mode / 终端尺寸不存在）。
- **不做渲染观感与主观体验的自动判定**——自动面 = 可脚本化面；「真机上好不好用」仍由人工判。
- **不进单入口执行集 / 不用 `slow()` / 不动分层机制与既有 runner / 不改发布门脚本**（承 §2–§4 与 §6.2 N18）。
- **不调真实付费端点**（真端点 smoke 保持独立形态）。
- **不代立各端验证面的设立口径**——能力归属 = 工具系统统一面（见 `TOOLS.md` §4.7）；各端对位用例是否同期设立属另批裁定（本档不代立规）。
