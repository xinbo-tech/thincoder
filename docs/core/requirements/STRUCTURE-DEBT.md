## 1. 总体定位

结构债的病痛与治疗时机**错开**（平时无症状、撞上才暴露），因此必须靠**文档显式追踪**防「挂账不处理」。
本板块规定：结构债如何度量、何时必须处理、每批如何独立立项。

## 2. 功能性需求

| # | 需求 | 说明 |
|---|---|---|
| **F-SD1** | 显式追踪 | 结构债评估与清理在文档面显式记录（设计侧总账 = `docs/core/design/STRUCTURE-DEBT.md`；具体清理随批落批次档 / 归属设计档） |
| **F-SD2** | 每批独立立项 | 每批独立走工程模式（设计 → 评审 → 实现），批档独立成文 |
| **F-SD3** | 触碰到即处理 | 撞上结构问题的当批不挂账——当场就地修正，禁止叠最小补丁掩盖症状 |
| **F-SD4** | 不建平行登记面 | 同一机制只在一处详述（单一权威源）——结构债不在多处各立清单 |

## 3. 非功能性需求（硬指标）

| # | 维度 | 标准 |
|---|---|---|
| **N-SD1** | 源码文件超硬限 = 必须拆 | 文件行数硬限 = 500（无豁免通道）；跨档位文件在设计里必须带拆分计划 |
| **N-SD2** | 超软线 = 主动拆分评审 | 文件 300 行 = 建议线（advisory），触线即评估 |
| **N-SD3** | 函数档是第一判据 | 文件未超硬限但含超长单体函数仍不合规（函数随生长即分解，不先写整体再拆） |
| **N-SD4** | 文档同标准 | `docs/` 文档无 >300 字符单行（表格行豁免）——批量检查 `scripts/doc-check-width.mjs` |
| **N-SD5** | 合并仓单一标准 | 范围 = 合并仓全仓（核包 + 两产品树）——同一标准、一次检查（**收正**：旧档「双树覆盖 / 两仓各自检查」为合并前口径） |

## 4. 范围边界（不做）

- 不做自动重构（判定与清理走批次立项，不设常驻自动改写）。
- 不建第二份债清单（唯一总账 = 设计侧 `docs/core/design/STRUCTURE-DEBT.md`）。
- 软件结构债不设「存量豁免 / 入基线」通道（存量不是合法态）。
