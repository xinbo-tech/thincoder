# 文档检查（DOC-CHECK）· 需求

> 用户裁定（2026-10-18 16:17 / 16:24 / 16:25 逐轮定案）：「心目中的文档检查应该是在一轮设计或者开发这里的动作结束后，向以前的 verify 一样，对修改过的文档做一下即时的检查，发现问题以后直接打回让 agent 当场修改，不要把问题留到以后」∥「肯定不能是只查改动行啊！全文档都要检查的！」∥「这些悬空指针怎么留下来的？不就是因为你以前没有当场修吗！」
> 判据单源 = `docs/core/design/DOC-DISCIPLINE.md` §3.20（锚 ∥ 行宽两条，本档不重述口径）。

## 1. 模块目标

一轮设计或开发动作结束时，对**本轮改过的文档**当场做机器检查——发现问题**当场打回**，由发起该轮动作的 agent 在同轮内修正，不进入台账。

**治的病 = 挂账**：检查结果记一笔就走，等以后再处理时，当时的情境（这是举例？是类名？是真指针？）已经不在，问题从「一眼能改」变成「没人能判」。

**为什么必须是当场**：假阳（举错例子、类名当指针）在改动发生的当下一眼可辨；脱离上下文后无法判断该改文档还是改引擎。

## 2. 功能点

| # | 功能点 | 判据 |
|---|---|---|
| **F1** | **三个触发点** | 设计轮交付（eng-designer）· 实施轮交付（eng-coder）· 父侧收口前——各跑一次 |
| **F2** | **范围 = 调用方给的那几档，全文** | 清单两来源（**都不经声明域过滤——没有 `scanDirs` 这层**）：**子代理**（无 git）= 本会话触达记账（`_touchedFiles`）；**父侧** = 触达记账 ∪ 本批提交 diff（`git diff <批起 sha> --name-only -- docs`）。**每档全文检查**（不是只查改动行；不是全仓）。**为什么**：检查范围就是问题归属——判了本轮没碰过的档，别轮的存量问题会记到本轮头上，交付被档外债务拖住（这正是当年「技术待办爆炸」的成因）；范围由调用方说清，本轮判了什么才可复述、可复核 |
| **F3** | **判据 = 引擎现有两条** | 锚（`档缺` / `节缺`）+ 行宽（内置常量 `300`）；**无 `checkConfig`、无任何按项目的参数面**；不新增判据。**裸名指针不跨目录解析**：引用写仓根相对全路径，或与所在档同目录（D4 实现坐标口径）。**为什么**：跨目录解析必须靠一张「全域目录索引」才成立——为了认出一个裸名而重建索引，等于把刚删掉的全仓扫描请回来；写全路径后解析零索引，逐档判就是全部。行宽之所以是常量：参数化的前提是「不同项目确需不同判据」，实测没有项目改过，而可配即会漂；改判据 = 改代码、走评审 |
| **F4** | **命中 ⇒ 拒绝交付** | 工具返回**拒绝**信号（非零退出 / 明确 refuse），不是「报告 + 继续」 |
| **F5** | **当场修** | 被拒的 agent 必须在**同一轮**内修正并复跑至零命中，方可交付 |
| **F6** | **不挂账** | 命中项**不得**转入台账、不得「记一笔继续走」、不得留到下一轮 |
| **F7** | **拿不准 ⇒ 上抛用户** | 修正方式不明（是举例 / 类名 / 真指针？）⇒ 上抛用户裁决；不猜、不静默豁免 |
| **F9** | **结构兜底 = batch 工具两机械点** | 强制不靠提示词纪律（判据 = `ENGINEERING-MODE-V2.md` §1 判据句「靠哪个结构兜底」）：① **子代理写批次档段**（§2 / §5）⇒ batch 工具自动跑 gate——REFUSED ⇒ **拒写**，命中清单回给写者同轮修；② **父侧收口**（`close` ∥ 状态行 →「已收口」）⇒ 自动跑 gate——REFUSED ∥ ERROR ⇒ **拒绝收口**。用户裁定 2026-10-18 17:40：「gate挂到batch工具的机械点可以」 |
| **F10** | **可指定档集 = 唯一的取范围方式** | `report` 面**必须**给显式档清单（`docs`: array）：给了 ⇒ 只判这些档（每档全文，判据不变）；**未给 ⇒ 明确报错要求显式清单**——不存在「未给就查全域」的兜底支。清单内档须盘上存在；缺档 ⇒ 报错点名，不静默跳过、不降级为全域。空清单 ⇒ 报错。`gate` 面同样只判传入档。**为什么**：兜底支存在，调用方迟早依赖它（忘了传 `docs` 也能跑），全仓扫描便以「默认值」的形式悄悄回来——**有默认范围就等于有全仓扫描**，只是没人再看得见它。**来源**：用户 2026-10-19 11:14「不能指定检查哪些文件，这个有问题」+ 2026-10-22 10:27「只查指定文件…你还留着一个门？」 |

## 3. 边界（不做什么）

- **不查未改的档**——责任边界 = 本轮触碰面。未触碰档的存量问题属清账，另事处置。
- **不做全仓扫描**——全仓扫描 = 清账动作，不是每轮的交付门；做了会把别的轮次的问题带进本轮，正是「检查范围把开发思路带偏」的成因。**判据句 = 代码内 `scanDirs` 零消费、`anchors.domain` / `anchors.roots` 零存在**：没有全仓基线，就没有「未给清单时」的兜底支。本仓存量 696 条裸名指针（`#1731`）按新口径改全路径——**工具不为自己仓库的存量债务放宽判据**，放宽一次，判据就再也不是判据。
- **不新增判据**——只有锚 + 行宽两条。D2 重复、D8 历史残留、计数三值互斥这类跨句判断不纳入（机器判不了，靠评审）。
- **不改「用户令 > 机检」总则**——机检不得成为拒绝用户指令的理由。
- **不替代评审**——机检只判机器能判的（指针解析 / 行宽）；内容质量归评审与执行者。
- **不引入豁免清单**——修正靠「改文档」或「修引擎」，不靠「登记后放过」。

## 4. 验收（逐条可机检）

| # | 判据 | 方式 |
|---|---|---|
| **AC-1** | 改过的档**全文**检查——改动行之外的同档存量问题也报 | 构造：某档改一行、另有存量问题 ⇒ 两处均报 |
| **AC-2** | 未改的档不报 | 构造：全仓有存量问题的档未被本轮触碰 ⇒ 不报 |
| **AC-3** | 有命中 ⇒ **明确的拒绝 verdict**（非报告） | 构造：命中 ≥1 ⇒ 工具首行返回 `DOC-CHECK GATE: REFUSED（命中 K 条）`；三处强制面（交付协议 / §6 前置 / 父侧复跑）均以该 verdict 为判据 |
| **AC-4** | 零命中 ⇒ 放行 | 现状实测：全仓 0 命中（2026-10-18 16:27） |
| **AC-5** | 引擎假阳 = 0 | 现状实测：修引擎后 158 → 0（2026-10-18 16:27） |
| **AC-6** | 命中项不落台账 | 构造：命中后交付被拒 ⇒ 台账无新增行 |
| **AC-7** | batch 工具机械点：子代理写批次档段命中 ⇒ **拒写**（返回串含 verdict + 命中清单）；父侧收口命中 ∥ ERROR ⇒ **拒绝收口**；零命中 ⇒ 放行。**范围按作者归属分域**：K = 命中 ∩ **本批笔域集**（父侧触达账 ∪ 本批提交 diff）的条数 ⇒ K ≥ 1 拒；命中 ⊆ **他批在途集** ⇒ 不阻收口，另起固定行逐档报明（请其作者在其批修复）——**按作者分界，不按条豁免** | 构造：夹具域命中档 ⇒ 拒写面；零命中 ⇒ 写入放行；他批在途档命中而本批笔域干净 ⇒ 收口放行 + 报面列该档；既有身份 / 冻结 / 占位拒因逐字不变 |
| **AC-8** | `report` + 显式档集：只报清单内的档（清单外的存量问题**不报**）；不在盘的档 ⇒ **明确报错点名**，不静默跳过；`docs: []` ⇒ **明确报错**；**不给 `docs` ⇒ 明确报错要求显式清单（零遍历、零全域兜底）** | 构造：全域有存量问题档 A、清单只给干净档 B ⇒ 0 命中；清单给 A ⇒ 报 A；给不在盘的档 ⇒ 报错点名；`docs: []` ⇒ 报错；**不给 `docs` ⇒ 报错且不读任何档（读盘计数 = 0）** |
