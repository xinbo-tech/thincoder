# 文档检查（DOC-CHECK）· 需求

> 用户裁定（2026-10-18 16:17 / 16:24 / 16:25 逐轮定案）：「心目中的文档检查应该是在一轮设计或者开发这里的动作结束后，向以前的 verify 一样，对修改过的文档做一下即时的检查，发现问题以后直接打回让 agent 当场修改，不要把问题留到以后」∥「肯定不能是只查改动行啊！全文档都要检查的！」∥「这些悬空指针怎么留下来的？不就是因为你以前没有当场修吗！」
> 判据单源 = `docs/core/design/DOC-DISCIPLINE.md` §3.20（锚 ∥ 段长两条，本档不重述口径）及 §3.25 条目 Y（依据行逐字引文——挂在「锚」这条判据内部的第二个判法，闸仍是两条）。

## 1. 模块目标

一轮设计或开发动作结束时，对**本轮改过的文档**当场做机器检查——发现问题**当场打回**，由发起该轮动作的 agent 在同轮内修正，不进入台账。

**治的病 = 挂账**：检查结果记一笔就走，等以后再处理时，当时的情境（这是举例？是类名？是真指针？）已经不在，问题从「一眼能改」变成「没人能判」。

**为什么必须是当场**：假阳（举错例子、类名当指针）在改动发生的当下一眼可辨；脱离上下文后无法判断该改文档还是改引擎。

## 2. 功能点

| # | 功能点 | 判据 |
|---|---|---|
| **F1** | **三个触发点** | 设计轮交付（eng-designer）· 实施轮交付（eng-coder）· 父侧收口前——各跑一次 |
| **F2** | **范围 = 调用方给的那几档，全文** | 清单两来源（**都不经声明域过滤——没有 `scanDirs` 这层**）：**子代理**（无 git）= 本会话触达记账（`_touchedFiles`）；**父侧** = 触达记账 ∪ 本批提交 diff（`git diff <批起 sha> --name-only -- docs`）。**每档全文检查**（不是只查改动行；不是全仓）。**为什么**：检查范围就是问题归属——判了本轮没碰过的档，别轮的存量问题会记到本轮头上，交付被档外债务拖住（这正是当年「技术待办爆炸」的成因）；范围由调用方说清，本轮判了什么才可复述、可复核 |
| **F3** | **判据 = 引擎现有两条** | 锚（`档缺` / `节缺`）+ 段长（内置常量 `300`）；**无 `checkConfig`、无任何按项目的参数面**；**不新增闸判据**（`report` 面的只读清点见 F11——不进闸、不产 verdict，因此不属本条射程）。**裸名指针不跨目录解析**：引用写仓根相对全路径，或与所在档同目录（D4 实现坐标口径）。**为什么**：跨目录解析必须靠一张「全域目录索引」才成立——为了认出一个裸名而重建索引，等于把刚删掉的全仓扫描请回来；写全路径后解析零索引，逐档判就是全部。段长之所以是常量：参数化的前提是「不同项目确需不同判据」，实测没有项目改过，而可配即会漂；改判据 = 改代码、走评审。**判据不分适用面**：两条判据对所有档一律判，工具描述面（`thincoder-core/tool-docs/`）同样受段长约束——该面的读者虽然是模型，但长段里的细节照样被跳过；分面豁免曾使 29 档 39 段长期超标而无人发现 |
| **F4** | **命中 ⇒ 拒绝交付** | 工具返回**拒绝**信号（非零退出 / 明确 refuse），不是「报告 + 继续」 |
| **F5** | **当场修** | 被拒的 agent 必须在**同一轮**内修正并复跑至零命中，方可交付 |
| **F6** | **不挂账** | 命中项**不得**转入台账、不得「记一笔继续走」、不得留到下一轮 |
| **F7** | **拿不准 ⇒ 上抛用户** | 修正方式不明（是举例 / 类名 / 真指针？）⇒ 上抛用户裁决；不猜、不静默豁免 |
| **F9** | **结构兜底 = batch 工具两机械点** | 强制不靠提示词纪律（判据 = `ENGINEERING-MODE-V2.md` §1 判据句「靠哪个结构兜底」）：① **任一次 append**（§1–§6，含 depth-0 与评审写 §3）⇒ batch 工具自动跑 gate——REFUSED ⇒ **拒写**，命中清单回给写者同轮修；**强制集 = 本次写入文本的命中 ∪ 子代理触达账命中**，批档已落段命中只入回执、不阻写；② **父侧收口**（`close` ∥ 状态行 →「已收口」）⇒ 自动跑 gate——REFUSED ∥ ERROR ⇒ **拒绝收口**。用户裁定 2026-10-18 17:40：「gate挂到batch工具的机械点可以」 |
| **F10** | **可指定档集 = 唯一的取范围方式** | `report` 面**必须**给显式档清单（`docs`: array）：给了 ⇒ 只判这些档（每档全文，判据不变）；**未给 ⇒ 明确报错要求显式清单**——不存在「未给就查全域」的兜底支。清单内档须盘上存在；缺档 ⇒ 报错点名，不静默跳过、不降级为全域。空清单 ⇒ 报错。`gate` 面同样只判传入档。**为什么**：兜底支存在，调用方迟早依赖它（忘了传 `docs` 也能跑），全仓扫描便以「默认值」的形式悄悄回来——**有默认范围就等于有全仓扫描**，只是没人再看得见它。**来源**：用户 2026-10-19 11:14「不能指定检查哪些文件，这个有问题」+ 2026-10-22 10:27「只查指定文件…你还留着一个门？」 |
| **F11** | **`report` 面多一条只读清单：行号坐标** | `report` 面在两条闸判据之外，**逐处列出**文中的行号坐标形引用。**形** = 一个名字后面跟 `:` 加数字，且那个数字是**行号而非节号**。**三种写法都要扫**：① 紧贴（档名紧跟 `:` 加数字）；② 承名（同行前文出现过档名，坐标本身只写 `:` 加数字）；③ 段落承名（档名在上一行、坐标在续行）。**它是清单，不是判据**：不产生 verdict、不进 `gate`、不阻断任何写入；`gate` 面的两条判据与它们的效力一字不改。**为什么要它**：行号引用钉的是位置、不是内容——上面插一行，它以下整片引用同时失效，所以存量必须能被**清点**；但清点不等于立闸（用户 2026-11-01 裁定：机械闸拦不住绕行、只挡老实人）。**量法单源**：**清单块的首行**打印本次使用的抽取式与扫描域，别处不另写一套。**为什么是清单块内而不是报告页首**：读数会被整块复制走（贴进对话、贴进批档），量法得跟着读数一起走——放在页首，复制一半就散了。清存量期间同一件事被扫出过三个互不可比的读数（窄形 0 ∥ 承名形 119 ∥ 段落承名形 30），根因就是没有统一量法。**为什么三种写法算同一条而不是三条**：读者拿着 `:` 加数字去别处找，行为完全一样；换行不改变它是位置引用。**来源**：用户 2026-11-01 21:40 原话「开」 |
| **F12** | **豁免判定单一源：三处消费同一份定义** | 「一个档名是不是豁免」的判定，**闸判（锚）** ∥ **兄弟脚本 `scripts/prompt-refs-check.mjs`** ∥ **`report` 面的行号清单** 三处必须消费同一份定义，不得各自维护一张表。**现盘的病**：`thincoder-core/doc-check/anchors.mjs` 只导出了 `CANON_OPERANDS`（三张豁免表里的一张），`FILENAME_CLASSES` 与 `PLACEHOLDER_STEMS` 是私有的 ⇒ 兄弟脚本只拿到三分之一，把占位符干名与常规档名（`x.md` ∥ `file.md` ∥ `foo.md` ∥ `example.md` ∥ `todo.md` ∥ `NAME.md`）当成违规报了出来（实测 10 条命中里 6 条属于这一类）。**为什么它是 F11 的前提而不是另一件事**：行号清单若不知道哪些名字是占位，就会把 `x.md:12` 这类示例也列进去——**一份自带假阳性的清单没有读者**，而清单不做闸、它唯一的资产就是可信度。**验收口径**：共用后 `node scripts/prompt-refs-check.mjs` 从 **10 条降到 4 条**，且那 4 条真违规（裸档名未写仓根路径）逐字不变；**那 4 条本批不修**（存量归清账），本批只让判定对起来。**来源**：父侧 2026-11-01 21:42 实读 |
| **F13** | **依据行逐字引文（命中类 = `引缺`）** | **形**：`依据` + **可选**分隔符（`:` ∥ `：` ∥ `=`）+ 档路径（可带反引号）+ `「` 逐字引文 `」`；档路径 token 与 `「` 之间只允许分隔符与反引号——中间夹进别的字符就不构成标记。**判**：引文必须是所指档里**一段连续子串**——不改写、不省字、不拼接，且**不做**空白折叠 / 全半角 / 大小写换算（换算一次，引文就可以「大致对」，判据随之失效）。不是 ⇒ 命中类 **`引缺`**。**为什么不并进 `档缺`**：`档缺` 说的是「档不在盘」，读者据此去查路径；引文错时路径是对的，合并会把读者指向错的地方。**闸仍是两条**：它是「锚」这条判据内部的第二个判法（路径解析 + 引文存在），verdict 串与命中计数口径不变——两因都计入「锚 N 条」。**边界**：只判**自称依据**的行；**不判依据对不对**（引注释当契约这类，机检照样看不见，归评审面——见 §3.25 评审面）；空引文：**引文面不判**，但该行路径 token 仍归锚面照判（不因引文空而整行让位——让位会让悬空档名凭空少报一条）；零豁免入口（存量天然为零：域内标记形 **0** 行——**读数不入判据**，文档一增就漂，判据只认 0，没有「老的不算」这条口子）。**为什么**：引二手当依据已经真出过两次——一次把一个**不存在**的条文挂到档名下，一次把**注释**当契约（后果 = 照设计档写，写门会把每一笔写都拒）。两次评审都没命中，因为档写反、代码写对，行为判据全绿、两边各自自洽。**触发前提**：本判据只在写作面**教了写法**之后才可能命中——写作面不改，全档 0 标记就是它的终态（死判据）。 |

## 3. 边界（不做什么）

- **不查未改的档**——责任边界 = 本轮触碰面。未触碰档的存量问题属清账，另事处置。
- **不做全仓扫描**——全仓扫描 = 清账动作，不是每轮的交付门；做了会把别的轮次的问题带进本轮，正是「检查范围把开发思路带偏」的成因。**判据句 = 代码内 `scanDirs` 零消费、`anchors.domain` / `anchors.roots` 零存在**：没有全仓基线，就没有「未给清单时」的兜底支。本仓存量 696 条裸名指针（`#1731`）按新口径改全路径——**工具不为自己仓库的存量债务放宽判据**，放宽一次，判据就再也不是判据。
- **不新增判据——闸只有锚 + 段长两条**（F13 的引文面**挂在「锚」内部**，是它第二个判法，不另立第三条；verdict 串与命中计数口径一字不改）。D2 重复、D8 历史残留、计数三值互斥这类跨句判断不纳入（机器判不了，靠评审）。**F11 的行号坐标清单不属判据面**：它不进闸（不产 verdict、不阻写、不影响放行），只是 `report` 面的一份清点，理由写在该条里。**这条边界的对象始终是闸**，不是「引擎能不能数出一件事」——数得出来而没资格拦人的，写成清单。
- **不改「用户令 > 机检」总则**——机检不得成为拒绝用户指令的理由。
- **不替代评审**——机检只判机器能判的（指针解析 / 段长）；内容质量归评审与执行者。
- **不引入豁免清单**——修正靠「改文档」或「修引擎」，不靠「登记后放过」。
