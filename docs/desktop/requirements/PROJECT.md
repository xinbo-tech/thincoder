# 桌面端（DESKTOP）· 需求

> 板块 = **桌面端产品定性**——ThinCoder 第三个接入端的定位、功能范围与边界。
> 本档 = 桌面端产品级定性的需求层权威；产品族定性（三端关系）与跨产品共享契约见 `docs/core/requirements/PROJECT.md`（§1 / §3）。
> 核机制面（agent 主循环 / 工具 / 记忆 / 配置）**只住核**，本档不重述（单一权威源）。
> 建档：2026-09-25（用户裁定「增加桌面端」；同日收敛 = 单项目 + 项目内多会话 · 三平台从第一天 · 宿主 = Electron · 前端自持且零框架 · 文件视图与编辑器暂缓）。
> 本档坐标 = as-of 2026-09-25 实核（仓根 = `thincoder/`）。

## 1. 模块目标

给不想、不能用 VS Code 的人一个**独立桌面入口**：同一个 agent、同一份配置与会话、比终端更宽的会话与活动视图——单项目多会话，没有终端也能配好并开始干活。

## 2. 定位

| 项 | 内容 |
|---|---|
| 品类 | 通用 AI 编码智能体的**第三个接入端**（形态 = 桌面应用）——不改品类定性（`docs/core/requirements/PROJECT.md` §5.1） |
| 目标用户 | ① 不装 VS Code 的开发者；② 需要比 TUI 更宽的会话 / 活动 / 后台视图的人；③ 不熟命令行的使用者（首启无终端可完成配置） |
| 与另两端 | 同级独立产品、互不依赖；读写同一份 `~/.thincoder/config.json` 与 `~/.thincoder/sessions/`（承 `docs/core/requirements/PROJECT.md` §3 的 C1 / C2 契约） |
| 项目模型 | **单项目**：一次服务一个工作目录（会话按 cwd 寻址）；多项目并行 = 开多个实例（核已有跨实例协作面） |
| 宿主 | Electron——桌面运行时按**宿主平台**口径（与扩展端把 VS Code API 当宿主同支）；Electron 随发行物分发，其体积 / 供应链 / 三平台打包链成本落本端发行面 |
| 前端 | **本端自持**（不共用扩展端 Webview 代码）：零框架手写，纯 DOM + 浏览器原生（2026-09-25 用户裁定） |
| 壳装配 | 本端独有（核装配的第三份——CLI ∥ 扩展端各一份）；是否抽共享层为独立议题，不并入本程序 |

## 3. 界面形态

> 本节形态 = 父侧提案，2026-09-25 用户认可后落档；控件 / 样式 / 断点等细部留给设计轮。

### 3.1 主界面 = 左列 + 会话标签页

```
┌────────────────┬────────────────────────────────────┬────────────────────┐
│ 左 · 项目与会话  │ 会话标签页（当前 = A）               │ 本会话活动池        │
│ 项目目录        │ 标签条：[ A ● ][ B ⚠ ][ C ] +        │  ▸ 子代理块（工具名│
│ 会话列表 +新建  │ 会话头：provider / 模型 / 档位 / ENG  │    + 状态）        │
│  ▸ A ● 运行中   │ 对话流：流式 token · 推理块 · 工具卡  │  ▸ advisor/consult │
│  ▸ B ⚠ 待审批   │ 审批卡（流内）· 错误卡                │  ▸ 队列            │
│  ▸ C           │ 输入框（Enter 发送 / Shift+Enter）   │  ▸ 待审批（计数 +  │
│ ── 项目级 ──    │                                      │    操作区）        │
│ 台账行 · 批次    │                                      │ 随标签切换 · 可折叠 │
└────────────────┴────────────────────────────────────┴────────────────────┘
状态栏：上下文占用（活动会话） · 非活动标签待审批提示
```

- **左 · 项目与会话**：项目目录（单项目）· 会话列表（**全部**会话 = 历史，运行中 / 待审批带位标；与 CLI / 扩展端是**同一份**——共享会话目录，点开即可续）· 新建入口 · 底部**项目级信息**（台账行 · 批次状态——**项目一份，不随会话走**；台账按项目根存储，批次相位住项目根的 manifest 档）。
- **中 · 会话标签页**：标签条 = **已打开**的会话（可关，每个带状态位 ● 运行中 / ⚠ 待审批 / ✓ 完成）；标签内 = 会话头 + 对话流 + **右侧本会话活动池**（两栏并列；池可折叠——折叠后对话流得全宽）。
- **会话头（每会话）**：provider / 模型 / 推理档位 / **工程模式** / AUTO——这些是**会话级**状态（随会话槽持久化，切标签即随之切换，与 CLI / 扩展端同一份槽；槽字段实证 = `activeProvider` / `activeModel` / `engineering` / `autoApprove`）。
  注意区分：**工程模式状态**是会话级（住会话槽），但它 **ON 方向的准入判据**要读项目根的 manifest 档——两者不同层，不得混为一谈。
- 两处会话入口**语义不同、不可合并**：左列 = 全部（历史，点开成标签页），标签条 = 已打开（活跃）。
- **对话流**：消息流（流式 token · 推理块）· 工具卡（名称 + 参数摘要 + 状态 + 可展开结果，**含改动摘要** = 文件 + 增删行数，纯文本，不做 diff）· 错误卡 · 审批卡（流内嵌）· 输入框。
- **活动池（每会话一份 · 会话视图内靠右）**：子代理活动块（粒度 = 工具名 + 状态，不回显内容）· advisor / consult · 队列 · 待审批（计数 + 操作区）。**位置与「全局右栏」同形，差别只在归属**：每会话一份、随标签切换（全局常驻池不存在——见 §3.4）。
- **状态栏**：活动会话的上下文占用（实时读数）· **非活动标签的待审批 / 运行提示**（跨会话告警位——不静默等待）。会话配置项不在状态栏重复呈现（它们住会话头——同一事实只出现一处）。

### 3.2 一回合的时序（可感行为）

1. 用户发送 ⇒ 对话流流式推进，本会话活动池出现活动块；
2. 需要用户点头时：**对话流内嵌审批卡** + **本会话活动池的待审批计数 +1** + **标签页状态位变 ⚠**；若你正在别的标签页，**状态栏给提示**（不静默等待）；
3. 子代理只在活动池活动（粒度 = 工具名 + 状态，不回显内容）；**并发可见性靠标签页状态位承担**（多会话并行时不必翻页也能看见谁在跑 / 谁在等）；
4. 回合收尾：结果进对话流，状态栏上下文占用更新。

### 3.3 首启（无终端可完成）

选 provider → 填 key（真调一次校验）→ 选工作目录 → 可用。
若 `~/.thincoder/config.json` 已存在（CLI 或扩展端已配）⇒ **跳过向导**，直接进主界面。

### 3.4 不出现在界面上的

文件树 · 编辑器 · 内置 diff · 终端面板 · 常驻多项目面板 · **常驻全局活动栏**（活动池随会话——§3.1）——均无；前两项 = 用户裁定的暂缓项；内置 diff / 终端面板 / 常驻多项目面板 = §5.2 边界；常驻全局活动栏 = 形态裁定。

### 3.5 待设计形（本轮不锁）

- 同项目多会话**并行跑**时，活动池的池 / 队列分层显示形态；
- 标签页状态位的精确集合（运行中 / 待审批 / 完成 / 空闲的取值与优先级）；
- 会话行**标注来源端**（该会话由 CLI / 扩展端 / 桌面端所建）——核侧「**创建端**」字段**已落地**（`listSlots[].createdBy` · 台账 #372 · 2026-09-25）；字段缺失（老槽）时**退化为不标注**（**不猜测**——「当前占用端」与「创建端」不同义，不得冒充）。

## 4. 功能点

| # | 功能点 | 判据（可机检） |
|---|---|---|
| D1 | 项目入口 | 打开文件夹 / 最近项目 ⇒ 建立该目录上下文（会话按 cwd hash 寻址）；重启后最近列表仍在 |
| D2 | 会话族 | 新建 / 列表 / 切换 / 删除 / 重命名 / 接续；与 CLI、扩展端读写**同一** sessions 目录 ⇒ 三端可接续同一会话 |
| D3 | 对话流 | 发送、流式 token、推理块、工具调用卡与结果、错误与耗时；可中断 |
| D4 | 活动与后台 | 子代理活动块（粒度 = 工具名 + 状态，不回显内容）、advisor / consult、挂起态与 digest、队列表 |
| D5 | 审批与模式 | 工具审批门（once / always / reject）、AUTO 模式、工程模式（ENG）可见面与凭证链 |
| D6 | 模型与档位 | provider → 模型两级选择、推理档位（含 Auto / off 族）、effort 菜单与回执一致 |
| D7 | 设置与凭据 | provider 增删、key 管理、preset / custom 三协议、agent 参数面板、i18n（en / zh） |
| D8 | 记忆与检索 | memory / code_search / doc_search 与索引状态（**复用核**；属 agent 工具面，非 UI 搜索框） |
| D9 | MCP | 服务器增删与工具入口（复用核） |
| D10 | 台账与批次面 | 台账行、批次状态可见（对齐另两端既有面） |
| D11 | 首启向导 | 无终端完成：选 preset → 填 key → 校验通过即可对话 |
| D12 | 发行面 | 三平台（Windows / macOS / Linux）可安装可启动的产物；版本与升级路径（细目留设计轮） |

## 5. 边界

### 5.1 暂缓（本轮不做，登记为后续议题）

- **文件视图与编辑器**（打开 / 编辑 / 保存 / 内置 diff）——2026-09-25 用户裁定暂缓；
- **常驻多项目面板 / 项目切换器**——多项目并行以多实例满足。

### 5.2 不做

- 云服务 / 托管平台、模型 / 推理服务、工作流引擎；
- 复制核机制（机制只住核）；另立会话 / 配置存储格式（照既有契约）；
- 既有 ACP 面之外的新协议面；
- 通用编辑器 / IDE（`docs/core/requirements/PROJECT.md` §5.3——桌面端同受此限）。

## 6. 非功能

| 项 | 要求 |
|---|---|
| 平台 | **Windows / macOS / Linux 从第一天即目标**（三平台产物可安装可启动）——不是「先 Windows 后扩」 |
| 平台差异面 | 路径与大小写敏感、行尾、进程与信号、窗口壳与原生菜单——由设计轮逐项定形；进程终止**复用**核单一实现 `thincoder-core/tools/process-tree.mjs`，不另写一份 |
| 依赖 | 零第三方运行期依赖——前端零框架手写；宿主 = Electron（宿主平台口径） |
| 性能 | 启动可接受、长会话渲染不退化（阈值与测法留设计轮） |
| 凭据 | key 明文落 `~/.thincoder/config.json`（承 `docs/core/requirements/PROJECT.md` §3 的 C8） |
| 国际化 | 承产品定性（英文为默认面，含 zh） |
