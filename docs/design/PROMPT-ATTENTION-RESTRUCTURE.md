## 需求

- **总体目标**：按**人类可读 + 注意力优化**标准重排全部提示词文件——让关键控制规则（用户批准门/推进档位/叫停）落在模型的高注意力区——不再埋在千字行中段。内容语义零改动；重排后并入 AUTO-PROGRESS-SWITCH 开关段（先重排再加段）。
- **注意力优化方法论（7 原则——本设计的行为依据——重排按此执行）**：
  1. **优先级排序**：最高优先规则（听用户的闸/批准门）放文件最前部——不是埋在 flow 中段
  2. **规则独立成短句 + 加粗关键词**：关键指令一行一条——加粗触发词（WAIT / explicit approval / go）
  3. **命令句 + 否定强调**：闸用祈使/禁止句（"Do NOT spawn until the user says go"）——非叙述性描述——命令句注意力权重更高
  4. **关键规则放首/尾**（serial position）：批准门等放每条消息处理规则的顶部——利用开头结尾高注意力
  5. **减量提权**：长文机制细节从正文移走/指向文档——减少总量提升剩余注意力——执行时真需要的才留
  6. **关键锚点多处重复**（不同措辞）：顶部总则 + 具体 flow 点 + Hard Rules——多处命中同一约束
  7. **视觉锚**：`>` 块引用 / 加粗 / 独立行——让关键行在 token 流里有结构性凸起
- **功能性**：
  - F-1（全文件重排）双端 src/prompts/ 全部 15 文件按 7 原则重排——标题独占行 + 规则短句化 + 关键控制规则前置 + 视觉锚
  - F-2（注意力分布校验——非行宽）每个文件验收 = 检查：最高规则是否在前 20%？命令句是否带否定强调？关键锚是否首尾/多处？——行宽只是副产品不是目标
  - F-3（开关段并入）AUTO-PROGRESS-SWITCH 的 auto/manual 档位规则——作为最高规则之一放每个文件最前部（与批准门同层级）
  - F-4（锚断言联动）ENGINEERING-MODE §2.9 逐字锚 + 测试 fail-when-unchanged——重排后从"整行全文 includes"改**关键子串 includes**（语义锚）——否则重排必红
  - **范围边界**：内容语义零改动（纯拆行/换行/换位/提权——不改任何规则含义）；**排版双端统一**（实测 9 文件字节一致 + 6 文件差 0-2% 零星差异——重排一份方案应用到双端——端特有内容段（如 VSC engineering L66 R14 池规则段）原地保留——非各自独立排版）；ENGINEERING-MODE.md 本身已 🟢 不重排（只联动 §2.9 锚）；混批事故核（fe6d62d 的 src/tui 改动）单独排查不混此设计。
