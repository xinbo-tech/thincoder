### 1.1 病

**`batch append` / `batch close` 的内置文档门，回执写着 `DOC-CHECK GATE: PASS（0 档）· 范围 0 档`，实际一档未判。**

**这比「没有门」更坏：一个**没跑的检查**说「通过」，读的人据此不再查。**

**今天这件事真实发生过**：我今天多次看到这行回执，当它是绿；四个批档累积出 **63 条悬空锚**（`#1842` 15 条 · `#1843` 48 条），全部靠**显式**跑 `doc_check(mode:"gate", docs=[…])` 才暴露出来 —— 没有一条是 `append` 的门给的。

### 1.2 根因（实读，不是推断）

**`thincoder-core/agent-tools/batch-gate.mjs:151-153`：**

```js
// 批档自身不入范围（载体不是判据对象——判它只会把载体的超段记成本批欠账）。
const selfKey = pathKey(resolve(abs))
const touched = docPaths(agent?._touchedFiles, base).filter((p) => pathKey(p) !== selfKey)
```

**⇒ 门**刻意**把目标批档排除在判域之外。**

**`:165` 的回执分两支：**

```js
: (res.checkFiles.length ? "DOC-CHECK GATE: PASS" : "DOC-CHECK GATE: PASS（0 档）")
```

**⇒ 判域为空时，回执与「判过且通过」只差一个括注 —— 而括注 `（0 档）` 读起来像「0 条问题」。**

### 1.3 症状不在「理由不对」，在「理由的对象被换掉了」

**设计给出的理由是：「载体不是判据对象——判它只会把载体的超段记成本批欠账」（`batch-gate.mjs:151`）。**

**用户 2026-10-27 19:40 原话：「以前不纳入是指批档目录里的存量，你就趁机扩散成批档都不检了？」**

**⇒ 扩散链在代码里看得到：**

```
doc-check/index.mjs:9
  「判了本轮没碰过的档，别轮的存量问题会记到本轮头上」
   ↑ 原意：别轮的存量，不该记到本轮头上

batch-gate.mjs:151
  「批档自身不入范围（载体不是判据对象——判它只会把载体的超段记成本批欠账）」
   ↑ 借用了同一套理由，但把对象换成了「本轮自己正在写的批档」
```

**⇒ 存量不该记到本轮头上 —— 所以本轮自己写的也不判。对象被换掉了，结论就反了。**

**而它扩散到的地方恰好最不该排除：批档是唯一一份「每轮都在被写、且写它的人各不相同（§1 主 agent / §2 designer / §3 评审 / §5 coder）」的文档 —— 最容易出漂移的面，门偏偏把它排掉了。今天 63 条锚、四个批档、三段不同作者，就是这个排除的必然结果。**

**（我曾在本节写「载体不是判据对象这一半成立」，那句话被用户裁掉了，已删。）**

### 1.4 方向（用户裁定，不再二选一）

**批档进判域，两个 `scope` 都进 —— `writer`（`append` 时）与 `close`（收口时）都判。**

**但「判谁」必须分清：判的是**本轮写的部分**，不是整本批档的历史。**

**⇒ 存量不属于本轮的，确实不该记到本轮头上（`doc-check/index.mjs:9` 的原意仍成立）；本轮刚写进去的裸档名与超长段，必须当场拦住。**

**实现上用**点火基线**（本批已有的 `run.section3BlocksAtStart` 是同形做法）：写前记快照 / 或按「本次 `append` 的目标段」判，由设计席判哪种更简。**

**不是「收口那一刻才查一次」，是每次写它的时候都过门：写的时候就拦住，不让漂移攒到 63 条再靠人显式跑。**

**设计席要自己判清的四件（不照搬我的措辞）：**

| # | 待定 | 为什么必须说清 |
|---|---|---|
| 1 | 拦住时回执怎么写（谁该改、改什么） | 写这一段的人被自己刚写的东西拦住，回执要说清是他的笔还是别人的笔 |
| 2 | `append` 被拒后，这一段算写了还是没写 | **append-only 语义不能破** —— 半写、重写、错位都是新病 |
| 3 | `§3` 评审段的段落长度 | 评审写表本来就长，会不会一动就撞 |
| 4 | 命中项分不分「记录面 / 实现面」 | 如果分区能让人一眼看出该改哪、那就分；如果分区只是多个维度，就不分 |

**⇒ 第一到第四条都不是「可选」，是设计要落清的对象；但怎么做由设计席判，可推翻我的措辞，只要给理由。**

### 1.5 边界（不做）

- **不改 `doc_check` 引擎的两条判据**（锚 ∥ 段长）——**判据本体不动，动的是「判谁」**
- **不动 `scope` 的两取值语义**（`writer` / `close` 仍然两个值、零第三值）
- **不动 append-only 语义**（被拦住的那段不得半写）

**机制设计**

**判域（判谁）**

| scope | 范围（单集，无第二集） | 强制集（进 K、能拒） | 明示集（入回执、不阻） |
|---|---|---|---|
| `writer`（全部 append） | 写者触达账（既有）∪ **本次写入文本** | 本次写入文本的命中 ∪ 子代理触达账的命中（既有） | 批档**已落段**的命中 |
| `close`（`close` ∥ `status`→已收口） | 触达账 ∪ 本批提交 diff ∪ **批档自身** | 范围内全部命中 | —（fail-closed） |

**批档自身两 scope 都入**：删 `thincoder-core/agent-tools/batch-gate.mjs:151-153` 的 `selfKey` 过滤，并把 `resolve(abs)` 显式并入范围（触达账腿已有它，显式并入使「第一次 append 前」也成立）。

**为什么「判整本批档」＝「判本轮写的部分」（不加点火基线）**

批档**生于此轮、冻结于此轮**：`batch` create 落骨架，`close` 之后整档冻结（实读 `thincoder-core/agent-tools/batch.mjs:204-206`「已收口档不回改」）。

⇒ 批档全文字面即本轮的笔面，**档内没有「别轮写的存量」可排**。存量 = 别批的档，已由「单集 ⊂ 本批笔域集」排除。

⇒ 点火基线（写前快照 / 段内起点标记）**不需要**：它解决的是「同一档里新旧混住」，而批档不存在这种混住。加基线 = 多一个会失真的状态，换不来新判别力。

**`writer` 面为什么只拒「本次写入文本」**

append-only 下，别人的段落**字面改不动**（工具只有 append 与状态行两个写入口）。拒一个改不了的人 ⇒ 每次重试都拒 ⇒ 这一段永远写不进 = 无账之笔。

这与既有 `ERROR` 在 `writer` 面放行同一条理由（子代理无法重启会话），本批只是把它**精确到文本**：拒的东西 = 你手里正拿着的这段。

⇒ 已落段的裸档名 / 超长段：照实进回执（点名段号 + 作者 + 行），不阻本次写；**收口面 fail-closed 当场拦**，那里收口人改得动。

**候选文本怎么判（零引擎改）**

把 `body` 写成 `docs/batches/` 下的隐藏临时片段档（`.gate-<pid>-<rand>.md`），与批档**同目录**——锚解析序两级（`thincoder-core/doc-check/anchors.mjs:86-92`）的第 ② 级是「引用方档所在目录相对」，同目录 ⇒ 判法与批档本体逐字同源。

一次 `runDocCheck` 判**两个档**（批档 + 片段），按命中所在档切强制集 / 明示集；回执把片段档显示成 `本次写入文本`，不出临时路径。片段档在 `finally` 删。

**被拒 = 零字节（append-only 零破）**

门位不动：既有拒因全部之后、`insertIntoSection` / `writeFileSync` 之前（实读 `thincoder-core/agent-tools/batch.mjs:235-237`）。

⇒ 拒后：档字节逐字不变、段号不前进、轮次 N 不推进、批档里**不留任何「曾尝试」痕迹**。修好文本重 `append`，落进来的是**那一段的第一次写**，不是重写。

**回执行形（三处，唯一用户可见面）**

| 面 | 首行 / 行 | 说什么 |
|---|---|---|
| `writer` 放行 | `[doc-check gate] DOC-CHECK GATE: PASS · 范围 N 档` | 本次文本 M 行判过；已落段命中 ⇒ 追加一行点名 |
| `writer` 拒 | `DOC-CHECK GATE: REFUSED（本次写入文本 锚 A 条 · P 段…）` | 逐条 `✗ … 本次写入文本:12` + 修法 + 「一个字没写」+ 已落段命中另列（标明不属你的笔、收口面会拦） |
| `close` 拒 | `DOC-CHECK GATE: REFUSED（…）` | 逐条 `✗ 档:行`；命中在批档内 ⇒ 每条带 `§N（作者：<角色>）`，答「谁该改」 |

**判域空 ⇒ ERROR**

范围恒含批档自身（在盘即入）⇒ 两 scope 的判域**恒非空**，`PASS（0 档）` 不再可达。

构造异常（批档竟不在盘）⇒ `DOC-CHECK GATE: ERROR（判域为空——批档自身应恒在判域）`，**不产 PASS**。
