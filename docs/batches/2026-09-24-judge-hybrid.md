### 1.1 目标与理由

**问题**：bench 的**文本语义判据**靠词表/正则——**结构性不可靠**。实证（2026-09-24 同日）：4 处判据缺陷**全部**出在此面——① `vision.3` 拒答词表 5 词漏「0只猫」「一只猫也没有」；② `multiturn.1` 追问只认问号（「请提供：…」式正确追问被判未追问）；③ `multiturn.2` 候选计数「恰 3」被标题/解释行撑坏；④ `multiturn.3` 要求首步必须 `send_email`（先 `get_time` 定时间被误判）。机理 = **自然语言表达无限 vs 规则枚举有限**（词表永远在漏 + 反向可 gaming）。
**目标**：**混合判分**——判据按性质分层：**确定性面**（数字 / vm 执行 / 整串 JSON / 工具结构）**保持机器判**（零假阴/零成本/零随机）；**语义·语用面**（拒答 / 追问 / 候选质量等）**引入 LLM 裁判**（结构化裁决 + 可审计理由）。

### 1.2 POC 证据（在案 · 已实跑）

5 条**被词表判错**的真实响应 → 独立 AI 裁判（deepseek-flash · temperature 0）重判：**5/5 判准**（每条附准确理由，如「明确表示图中没有猫，正确拒绝了无中生有的提问」）· 单判 **<1.4s** · **¥0.0006/判**（全量 ~25 语义题 ≈ ¥0.02/跑）。
**两条 POC 教训（直接进设计）**：① **judge 输入必须回合精确**（首跑把多轮题喂成回合 2 文本致误判——喂错素材比判错更坏）；② **judge 预算须留足**（400 token 被思考烧尽 ⇒ 空输出 ⇒ parse-fail）。

### 1.3 需求要点

1. **混合架构**：`lib/grade.mjs` 增 `aiJudge`（走核 `chat` 路径，零新依赖）；`cases/` 语义题接入；**确定性判据零改动**（零回归）。
2. **aiJudge 机制**：输入 = 题面 + rubric（明确判据）+ **响应原文（回合精确）**；输出 = 结构化 `{verdict, reason}`；**fail-closed**（解析失败/超时 ⇒ `error`，**禁猜**）。
3. **judge 独立性**：judge 模型可配置且**独立于被测**（默认第三方；双判/仲裁 = 设计裁）——判分器不得静默用被测同家模型。
4. **可复现性**：judge 模型 + 版本 + 时点**入结果 JSON 与报告**；judge 换代 = 判分口径换代（与 `suiteVersion` 绑定规则 = 设计裁）。
5. **成本分账**：judge 调用成本**单列**（不进被测模型的成本表——否则被测成本被污染）。
6. **降级口径**：judge 不可用（网络/配置缺）⇒ **明示 error 并停下上报**（**禁静默回退词表**——回退即假阴回归）。
7. **题面-判据一致性（顺带面）**：扫全用例——修正同类不一致（已知 example：`json.3` 题面未写「不要代码围栏」而判据按整串 parse 判）。

### 1.7 追加需求（用户 2026-09-24 01:07）

**原文**：「机械判错的结果应该用LLM复核一次。」

**含义**：**机械判据（确定性面）判 `fail` 的结果，追加一次 LLM 复核**——目的 = 捕捉机械判据的假阴（题面-判据不一致 / 判据过严 / 解析边缘），让每个 fail 都过第二只眼。

**设计增量**：
1. **触发面**：机械判据 verdict = `fail` 的 run → 复核（语义面主判已是 judge，无叠加；`error` 除外）。
2. **复核输入**：题面 + **判据条文** + 响应原文（回合精确）→ 输出 `{verdict: uphold | overturn, reason}`。
3. **结果处置（裁定点——给结论与理由）**：a) `uphold` ⇒ fail 维持；b) `overturn` ⇒ 候选一：**独立分类「复核翻案」**（**不自动改 pass**——机械 fail 有规则依据，翻案的正确处置 = 修题面/判据 + 进判据演进清单）；候选二：以复核为准改判（pass）。**二选一给裁定与理由**，并定义该分类在结果 JSON / 报告 / 能力矩阵中的呈现。
4. **成本**：仅 fail 触发（占比低）——≈¥0.0006/次（POC 价）——独立记账同 §1.3-5。
5. **同期可用的复核价值案例**：`json.3`（glm 带围栏 fail——真 fail 还是题面-判据不一致，复核能显影）——复核结果直接喂「题面-判据一致性清单」（§1.3-7）。

### 2.3 机制设计（摘要）

1. **判官（§2.10）**：输入 = 三段（题面 / 冻结 rubric / **该回合**响应原文——声明式 `judge.turn` + 单取值点，POC 教训①结构性防复现）；输出 = `{"verdict":"pass|fail","reason"}` 严格解析（与严格 JSON 面同口径）；**fail-closed**：解析失败 ⇒ 放大预算重试一次（×2，上限 8192），两次不成 / 超时 / HTTP 错 ⇒ 判定 `error`（禁猜、禁回退词表）；预算默认 2048（下限 1024 —— POC 教训②）、超时 30s、temperature 0，与被测 `--max-tokens` 解耦；判官**必备**（缺 ⇒ 拒跑，「无判官跑法」不存在）。
2. **判据分层（逐例）**：判官面 11 例 / 机械面 20 例（6 例混合，短路顺序 = 机械面先跑、已 FAIL 不调判官）；确定性判据（`numEquals` / `vmRun` / `strictJson` / `toolShape` / `textRules` 其余规则）**行为零改动**——只删判官化后无调用者的词表/计数件（`keywordSet` / `COLOR_FAMILIES` / `colorMatch` / `countEnumerations` + `enumerateCount`）。
3. **词表去留 = 全废（不留快通道）**：假阳面词表自除不了（「不是红色」命中「红色」）+ 口径两级 + 成本证据（¥0.0006/判）。
4. **复核（§2.11）**：触发 = run `fail` ∧ 非判官裁决 ∧ 用例含机械面；输入 = 题面 + `mechRubric` + 逐回合响应观测（文本 + 工具事实）+ 机械失败断言；输出 `{"verdict":"uphold|overturn"}`；**翻案 = 独立分类、不自动改判**（用户 01:08 裁定），仍在 `fail`、不计 pass，呈现 = JSON `runs[].review` + 判定 `⟲` + 矩阵 `⟲` + 脚注 + 《复核翻案》小节 + 告警计数；复核失败 = fail 维持（不降 error）。
5. **成本 / 元数据 / 降级**：判官 / 复核成本走 `prices.json` 同一匹配与成本式，单列两列（不进被测成本与相对归一化）；`judge` 块（provider / model / host / temperature / maxTokens / timeoutSec / promptVersion / frozenAtSuiteVersion / sameVendorAsTested / 次数 / 成本）+ 逐调用 `at`；降级三级 = 启动面拒跑（不落档，退出码 1）/ 运行面 `error`（不回落）/ 判定全灭（落档 + 退出码 1）。
6. **题面-判据一致性**：扫全 25 例 + 3 人工条 ⇒ 修正 3（`json.2` / `json.3` / `tools.4` 题面补词）· 有意判定 3（`reasoning.3` / `tools.3` / `multiturn.1` 判据注明）· 其余 19 一致。
