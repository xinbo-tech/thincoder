### 2.3 机制判定（收敛 · 判由 ∥ 证据 ∥ 逐候选成立性）

**主因（收敛）= 窗口后台态的「停摆—复显」相变**：窗口后台（Chromium 原生遮挡判定 ⇒ 页面 hidden；Electron 默认 `backgroundThrottling: true`）⇒ 渲染 ∥ 动画 ∥ 定时器停摆 + 绘制停止 + 进程后台类；主进程侧事件流（IPC）不停 ⇒ 停摆期一切渲染请求延后、复显时刻**集中偿付**（引擎侧样式 ∥ 布局 ∥ 绘制 ∥ 光栅——软合成路径全 CPU 承担），且复显相变本身排队于未及时处理事件的主线程之后。

**判由**：
① 触发面锁定（§1）——两活体实录均落「已 focus ∥ visibility 未复/渲染停摆」窗（focus→visible 迟滞 = 17s ∥ 10s ≈ 用户所感假死时长）；rAF 停摆跨窗（22.2s）；复后 200/300ms 抖动；
② 应用侧偿付**可证有界**（帧合并单飞 + 脏键集 + 作业单闭集 + 面窗有界——`thincoder-render-core/flow/frame.mjs:26-68` ∥ `thincoder-desktop/renderer/store.mjs:100` ∥ `:143-147` ∥ `thincoder-desktop/renderer/views/chat-stream.mjs:23-72` ∥ `thincoder-desktop/renderer/views/chat-scroll.mjs:28`）⇒ 10–17s 不可能是应用积压量，只能是「相变 + 引擎侧偿付」的时长；
③ 签名排除项：JS 堆 ≤20MB（全样本）⇒ 非 GC；主进程健康（49–187MB ∥ 低 CPU）⇒ 非主进程；应用层零焦点回调面 ⇒ 非自身注册面。

**逐候选成立性（a–e）**：
- **a（遮挡停摆 + 复显冲刷）＝ 成立（主因）**——时相锁定 ∥ 应用侧有界性证明如上；「冲刷」在应用侧有界，时长由相变与引擎侧偿付支付。
- **b（帧循环追赶 ∥ 分块让渡）＝ 不成立**——帧合并单飞 + 脏键集（Set）∥ 作业单闭集，本无无界队列；分块让渡 = 改帧率语义（用户可见行为）⇒ 越界。
- **c（渲染规模）＝ 成立为放大器（非扳机）**——工作集 382MB–1.3GB 为全窗重绘 ∥ 布局的规模乘数；非遮挡期风暴族（往批 E2/E4-JS 在册）与本批同签名不同时相——本批零动。
- **d（软合成重绘）＝ 成立为放大器（应用不可改）**——`--disable-gpu-compositing` = 环境注入（全仓零代码命中；`scripts/desktop-debug.cmd:8` 亦不带）⇒ 不属应用修面。
- **e（堆/GC）＝ 排除**——JS 堆 ≤20MB（20+ 例全样本；往批 GC 假设已销）。
