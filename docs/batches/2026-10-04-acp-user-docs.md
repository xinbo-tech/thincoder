### 2.4 「及时」机制设计（E2 —— 已落）

**形式（两层）**：① **面清单 + 义务句**（板块级——单源 = `docs/cli/design/ACP-CLIENT.md` §14；正文单源判定 = 指南正文住站仓页，其余面 = 摘要/指针/提及，只引用不重述）；② **收口检查单槽位**（通用机制面——`docs/core/design/BATCH-RECORD.md` §5.3 前置块 ∥ `docs/core/design/DOC-DISCIPLINE.md` D7 行槽位枚举）。**触发 = 能力批收口轮**（缺口本体 = 能力批收口无同拍义务——本机制把义务挂上该轮；「用户可感」由收口轮判定，存疑 ⇒ 逐面对照兜底）。

**义务语义（照 §14 落文）**：用户可感能力变更（新增 ∥ 改变用户可见行为）⇒ 收口前逐面对照面清单：面 1（指南正文）**必更** ∥ 其余面**随核对**；落入 = ① 同批更新（跨仓**站仓轮**——页更新 + 部署；执行与判据 = `docs/RELEASE.md` §5.8）∥ ② **挂账有据**（台账行 + 触发批坐标）；**不得静默跳过**；无涉面批 ⇒ §6 记「用户文档面同拍：无」。豁免面 = `changelog.html`（发布环单源 = `docs/RELEASE.md` §6）。

**三面同步状态**（先例 = 2026-09-19 ledger-lifecycle 三面）：设计面（DOC-DISCIPLINE D7 ∥ BATCH-RECORD §5.3）= **本轮已落**；需求面（`docs/core/requirements/ENGINEERING-MODE-V2.md:602`）∥ 提示词面（`docs/core/design/prompts/discipline-engineering.md:160`）= **主 agent 域**（U1——不阻塞本批）。
