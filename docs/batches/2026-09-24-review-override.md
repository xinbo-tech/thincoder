### 2.5 关键决策

| # | 决策 | 理由 | 被否候选 |
|---|---|---|---|
| D1 | 改判落点 = **编排面**（`pipeline.mjs` executeRun），非渲染面 | JSON 是单源（md 完全由 JSON 渲染）⇒ 判定须在记录层翻转；下游（用例判定 / 矩阵 / 成本 / 告警 / 退出码）零改动自动随动 | 渲染面派生「有效判定」（被否：JSON 说 fail、报表说 pass = 两级真相）；新增 `effectiveVerdict` 字段（被否：全链聚合 / 渲染 / 重算都要改——为同一事实造第二真相源） |
| D2 | `run.detail` **维持原机械断言原文**（不前缀、不改写） | 判定与 detail 正交——detail = 机械判定当时的记录；纠正事实住 `runs[].review`（`⟲` + 复核理由） | 前缀式改写 detail（被否：语义漂移 + 复核输入取值的时序耦合，多一处出错面） |
| D3 | v4 报告**不重跑** | v4 翻案 0 起 ⇒ 改判规则对 v4 数据零作用（判定面等价）；重跑只换版本数字 + 重付全量被测成本；报告 = 时点产物，改档破「md 由 JSON 渲染」恒等式 | 重跑落档 + v4 清理（被否：零收益——KD-25 先例的前提（判据缺陷代际 · 数据不可比）在本批不成立）；报告内加注（被否：回改记录面 + md↔JSON 失配） |
| D4 | 复核**仍保持单判**（不因改判升双判） | 对照轴 = 机械 vs LLM（KD-18）；问题面窄且有据；双判成本 +100% 且无「无多数」降级路径；误翻案面由承接机制显影 | 复核同双判（被否：§2.11 判位数裁定 / KD-26） |
