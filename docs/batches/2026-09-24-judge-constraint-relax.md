### 2.2 机制设计（放宽后的口径）

- **允自判（无准入闸）**：判官三槽（A / B / C）可与本次被测集合重合——不设拒跑闸；判官不干预被测选择（用户 2026-09-24 03:16 裁定）。
- **明示三级（不得静默）**：① 同位（`provider:model` ∈ 被测集合 = 自判）⇒ 报告判官行标注「该位 ∈ 被测（自判）」；② 同渠道（provider 命中 · 异 model）⇒「与被测同渠道」+ 该位 `sameVendorAsTested = true`；③ 无重合 ⇒「与被测无重合」。三态各出 `warnings` 一条（点名位次与重合级别）。
- **标注源（D2 单源）**：渲染面从结果 JSON 派生（被测集 = `models[].provider:model`；判官槽 = `judge.judges[]` / `judge.arbiter`）——判官块**不另存字段**（重合事实已由两侧键共同承载；存第二份 = 可漂移的第二真相源）。
- **保留不动**：A≠B、仲裁员 ∉ {A,B}（判官内部配置面 · 引擎细节）· 判官必备（缺 ⇒ 拒跑）· `frozenAtSuiteVersion` 冻结绑定 · 预算下限与越界拒载 · fail-closed 降级三级 · 判官 / 复核成本分账。
- **`sameVendorAsTested`**：字段与计算式不变（渠道级重合布尔——同位态下必然为 `true`）；表述精度由渲染面三级标注承担；不新增字段（schema 零改 ⇒ 夹具 / key-set 断言 / JSON 样例零波及）。

### 2.3 三条设计结论（批次档 §1.2 交设计裁定）

1. **重合位标注 = 三级标注（渲染面派生）**：零标注会把「自判」这一实质事实静默（与「不得静默」原则冲突）；schema 增字段被否（冗余 + 波及夹具 / `report-render.test.mjs:179` key-set 断言 / `§2.2-7` JSON 样例）。
2. **`SUITE_VERSION` 不 bump**：判分口径（rubric / 提示模板 / 判官身份）零变化——放宽的只是启动准入闸；被放开的 run 此前不存在 ⇒ 无既有产物失效（v3 在档报告三槽与被测本就无重合）；bump 会令 `judge.json.frozenAtSuiteVersion = 3` 失配、强制重跑唯一在档报告，收益为零。
