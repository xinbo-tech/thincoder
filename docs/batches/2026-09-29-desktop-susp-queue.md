### 2.2 机制设计（三层链 · 逐处）

**破口复核（as-of 2026-09-29 03:3x 实读，与 §1 三链一致）**：① 宿主 `turn-driver.mjs:128-130` 窗内受理回执 `{ ok: true }`（无 `queued`）⇒ 渲染面无从判「入队」；② 核件面板 `composer/panel.mjs:300` 排队支 ⟺ `busyState() === "running"`（`susp` 落直发支）⇒ `mount-composer.mjs:148-157` `onUserEcho` 判据仅 `busyOf` ⇒ 窗内提交**写本地块入流**；③ 退流兜底 `composer-wire.mjs:55` 仅认 `queued === true` ⇒ 本径零退流；附：窗队不进镜面（`ev:queue` 快照只覆盖忙态队）。

**修向 = C（宿主面 + 端侧面并做）· 不触核件**——三层逐处：

**（1）宿主面**（`src/main/turn-driver.mjs` ∕ `suspension-drive.mjs`）：
- **窗内受理回执补 `queued` 标志**：`send` 挂起支 ⇒ `{ ok: true, queued: true }`（语义 = 「受理入队——消费前不入流」，与忙态队回执**同形同义**）；窗内携附件 ⇒ **同受理**（同回执形——**载具层携图**：窗条目携 `images`、送达面 `prepareTurnAttachments` 判决、降级码随 `delivered.degraded`；核件输入面 = 文本单形不变）；`busy` = 窗径竞态防御档（受理径无附件拒面——实际不可达）。
- **窗队共镜**（`ev:queue` 两源）：窗内受理 ∕ 窗内消费（`delivered`）∥ 残输入续发（逐条 `delivered`）∕ 窗中止清队（空快照）⇒ 帧；`entry.pending` 条目形 `{ text, ts }`（残输入兜底投影随形）；`suspension-drive` 注入 `postQueue`（= `chain.postQueue`——**帧构造仍单点住 `turn-chain.mjs`**，该档零改）。
- **并源读面**：turn-driver 供 `queueView`（`snapshot` = 忙态队 ∪ 窗队合并快照——窗读面懒取，构造后无早期调用）⇒ 链 `postQueue` 全帧与 `queueSnapshot`（`history:page` `queue` 键）**同源单点**。
- **两源互斥不变量**（单镜无交叠歧义之据）：窗开前忙态队已尽（`takeOver` 队列先于接管——续发至队空才入窗）；窗内提交恒走窗径（`send` 先判 `suspension.active`）⇒ 两队按键不同时非空；竞态残径（窗开 ∕ 忙态并存）下合并不变量 = 串联快照（忙态先）——显示恒为真值，零谎。

**（2）端侧面**（`renderer/views/chrome.mjs` ∕ `composer-wire.mjs` ∕ `mount-composer.mjs` ∕ `composer-sync.mjs`）：
- **判据单源**：`views/chrome.mjs` 增 `suspActiveOf(state, key)`（`busyOf` 邻位——同族）；`composer-sync.turnState` 改用之（零行为变，消重复直读）。
- **出泡钩抑制面扩 `susp`**：`onUserEcho` 判据 = `busyOf ∨ suspActiveOf` ⇒ 窗内提交**零本地块**（稳态零块——非「先写后退」）；**抑制径恒登记**（`noteEcho(key, null)`——退流锚恒指本提交，防误摘既往真块）。
- **回执面（`sendDirect`）**：队形回执（`queued === true`）⇒ ① `retractEcho`（滞后正径兜底——端判闲 ∕ 宿主已入窗的竞态窗：`ev:susp` 未至时本地块已写 ⇒ 此处退流）② **挂起空闲复位**：`suspIdleOf`（= `suspActiveOf ∧ ¬busyOf`）判据真 ⇒ `setLoading(false)` + `onLoadingReset()`——直发径未起跑 ⇒ `ctx.isRunning` 门禁归位（防窗内残余 Ctrl+C/I 假 affordance）。判据含 `¬busyOf` 之由：窗内回合（`running` 位标在）不得复位（防误关真回合的 Stop 门）。
- **失败径**（`ok` 假——queue-full ∕ busy ∕ provider-invalid ∕ aborted）：补 `retractEcho` ⇒ 本地块**退流** + 既有失败行（`[data-notice="send-failed"]`）在场；文本召回 = 输入历史 `↑`（既有单源，零新面）。判据 = KD-23 既有句「失败径仍『稿逐字留 + 零块』」——本地先行出泡之回滚面**即此退流**。

**（3）消费时刻交接**（与「出泡不变式」对齐）：窗内消费点 = `driveTurn` 用户回合（`!autoTurn`）∥ 残输入续发（`resumeResidual` 逐条）——同点出 `ev:queue` 消费回执（`delivered = { text, ts? }`，`ts` 缺省不携——禁假造）⇒ 归约面 `onQueue` **入流恰一枚**（键门 = 活动会话）；本地块零重复（本径零本地块 + 退流兜底）。**「每受理消息恰一枚真块」**：直发径 = 本地先行 ∥ 挂起径 = 消费回执补写——两写者按键互斥，无同条双现。

### 2.6 关键决策与 VSC 零回归依据

- **修向 = C（并做）· 不触核件**（逐候选给据）：
  - **A 单做（宿主回执 + 镜面）不足**：本地块先写后退 = **瞬态先写后退（可见闪烁）**（退流兜底终态亦零块——非稳态问题）；且无带面 ⇒ 带面判据（AC-1 后半）不达。
  - **B 单做（端侧判忙面扩 susp）不足**：宿主回执无 `queued` 时渲染面无法区分「窗内入队」与「直回合起跑」——`sendQueued` 兜底出泡（`composer-wire.mjs:75-78`）会把窗内受理写成消费前流内块（违 AC-1）；且无镜面 ⇒ 带面不可见（AC-1 后半不达）。
  - **C 采取**：A 的宿主面（回执 `queued` + 两源共镜 + 消费回执）+ B 的端侧面（抑制面扩 susp + 回执面退流/复位）——判据三面（零块 ∕ 带面 ∕ 恰一枚）逐条落位。
- **不触核件 `composer/panel.mjs`**（备选「gated deps 谓词 ⇒ 面板排队支扩 susp」被否，给由）：① 面板排队支的 `queueCount` 满队守卫会对窗队**隐式施加 8 上限**（宿主窗队无容量面 + 本批不增容量语义 ⇒ 违「其余可见面零动」）；② `_qLocal` 同 tick 自增语义属忙态队（窗队无本地计数面）；③ 共用件零改 ⇒ VSC 零回归为**结构性成立**（diff 判据），无需逐处行为核对。端侧直发支残余（`setLoading(true)` 之 `isRunning`）已由回执面条件复位消解（§2.2(2)）。
- **镜像形 = 扩 `ev:queue` 快照面（非新通道）**：带面 ∕ 段 14 ∕ 冷启 `queue` 键 ∕ 消费回执四面均已单写者挂 `ev:queue`；新通道 = 第二写者 + 归并层（面增），而并源在两源互斥不变量下**精确无歧义** ⇒ 最小改动胜。
- **失败径 = 退流 + 失败行（非保留）**：保留块 ⇒ 违 KD-23 既有判据「活流块 ⟺ 该条已受理」+ 重试成功同条双现；退流后「零块 + 稿留历史」= KD-23 失败径原句（本批补齐其本地先行回滚面）。
- **窗队容量 = 不增**（无判据要求；VSC 侧 `susp.pendingInput` 有 8 上限——端差登记观察，见 §2.8 #4）。
- **VSC 零回归判据**（单源）：`thincoder-render-core/**` 与 `thincoder-vscode/**` 零改（AC-7 机检 diff）+ 桌面只改端侧（renderer 四档 + main 两档）——VSC 消费面（`panel.mjs` ∕ `queued-mark` 流内标记形）逐字零变。

### 2.7 边界（不做）
