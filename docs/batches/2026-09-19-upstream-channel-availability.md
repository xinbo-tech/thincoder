### 2.3 设计结论（交付二：主分支 = 唤醒面）

1. **唤醒条件** = 入队一条 `kind:"ask"`（`parent-channel.mjs:88-95` 之后）；`note` 不唤醒（避轮风暴，登记为可一行扩的边界项）。
2. **唤醒实现** = 复用 W1 通道：核单点 `wakeAsyncWaiters(parent)`（现 `async-settle.mjs:281` 的 `splice(0)` 循环逐字迁入；settle 尾改调用同函数）+ `pushChildUpstream` 的 ask 分支尾调一次。
3. **开轮谓词** = `upstreamWaiting(carrier)`（`parent-channel.mjs` 新导出；`carrierField` 吸收；队列中存在 ask 为真）——三驱动第 2 步判据追加（核 `suspension.mjs:187` · CLI `:231` · VSC `:283-284` 对位）。
4. **轮类型 / 注入 / 回复** = auto 轮（`autoTurn: true` 不变 ⇒ spawn 门 / guard 继承 / resume 语义沿既有）+ 新旗标 `upstreamTurn`（仅供域文本选择）；注入点（`agent.mjs:225`）与回复路径（`send` → `subagent-actions.mjs:319-320` → 子 `agent.mjs:223`）**零改**；**回复可达性实核** = `send` 属 dispatch 控制类豁免（`dispatch.mjs:97-99` → `:257` 免权限门；auto 轮门 `subagent.mjs:186` 只覆盖 `escalate`）⇒ manual 档 auto 轮内可调。
5. **域文本** = 新常量 `UPSTREAM_TURN_DOMAIN`（`agent/helpers.mjs`）——digest 域文本（「No one is waiting…organize only」）与 ask 轮相抵，**不得沿用**；逐字建议见 §6.27.12.8，**内容权 = 父侧**（落笔前须父侧确认字面）。
6. **不变量守护声明（五条逐条）**：① 非阻塞地基**结构不变**——`notify_parent` 侧零改、无等待 / 拉取导出，唤醒为同步调用；② F-UC1–F-UC6 语义零改（无降级分支落地）；③ **零新增计数 / 上限**——无新常量、无新门（`UPSTREAM_*` 三常量语义与数值零改）；④ 不动 consult / depth-0 面（装配面与判定条文零触）；⑤ settle / digest / 用户输入三路唤醒语义零回归——`wakeAsyncWaiters` 抽自 settle 尾（循环体逐字，唯一差分 = 读径改 `carrierField` 吸收，严格超集）+ U5 全绿判据。
