## §1 本批目标与条目（主 agent）

**交付目标**：工程模式 v2 · 阶段 1 = 研发项目机制本体的**架构设计（Architecture Design）**。

**本批条目**（对应 v2 需求草案第 5–9 章，逐一给架构级方案）：

| # | 条目 | 需求依据 |
|---|---|---|
| 1 | 三账架构：PROJECT-MANIFEST（JSON）· 台账（SQLite）· 批次档（md）——各账落地形态 + 三账咬合 | v2 §5 |
| 2 | 文档体系架构：项目需求/功能规格/架构设计/模块设计 四层 + 目录约定（默认值 + 声明面覆盖） | v2 §6 |
| 3 | 角色架构：主 agent / eng-designer / eng-coder / advisor 四角色 + 写权矩阵 + 互锁机制 | v2 §7 |
| 4 | 规则架构：交接契约 / 委派治理 / 纪律兜底 / 提示词单向生成 / 测试纪律（简化）/ 机检引擎（一个引擎+声明面） | v2 §8 |
| 5 | 情境架构：阶段 / 接入 / 轮次三旋钮 + manifest 字段落地 | v2 §9 |
| 6 | 评审与凭证：advisor 设计评审 + token 门（继承 v1，只微调） | v2 §8.5 |

**边界**：
- 本批只出**架构设计**（阶段 1），不做实现；
- 委托开发方法论（v2 第 4 章）与对甲方的交付物，**延后到阶段 2**；
- 需求草案原文 = 设计唯一依据，**只许引用、不许改写**（用户 2026-09-17 明确：怕「精化」丢细节）。
