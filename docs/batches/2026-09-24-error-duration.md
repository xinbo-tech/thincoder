### 1.1 目标与裁定

**事实链（父侧实核）**：v4 中 `qwen3.8-flash` 的 `instructions.3` run = `error`（`detail` = 「接口错误：TimeoutError: The operation was aborted due to timeout」）——`calls[0].totalMs` / `run.metrics.totalMs` 均 `null` **且从未记录**（client 层超时路径未落盘耗时）⇒ 用时表按「`null` 不计入」排除（脚注已明示）⇒ **qwen 累计 170115 ms 未含该次超时**（超时上限 = 120 s（`--timeout 120`）⇒ 实缺 **≈120 s**）。
**影响（推算 · 近似）**：补录 ≈120 s 后 qwen ≈ 290 s **将落到第 3**（现列第 2；mimo 175781 ms 升第 2）——**失败代价不进合计 ⇒ 排名失真**。

**裁定**：
1. **采集面**：失败调用（超时 / 接口错）**记录其耗时**（发起 → 失败的墙钟——client 层 catch / abort 处落盘 `totalMs`；ttft / tokens 仍按实缺 `null`）；
2. **计时口径**：`totalMs` 语义 = 该 run 实际占用墙钟——失败调用照记；成功路径口径零改；
3. **用时表**：「`null` 不计入」保留（**未记录才不计**）；采集补全后 error run **自然照计**；脚注保留（「未参与累计」明示）；
4. **v4 追溯**：该次耗时**已丢**（日志仅「→ error」无耗时 · 前后行无时戳）⇒ v4 在档保持现状 + 脚注；**不重跑**（用户未点名）。
5. **版本口径**（记录面补全是否 bump）= 设计轮给结论（倾向不 bump）。

### 2.2 机制设计（实现形态 · 精确落点）

**① 采集落点 = `bench/lib/client.mjs` `runCase`（唯一功能改点）**：

```js
const callT0 = Date.now()                 // 新增：call 尝试点（try 之前）
let call
try { call = await transport.call({ … }) }
catch (e) {
  const rec = { round, ttftMs: null, totalMs: Date.now() - callT0, tokens: null, toolNames: [], finishReason: null, throttled: false }
  …
}
```

- 观测点 = **调用侧**：传输面抛错时「发起 → 失败」的唯一可靠收口位（错误对象挂耗时 = 被否候选 ①——设计档 KD-30）；
- 记录式与成功路径同源（`Date.now()` 差）——不引入夹取 / 下限；
- **任何**传输面抛错（超时 / 接口错 / 夹具脚本耗尽）均照记——≈ 0 ms 亦如实记录（不设阈值、不回落 `null`）；
- 该路径同时服务用例 lane 与人工 lane（`pipeline.mjs` 两处 `runCase` 调用）与 dry-run 夹具传输——语义单源。

**② 口径 / 呈现面（注释与文案 · 零公式改）**：`metrics.mjs` 头注 + `runMetrics` 注释补「total = Σ per-call 耗时（成功 = 传输面实测；失败 = 发起 → 失败墙钟照记）」；`report-time.mjs` 口径行须含两短语「error run 已记录耗时照计」「`null` = 未记录」+ 脚注句加「未记录」定性（= `render.4` ⑦ 的断言面）；Σ / 倍率 / 排名 / 采样 / 脚注算式零改。

**③ 版本口径 = 不 bump（结论）**：规则层（测什么 / 怎么算 / 什么进数字）零改——本批 = 实现向已宣告规则（§2.3-7「error run 已记录耗时照计」）对齐的**采集完整度补全**；bump 的机械代价 = `SUITE_VERSION` 单轴整数 ⇒ 连带改 `judge.json.frozenAtSuiteVersion`（`bench/lib/judge.mjs:82-83` 不等即拒跑）⇒ 向「判分口径换代」发假信号；可比性由在档自述承载（v4 用时表脚注明示 1 个 run 未参与累计）。
