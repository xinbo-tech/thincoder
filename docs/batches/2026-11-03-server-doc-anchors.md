## 2.1 方案与理由

**决定**：把两档内每一条 `.md` 指针改成**仓根起解析得通的形**（默认 = 仓根全路径；两类例外见 2.7 K2），指向不变、语义不变；三行已删档引用按 D8 删句；两段超长按结构重组拆开。**不新建文档、不改机制、不动代码。**

**理由（三条，均本轮实测）**：

- **只有全路径形稳定**：解析序 = ① 仓根相对全路径 → ② 引用方档所在目录。`thincoder-core/doc-check/anchors.mjs` 档头逐字「① 仓根相对全路径 → ② 引用方档所在目录相对。零命中 ⇒ `档缺`，并**列同名候选**」。写回溯前缀那一支无效——抽取式的左界排除集含 `/`，回溯段整段被吃掉，抽出的 token 仍是子目录段形，两级都不命中。⇒ 全路径是与解析序无关的形。
- **本仓已有书写纪律，不是本席自定**：`docs/core/design/DOC-DISCIPLINE.md` 逐字「**书写只有一个答案：全路径。** …③ 给的是**书写规范**——规范档之间互引同样写全路径（「锚写自仓根完整路径」无条件成立）。据 ① 把裸名当安全写法是本末倒置：档一搬家，它就成悬空。」
- **同病存量不止机检报出的那部分**：同档逐字「**存量无豁免**：既有存量（含历史行）同属违规，**不得以「存量 / 入基线」申请豁免**（阈值 = 0）。」＋「触达即清——本批碰到的档，命中就在本批修；改动不改变命中是否归本轮。」两档都在本批写面内 ⇒ 存量归本轮，逐类见表 1B。

## 2.2 机制设计（目标态）

**目标态一句话**：两档内任意一条 `.md` 指针，**从仓根起就能解析**，与它住在哪一层、以后搬到哪一层无关。

```text
形                       例（引文，不作档面写法）          解析序①命中  搬一层后
仓根全路径（目标形）     docs/server/design/webui/ADMIN.md   是            仍是
只写子目录段（现病形）   webui/ADMIN.md                      否（靠②接住） 断
```

**接口契约（本批无新增接口）**：

| 面 | 改前 | 改后 |
|---|---|---|
| 指针形 | 两档混用子目录段形与全路径形（逐类见 2.4 表 1A ∥ 表 1B；门看不见的行见 2.4.5） | 统一仓根起解析得通的形——无例外类 |
| 指向语义 | —— | **零变**：每处仍指原来那一个档（逐类见 2.4 表 1A ∥ 表 1B） |
| 已删档引用 | 3 行点名一个已退役对象 | 该对象不再被点名（D8 删句） |
