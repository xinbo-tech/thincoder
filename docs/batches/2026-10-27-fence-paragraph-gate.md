## 根因

`thincoder-core/doc-check/paragraph.mjs:27-30`：

```js
export function fenceMark(l) {
  const m = /^\s*(`{3,}|~{3,})/.exec(String(l))
  return m ? m[1][0] : null        // ← 只取「第一个字符」，长度丢失
}
```

闭合判定只比对字符（`:101` `else if (mark === fence) fence = null`）⇒ 四反引号 ```` ```` ` 与三反引号 ` ``` ` 返回同一个 `` ` `` ⇒ **外层围栏被内层开启行提前闭合**，其后代码行按正文处理并合并成段。

**同一份逻辑**在 `thincoder-core/doc-check/anchors.mjs:109-117` 复制了一遍（`:114` `else if (mark === fence) fence = null`）——**同一处 bug 两个落点**。

## 影响面

- **判据误报**：任何含嵌套围栏（README 展示代码块的常规写法）或围栏内含反引号行的文档，其代码行被并成段，超 300 字即误报「文字太长」。
- **误报的代价**：`doc_check` 是交付门（`mode:"gate"`），误报会拦住正当交付，或逼作者为过门而压代码块行数——**判据反过来塑造了文档**。

## 修法

`fenceMark` 返回 `{ ch, len }`（标记字符 + 长度）；闭合条件 = **同字符 ∧ 长度 ≥ 开启长度**（CommonMark 的围栏闭合语义）。两处块扫描（`paragraph.mjs:98-105` ∥ `anchors.mjs:109-117`）同步改；`isFenceLine` 判 `!== null` 不受影响。
