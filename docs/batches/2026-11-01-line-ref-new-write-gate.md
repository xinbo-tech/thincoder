## 1. 讨论与结论（主 agent）

**覆盖账 = #1964**

### 1.1 用户令（逐字 · 两条）

> 20:52：「**我不管原来是怎么样的，细则是怎么说的，我只有一个强制性要求：不能用行号做引用**」
> 20:54：「**我没要求你现在就扫存量，但是必须先把新增阻止住。不能再有任何例外，任何开口。**」

### 1.2 这两句合起来的意思

**规则已经有了**（`docs/core/design/DOC-DISCIPLINE.md:49` 起，父侧已落）：指规则用节名 + 逐字引文、指代码用符号名、读数不配行号。

**但它现在只是一条纪律，靠人记。** 用户要的是**机械闸**：**新写进去的，当场拒。**

**并且「不能有任何例外、任何开口」** —— 这句话把设计空间压到只剩一条：**判据不能有豁免名单。**

### 1.3 设计约束（这三条决定了形态）

**① 闸只能看新增行，不能看整档。**
存量活档约 6,000 处、生成区 4,631 处 —— 整档判会把所有档锁死，**而锁死之后唯一的出路就是造一张豁免名单**，那正是用户禁掉的「开口」。

**② 判据 = `git diff` 的 `+` 行。**
新增行是「这一笔写了什么」的机械事实，存量天然不在里面。**不需要豁免名单 —— 因为它从一开始就不判存量。**

**③ 落点选在交付门，不选在写工具。**
写工具对内容无判别语义；交付门本来就在判「本轮写了什么」，**多加一条判据不新增机制面。**

### 1.4 要判清的一件事（设计席答）

**行号引的形态怎么认。** 盘上已有 `docs/core/design/DOC-DISCIPLINE.md` 的 §3.21 条目 T（三形闭枚举：文件坐标 / 符号坐标 / 裸坐标）。

**本闸用哪几形、为什么排除另外几形**，要给理由。**只要有一形被排除，就必须说清它为什么不会成为「开口」。**

**已定的一条排除**：符号坐标（`maxTokens:131072` 这类）在代码里与值字面不可分，条目 T 已判它是假阳面 —— **这不是豁免，是它根本不是行号引用。**

### 1.5 设计席任务（父侧口述落档 · 排队中，起来先读本节）

**一句话**：**给交付门加一条判据 —— 新增行里出现行号引用 ⇒ 拒。**

**形态三条（已定，不要重开）**：

1. **只看新增行**：判据域 = `git diff` 的 `+` 行（相对 HEAD 的工作树改动）。**存量不进判据域** —— 这就是「不需要豁免名单」的全部理由。
2. **判据域覆盖全仓跟踪面**：`.md` / `.mjs` / `.js` / `.cjs` / `.json`。**不做「只判 docs/」的收窄** —— 收窄就是开口。
3. **拒文要指名**：`档:行` + 那一行的原文片段 + 该改写成什么（节名 + 逐字引文 ∥ 符号名 ∥ 量法 + 日期）。**拒文只说「不许」等于没给出口。**

**你要判的三件**：

- **形态闭枚举**：用条目 T 的哪几形？裸坐标（`:NN` 无路径）算不算?**算与不算都要给判据，且判据本身要能判否。**
- **误阳面**：`http://x:8080` · `10:30` · `maxTokens:131072` · JSON 的 `"a":1` —— 逐类给出处置与理由。**处置不是豁免，是它不构成「指向某档某行」这个语义。**
- **既有测试面**：加了这条，`thincoder-core/doc-check/**` 的既有用例会不会红（它们自己的夹具里可能有行号引）。**先量再写。**

**写域**：`docs/core/design/DOC-DISCIPLINE.md`（新判据的规范句 + 条目表）+ 本档 §2。**代码面零触**（实施轮）。

**交回来**：① 判据句逐字 ② 形态闭枚举 + 逐类误阳处置 ③ 与既有条目 T 的关系（扩展 ∥ 并列 ∥ 取代）④ gate 首行。
