### 2.5 承接机制设计（产出-承接-销账 · 落点机制正本 = 设计档 §2.12）

1. **产出（机器 · 每次运行）**：报告《复核翻案》小节尾部「承接清单」段（渲染面从 `runs[].review.verdict === "overturn"` **派生** · 按 `caseId` 归一 · 不新增 JSON 字段）+ 控制台复核计数行与「翻案 ⇒ 判据修复必修（承接清单见报告《复核翻案》小节）」提示。
2. **承接（人工 · 主 agent）**：逐条落**台账**（`kind=tech_todo` · `board=MODEL-BENCH` · `status=待设计` · evidence = 报告 md 相对路径 + 机械失败断言 + 复核理由；**同 `caseId` 多条 run 翻案 = 一条条目**）；修复批直接立批时，条目可由该批需求条目承担（先例 = 台账 #253）。
3. **销账（人工确认 + 机检证据）**：状态流 待设计 → 在途（立批）→ 待核销（修复落地）→ 已核销（主 agent 确认）。**关闭证据（机检化）** = ① 该 `caseId` 定点复现用例在册（构造串：修复前 fail / 修复后 pass——首例 = `judge.13` / `text.1`）② `SUITE_VERSION` +1（代际标记，同步 `judge.json.frozenAtSuiteVersion`）③ 条目 evidence 记修复批档坐标。**不为每条翻案强制全量重跑**（成本；重跑按 §2.7 场景与用户点名）。
