### 2.3 处置标准（单一判据）

**处置单位 = 行，结论只有三种**：

| 处置 | 判据 | 说明 |
|---|---|---|
| 改指 | 该行的指称对象还活着，只是坐标旧了 | 目标须盘上可解析；改后复扫零悬空 |
| 改述 | 对象没了，行内的现态语义还在 | 去掉死坐标 / 死词形，保留现态论断——不得换名了事 |
| 删 | 行内除旧值之外无现态内容 | 整行删；同轮扫该档与兄弟档引用，悬空同轮收正 |

三种之外**没有第四种**。「零触碰 / 保留 / 在册 / 残差 / 基线」不是处置结论。

**为什么时点锚不再是处置依据**（本批的因，不是本批的账）：

读数行会被检索当成现行做法——检索不带「这是历史」的标签，旧读数与现读数在读者眼里同形、同权。作者一旦能靠「这行带日期」换到免改，他就有动机把现状写成带日期的形状：写「某日实读 = N」比写「判时实读」省事，而后者才是能自判的形。
所以判类只看行内现态语义在不在，不看这行是不是读数、带不带日期。

**身份判法（父侧 §1.11 ① 的硬约束）**：例外的判法只能是**身份**，不许是**位置**。

- 身份 = 逐处读原文判它是什么（读语义判）。
- 位置 = 某个行号区间 / 某张清单 / 某个目录。以位置划定的例外就是自留口子的标准形。

**§4.5.4 例外三条（已裁 · 保留，理由是身份不是位置）**：① 规则正文须能写出被禁字面（删掉规则就写不出来）② 角括号占位模板不指向任何在盘档 ③ 目录级归属句指整树不指某一次执行。
`:1900` 那句「例外集不得当作机判豁免位写入脚本」留——它是防止例外变成免检点的唯一一道。

**「为什么」的写法（用户 §1.13 裁定）**：写机制因果，不写事故叙事。

| 形 | 例 | 判 |
|---|---|---|
| 机制因果 | 「旧读数会被检索成现行做法——检索不带『这是历史』的标签」 | 留：现在仍成立，读者据此能判新场合 |
| 事故叙事 | 「2026-10-14 那次清理开了这个口子」 | 删：这是历史，本身即污染源（git 里有） |

**自判验收（并入 A 组）**：改完之后，一个只读该档、没见过用户的场合，遇到「这张表是读数，删不删」能自己判对；判不对 = 因没写够，退回重写。
