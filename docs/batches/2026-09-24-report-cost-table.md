### 2.3 机制设计（要点）

1. **成本表列集 = 五列**：{模型 · 总成本 · 每任务成本 · 每通过任务成本 · 相对成本}——判官 + 复核两列渲染删除；脚注 = 分账原则句（含「不参与相对成本归一化」· **不列金额**）；「判官位未录价 ⇒ 成本列 = 已录价位之和」缺价句随金额一并退场（金额零展示 ⇒ 该句无指涉；缺价面仍由 `warnings` + 控制台承载）。
2. **报告零展示评估开销金额（三处）**：① 成本表；② 概览账目句 → **评估开销分账句**（原则保留 · 不列数字 · 账目见结果 JSON）；③ 判官行逐位「成本」字段（其余字段照留：provider:model / 参数 / 模板版本 / 调用次数 / 与被测重合标记）。**统计 ≠ 开销**：调用次数 / 分歧率 / 仲裁 / 复核次数 / 翻案 / 复核失败住非成本面（判官行 / 告警行 /《复核翻案》）——不重复列于概览。
3. **JSON 字段零改**：`judge.judges[].costCny` / `judge.arbiter.costCny` / `judge.costCny` / `review.costCny` / `aggregate.judgeCostCny` / `aggregate.reviewCostCny` / 逐位逐尝试 `calls[].costCny` 照记照算；`--recompute` 照旧重算（`recompute.5` 断言零改）；分账规则（不进 `runs[].metrics.cost` / `aggregate.costCny`）与相对成本归一化零改。
4. **用时表**（KD-28）：列 = {模型 · 累计耗时 · 相对倍率 · 排名 · 采样 run 数}；累计耗时 = Σ 该模型面内**实际执行** run 的 `runs[].metrics.totalMs`（`skipped` 不入；**error run 已记录耗时照计**；`null` 不计入 + 脚注 · 全 null ⇒ 格 `—` 居末）；相对倍率 = ÷ 表内最低者（1.0× · 同成本表「相对成本」体例）；排名 = 升序 · **同值并列顺延**（1 · 1 · 3）；落位 = 速度表后（结果段序：能力矩阵 / 速度表 / 用时表 / 成本表）；轴门控 = `speed`（CLI 词表零改）；与速度表「总耗时（中位）」口径不同、并存。
5. **版本与在档口径（KD-27）**：两项变更均属**呈现面**（数值 / 判定 / 分账 / 计时零改）⇒ **不 bump**（`SUITE_VERSION` 恒 5 · `judge.json.frozenAtSuiteVersion` 恒 5 ⇒ 判官配置档零改）。理由：`SUITE_VERSION` 与 `judge.json.frozenAtSuiteVersion` 机检绑定（`bench/lib/judge.mjs:82-83` 不等即拒跑）——呈现面 bump 会强制改判官配置档（判官身份零变化）并把「判分口径换代」的错误信号写进版本号；版本号语义 = 测量与判定口径（KD-2）⇒ 在档报告与新版报告数字同源可比。
6. **在档报告（`bench/results/2026-09-24-flash-compare-v4.{md,json}`）**：**产物零改**（不重跑 · 不重渲染——KD-10 覆盖保护 + 本批禁令）；在档 md = 本批前形态（含判官 + 复核两列 · 无用时表）——**形态注**住设计档 §3 行 + README；**数值零改 ⇒ 数字读数仍有效**；现行形态 = `--recompute --from bench/results/2026-09-24-flash-compare-v4.json`（落 `flash-compare-v4-recalc` 新对；原档不动）。
   **可选处置（超本批禁令 · 需用户点名）**：① 「在档即现行形态」⇒ 人工删旧对 + 同参重跑（§2.1-7 同名拒写 ⇒ 无静默覆盖路径）；② 或 `--recompute` 落 `-recalc` 对（两对并存）。设计侧不自行择一。
