## §1 讨论（主 agent）

### 批次范围

**第 4 批 = C（批次档段写入工具）**——用户 2026-09-10 实测反馈带出：*「CLI 我试用了一下，至少到 designer 都还正常，还没开始评审。我觉得是不是评审要先把 C 落地啊？」*

**本批 = C（批次档段写入工具）**——**编号避让**：并行会话的「模型选择面重构」批（`2026-09-10-MODEL-SELECTION.md`）已用序号「第 3 批」，本档**改称第 4 批**（同仓并行，主题为身份、序号只作序）。

**动机（用户判断）**：第 2 批已落地 **§2（designer 自写）**；本批做 C 才能补上 **§3（评审自写）**——否则六段里 §3 永远靠父侧代写。
顺序理由：**VSC 镜像会把六段机制原样搬过去，C 没定就会把「§3 靠代笔」复制过去**（镜像面返工代价更高）。

### 谈成什么（逐条——2026-09-10 用户裁定）

1. **形态 = 批次档段写入专用工具**（用户：「给个批次档专用工具？」）：一个**无路径参数**的工具（目标档由 spawn 注入 + 门禁）——**语法上写不到别处**。
2. **角色 × 段白名单**：`eng-designer → §2` · `设计评审子代理 → §3` · `eng-coder → §5`；跨段/越段写入被拒——「一段一作者」由纪律升为**机械事实**。
3. **append-only**：只追加，不覆写不删除；多轮评审 → 追加 `### 轮次 N（评审子代理）`。
4. **§3 内容 = 完整发现表（用户拍板）**：用户问「最后不是有个评审结论吗？」「那个红黄蓝的表要没有还有什么意义？」——**裁定 B：🔴/🟡/🔵 发现表全文 + VERDICT + 计数都落档**（理由：评审报告只活在 session，批次档是唯一持久档案）。
5. **逐字不经转述**（用户质疑点）：表由评审者自己原样写入，父侧不得代润色/缩减。
6. **凭证行由工具剥除**（§2.7 既有铁律）：token/designId 形态行写入前过滤——**模型可能忘，机械不能忘**。
7. **父代理段（§1/§4/§6）不纳入工具**（用户默认采纳）：父代理走普通文档写，本工具只管子代理各写己段。
8. **来源戳**（用户默认采纳）：工具加盖 `轮次 N（评审子代理）`——代写与否一眼可辨。
9. **失败明示**：写不进去 → 报告「§× 未写入」；回退父侧代写**必须打标**（不得静默、不得假装写过）。
10. **安全面不扩**：**代码评审保持纯只读**——写权只对**设计评审**开，不给 advisor 通用 `write`。
