### 2.3 机制设计

**病灶（实读 2026-10-08）**：`streamHttpResponse`（`thincoder-core/proxy.mjs:85`）响应体路径 = 头到齐 ⇒ `remaining` 首段直写（`:140-141`）+ `sock.pipe(body)`（`:142`）；`text()` = 原样 concat（`:160-164`）。**全档零分块解码** ⇒ 携 `Transfer-Encoding: chunked` 的响应把块长帧（`<hex>\r\n`…`0\r\n\r\n`）原样吐给消费方：探针 `text()` = `7378\r\n{…` ⇒ `JSON.parse` 失败 ⇒ `non-JSON response`（gemini 桌面「校验失败」定案）；SSE 面 = 帧字节（CRLF + hex）插进事件流（块边界落在线中 ⇒ `data:` 行被提前截断）。
**判定键**：按 `Transfer-Encoding` 末段 token（大小写不敏感）= `chunked`。证据 = 同 URL 同代理 curl 解出 24315B 合法 JSON（curl 按头解码）⇒ **头在场**；不做启发式嗅探（头缺席而帧在场 = 协议违规，见 §2.9 边界）。

**单点**：解码阶段落 `streamHttpResponse`——两条代理分支共用（https：`tunnelHttps` `:237` ⇒ 本函数；http：`proxyFetch` `:299-302` ⇒ 本函数）；直连分支（无 `proxyUri` ⇒ 原生 `fetch`）零触（undici 自解）。

**数据流（改后）**：
`sock 'data'` → 头阶段按**字节**累积（`Buffer`，替代 `:122` 的 `toString("utf8")` 往返）→ 命中 `\r\n\r\n` ⇒ 解析响应头 ⇒ 取 `remaining`（Buffer 副本）⇒
- **非 chunked**：`remaining` 直写 body + `sock.pipe(body)`（现状语义，零动）；
- **chunked**：挂 `sock.on("data")` ⇒ 解码器 `push(d)`（`remaining` 先入）；解码器 `onData` ⇒ `body.write()`；`onEnd`（`0` 块）⇒ body 结束（不再 `pipe`）。

**解码器（新档 `thincoder-core/proxy-chunked.mjs`——流式状态机）**：
- 状态流 `size → data → crlf → …`（块数据到达即吐 `min(可用, 待吐)`，**只保有帧头**——`size` 行上限 1KiB，超限判畸形）；
- `size` = 十六进制 + 可选 `;扩展`（扩展忽略）；块尾须恰为 CRLF；`0` 块 ⇒ `onEnd`（其后 trailer ∥ 余字节读取即弃——`Connection: close` 语义下无复用面）；
- **畸形回退 = 透传**（倾向案——P1）：已持有字节原样吐出 + 其后全部字节直通；不报错（不把协议违规升级成连接失败）、不截断（零静默丢数据）、回落今日行为（违协议代理此前「能用」形态零回归）；
- 终止面：`0` 块之前对端断连 ⇒ 流截断，语义同今（body 随 `sock` close 结束）；
- API：`createChunkedDecoder({ onData, onEnd }) → { push(buf), mode }`（`mode` ∈ `chunked` ∥ `raw` ∥ `done`——供测试与诊断）。

**body 结束幂等**：`0` 块（解码器）∥ 对端 close（现 `:167-170`）两径都会 end body ⇒ 加 `writableEnded` 门（同处一行）。

### 2.7 关键决策（K1–K5）

| # | 决策 | 理由 / 否决备选 |
|---|---|---|
| K1 | 解码落 **`streamHttpResponse` 单点** | 两条代理分支共用 ⇒ 一处覆盖全部消费面（探针 ∥ 拉取 ∥ SSE ∥ web ∥ 标题）；直连面原生 `fetch` 自解零触。被否：各消费点自防（复写多处 + 漏面） |
| K2 | 解码器**独立成档** `proxy-chunked.mjs`（≈70 行） | `proxy.mjs` 303 行已越 300 咨询线且 #1042 在拆；状态机自持、可独立单测；先例 = `stream-destroy.mjs`（35 行单点档）。被否：内联 `streamHttpResponse`（越线叠加 + 测面被迫过 socket） |
| K3 | 畸形帧回退 = **透传**（倾向案，P1） | 零静默丢数据；违协议代理此前「能用」形态零回归；不把数据问题升级成连接失败。被否：报错（消费面文案退化 + 违协议代理从「能用」变「不可用」）∥ 截断（SSE 面静默丢尾 = 假正常结束） |
| K4 | `content-encoding`（gzip 族）= **列册边界**，本批不处置（P2） | 代理分支请求不发 `Accept-Encoding`（`proxy.mjs:181` 实读：仅调用方 headers + `Host` + `Connection: close`）⇒ 合规服务端不压缩；复现响应无 `content-encoding`；同族修复形态已知（同单点加解压阶段）⇒ 记账待触发，不预扩范围 |
| K5 | 头阶段缓冲**字节化**（`Buffer` 累积 + 副本交接，替换 `:122`/`:140-141` 的 utf8 往返） | 解码器须以字节接手 `remaining`（chunked 首段衔接 = 本批设计点）；顺带修正二进制载荷在头/体交界的 utf8 污染（同一行改动面）；文本响应零可观测差异 |
