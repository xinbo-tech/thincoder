## 要治的病（本会话同一晚两次，都不是假设）

**① 父侧把一个不存在的条文挂到档名下。**
我说「存量太大就别碰」是 `docs/core/design/DOC-DISCIPLINE.md` 的规定。用户问了一句「这是我们的规则吗」，实读该档：写的是**反面** ——「**存量无豁免**：既有存量（含历史行）同属违规，**不得以「存量 / 入基线」申请豁免**（阈值 = 0）。」全档十二条相关命中，**没有一条**是我说的那句。

**② 设计席把注释当契约。**
设计档写「`ledgerQuery` 不传 `boundary`」，依据是 `thincoder-core/agent/live-batch.mjs` 的**注释**；而 `thincoder-core/ledger-db.mjs` 的 `@param` 写着**必传**，体内 `resolve(boundary)`。照设计档写，写门会把每一笔写都拒。

**⇒ 两次的共同点：引的是**二手**（记忆 ∥ 注释 ∥ 转述），而**判据必须满足的是一手**（规则原文 ∥ 契约声明）。**
**⇒ 而现有验收抓不住**：行为判据全绿，因为「档写反、代码写对」两边各自自洽。

## 三条让它不变成体系（父侧定，不许扩）

1. **只认带标记的行** —— 普通叙述一句不动，不加维度、不做全档扫描改造。
2. **只查「存不存在」** —— 不判它是不是对的依据（那是甲的事）。判据越界就会变成新的误报源。
3. **存量天然为零** —— 老文档没有这个标记，一条命中都没有 ⇒ **不需要任何豁免通道**。这条最要紧：不许出现「老的可以不改」。

## 边界（不做）

## 关键决策

1. **最接近先例 = 锚判据本体**（`anchors.mjs` 的 `档缺` ∥ `节缺`）：对齐——同一档、同一抽取面、同一解析序、同一 verdict 词；偏离 = 只多一个命中类名 `引缺`（理由见上抛 ①）。
2. **不加第二个检查器**（§1 边界）：引文判定并入锚判据的同一遍逐行扫，判据面仍是两条（引缺是第 ① 条内的一个命中类，不是第三条判据）。
3. **存量为零靠实测不靠声明**：读数与域 = 设计档 §3.25 存量条（主读 标记形 0 行 ∥ 副读 `引缺` 0 条）；档数不入判据，同一读数即「不需要豁免通道」的判据。
4. **空引文不立分支**：`「」` 不构成标记——一个从没出现过的输入不配一条防御支路；代价写进设计档边界。
5. **引文只做 CRLF 归一与首尾去空白**，不做空白折叠 / 全半角 / 大小写换算：判据越界就是新的误报源（§1 第二条）。
6. **不判「是不是对的依据」**——注释里那句逐字存在也照样过（§1 已明写乙只能抓一半），归甲。
7. **集成用例走「本次写入文本」而非「触达账」**（第 2 轮 #3 裁定取甲）：写门对两处命中打两种标签——落本次 append 正文（同目录片段档）⇒ `本次写入文本（锚 N 条）`；落写者触达账 ⇒ `触达账（锚 N 条）`。用例要测的是「写者往档里写错引文、当场被拒」，所以错引文写进被写的这一段；写成「某档进触达账」测的就成了「触达账里有一处错」，离用户动作远一层。实跑读数与逐字串 = 设计 §3.25「实跑读数」行。
8. **判据面不放档数**（第 2 轮 N1）：存量为零只写「标记形 0 行」，档数随文档增减而漂，写死的值每变一次就失真一次（同 `A-DD19` ④）。
9. **泛指族补进 `A-DD26` ②**（第 2 轮 N3）：原判据式只抓带节号的指针，无节号的泛指（`本批` + 声明文件清单 / 受影响文件表 / 任务书）落在射程外——补一臂按族不按枚举；现盘复扫该臂新增命中 **0**（读数见上节复扫读数）。
