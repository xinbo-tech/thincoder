### 2.2 机制设计（三问裁定——逐问「裁 + 判据」）

**① 文件发现 = 项目根单层**（`join(cwd, ".mcp.json")`；无向上多级搜索）。

判据：a) 对齐基准实读——CLI `thincoder-cli/src/cli/make-agent.mjs:61-64`（`join(cwd, ".mcp.json")` + `existsSync`；`cwd` = `process.cwd()` = 项目根；全块零循环 ∕ 零上溯）；b) 桌面同层——装配 `cwd` = `projects.currentCwd()`（注入点 `thincoder-desktop/src/main/agent-host.mjs:171-172`）经核缝 `thincoder-core/agent/assemble.mjs:105`（ctx 携 `cwd`）传入，语义 = 项目根；c) 多级搜索无判据——父目录 `.mcp.json` 属别项目（越项目边界），且 `.mcp.json` = 跨工具约定名（逐工具在自身项目根读之惯例，`docs/TODO-archive.md:149` 在册）；d) 读取时机 = 每次装配读一次（文件变更 ⇒ 下次装配生效——沿 CLI 与幂等连接表口径，`docs/core/design/MCP.md` §6.4）。

**② 信任面 = 装配期零交互确认**（无「首次信任」门；项目文件与 `config.mcp.servers` 同信任域）。

判据：a) 对齐方向明示（§1.2「桌面向 CLI 现行为」）——CLI 实测零门（`make-agent.mjs:59-84` 读 ∕ 合并 ∕ 连接全程零交互）；b) 跨端差纪律——桌面单侧加门 ⇒ 同项目「CLI 连、桌面不连」的用户可见差，且非宿主能力面（两端同为本地进程 ∕ 同语义 spawn）⇒ 默认消除；c) 信任域同判——两源同为「用户自持机器上、用户可读写范围内的本地文件」；项目目录 = 用户显式打开的工作区（`openProject` 显式动作）；d) 未来若引入「项目信任」机制，须三端同拍另批裁定——本批不预置开关、不设「按需」出口。

**③ 优先级 ∕ 合并 = `config.mcp.servers` 同名优先；异名并入（追加序在 config 之后）**。

判据（对齐基准逐条 = `make-agent.mjs:66-79`）：a) `mcpServers` 须为**对象**形；数组形 ⇒ 跳过 + 记录（非致命）；b) 条目 = `{ name, ...server }`（键名注入，逐字同 CLI）；条目非对象 ∕ 数组 ⇒ 跳过；c) 同名（name 已在 config 列表）⇒ 跳过文件源条目（config 优先）；d) 读 ∕ 解析失败 ⇒ 非致命（记录 `[mcp] Failed to read .mcp.json: …`，零中断）；e) 连接 = 合并列表整体 `Promise.allSettled`（config 先 ∕ 文件源后；失败落 `_mcpWarnings` 不抛——沿 `agent-assemble.mjs:38-49` 现形逐字）。

**实现面三裁（随三问）**：a) **端本地实现**（勿改 CLI；核零改——核缝 ctx 已携 `cwd`，桌面端壳自持合并；多实现面纪律 = 各面独立实现、语义同源（正源 = `docs/core/requirements/METHODOLOGY.md:77` F7-3——含 2026-09-28 收窄；合并语义单源 = `docs/core/design/MCP.md` §6.4））；b) **非变异**——桌面构建新数组，不回写 `config.mcp.servers`（CLI `:76` 的 push = 实现细节非语义面；可观察语义 = 连接集合 + 顺序；端侧零内存副作用）；c) **管理面不动**——列表 ∕ 增删改 ∕ 重连 ∕ 探活仍只操作 `config.mcp.servers`（`.mcp.json` 源不进管理列表——沿 CLI `/mcp` 口径，单源 `docs/core/design/MCP.md` §6.5:93；同名遮蔽效应在册：config 条目存在 ⇒ 文件源同名片装配期不可见；删 config 条目 ⇒ 文件源条目下次装配重现）。**生效时机** = 下次装配（会话新建 ∕ 重装）——无热观察（对齐 CLI）。
