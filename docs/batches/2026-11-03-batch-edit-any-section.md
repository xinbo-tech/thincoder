### 2.3 机制设计（一句话与三处非显然处）

一句话：`edit` 的段域由 §2 常量换成「同模式 `append` 白名单」，其余判定（锚唯一、状态行独占、骨架保护、剥凭证、冻结门、机检门、记账、一次写盘）逐条复用——不新开写盘路径、不新增动作、不新增参数。

三处要写明的非显然处：

1. **段序门只挂 `append`**：门护的是「实施记录不得先于评审通过」，而 `edit` 必须有既有锚（零命中即拒）⇒ 写不出原本不存在的内容，造不出「先实施」。反过来在 §3 进行中时拒掉 §5 的旧行，正是 `#2021` 那种死锁。
2. **§3 裁定行不设独占**：裁定行只在 `append` 时被读（`verdictGapOf` 判的是本次写入的块）；删一行不改变任何机器判据，只改那一块证据的可读性——作者自负、git 留底。因此行级独占只留状态行一条。
3. **状态行独占是冻结判据的输入端**：§1 状态行是冻结门 / §5 门 / 收口门 / 核销门唯一的读面，让 `edit` 碰到它 = 生命周期流转可被一次改写伪造。

### 2.6 关键决策（含被否）

- **段域一处单源**：`edit` 与 `append` 读同一张白名单表，不另立第二张。被否 = 给 `edit` 单列一张（第二份枚举 = 漂移源）。
- **行级独占只留状态行**（用户 2026-11-03 裁）；§3 裁定行不设独占，理由见 2.3 第 2 条。
- **不加留痕行**：依据 = 用户倾向（D8 历史住 git）+ 留痕行会往被保护的那一段里塞第二种读法。被否 = 段尾自动补 `〔原名 x 行 ‖ 新 y 行｜时间〕`（读的人要读两层，且 §2 那种「只须一种读法」当场失效）。
- **改时零拦截**：「改写是否追认既有记录」放到收口对账（D7 两半），不在改的那一刻拦。被否 = §5 非空即拒 `edit §2`（把设计变更传播这条正路关掉，写者绕去文件工具直写）。
- **代价如实登记**：证据面「字面不可改写」这一层没有了；事后复原靠 git + 收口对账。这是用户裁定的直接代价，不是遗漏。
- **机检判集按命中类分两套**（父侧 2026-11-03 裁）：**段长类**判本次写入文本、**锚类**判整档。被否 = 一律判整档（一条早先就在的超长段会锁死该段任何无关改动，`#2021` 的死引文仍收不了口）∥ 一律判新文（失效引文只要不碰那行就收得过，引用完整性掉档）。
