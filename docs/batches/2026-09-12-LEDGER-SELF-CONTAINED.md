### 提示词层承载（R3 展开——2026-09-12 04:24 用户追加）

用户口径：**所有这些约束应该在提示词层面，而不只是文档层。**

**为何是提示词**：需求/设计档是规格（人读、评审对象、可追溯）；**提示词是代理运行期真正注入并遵循的纪律**——只在文档层落 = 文书合规、行为不变。本批的病因（前任「能记一处就不写两处」）正是**行为习惯**问题，必须在纪律层改。

**必须进提示词的行为条款**（R1 / R2 / R6 / R7 的行为面）：

1. 台账**只收本仓条目**——禁登记他仓 / 他项目 / 他产品线事项；**跨仓指针同样禁**（含本产品双端）；
2. **批次档同规**——各仓记各仓的；
3. **文档体系各仓自持**（需求 / 设计 / 批次档 / 台账）——且 **缺的层必须补齐**：**不得以「另一仓已有」「避免重复」为由省略本仓文档**（← 直击病因，本条为行为面的关键句）；
4. **台账头部自持**——不引用本产品仓内路径（与并行批 `PROSE-ANCHOR-RETIRE` 同族）。

**落点要求**：双端 `discipline-engineering.md` + 视情 `persona-*`（角色写域句）+ **normal 模式覆盖面须逐处判定并在设计档给出结论**（normal 模式下代理是否也会建台账 / 文档？不得默认「另一仓另说」）。双端语义同源、各端原文自持。

**与机制层的分工**：提示词 = 纪律（行为约束）；机检 = 闸（fail-closed，R4）。**两者都要，不互相替代**。

**措辞纪律**：读提示词的是模型——条文须**可执行、无维护者注**（日期 / 批号 / 评审号 / 档内引用不入提示词正文）。
