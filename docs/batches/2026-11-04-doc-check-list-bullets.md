## 父侧判断更正（2026-11-04 21:35）

**前一节末句「本仓 `docs/**` 零处 ⇒ 本仓未被该缺陷命中，修的是产品行为、不是本仓的账」作废。** 用户当场指出：「你现在是机械拦截的，出了就写不进去，你当然看不到啊！」

**更正后的事实**：本仓之所以 0 处，正是因为这个缺陷在**写门**上生效——

```
文档里写 `· 一` `· 二` `· 三` …（每项几十字）
  ⇒ 段判据把它们并成一段 ⇒ 超 300 字
  ⇒ 写入当场被拒
  ⇒ 仓里永远留不下这种行：不是「不存在」，是「进不来」
```

**这条改变了本批的严重性定级**：它不是「给出误报、读者改一改」的骚扰，而是**合法中文列表文档被挡在门外**，且报错文案说的是「文字太长，难于阅读」——读者会去删内容，不会想到是判据认不出他的项目符号。

**由此追加一条验收要求**：本批必须给一个**写门面的复现读数**（把一段 `·` 项目符号列表尝试写入，修前被拒、修后通过），只证明「判据函数返回 0 命中」不算验过——这条路正是用户看不见它的原因。

## 机制设计

- **判据单源** = `thincoder-core/doc-check/paragraph.mjs` 的 `isListItem`。
- **实现形态钉死**：两式 = **两个正则以 `||` 连接**——首式 `^\s*(?:[-*+]|\d+[.)、]|[·•])\s` 只在字符组内加 `[·•]`（ASCII 两族与尾 `\s` 逐字不动）∥ 次式 `^\s*[①-⑳]`。不许写成一式交替：圈号不要求尾随空白、其余三族要求 ⇒ 单式就得把尾 `\s` 移进分组，`git diff` hunk 随之多动结构，源面判据（hunk 只动该字符类与同行注释）当场不成立。
- **两式各自的空白要求**：`·` `•` 要标记后空白；圈号不要求——无空白圈号形是真实写法，场景逐处见设计子块「改后触达面」的 ② 读。
- **方向性质**：认出列表项只断段、不造段 ⇒ 段数只增、段长只减 ⇒ 命中只减不增，不造新红。
- **免扩后复跑清账（偏离先例 §3.5 条目 F）**：F 的复跑是为找扩后新入判；本条方向单调 ⇒ 复跑清不出新账。读数照给（设计 §3.18「改后触达面」，含扫串与逐处坐标），用途 = 证明方向性质。
