- **落点候选核对**：批件候选一「`doc-check` 已有批次档解析面」**不成立**——`scripts/doc-check*.mjs` 全域无批次档解析；`checkConfig.anchors.exclude` 恰含 `batches`（批次目录在机检域外）；引擎头注明写「台账一致性不并入」+ KD-M8-2（`check-ledger*` 作废、不并入）。

**修法**：**写入时门（fail-closed）**——`thincoder-core/ledger-cmd.mjs` 两条写命令（`ledgerAdd` / `ledgerUpdate`）落盘前判**结果行**：`status ∈ {在途, 待核销}` 且 `task_book` 非空 ⇒ 解析其文件部分，**不可解析 / 非文件 ⇒ throw**（行不变；判位与迁移表拒同层）。

- **解析口径**：文件部分 = **首个 `§` 之前的子串**（trim）；`§` 之后 = 节号 / 注记，**不参与存在性判定**（覆盖现盘三形态）。解析基准 = 调用 `cwd`（= 台账库关联键的项目根）：`resolve(cwd, 文件部分)`。**缺文件部分**（`§2` / 全空白）⇒ 不可解析 ⇒ 拒。
- **失败文案**（逐字）：`ledgerUpdate：task_book 指向的档不存在：<原值>（解析 = <绝对路径>）` · `ledgerUpdate：task_book 不可解析（缺文件部分）：<原值>`。
- **射程** = 结果行状态属 `{在途, 待核销}`；待讨论 / 待设计行不判（判据句逐字）。
- **选型理由（台账侧 vs 机检引擎侧）**：① 与已落半幅**同层同生命周期**（同一条判据句的两半劈到两层 = 两套失败面）；② 台账库在用户数据目录（工作树外、按项目根 sha1 键控），引擎源域 = `docs/**` 的 .md——接库即新增 DB 依赖面；③ KD-M8-2 既有裁定「台账一致性由 SQLite schema 承接、**不并入**机检引擎」——引擎侧落点 = 反转该裁定。

**落点**：`docs/core/design/LEDGER.md` §6.1（新增·单一权威）+ §2 半幅分层句 + §8（AC-M2-8 · T11–T14）+ 变更记录；实现 = `thincoder-core/ledger-cmd.mjs`。→ **设计侧已落盘**
