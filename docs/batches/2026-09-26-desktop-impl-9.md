**校验面（`provider:verify` 口径 = 本端口径单源）**：真调一次 = `probeChannelModels(name, provider)`（`thincoder-core/provider/list-models.mjs:152`）——**探 `/models` 非真对话**、**绝不抛**（失败经 `classifyProbeFailure`（`:125`）分档 `timeout` / `malformed`）、失败不缓存（`recordAdmission`（`:132`）/ `admissionOf`（`:140`））。与 CLI `mcp` 式「探不通 ⇒ 零保存」**不同源**：`provider:verify` 只出读数（`{ ok, reason, models? }`），**保存与否由用户在设置面显式决定**（探不通仍可保存——离线/代理场景不阻断；卡面明示「未校验通过」）——此分歧为**有意**，理由 = 渠道 key 的可用性不只在探测当下（与 MCP 服务器配置「配错必连不上」不同）。

**模型面**：`model:list` = `listModels(provider, { signal })`（`thincoder-core/provider/list-models.mjs:96`——format 分派 + 排序住核）· 渠道不可用文案 = `channelUnavailableMessage`（`:109`）直传。

**agent 参数面板（`settings:agent`）**：键面 = 核点分路径表 `_SIBLING_SHAPES`（`thincoder-core/agent-tools/settings.mjs:42`）+ 派生类型表 `TYPE_MAP`（`:62`）+ 完备性自检（`:85`）；敏感判定 `/ 遮罩 = `isSensitiveKey`（`:22`）/ `MASKED`（`:19`）**复用，不做第二份**；值校验 = `_checkKnownKeyValue`（`:134`）经核 `settings` 工具面同源判据（端侧不另立白名单）。`settings:agent` 处理体 = **同键面**的读 + 写（写走 `writeConfigAtomic`；读走 `loadConfig`）——不经 agent 工具（工具面 `set` 自带审批门、且需装配态）。

**MCP 面**：读 = `loadConfig()` 的 mcp 节（热重载先例 = `reloadMcpFromDisk`（`thincoder-core/config.mjs:358`））；探活 = `probeMcpServer(config)`（`thincoder-core/mcp.mjs:82`，真连一次）；保存/删除 = `writeConfigAtomic` 改 mcp 节 + 连接面随动（`connectMcpServer`（`:225`）/ `closeAllMcp`（`:269`）/ `removeMcpTools`（`:285`））——**探活失败 ⇒ 回执 `{ ok:false, reason }` 且零写盘**（CLI `thincoder-cli/src/tui/cmd-mcp.mjs` 先例 D-Q1 同口径）。

**项目级信息面（`ledger:read` / `batch:status`）**：台账读 = `ledgerQuery`（`thincoder-core/ledger-cmd.mjs:15`）/ `ledgerCount`（`:28`），**经 `thincoder-core/ledger.mjs` 动态 import**（W8 契约②：`ledger-db.mjs` 静态 import `node:sqlite` ⇒ 消费侧禁静态 import——实读 `thincoder-core/ledger.mjs:15`）；项目相位 = `readManifest(cwd)`（`thincoder-core/manifest.mjs:334`；整档缺 ⇒ `{ ok:false, reason:"missing" }`——**绝不静默 fallback**）+ 路径单源 `manifestFilePath`（`:233`；不重写根解析式）。相位值域 = `initial-dev` / `production`（`MANIFEST_SCHEMA.enum`——`manifest.mjs:261`）。

**语言面（#397 收口）**：键 = `locale`，值域 = 核 `SUPPORTED_LOCALES`（`thincoder-core/i18n.mjs:20`）· 归一 = `normalizeLocale`（`:75`；缺 / 未知 ⇒ `"en"` · `zh-CN` → `zh`）。**谁写 / 何时写 / 缺省**三问一条落定：①写者 = 桌面设置面（`config:write`，本批为**首写者**——核侧无 locale 持久化写点，实读 `thincoder-core/i18n.mjs` 全档 + `config.mjs` 导出面）；②时点 = 用户在设置面切换语言（即时写 + 即时重发语言面 `projectDictionary(locale)`（`i18n.mjs:101`），不重启）；③缺省 = 无键 / 非法值 ⇒ `"en"`（`normalizeLocale` 内，零端侧兜底）。**跨端共享字段声明**：`locale` = **端无关偏好键**（任一端写、他端读；非会话 / 槽属主字段、非写竞争面）——`docs/desktop/design/PROJECT.md` §6.2 A2 的「不增跨端共享可变字段」在此**不适用**（该条针对属主型状态），决策入册见 §2.7 KD-9 续。

**密钥纪律**：key 明文只落 `~/.thincoder/config.json`（承 `docs/core/requirements/PROJECT.md` §3 C8 · 桌面需求 §6）；**值不入文档 / 不入日志 / 不进用例夹具**；回显一律过 `MASKED`（`thincoder-core/agent-tools/settings.mjs:19`）；通道载荷**只回遮罩后值**（`provider:list` 不返 key 原文——返 `{ hasKey: boolean, masked }`）。

**向导闸（首启三步）**：闸读数 = `configPath()`（`thincoder-core/config.mjs:27` re-export 面）**存在性**——存在 ⇒ 跳过向导直进主界面（需求 §3.3 逐字）；不存在 ⇒ 向导三步（选 preset → 填 key（`provider:verify` 真调一次）→ 选工作目录（`project:open`））。**步骤复用**：向导的渠道表单与 `provider:verify` 出口 = `thincoder-desktop/renderer/views/settings.mjs` 导出面（单一 owner、零副本——沿批 7 `approval.mjs` 操作区描述符先例）。配置存在但不可解析 ⇒ 不静默重置：向导不进、设置面可进 + 明示「配置不可读」（`loadConfig` throw 直传）。
