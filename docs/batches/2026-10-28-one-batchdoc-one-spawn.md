### 1.1 病（父侧亲历 2026-10-28 11:34）

**★ 三个席的自述一致指向同一句：**

### 1.2 提示词的缺口（父侧实核，不是印象）

**`thincoder-core/prompts/` 里 `batchDoc` / `task book` 相关条文十几处，逐条看过，没有一条说「一个批档不能给多个 spawn 用」。**

**⇒ 最接近的是这两句，而两句都只说「是任务书」，没说「是谁的」：**

- `thincoder-core/prompts/common.md:385`：「**The task book itself**: `batchDoc` = the batch-record path = **your task book** (mandatory on every eng-designer / eng-coder spawn)」
- `thincoder-core/prompts/persona-engineering.md:438`：「It is the task book that spawn implements: omitted, or path unreadable, mechanically refused.」

**★ 工具描述（`thincoder-core/agent-tools/subagent.mjs`）也只说：「the task book **this spawn** implements/writes. **This IS the task book** for engineering roles」—— 单数措辞，却没有任何一句禁止多个 spawn 共用同一个路径。**

**⇒ 条文用的是单数，机制却不拦复数 —— 缺口在「措辞暗示了唯一性，但没有一条把唯一性写成规矩」。**

### 1.3 该补什么（一句话）

**一个批档 = 一个 spawn。多席并行 ⇒ **各开一批**（各自的批档 + 各自的台账行）。**

**★ why 要带上（否则下一个人看不出为什么不能复用）：**

> **批档 §2 是**这一批**的账（含全批条目、受影响文件、验收、上抛项）。一个 spawn 拿到它，读到的就是全批 —— 它无法从中分出「哪些是我这一席的」。多席共用 ⇒ 每个席都按全表做 ⇒ 同档多写者、互相覆盖。**分席 = 分批档**：把「这批谁做什么」写进各自的 §2，子代理读到的就是它自己那一份。**

### 1.4 落点（父侧给方向，设计席定形）

**★ 具体落点由设计席定，但硬约束三条：**
