# Thincoder Server —— 项目需求

> 板块 = server ∥ 组件落点 = `thincoder/thincoder-server/`（子目录形式——2026-10-04 用户定）∥ 本档 = 需求档（五要素已齐——2026-10-06 用户确认）。

## 1. 总体目标

**模块目标**：为 ThinCoder 开发团队提供统一的模型 token 网关——集中凭证、计量、配额，数据不出内网；后续逐步增加团队协同能力。

**服务对象**：开发团队（内部工具面，非对外产品）。

**形态**：内网一台服务器上常驻，团队内网可达，非公网部署。

**演进方向**：第一步 = token 网关；第二步起 = 团队协同。

**关系面**：独立新件。与既有 `ai-gateway` 不耦合、无收敛计划；其设计与实现经验可作参考。

**形态决定（已定 · 2026-10-04）**：server 落 **`thincoder` 仓子目录**——`thincoder/thincoder-server/`（与 `thincoder-core` ∥ `thincoder-cli` ∥ `thincoder-vscode` ∥ `thincoder-desktop` ∥ `thincoder-render-core` 同级）。

依据（2026-10-04 咨询裁定）：

- 本仓**分仓例外论**（拆仓只为例外：独立部署 ∥ 独立发布 ∥ 独立生命周期——server 三条均不成立）；
- **先例方向 = 收敛**（VSC 仓经 subtree 并入本仓——走回头路无益；且每仓需自持一套 AGENTS ∥ 文档 ∥ 台账 ∥ manifest ∥ 批次流程）；
- **协议耦合**（server 大概率直用 core 协议/类型/逻辑——同仓直连 import；协议两端可一提交同改同审）；
- **发布面不构成拆分理由**（单仓多产物已跑通：npm cli ∥ vsix ∥ 桌面安装包——server 只是又一产物，从子目录部署）；
- **可逆性不对称**（先同仓后分 = subtree split——易；先分后并 = VSC 并仓代价——贵。低后悔路径 = 先同仓）。

**例外重启条件**（满足其一再议单仓）：① 真·独立生命周期（他人维护 ∥ 独立对外版本且与客户端解耦 ∥ 不依赖 core 的异栈）；② 硬隔离需求（如对外开源/外发——subtree split 亦可解）。

## 2. 功能性需求

**第一步 = token 网关，功能点十四条**：

1. **统一入口**：真实 provider key 只存网关；团队成员持团队 key + 网关地址接入。成员机器不再放真 key。
2. **OpenAI 兼容面**：`/v1/chat/completions`（SSE 流式）。ThinCoder 四端以 `baseURL` 指入即用；其他 OpenAI 兼容工具同。
3. **计量**：逐请求记录（成员 × 模型 × 时段 × token 数），供计量看板查询。
4. **配额**：按成员设额度；超额 = 拒 + 明确提示。
5. **凭证管理**：团队 key 签发/吊销；上游 provider key 配置。
6. **向量接入面**：`/v1/embeddings`（OpenAI 兼容），数据不出内网。旁路引擎（Ollama / TEI 等内网独立进程）承载推理；网关只做协议面与记账；引擎起停手动。
7. **轻量账号体系（B 案——用户 2026-10-06 08:04 定）**：成员 = 账号（用户名 + 密码散列）；角色 admin ∥ user；**网页登录**——成员自助取/换个人 key + 看自己用量 + **自助改密**（用户 08:05 定）∥ admin 登录管成员/配额/吊销（现看板升级为受门禁的管理页）；
   首个 admin = 首启引导（env 或本机 CLI）；运维 CLI 降为服务器本机兜底。**admin 重置成员密码 = 在**（用户 2026-10-06 08:06 定——忘密兜底）；**形状 = 定稿**（AC-7 已落——设计 `accounts/ACCOUNTS.md` §5 七判据）。
8. **分发与部署（用户 2026-10-06 08:24 定——「支持 npm 发布和 docker 方案」）**：**npm 发布**（包名拟 `@thincoder/server`——装机 = `npm i -g`）+ **Docker 镜像**（Dockerfile ∥ compose 样例）两路；守护 = systemd（裸机路）∥ docker restart 策略（容器路）；**入发布序列**（RELEASE.md 扩展 = 随发布面轮）；registry ∥ 首版号 = 部署时确认。（AC-8 已落——见验收表。）
9. **provider 预设（用户 2026-10-06 11:20 定——「我希望加」）**：server 配置支持**内建 provider 预设**——管理员按预设名添加常用上游（免手写 `baseURL`/默认模型）；预设覆盖面与配置形态 = 设计轮定（**形态 = 定稿**：server 自持表——KD-SV-17 ∥ 起步 20 家 OpenAI 兼容子集）；零第三方运行期依赖（沿 §3）。
10. **自动更新（用户 2026-10-06 15:33 定「server我也希望实现自动更新，那docker里的也能吗？」+ 15:37 裁「用不用容器都走npm路径升级，容器只做个壳就行」）**：
   **两路统一走 npm 版本身份与升级路径**——版本身份 = npm 包（`@thincoder/server`）；**容器 = 壳**（镜像 = node + 引导层——App 代码由 npm 取装，容器不自带版本身份）；
   **形态 = 定稿**（设计轮：`autoUpdate` 三档默认 `notify` ∥ 壳收敛 `TC_SERVER_VERSION` 三态 ∥ ready 行版本可见性——KD-SV-18；机制全文 = 设计 `ops/OPS.md` §5.4）；升级 = 装 npm 新版 + 重启；回滚 = 版本回指 + 重启；前置 = 发布面上线（registry 有新版本源）。
11. **控制台 provider/模型管理（用户 2026-10-06 16:01 定——「开啥玩笑！你觉得这是一个产品该干的事儿吗？！」）**：provider 与模型的配置管理**必须上控制台**——管理员在界面里增删改 provider、选/开放模型，**不再只靠 `config.json` + 重启**；

12. **首版完备化（用户 2026-10-06 16:04 定——「好歹像个完整的产品！你自己先反省一下，看看还漏了什么，都给补齐了」）**：补齐清单（审计发现——均父侧实核）——

**依赖**：

- 上游：各 provider 的 OpenAI 兼容聊天端点；内网嵌入引擎（旁路进程）。
- 本仓：node 标准库为主（零第三方运行期依赖）；存储候选 `node:sqlite`；是否复用 core 的 provider 层交设计轮定。
- 消费方：ThinCoder 四端 + 任意 OpenAI 兼容工具。
- 网络：内网服务器可达（内网 IP / 端口）。

## 3. 非功能性需求

- **安全**：仅内网可达（bind 内网接口）；**真实 provider key 只存网关**（成员侧零真 key）；团队 key 逐人签发/可吊销。
- **性能**：流式转发（SSE 逐块透传——不整段缓冲）；单机常驻（团队规模级并发）。
- **依赖纪律**：沿本仓纪律——**零第三方运行期依赖**（node 标准库为主；存储候选 = `node:sqlite`）。
- **可靠性**：常驻进程（崩溃恢复 ∥ 开机自启 = 部署面——**薄面已落**：`ops/OPS.md` §5（systemd ∥ 容器 restart 两路））。
- **增长规划（用户 2026-10-06 08:11 令——server = 长期平台，未来功能与规模均会大幅增长）**：架构须为增长**留对断点**——路由注册制（新端点零改主干）∥ 存储迁移链（`user_version` 逐版可迁）∥ 会话无状态倾向（多实例就绪）∥ 模块边界可拆 ∥ 配置面段形可扩；**演进写法 = 触发条件式**（多实例/协同/对外各有触发条件与决策点，见设计档）；**不为未来预建**（队列/缓存/拆分/插件/ORM 一类不落）；

## 4. 不做项

- 不做**对外销售/计费**（那是 `ai-gateway` 的域——本件 = 团队内部）；
- v1 不做**多租户**；
- v1 不做**模型别名/路由**（已降级为后续可选）；
- v1 不做**非 OpenAI 协议的翻译**（只 OpenAI 兼容面）；
- v1 不做**配额阈值告警**（80% 等——暂缓，后续再加）；
- v1 不做**嵌入引擎的管理面**（旁路引擎进程 = 手动起/停；网关只管协议面与记账）；
- v1 不做**独立客户端管理台**（管理面 = 内嵌网页（B 案）——不做桌面/独立应用形态）；
- v1 不做**组织架构同步 ∥ SSO ∥ 双因素 ∥ 密码找回**（「找回」需外部通道（邮件/短信）——留「团队协同」步；**改密 = 在**——用户 2026-10-06 08:05）；

## 5. 范围边界

- 本件 = ThinCoder 团队**内部**工具面（服务开发团队本人）；
- 与 `ai-gateway`（客户向）**划界不耦合**——参考其经验但零共享运行面；
- 「团队协同」= 本件的**演进方向**（第二步+；本需求档先只定第一步）；
- **后续议题（2026-10-06 定案）**：内部算力集群的**模型感知路由**归本件（模型名 → 后端组 ∥ 组内挑实例——集群就位时开批，台账在册）；**通用负载均衡用外部工具**（如 HAProxy——不集成进 server）。
