## 1. 扩展点（现有形态里已留的断点）

| # | 扩展点 | 现状（第一步） | 增长时怎么用 |
|---|---|---|---|
| G1 | 路由注册行制 | 分派 = 「method + path → 处理函数」注册行（`thincoder-server/src/gateway/server.mjs`（已落盘））；新端点 = 注册一行 + 新处理模块 | 不塞主干 if-else——端点增长不动分派结构 |
| G2 | 存储迁移链 | `PRAGMA user_version` + 顺序迁移段（机制写实 = `store/STORE.md` §3） | 结构变化 = 追一段（+1）——旧库启动自动升 |
| G3 | 会话无状态倾向 | 会话 = 库表单源（`sessions`——逐请求查库）；进程内零会话内存态（`accounts/ACCOUNTS.md` §2） | 多实例就绪——加实例不动会话面（共享存储 = §2 触发项） |
| G4 | 模块边界（三层树） | 板 → 域 → 档：代码 `thincoder-server/src/<域>/<档>.mjs` ∥ 文档 `docs/server/design/<域>/<档>.md`；六域目录自第一步立；单档 ≤300 软线（逼近即拆——预案随档在册） | 新档落同域目录（零跨域动 ∥ 零路径重排）；域内拆档 = 加档不加层；新域 = 新目录 + 新域档（本域论） |
| G5 | 配置面段形 | 配置 = 段形 JSON（`bootstrap` ∥ `providers` ∥ `embedding`……——`ops/OPS.md` §1）；段内字段可扩 | 新能力 = 新段（或段内加字段）+ 校验同步扩 |
| G6 | 文档单源可拆档 | 设计 = 板 2 档 + 域 6 档（信息单源；各档自带决策段与变更记录） | 域档再拆 = 域内落档（同 G4 规则——零跨域动） |

## 2. 触发条件式演进（到点才建——逐条给触发与决策点）

| 演进项 | 触发条件 | 到点决策点 |
|---|---|---|
| **多实例**（≥2 实例 ∥ 进程外前置） | 并发超单进程承载 ∥ 高可用需求出现（重启窗口不可接受） | 存储单写者如何跨实例（网络库 ∥ 写面单实例化——先量再定）＋ 前置 LB（通用负载均衡用外部工具（如 HAProxy）——不集成进 server；台账 #955 在册）；SSE 长连的粘滞/超时参数 |
| **集群模型感知路由**（模型名 → 后端组 ∥ 组内挑实例——需求 §5 定案；台账 #955 在册） | 内部算力集群（DGX-spark）就位——就位时开批 | 派发层扩展方式——组语义（模型名 → 后端组）与 KD-SV-4 精确清单派发的关系（`gateway/API.md` §6——叠加式扩展，先量再定）；组内挑实例与健康面 ∥ 流式透传与用量提取同口径保持 |
| **团队协同**（第二步） | 第一步上线条 ∥ 用户排期 | B 案（账号/角色）为地基——叠加面（组织/通知/…）另档（需求 §1 演进方向） |
| **对外面**（计费 ∥ 公网 ∥ 多租户） | 业务出现对外诉求（再议） | 与 `ai-gateway` 的界（不耦合）重画 ∥ 安全面（TLS ∥ 鉴权模型）重估——本档不预设 |

## 3. 明确不预建（第一步不落——点名备查）

- 消息队列 ∥ 缓存层（Redis 类） ∥ 微服务拆分 ∥ 插件系统 ∥ ORM —— 未到触发条件（§2）；引入即违零依赖与最小面纪律——触发重估 = 随 §2 对应行。
