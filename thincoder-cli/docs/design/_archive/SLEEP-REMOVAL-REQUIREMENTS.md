## 总体目标（历史）

删除 `sleep` 工具。该工具在编程场景**零真实使用**（两端会话历史 9828 个 session 文件中 0 次模型调用），且其工具说明 "wait for an async task to finish" 误导模型在同步阻塞工具（如 advisor）之后调用 sleep 空等——造成 10–300 秒无效等待。删除比修改说明更彻底：只要工具在列表里，模型就有调用动机。

## 功能用户故事（历史执行范围）

- **FR1 · 工具表无 sleep**：模型不再拥有 sleep 工具，杜绝"同步工具执行后 sleep 空等"误用。
  - 验收语义：工具定义/注册删除，模型工具表无 `sleep`。
- **FR2 · 提示词不指向 sleep**：路由规则删除。
  - 验收语义：`discipline.md` 的 "sleep → dedicated tools" 表述删除；真实等待需求允许走 bash 内联命令。
- **FR3 · 内部等待不受影响**：代码内部真实的等待逻辑不受影响（速率限制/重试退避）。
  - 验收语义：`_rateHooks.sleep` / `embedding.mjs` 内部 sleep 函数保留（非工具、模型不可见）。

- **N4 可测试**：删除后工具表不含 sleep 的断言测试（可选）；现有测试中 sleep 用例删除。

## 现状注（2026-09-06 起）

"模型需要在回合内等待异步事件（子代理 settle / 文件出现 / 端口就绪）"的真实需求由 `wait_for` 工具满足：

- 条件语义化——advisor settled / subagent id:N done / consult done / file exists / port open。
- 未知条件显式报错，绝不静默空等。
- 内置有界 timeout（默认 30s、cap 600s）替代无界 sleep-then-wait。

同步工具（advisor / 阻塞 subagent spawn / verify）返回即完成、等待无意义——该防误用语义由 wait_for 说明与 TOOLS.md §16 承接。
