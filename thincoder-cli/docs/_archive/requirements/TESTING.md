## 1. 总体需求

一次代码改动的验证必须**按层收口**，避免"随便改一点就跑上千个测试"——浅改浅验、深改深验、链终一次全量。
验证成本的大头是重 IO 而非用例数量，因此分层按**耗时**而非目录切分。

测试体系同时按**寿命**组织：单元测试是开发期工具（为改对代码而写——用过即退役，批次收口逐条处置）；
集成测试是业务资产（业务设立 + 生产补入——常驻，承担发布门验收）。两类来源不重复覆盖（单元不属于验收面）。

## 3. 非功能性需求

| # | 维度 | 标准 |
|---|---|---|
| N1 | slow 门（分层执行） | **作用域 = 单元档（`test/` 顶层 `*.test.mjs`——快/全两层执行面内）**：需真实 fs / git 子进程 / 定时器 / 网络的测试（单用例 >500ms）用 `slow(name, fn)` 包装——快层自动 skip（可见 `↯ skipped`，不隐身），全量（`npm run test:full` / `THINCODER_TEST_FULL=1`）跑；集成档不在本门作用域（不得用 `slow()`——设计档 §4.3） |

| N6 | 阈值实测依据 | >500ms 的测试约占全量 CPU 的 **95%**，而 <5ms 的过半测试合计仅 376ms——**数量不是成本，重 IO 才是** |
| N7 | ②集与需求同步演进 | 需求发展/行为变化必须触发集成集评估（主 agent——不外包不自动）；集成集不得落后于需求（判据 = 每批 §6 处置行 ②半 有记录） |

## 4. 范围边界（不做）

- 不用目录分层做**快/慢分层**（`test/**` 是唯一约定入口；同档门控让单文件调试与全量永远走同一断言）——集成集以 `test/integration/` 子目录分界属**生命周期**划分（①/②③），非执行层划分（见 F12）
- 不设独立测试角色（维护模型零新角色——职责随既有角色，见 §2.1）
- 集成集不调真实付费端点、不依赖人工操作（真端点 smoke 仍独立于所有层）
- 不维持存量测试库存（2026-09-07 起"按需加"）——本机制为"按需加"的产物补寿命与收口处置

## 5. 散文锚测试退役（PROSE-ANCHOR-RETIRE）

> 来源：用户 2026-09-12 裁定 R1–R5（批次档 `../batches/2026-09-12-PROSE-ANCHOR-RETIRE.md` §1）。
> 一句话：**读档断言「某句在场 / 缺席」的测试一律不做**——收益无实证（举不出该类锚抓到真实漂移的记录），成本可量化（改一字即红、失败信息零信息量、锚红后的动作永远是「把字改回去」）。
> 设计 + 逐条删除清单 = `../design/TESTING.md` §11。
> 双端语义同源：本档 F15–F22 / N10–N12 与对端档 `requirements/TESTING.md`（VSC 仓）同标识、语义同源、各端原文自持（不做 byte-identical）——对端条目自持于对端档，本档不代写对端规。

### 5.1 判据（三条同时成立 = 散文锚）

| # | 条件 |
|---|---|
| ① | 断言对象是**非测试档**文本（`src/**` · `docs/**` · `AGENTS.md` · `README*` · 仓根 `*.md` / `*.json` · `package.json` · `scripts/**` · `bin/**` · `webview/**` · `locales/**`〔资源文本保留——C1-d〕）或其派生切片 |
| ② | 断言其**文本内容**在场 / 缺席 / 出现次数 / 相对顺序（`.includes` · 常量子串 `assert.match` · `.startsWith` · `.endsWith` · `.indexOf` · 文本计数） |
| ③ | 断言对象**不是**结构机检保留面所判的属性（保留面 = F17 封闭枚举） |

**载体判据（判据 ① 的落地口径）**：断言对象是**执行产物**（函数 / 工具返回值、子进程输出、渲染帧、测试自建临时域文件）或**结构 / 数值常量** → 不命中 ①；
经 `import` 取到的 src 静态文案字面量 → 命中 ①。

**判据补充（2026-09-12 修正轮——PA-A1 / PA-A2 / PA-A3 裁定；判据 ① 的「实质」判法）**：

| # | 补充 | 内容 |
|---|---|---|
| C1-a | **提示词句子不豁免**（PA-A1） | **不问文本从哪来**（读盘 / 装配器或渲染出口的返回值 / 写入 `systemPrompt` 的装配结果），只问**断言的是否是提示词句子**——断言提示词句子（装配器传出的话语、注入块、降级句、槽文本，以及装配产物**与字面常量的全文相等 / 不等**）→ 命中 ①；**「不读文件」不是豁免理由** |
| C1-b | **工具契约面与工具返回文案保留**（PA-A3） | **模型实际收到的工具契约对象**（`tool.description` / 参数说明）与**工具返回 / 拒绝文案** → 契约守卫 / 行为输出，非文档散文锁 → 不命中 ①；读 `src/**` 源码档文本（含源码里的描述串）仍命中 ① |
| C1-c | **非句子对象保留**（载体判据原义） | 结构 / 数值 / 判定信号（槽文件表与集合成员、长度、警告清单与警告文案、旗位、退出码）→ 不命中 ① |
| C1-d | **locales 资源文本保留**（PA-A2 裁定） | `locales/**` 文本值 = **产品资源文案**（界面 / 本地化面——产品面，与 C1-b 同族）→ **不命中 ①**（保留、不进清单）；读非测试档**源码 / 文档文本**仍命中 ① |

## 6. CLI 自动验证面（端到端 harness——E2E-HARNESS 批）

> 来源：用户 2026-09-14 立项裁定「可以」——缘起 = 用户问「你老说『我没有 TTY』，能有吗？可以做一个吗？」；方案采定 = **② ACP harness + ③ 伪 isTTY 补充**（选型口径：零 TTY · 零依赖 · 确定性）；**TUI 渲染层留人工真机**（用户自有终端 = 免费真 TTY）。
> 硬约束（实核已定）：**不引入原生模块**——Node 内置 `node:tty` 只能探测 / 包装、**不能创建 pty**（无 TTY 下 `new tty.ReadStream(0)` 抛 `ERR_TTY_INIT_FAILED`）；本机 `cl.exe` / `node-gyp` 不可用 ⇒ `node-pty` 一路不可行。
> 目标 = 补上 S2 验证链现缺的一环（「CLI 真的能起来并跑完一轮」现只能靠人工）——本面 = 不依赖人工 / 不依赖真终端 / 不依赖网络的端到端自动验证面。
> 设计 + 用例表 = `../design/TESTING.md` §12；任务书 = `docs/batches/2026-09-13-CORE-UNIFICATION.md` §2。
> 状态：需求定稿（用户立项裁定）；设计就绪待评审（§12）；实现随批。

### 6.1 总体需求

CLI 的「真能起来并跑完一轮」目前只能人工验证——S2 迁移验证链缺此环。本面为 CLI 建立端到端自动验证面：
以**真子进程**驱动仓库内真入口（`bin/thincoder.cjs`），覆盖 **ACP 协议会话面**与**伪 TTY + 管道的交互命令面**；
每用例确定性可重复（脚本化 provider / 隔离 HOME 与 cwd / 硬超时保底），接入既有集成集（发布门执行）。
**TUI 渲染 / 画布 / 按键面明确不测**（人工真机）。

### 6.2 功能性需求

| # | 需求 | 说明 |
|---|---|---|
| F23 | 真进程全链驱动 | harness 以**真子进程**驱动仓库内真入口（`bin/thincoder.cjs`）——验证 argv 分发 / 退出码 / stdout-stderr 分流 / 完整一轮运行的真实行为（非模块级 in-process 调用） |
| F24 | ACP 会话面驱动 | 以 ACP 协议（stdio NDJSON JSON-RPC）驱动 `thincoder acp`：initialize → authenticate → session/new → session/prompt 完整回合（含流式更新 / 工具调用与 `session/request_permission` 往返 / `session/cancel` 中止）——零 TTY 下可跑 |
| F25 | 交互命令面驱动（伪 TTY + 管道） | 无 TTY 环境下把 stdin 以供测试覆盖判为可交互、以管道输入作应答：覆盖**权限 y/n**（批准放行 / 拒绝停手）与非 TUI 命令行路径的交互分支 |
| F26 | 覆盖边界写死 | 「能测什么」逐条列明（按驱动面）；**TUI 渲染层次明确不测**——自动绿不得被误读为 TUI 已被验证 |
| F27 | 确定性与可重复 | provider 走脚本化 mock（零外网 / 零付费端点）；隔离 HOME 与 cwd；硬超时保底（挂死 = 失败，不永挂）；重复执行结果一致 |
| F28 | 接入集成集（发布门） | harness 作为集成集场景住 `test/integration/`（`test:integration` 自动收揽 + 发布门第三步骤执行）——不新增入口 / 不加脚本 / 不动快层 |

### 6.3 非功能性需求

| # | 维度 | 标准 |
|---|---|---|
| N13 | 零新增依赖（零原生） | 不引入任何 npm 包（尤其原生模块）——驱动仅 子进程 + 管道 + 协议 三件套；依赖面零变 |
| N14 | 零 TTY 可跑 | 全部用例在无 TTY 环境（开发 / 评审会话即此类）可跑并全绿——不要求真终端、不要求人工操作 |
| N15 | 确定性 | 零外网 / 零付费端点（脚本化 provider）；隔离 HOME 与 cwd；用例间零共享状态；重复执行结果一致 |
| N16 | 运行时长 | 单用例硬超时 ≤30s（超时 = 失败）；harness 全档墙钟目标 ≤3 分钟（首发实测后按读数校准——不得拖垮发布门） |
| N17 | 失败可诊断 | 断言失败输出含现场（子进程退出码 / 关键 stderr 尾段 / 协议帧或管道输出尾段）；无静默挂起（超时给可读失败句） |
| N18 | 分层关系 | harness 属集成集（②③ 寿命面）：不进快层（`npm test` 目标集合零变）· 不用 `slow()`（集成档红线）· 仅在 `test:integration` 与发布门跑；集成集既有纪律零改 |

### 6.4 边界（不做）

- **TUI 渲染 / 画布 / 按键交互不入自动面**（人工真机验证）——本批只到「TUI 守卫语义」与可脚本化面为止。
- **不引入原生模块 / pty 方案**（硬约束——`node-pty` 路线实测排除）。
- 不进快层 / 不用 `slow()` / 不动分层机制与既有 runner / 不改发布门脚本。
- 不调真实付费端点（真端点 smoke 保持独立形态）。
- **本批仅 CLI 仓**——VSC 对位面（是否设立对位 harness）属后续独立裁定（本档不代立规）。
- 不替代人工验收：harness = 行为回归网；「真机上 TUI 好用」仍由人工判。
