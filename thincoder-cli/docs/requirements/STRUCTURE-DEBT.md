# 结构债（STRUCTURE-DEBT）— 需求

> 板块：结构债（横切——跨双仓的结构债评估与分批清理）。需求层文档（`docs/requirements/`）。
> 来源：2026-09-10 自 `../design/STRUCTURE-DEBT.md` 抽取需求陈述（§1 目的 + 代码结构硬指标）。
> 状态：**现行**（路线图与分批入口见设计档）。设计见 `../design/STRUCTURE-DEBT.md`。

## 1. 总体需求

结构债的病痛与治疗时机**错开**（平时无症状、撞上才暴露），因此必须靠**文档显式追踪**防止"挂账不处理"。
本板块规定：结构债如何度量、何时必须处理、每批如何独立立项。

## 2. 功能性需求

| # | 需求 | 说明 |
|---|---|---|
| F1 | 显式追踪 | 结构债评估与清理路线统一记录于 `../design/STRUCTURE-DEBT.md`（本档为其需求层） |
| F2 | 每批独立立项 | 每批独立走工程模式（设计 → 评审 → 实现），批档独立成文 |
| F3 | 分批入口路由 | 本档（+ 设计档 §7）是分批入口——不逐档裸列批档清单（免双源漂移） |
| F4 | 触碰到即处理 | 撞上结构问题的当批**不挂账**（"撞错结构就改"——工程纪律层铁律） |

## 3. 非功能性需求（硬指标）

| # | 维度 | 标准 |
|---|---|---|
| N1 | **源码文件 >500 行 = 硬限** | 无豁免通道（触发"必须拆"） |
| N2 | 源码文件 >300 行 = 主动拆分评审 | 跨档位的文件在设计里必须带拆分计划 |
| N3 | 函数档是第一判据 | 文件 ≤500 行但含 300+ 行单体函数仍不合规 |
| N4 | 文档同标准 | `docs/` 文档无 >300 字符单行（格式债同属结构债） |
| N5 | 双树覆盖 | 范围 = thincoder（CLI）+ thincoder-vscode（VSC）双仓 |
