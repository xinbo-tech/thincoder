# 崩溃捕获与取证（CRASH-REPORTS）— 需求

> 板块：崩溃捕获与取证（CLI 崩溃诊断留痕——JS 异常记录 / Node 诊断报告 / TUI stderr 捕获 / 近堆上限堆快照）。
> 需求层文档（`docs/requirements/`）。状态：**现行**（2026-09-11 建档——随 TUI-OOM-FORENSICS 批；
> F1/F2 为存量迁移（R25、批档 TUI-STDERR-CAPTURE 已入 `design/_archive/`），F3 为本批新增）。
> 设计+测试见 `../design/CRASH-REPORTS.md`（机制权威）；本档只述需求。

## 1. 总体需求

CLI 进程崩溃时（含 JS 钩子拦不住的面：V8 原生 OOM/abort、外部终止），**事故现场默认留下可检索、可回传的诊断证据**——
不依赖复现、不依赖用户事先开任何开关。目标问题：「崩在哪、谁在持有内存」必须能在事后回答；
取证能力本身不得影响正常运行（尽力面）。

证据构成（按崩溃类型）：JS 异常/未处理拒绝 → 记录文件（F1）· V8 fatal → Node 诊断报告（F1）·
外部终止/native abort → stderr 捕获（F2）· **堆耗尽 → 对象级快照（F3——本批新增）**。

## 2. 功能性需求

| # | 需求 | 说明 |
|---|---|---|
| F1 | 崩溃留痕（R25——已交付，存量迁移） | JS 异常钩子写 `crash-*.json`；`process.report` 启用（fatal 自动写 `report.*.json`）；启动「上次异常终止」提示（24h 窗）。实现：`src/crash-reports.mjs`；本批仅清理模式扩展（N3），其余零改 |
| F2 | TUI stderr 默认捕获（批档 TUI-STDERR-CAPTURE——已交付，存量迁移） | TUI 启动 = 父进程包装 spawn 子进程（自身），子 stderr tee 双写（终端 + `tui-stderr-*.log`）。实现：`src/tui/wrapped-spawn.mjs`、`bin/thincoder.mjs`（包装门）；本批仅向子进程追加一个 Node 参数（F3③） |
| F3 | **近堆上限堆快照固化**（2026-09-11 批——用户原话：「这个参数你是不是能固化在代码里……碰到的时候他们能截图发给我」） | 堆接近 V8 上限时自动落一份对象级证据（`.heapsnapshot`——回答「谁在持内存」；Node 诊断报告只有分区统计、无对象级）。**默认开启**、固化进启动链；判定面如下四条： |
| F4 | **堆遥测/看门狗**（TUI-OOM-ROOTCAUSE 批——2026-09-11） | 运行期周期采样堆用量、按**堆上限比例**给阈值预警（边缘触发——每阈值档一次）：默认开启、可关（env）、可注入（测试缝）；预警面 = stderr 行 + TUI 行 + 诊断事件；**只看不治**（不强制 GC、不阻断运行）。判定面如下四条： |
| F5 | **异常退出的终端恢复**（TUI-OOM-ROOTCAUSE 批——2026-09-11） | TUI 包装父（`wrapped-spawn.mjs`）在子进程**非零/信号退出**时向终端补发恢复序列（mouseOff / 粘贴·键盘模式复位 / 退出 alt buffer / 光标·环绕复位——与 JS 崩溃恢复序列同源）——修「V8 fatal 不走 JS 钩子 → 鼠标上报未停 → 滚动飞数字串」次生面。判定面如下三条： |

F3 判定句：

- ① **默认武装·全路径**：任意 CLI 命令（TUI 子进程 / chat / acp / 其余）启动后近上限快照已武装——
  判定 = 注入缝断言「`v8.setHeapSnapshotNearHeapLimit` 以参数 1 调用恰一次」（真快照不跑——见 N4）；
  武装点 = 入口最前 `prepareCrashReporting()`（`bin/thincoder.mjs` 单点——全部命令同源）。
- ② **可关**：`THINCODER_HEAP_SNAPSHOT` 取关值集合 {`0`, `false`, `off`, `no`}（trim + 大小写不敏感）→ 不武装；
  未设/空串/其他值 → 武装（默认开——取证默认面）。
- ③ **落点与可见**：TUI 路径（主路径 = 实测崩溃路径）快照落 `~/.thincoder/crash-reports/`
  （与既有取证物同处——经子进程 `--diagnostic-dir` 定向）；其余路径落进程 CWD（Node 默认）。
  写出时 Node 原生 stderr 行 `Wrote snapshot to <路径>`（TUI 经 F2 的 tee 上屏 + 落日志）——用户/同事可截图回传。
- ④ **代价可知**：设计档落代价与取舍——体积 / 耗时 / 额外内存 / 次数上限 / 常态开销；
  不固化 `--max-old-space-size`（改堆上限会改变崩溃时机——批次档 §1 倾向同此）。

F4 判定句：

- ① **默认武装**：入口启动后看门狗在跑（注入缝断言：定时器恰注册一次；无堆压时零输出）。
- ② **可关**：`THINCODER_HEAP_WATCH` 取关值集合同 F3②（{`0`, `false`, `off`, `no`}——trim + 大小写不敏感）→ 不启动；
  未设/空串/其他值 → 启动（默认开——遥测默认面）。
- ③ **预警形态**：堆用量跨过阈值比例（设计档定值——比例制）→ 恰一次预警行（stderr 逐字 + TUI 行
  逐字——设计档；边缘触发不重复、跨档各一次）；未跨阈值零输出。
- ④ **开销与可移植**：阈值按 `heap_size_limit` 比例（无绝对 MB 常量）；周期采样常态开销
  可忽略（设计档落数字）。

F5 判定句：

- ① **异常退出补发**：子进程非零/信号退出 → 恢复序列在父退出前下发（注入缝断言：写入串含
  `mouseOff` 与 `mainBuffer` 序列——逐字）。
- ② **正常退出零干预**：子进程 exit 0 → 不补发（子自身清理序列为准）。
- ③ **失败面**：spawn error / 包装未启用 → 零动作（不写序列）。

范围边界（F3）：不做泄漏根因修复（姊妹批 TUI-OOM-ROOTCAUSE）；不改堆上限默认值；
不改 F1/F2 既有面（N3 清理扩展除外）；VSC 端无此面（CLI 单端）；不做启动提示（设计档 D4 理由）。

## 3. 非功能性需求

| # | 维度 | 标准 |
|---|---|---|
| N1 | 尽力面不阻断 | 武装失败/快照写失败不阻断启动与运行（独立 try/catch——同 F1 纪律）；失败静默 |
| N2 | 零常态开销与零回归 | 未近上限零快照行为、零周期开销（回调仅注册一次）；F1/F2 既有行为零变化（既有崩溃链用例全绿）；非 TUI 命令除「cwd 可能出现快照文件」外行为零变化 |
| N3 | 清理与判定集 | crash-reports 内 `Heap.*.heapsnapshot` 纳入 30 天写时自清理（与 `tui-stderr-*.log` 同族）；**不计入**「上次异常终止」提示判定集（不因快照文件误报） |
| N4 | 测试口径 | 注入缝断言（武装/开关矩阵）替代真实快照；真快照不随套件跑（实测代价 236MB / 约 10s @64MB 堆——污染且拖慢）；Node API 存在性守护（Node ≥ 24 基线） |
| N5 | 遥测零常态可感 + 零回归 | 看门狗周期采样开销可忽略（设计档落数字）；关值/未武装时零额外行为；既有命令输出面除预警行外零变化 | 用例 + 设计档代价表 |
| N6 | 遥测/恢复可机判 | 均以注入缝断言（假采样器/假时钟/假写端）；不依赖真实堆压与外进程 | 新用例全绿（快层；恢复序列 mock 族与 `test/tui-stderr-capture.test.mjs` 同源） |

## 4. 范围边界（不做）

- 泄漏根因修复（姊妹批 TUI-OOM-ROOTCAUSE；**堆遥测/看门狗已由该批承接——本档 F4**）
- `--max-old-space-size` 固化或上限调整（改变崩溃时机）
- 启动提示行（写时 Node 原生行 + tui-stderr 日志 + 设计档落点表已闭环——避免常态化噪音）
- 非 TUI 路径落点改向（无运行时定向手段；不为此引入双击进程）
- VSC 端对应能力；快照对比面（n > 1）；快照压缩/自动上传
