# 交付前核对清单（父侧强制 · 2026-09-15 用户批评后建）

> 用法：**每次交付报告前逐条打勾**；缺一条 ⇒ 报告里明写「清单未满，缺 X」✗ 不得静默交付。
> 来源：2026-09-15 用户多次点名违反的提示词已有纪律（都写得明白，缺的是"行动前逐条核对"的机械步）。
> 一作者：父侧自持（非文档体系档 → 不登记 README；生命周期 = 会话级）。

## 清单（8 条）

- [ ] **C1 新档挂接** —— 新建文档必须含：归属（部分+板块）/ 配对（design↔requirements 互指）/ 上游判据回指 / 下游批次档回指；README 地图登记行交父侧落（不挂 = 孤立小岛 ✗）
- [ ] **C2 路径限定提交** —— `git commit --only <显式路径>` 或等价的显式 `git add <逐文件>`；**无目录通配** ✗；commit 声明不得含未列文件
- [ ] **C3 归因先想"用户在写"** —— 工作树非本会话 M/?? ⇒ 先归因可能为用户在写（尤其 `thincoder-vscode/docs/COMPETITIVE_ANALYSIS.md`）✓ 有证据才归别的实例；不代提交用户档
- [ ] **C4 声明=实际** —— `files` 声明覆盖真实写域；目录级/开放域声明 = 缺陷（要么收窄、要么逐文件列）
- [ ] **C5 迁移三件同批** —— 位置变更批 = 位置 + 引用改指 + 机检射程，同批完成（缺射程 = 无守卫窗口+假绿 ✗）；新目录 ⇒ 同批入扫描器
- [ ] **C6 段落自写 / 不代写** —— 批次档六段各作者自写；父侧代写必打标；他线/用户在写档一字不碰
- [ ] **C7 已裁不重问** —— 派单/提问前先查既有裁定（memory/设计档/台账）；已裁 ⇒ 引用出处直接执行；真无裁定才上问（一次一件 ✗）
- [ ] **C8 方法/交付闭环** —— 凡处置 =「读原档 → 判 → 落 → 验证读数」；N=K+L+M 类闭合；零丢失证明；声称已派/已做 = 同轮有调用或读数
