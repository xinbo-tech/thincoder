# 结构债（STRUCTURE-DEBT）— 需求

> 板块：结构债（文件 / 函数粒度与文档格式的横切约束）。需求层文档（`docs/requirements/`）。
> 定位：本端结构债的**需求层登记面**（此前缺失——本档补建）；约束来源 = 工作区 `AGENTS.md`（文件档线）+
> 纪律层提示词（`src/prompts/discipline-normal.md` 代码结构判据节）+ `scripts/check-doc-width.mjs`（文档面机检）。

## 1. 总体目标

结构债的病痛与治疗时机**错开**（平时无症状、撞上才暴露），因此必须靠**文档显式追踪**防「挂账不处理」。
本板块规定：结构债如何度量、何时必须处理、每批如何独立立项。

## 2. 功能性需求

| # | 需求 | 说明 |
|---|---|---|
| F1 | 显式追踪 | 结构债评估与清理在文档面显式记录（本档 = 需求层登记面；具体清理随批落批次档 / 归属设计档） |
| F2 | 每批独立立项 | 每批独立走工程模式（设计 → 评审 → 实现），批档独立成文 |
| F3 | 触碰到即处理 | 撞上结构问题的当批不挂账——当场就地修正，禁止叠最小补丁掩盖症状 |
| F4 | 不建平行登记面 | 同一机制只在一处详述（单一权威源）——结构债不在多处各立清单 |

## 3. 非功能性需求（硬指标）

| # | 维度 | 标准 |
|---|---|---|
| N1 | 源码文件 >500 行 = 硬限 | 无豁免通道（触发「必须拆」）；跨档位文件在设计里必须带拆分计划 |
| N2 | 源码文件 >300 行 = 主动拆分评审 | 300 行 = 建议线（advisory），触线即评估 |
| N3 | 函数档是第一判据 | 文件 ≤500 行但含 300+ 行单体函数仍不合规（函数随生长即分解，不先写整体再拆） |
| N4 | 文档同标准 | `docs/` 文档无 >300 字符单行（表格行豁免）——批量检查 `scripts/check-doc-width.mjs` |
| N5 | 双树覆盖 | 范围 = 本仓（thincoder-vscode）+ CLI 仓（thincoder）——两仓同标准、各自检查 |
