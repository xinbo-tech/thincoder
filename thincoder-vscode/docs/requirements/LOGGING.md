# 日志（LOGGING）— 需求

> 板块：诊断事件日志（常驻事件骨架日志——机制在位）。需求层文档（`docs/requirements/`）。
> 定位：本仓 `src/log.mjs`（197 行）的**需求层登记**——机制实况记录；实现契约逐条住该模块头注（`src/log.mjs:1-30`）。W1 已迁核——现体 `thincoder-core/log.mjs:1`。
> 跨端：与 CLI 仓 `src/log.mjs` 同构镜像（语义同源、各自实现）——共享 `~/.thincoder/logs/`、同格式、同事件面。W1 已迁核——现体 `thincoder-core/log.mjs:1`。

## 1. 总体目标

用户实测问题（「子代理完成但主会话回合直接结束、无消化」）暴露：每次诊断都靠**临时插桩再删**——成本高、覆盖窄、撤后无痕。
本机制 = **常驻诊断事件日志**（保留一天）：问题发生时直接 `tail` / `grep` 定位断点——根治插桩循环。

## 2. 功能性需求

| # | 需求 | 验收语义 |
|---|---|---|
| F1 | 事件骨架日志 | 回合 / 工具 / 子代理 / LLM 调用的关键事件序列（时间戳 + 事件 + 关键参数 + 耗时）逐行 JSON 落盘 |
| F2 | B 级摘要 | LLM 响应头 ≤300 字符、工具结果头 ≤200、错误消息 ≤200——内容片段可查（空回复 / 乱码可见）；截断处带 `…` 标记 |
| F3 | 按天轮转 + 自动清理 | 文件名 `agent-YYYY-MM-DD.log`；**每进程每日首次写事件**时机会式删除超龄档（长驻 extension host 的启动清理覆盖不到）——用户零手动维护 |
| F4 | 覆盖面 | 主回合骨架（开始 / 结束 / 耗时 / 结果 kind）、LLM 调用（provider / 模型 / 耗时 / 状态——无内容）、工具调用（名 / 耗时 / 结果 kind）、子代理 spawn / 完成、挂起态进出 |
| F5 | 零侵入 | 写日志 fire-and-forget——失败静默，绝不影响主流程 |
| F6 | 两端一致 | 与 CLI 同事件面、同格式、同目录（共享 `~/.thincoder/logs/`）——镜像实现 |
| F7 | 性能 | 每事件一次小 append（<1KB）；只在事件边界记（非每 token）——正常回合事件数 <1000 |

## 3. 非功能性需求

| # | 维度 | 标准 |
|---|---|---|
| N1 | 静默降级 | 写失败（磁盘满 / 权限）进程内首次失败即置死（`_dead`）——当日不再尝试，不逐事件空转 |
| N2 | 行上限 | 单事件行 <512 字符；字符串字段上限兜底（head 300 / err 200 / 其余 120），超长丢可选字段 |
| N3 | 敏感零落盘 | 字段名精确黑名单（apiKey / designToken / password / secret / token，大小写不敏感 + 防御性 authorization / proxy / proxyUri）整字段丢弃；内容只扫密钥形态（`sk-` / `Bearer` / `key=`）截断到形态前；工具事件不记 args、URL 不入事件 |
| N4 | 保留窗口 | 最近 1 天（今天 + 昨天保留，更早删除；以文件名日期为龄基准） |
| N5 | 测试隔离 | `node --test` 进程（`NODE_TEST_CONTEXT`）默认不写盘；`THINCODER_LOG_DIR` 可强制指定目录（用例隔离用） |
